# 01. 采购退货现状与问题（As-Is）

> 依据当前代码与 schema：`lychee-erp-wm` / `lychee-erp-scm` / `lychee-erp-fi` / `lychee-doc`。

---

## 1. 业务缺口

P2P 已落地：

```text
PO ─► GR（过账：库存 + / GR/IR）─► AP（从收货开票）
```

内部领用已有反向单：`stock_issue_returns`（退料）。  
**采购收货没有反向业务单。** 错收只能整单冲销 `reverseGoodsReceipt`；质量退回、部分退供应商没有单据。

`WM_schema_design.md` 已划清边界：退料单**不是**客户退货或采购退货。流水账预留了采购退货类型，但没有表、没有 API、没有页面。

---

## 2. 现有单据各管什么

| 单据 | 模块 | 方向 | 现网能力 |
|------|------|------|----------|
| `goods_receipts`（`PURCHASE`） | WM | 入库存 | 从 PO 行汇入、过账、整单冲销 |
| `stock_issue_returns` | WM | 入库存 | 冲回内部领料；一对一原领料 |
| `stock_issues` 冲销 | WM | 对调进出 | 原领料有草稿/已过账退料则禁止 |
| GR 冲销 | WM | 出库存 + 回减 PO 已收 | **不**检查已开票、**不**检查是否已有退货 |
| AP 发票 | FI | 从 GR 开正数票 | 无贷项 / 红字；`source_doc_type` 仅 `RECEIPT` / `PURCHASE_ORDER` |

采购退货与退料的差别：要回写 PO 已收量、冲回暂估，并受 AP 已开票数量约束。

## 3. 已占位、未实现

### 3.1 流水账 `VENDOR_RETURN`

`StockTransactionType.VENDOR_RETURN`、`stock_transactions.transaction_type` 注释已列出。  
语义是采购退货出库，但**没有任何单据过账写入**。命名与「采购退货 / `PURCHASE_RETURN`」不一致，本波改名（见 `02` / `03`）。

### 3.2 收货来源 `PURCHASE_RETURN_ITEM`

`GoodsReceiptSourceDocType.PURCHASE_RETURN_ITEM` 与客户退货 `CUSTOMER_RETURN_ITEM` 并列。  
`GoodsReceiptGenerationServiceImpl` 对两者都是 `UnsupportedOperationException`。

`StockTransactionLedgerServiceImpl.typeForGoodsReceiptLine`：

```text
PURCHASE_RETURN_ITEM → VENDOR_RETURN
CUSTOMER_RETURN_ITEM → CUSTOMER_RETURN
```

这是错误对称：客户退货经收货入库说得通；采购退货是出库，不应做成收货转换。

### 3.3 收货冲销已把 `VENDOR_RETURN` 列入成本回取类型

`GoodsReceiptServiceImpl.reverseGoodsReceipt` 回取单价时包含 `VENDOR_RETURN` / `CUSTOMER_RETURN`。  
没有采购退货单时，这两项不会命中；说明早期曾设想「退货也走收货单」。

### 3.4 成本分析

`chartExp/财务/08.成本方法实现计划.md`：采购成本分析 V1 **不含**采购退货。本波不改分析口径，过账后分析会偏大，二期再扣减。

## 4. 收货过账今天做什么

`GoodsReceiptServiceImpl.postGoodsReceipt`（`PURCHASE_ORDER_ITEM`）：

1. 冻结 PO 单价 / 税 / 币别到收货
2. 库存物料：`applyGoodsReceipt`（`GOODS_RECEIPT`，+）
3. `updateReceivedQuantity(+txnQty)` → PO 行 / 主档 `PARTIAL` / `COMPLETED`
4. pegging：`PURCHASE_ORDER`（行）→ `GOODS_RECEIPT`（收货行）
5. `postGoodsReceipt` 凭证：借存货、贷 GR/IR、价差 `PRICE_VAR`（数量记账政策下整单跳过）

冲销：回减已收、删 pegging、反向库存、冲凭证。  
**不看** `invoiced_quantity`，**不看**下游退货（尚不存在）。

`updateReceivedQuantity`：已收减到负时**静默钳到 0**；行/表头状态按已收 vs 订购重算为 `APPROVED` / `PARTIAL` / `COMPLETED`，**不保留** `CLOSED`。PO 关单 API 尚未落地，但枚举与 MRP 已排除 `CLOSED`。超收由收货汇入校验（`is_unlimited_over_receipt` 默认 true），不在 `updateReceivedQuantity` 内。

收货行已有 `invoiced_quantity` / `invoice_status`。AP 从收货开票只带 `transaction_quantity − invoiced_quantity`。没有 `returned_quantity`。

`invoiced_quantity` **不是**等发票过账才回写：`ApInvoiceServiceImpl` 在发票行新增 / 改数量 / 删除（含 **DRAFT**）时就调用 `RemoteGoodsReceiptServiceImpl.updateInvoicedQuantity`。因此该列实际是「已被 AP 行占用（含草稿）」。强制上限只在 `updateInvoicedQuantity`：`newInvoiced ≤ transaction_quantity`，**不看**已退数量。从收货生成发票走 `getGoodsReceiptForApInvoice` 的 `billableQty`，但发票行仍可手改数量绕过该封顶。

## 5. 退料单已验证的模式（应对齐）

`stock_issue_returns`：

- 一张退料单只对一张已过账领料
- 明细必须挂原领料行；同单内一行对一行
- 仓、批号锁定；`stock_type` 可改
- `stock_issue_items.returned_quantity`（基本单位）；可退 = 原量 − 已退 − 其他草稿
- 过账写 `STOCK_ISSUE_RETURN`，成本取原领料流水
- 冲销退料回减 `returned_quantity`；原领料有退料则禁止冲销
- 状态 `DRAFT` / `POSTED` / `REVERSED`
- API：`returnable-issues`、`returnable-items`、`items/batch-from-issue`、`post` / `reverse`

采购退货应对齐这套，原单换成采购收货。

---

## 6. 应付现状（约束退货数量）

```text
收货：借 存货 / 贷 GR/IR
发票：借 GR/IR / 贷 应付
```

- 无 AP 贷项类型，无负向 `quantity` 约定
- 已开票后再退货且只冲库存 / GR/IR → 应付仍在，账不平
- 从收货开票已按未开票剩余计算，退货后必须同步压低可开票量（本波用「只退未开票」保证）

## 8. 若继续用「负收货」会错什么

把采购退货做成 `goods_receipts` + `PURCHASE_RETURN_ITEM`：

- 收货主档 `invoice_status`、从收货开 AP、GR/IR 方向都按入库假设
- 与已落地的退料「独立反向单」不一致
- 中文 / 枚举继续混用 `VENDOR_RETURN` 与采购退货

结论：独立 `purchase_returns`，流水账写 `PURCHASE_RETURN`。
