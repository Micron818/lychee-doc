## 1. 审查结论

| 问题 | 结论 |
|------|------|
| 能否做成负收货 / `PURCHASE_RETURN_ITEM` 转换 | **否**；独立 `purchase_returns` |
| 中文 / 流水账能否一个叫采购退货、一个叫 `VENDOR_RETURN` | **否**；一律 `PURCHASE_RETURN` |
| 已开票能否先退货再补贷项 | **否**；V1 只退未被 AP 占用（含草稿）；贷项只预留接口 |
| 锚点对 PO 还是对收货 | **一对一已过账采购收货** |
| 模块 | **WM**，菜单 `/wm/purchase-returns` |
| 退货后是否自动关 PO | **否**；`COMPLETED` 可回 `PARTIAL`（MRP 再买）；`CLOSED` 只改已收不改状态 |
| AP 闸门 | `getGoodsReceiptForApInvoice` **和** `updateInvoicedQuantity` 都必须扣已退单据量 |

编码从本文件 §5 按模块推进。

## 2. 已锁定决策

| # | 决策 | 值 |
|---|------|-----|
| 1 | 正式名称 | **采购退货 / `PURCHASE_RETURN`**。禁止「供应商退货」、`VENDOR_RETURN`、`VENDER_RETURN` |
| 2 | 已开票 | 可退 = `min(未退单据量, 未占用单据量)`。`invoiced_quantity` = AP 行占用（含 DRAFT）。须先改/删草稿或冲发票 |
| 3 | 贷项 | 本波不做；`RemotePurchaseReturnCreditMemoService` V1 只断言未占用，`afterPosted` no-op |
| 4 | 锚点 | 一张退货单 = 一张 `POSTED` + `PURCHASE` 收货 |
| 5 | 仓 / 批 | 锁定原收货行；库存不足拒绝过账 |
| 6 | `stock_type` | 默认原行，**允许改** |
| 7 | 模块 / 菜单 | WM，`/wm/purchase-returns` |
| 8 | PO | 回减 `received_quantity`；不自动 `CLOSED`。`COMPLETED`→`PARTIAL` 预期。`CLOSED` 只改数量不改状态 |
| 9 | MRP | 非 `CLOSED` 时已收减少后开量变大，允许再买 |
| 10 | `PURCHASE_RETURN_ITEM` | **删除**，不实现收货转换 |
| 11 | `VENDOR_RETURN` | **改名为** `PURCHASE_RETURN`。收货冲销回取列表只删 `VENDOR_RETURN`，不加入 `PURCHASE_RETURN` |
| 12 | 原收货冲销 | 存在草稿或已过账采购退货则禁止；`invoiced_quantity > 0` 一并禁止 |
| 13 | V1 范围 | 仅采购收货；不含委外 / 杂项 / 客户退货 / 换货 |
| 14 | 赠品 | 只出库，不冲 GR/IR |
| 15 | 成本分析 | 本波不扣减退货 |
| 16 | pegging | 不新增；用 `original_receipt_item_id` |
| 17 | 已退单据量 | `SUM(POSTED 退货行.transaction_quantity)`，禁止 `returned_quantity` 反换算 |
| 18 | AP 回写 | `updateInvoicedQuantity`：`newInvoiced ≤ txn − returnedTxn` |
| 19 | 冲销退货回加已收 | 与收货汇入同一套超收校验；将超则拒绝 |
| 20 | 凭证成本 | FI 使用原收货流水 `unit_cost`；最后一笔退完该行用剩余 GR/IR 金额清尾 |
| 21 | `approved_by` | 过账人，对标退料 |
| 22 | 期间 | `return_date` = 凭证日期；财务关帐随 journal。数量记账不新做库存关帐 |

## 3. 实现约定

### 3.1 数量

与退料同一计算器风格（可抽 `PurchaseReturnQuantityCalculator`）：

```text
postedReturnedTxn = SUM(POSTED 退货行.txn)
unreturnedTxn     = gr.txn − postedReturnedTxn − otherDraftTxn
unreturnedBase    = gr.base − gr.returned − otherDraftBase
uninvoicedTxn     = gr.txn − gr.invoiced
returnableTxn     = min(unreturnedTxn, uninvoicedTxn)   // FOC：只用 unreturnedTxn
```

过账：`txn ≤ returnableTxn` 且 `base ≤ unreturnedBase`。  
用户改退货数量时 txn→base 走现有单位服务，禁止写死比率。用 `compareTo`。  
**不要**把 `returned_quantity` 换回单据单位去算可开票。

过账回写 PO 用 **单据单位** `−transaction_quantity`（与收货过账 `+transaction_quantity` 对称）。

### 3.2 库存

对标 `StockOnHandInventoryService.applyStockIssue` 出库，类型 `PURCHASE_RETURN`。  
成本：`stockLedgerUnitCostResolver.findPostedUnitCostsBySourceDocItem(GOODS_RECEIPT, originalReceiptId, GOODS_RECEIPT)`。  
非库存物料：不过 `stock_on_hand`，仍回写已退与 PO。

数量记账政策：与收货相同，跳过评价分录。

### 3.3 凭证

新 `RemotePurchaseReturnFinanceService.postPurchaseReturn`：收货 GR/IR 的反向（贷存货、借 GR/IR、价差反向）。  
请求必须带每行冻结 `unitCost`（原收货流水）和本行冲回 PO 金额；FI **禁止**再查当前标准成本。  
该收货行退完时 PO 金额用剩余未冲（原行未税 − 已过账退货已冲），见 `02` §3.5。  
冲销走现有 journal reverse，不要改原收货 `journal_entry_id`。`postDate` = `return_date`。

### 3.4 贷项预留

```text
com.lychee.erp.common.service.RemotePurchaseReturnCreditMemoService

void assertReturnableAgainstInvoice(Long receiptItemId, BigDecimal returnTxnQty);
void afterPosted(Long purchaseReturnId);
void afterReversed(Long purchaseReturnId);   // V1 no-op；与 afterPosted 成对
```

V1 实现放在 FI（或 common 的空委托 + FI 覆盖）：只检查 `returnTxnQty ≤ uninvoicedTxn`（`invoiced` 含 AP 草稿）。  
**禁止**用 `// TODO` 代替类型。测试断言：已被占用的数量调用 `assert*` 抛 `ValidationException`。

### 3.5 可开票

两处都改，缺一不可：

1. `getGoodsReceiptForApInvoice`：`billableQty = txn − invoiced − returnedTxn`；`returnedTxn = SUM(POSTED 退货行.txn)`。剩余 ≤ 0 跳过；全部跳过用「无剩余可开票」i18n
2. `updateInvoicedQuantity`：`newInvoiced ≤ txn − returnedTxn`（替换现网只比 `transaction_quantity`）

过账 / 冲销退货后按 `billableTotal = txn − returnedTxn` 刷新行与表头 `invoice_status`。

### 3.6 原收货冲销

`GoodsReceiptServiceImpl.reverseGoodsReceipt` 开头：

1. 存在 `purchase_returns` 且 `original_goods_receipt_id` 匹配、`status ∈ {DRAFT, POSTED}` → 拒绝
2. 任一明细 `invoiced_quantity > 0` → 拒绝（含 AP 草稿占用）

回取成本类型列表：**只删** `VENDOR_RETURN`，不要加入 `PURCHASE_RETURN`。

### 3.7 PO 已收回写（本波 SCM 小改）

`PurchaseOrderItemServiceImpl.updateReceivedQuantity`：

- 行或表头已是 `CLOSED`：更新 `received_quantity`（仍不得为负），**跳过**状态重算
- 其余保持现网：0 → `APPROVED`，未满 → `PARTIAL`，满 → `COMPLETED`

冲销采购退货回加已收前：按该 PO 行 `is_unlimited_over_receipt` / `over_receipt_tolerance` 做与 `GoodsReceiptGenerationServiceImpl` 相同的上限判断；将超则 `ValidationException`。校验放在 WM 过账或 SCM remote 均可，须与收货汇入同一套数字。

### 3.8 命名检查

合并前全文搜索，不得残留业务含义上的：

- `VENDOR_RETURN` / `VENDER_RETURN`
- 「供应商退货」（locale / 注释 / 文档）
- `PURCHASE_RETURN_ITEM`

测试类名、i18n key 用 `purchase_return` / `purchaseReturn`。

## 6. 验收

1. 已过账采购收货 100，未开票 → 退 40 过账：库存 −40，`returned_quantity=40`，PO 已收 −40，流水账类型 `PURCHASE_RETURN`，有冲回凭证（成本启用时）。
2. 再退 60 成功；再退拒绝。
3. 收货 100 已开票 60（含 AP **草稿**占用）→ 最多退 40；退 50 被拒。草稿占用提示改/删发票行，已过账提示先冲发票。
3b. 退货 40 已过账后，AP 草稿把行数量改成 100 → `updateInvoicedQuantity` 拒绝。
3c. 收货 100 退 40 后再从收货开 AP → 可开票 60；已退满且未占用 → 无剩余行。
4. 赠品行：出库成功，无 GR/IR 行。
5. 原仓原批库存不足 → 过账失败；改 `stock_type` 后若该状态有库存则成功。
6. 仓 / 批号 API 传入与原行不一致 → 拒绝。
7. 原收货有草稿或已过账采购退货 → 收货冲销失败。
8. 收货行已开票 → 收货冲销失败。
9. 冲销采购退货单：库存、已退、PO 已收回复；原收货仍为 `POSTED`。
9b. 收 100 → 退 40 → 再收 40（已收回 100）→ 冲销该退货：若 PO 行无上限超收则成功（已收 140）；若超收关闭且将超则拒绝。
9c. 行/表头 `CLOSED` 时退货成功、已收减少，状态仍为 `CLOSED`。
10. 从收货开 AP：可开票 = 收货 − 已开 − 已过账退货。
11. 删除 DRAFT 退货后，可退数量立即恢复。
12. 全文无 `VENDOR_RETURN` / `PURCHASE_RETURN_ITEM` / 「供应商退货」作为正式名。
13. `from-source` 不再出现 `PURCHASE_RETURN_ITEM` 分支。
14. 委外收货不出现在 `returnable-receipts`。
