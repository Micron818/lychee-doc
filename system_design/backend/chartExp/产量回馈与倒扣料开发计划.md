# 产量回馈与倒扣料 (Production Report & Backflush) 开发计划

基于规范 ERP 的多模组单体架构设计，为确保库存帐务的严谨性和跨模组边界的清晰，PP 模组的产量回馈不会直接写底层的 `StockTransaction`，而是通过生成 WM 模组的 `GoodsReceipt`（成品入库单）和 `StockIssue`（倒扣料发料单）来驱动库存变动。

以下是逐步实现系统功能的开发计划：

## 阶段一：基础与通用层准备 (Foundation & Common Layer)
**目标：提供跨模组所需的枚举支持与 Remote 接口契约。**

1. **更新全局枚举类**
   - 修改 `GoodsReceiptSourceDocType`，新增 `PRODUCTION_REPORT` (用于成品入库标识)。
   - 修改 `StockIssueSourceDocType`，新增 `PRODUCTION_REPORT_COMPONENT` (用于倒扣料发料标识)。
2. **定义 PP 模组内部枚举**
   - 在 `lychee-erp-pp` 中新增 `ProductionReportStatus` 枚举 (状态包含：`DRAFT` 草稿、`POSTED` 已过账、`CANCELLED` 已取消)。
3. **定义跨模组接口契约 (Common 模组)**
   - 在 `lychee-erp-common` 模块下定义 PP 调用 WM 的 Remote Service（例如 `RemoteProductionInventoryService` 或复用现有 Remote Service 的扩展），负责封装：
     - a. 根据回馈单数据生成成品入库单并自动过账 (`GoodsReceipt`)
     - b. 根据回馈明细数据生成倒扣料发料单并自动过账 (`StockIssue`)

## 阶段二：PP 模组实体与持久层 (Entity & Repository)
**目标：完成产量回馈在关系型数据库中的实体映射与基础数据存取。**

1. **建立 JPA 实体类**
   - 创建 `ProductionReport.java` (对应表 `production_reports`)。
   - 创建 `ProductionReportComponent.java` (对应表 `production_report_components`)。
2. **建立 Spring Data JPA Repository**
   - `ProductionReportRepository`
   - `ProductionReportComponentRepository`

## 阶段三：API 模型与业务服务设计 (DTO & Service Logic)
**目标：实现 PP 模组计算倒扣料逻辑与草稿保存功能。**

1. **定义 DTO (Data Transfer Object)**
   - Request DTOs: `ProductionReportRequest`, `ProductionReportComponentRequest` (允许用户调整)。
   - Response DTOs: `ProductionReportResponse`, `ProductionReportComponentResponse`。
2. **定义 Mapper (MapStruct)**
   - 创建 `ProductionReportMapper` 负责 Entity 与 DTO 的互相转换。
3. **实现核心服务 `ProductionReportService`**
   - **自动计算接口**: `calculateBackflushComponents(orderId, goodQuantity, scrapQuantity)` 
     - 逻辑：根据 BOM 配比计算 (`required_quantity` / `planned_quantity` * (good + scrap))，并过滤出 `isBackflush = true` 的组件。
   - **保存草稿接口**: `createProductionReport(...)` 和 `updateProductionReport(...)`。
     - 逻辑：保存单据，状态设为 `DRAFT`。

## 阶段四：核心过账与跨模组流转 (Core Posting & Integration)
**目标：完成产量回馈单的过账逻辑，驱动 WM 发生库存异动并回写工单进度，建立关联追踪 (Order Pegging)。**

1. **WM 模组实现 Remote 服务**
   - 在 WM 模组中实现阶段一定义的 `RemoteProductionInventoryService`。
   - 内部封装调用 `GoodsReceiptService` 的生成与过账逻辑，返回包含单号与明细 ID 的 ResponseDTO (如 `RemoteProductionReceiptResponseDTO`)。
   - 内部封装调用 `StockIssueService` 的生成与过账逻辑，返回包含单号与明细 ID 列表的 ResponseDTO。
2. **PP 模组实现过账逻辑 (`postProductionReport`)**
   - 获取 `ProductionReport` 及其倒扣料明细，验证状态是否可过账。
   - **调用 WM API 1**: 发送成品数据，执行入库，获取生成的 `ReceiptNo` 和 `ReceiptItemId`。
     - **建立 Pegging 关联**: 在 PP 侧保存 `OrderPegging` 记录，建立 `PRODUCTION_ORDER` (Demand) 与 `GOODS_RECEIPT` (Supply) 之间的追溯关系。
   - **调用 WM API 2**: 发送倒扣料数据，执行发料，获取生成的 `IssueNo`。
   - **回写 PP 状态**: 
     - 累加 `ProductionOrder` 的 `completed_quantity` 和 `scrapped_quantity`。若达到计划量，更新工单状态为 `FINISHED`。
     - 累加 `ProductionOrderComponent` 中各个倒扣料组件的 `issued_quantity`。
     - 更新回馈单状态为 `POSTED`，将 `ReceiptNo` 和 `IssueNo` 存入新增加的字段中。
   - *（注：整个 `postProductionReport` 方法必须处于事务 `@Transactional` 环境中）*

## 阶段五：API 暴露与前端对接测试 (Controller & Testing)
**目标：提供 Restful API，并进行全流程防呆与完整性测试。**

1. **实现 Controller 层**
   - 创建 `ProductionReportController` 暴露所需端点 (Endpoint)。
2. **全流程功能测试**
   - 测试倒扣料数量是否准确。
   - 测试线边仓库存不足时，过账是否被 WM 拒绝，并且 PP 的业务回滚（回馈单保持 DRAFT）。
   - 测试工单完成度累加与状态自动变更。
