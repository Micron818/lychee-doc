# 供应商退款（Supplier Refund）· 完整目标设计

> **本期不要按本目录编码。** 开发入口是 [../供应商退款-主流程V1](../供应商退款-主流程V1/README.md)（无行过账、核销状态机、换日冲销、付款汇兑前置等均推迟）。  
> 本目录保留完整目标口径，供后续增强对照，不要与 V1 混用。

本目录描述 **已付款 AP 发生数量型采购退货后，供应商向公司退回现金** 的处理。

供应商退款是资金流入，复用 `payments`：

```text
payment_type    = RECEIPT
partner_type    = SUPPLIER
payment_purpose = SUPPLIER_REFUND
```

它核销的是应付贷项中由已付金额形成的 **待退款开放金额**，不是作废原付款，不重复处理采购退货，也不再次回减收货占用。

## 已锁定范围

- 本期只做：已付 AP → 应付贷项 → 供应商现金退款。
- 不做：供应商预付款退回、贷项冲抵未来 AP、客户退款、银行流水导入。
- 原付款保留 `POSTED`；只有原付款本身错误或银行交易被撤销时才走付款 VOID。
- 退款资金可先到账成为未分配供应商退款，再核销已过账应付贷项。
- 一张退款收款可核销同公司、同供应商、同币别的多张贷项。
- 退款使用退款日汇率；按贷项历史汇率逐行计算已实现汇兑损益。
- 汇兑组件按可复用方式设计，但本期只接供应商退款，不顺带改造普通 AP/AR 收付款。
- 普通 AP 付款汇兑正确落地是“启用外币供应商退款”的前置；本位币退款不受影响。
- 若原 AP 存在有效付款折扣，本期禁止形成待退款开放金额；“有效”指 POSTED 付款中引用该 AP 的 APPLIED 行，详见 [02-目标流程.md](./02-目标流程.md#32-贷项过账拆分)。
- 后补核销使用独立核销日；撤销退款核销或退款 Payment 时由用户选择开放期间的冲销日。

## 单据分工

| 单据 | 负责 | 不负责 |
|------|------|--------|
| 应付贷项 | 冲减采购成本/暂估与应付；释放收货开票占用；形成待退款开放金额 | 银行资金 |
| 采购退货 | 库存出库、冲回 GR/IR | 应付与银行资金 |
| 供应商退款 | 银行流入、核销贷项待退款金额 | 库存、税额、收货占用 |
| 付款 VOID | 撤销错误的原付款 | 表达一笔后来发生的真实退款 |
