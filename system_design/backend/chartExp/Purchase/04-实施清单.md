## 3. 审查补上的实现约定

### 3.1 `convert_status` 生产 / 采购共用

列在 `mrp_results` 上，不能只给 PURCHASE 用。

| `suggested_action_type` | 转出 | `converted_quantity` | `convert_status` |
|-------------------------|------|----------------------|------------------|
| `PURCHASE` | 可部分转 PO | 累加本次量 | 由数量派生 |
| `PRODUCTION` | 仍整行转 PLO | 转出时 = `required_quantity`；回退 PROPOSED PLO 时减回 | 未转 `OPEN`；转完 `CONVERTED`（无 PARTIAL） |

新结果一律 `converted_quantity = 0`，`convert_status = OPEN`。

派生（`BigDecimal.compareTo`，不要用近似浮点）：

```text
converted <= 0     → OPEN
remaining > 0      → PARTIAL
remaining <= 0     → CONVERTED
```

清理：`convert_status = OPEN` 的结果可删（含未转的 PRODUCTION）。  
`PARTIAL` / `CONVERTED` **不得**进入 `resultsToDelete`，**不得**删其 `MRP_RESULT → PURCHASE_ORDER` / `PLANNED_ORDER` pegging。  
`PROPOSED` PLO 对应的已转 PRODUCTION 结果：维持现网 `findConvertedButUnfirmedResultIds`（改查 `convert_status = CONVERTED` + PLO `PROPOSED`）。

删除 MrpRun：该 Run 下存在 `convert_status <> OPEN` 则拒绝（补上布尔时代 PARTIAL=`false` 仍能删 Run 的洞）。

### 3.2 「该厂最新 Run」

对工厂 `F`：

```text
COMPLETED + OPERATIVE
AND (factory_id = F OR factory_id IS NULL)
按 id 倒序取 1 条
```

全厂 Run（`factory_id` 空）对所有厂都算「覆盖该厂」。之后若只跑了厂 A，则 A 的最新是 A 的 Run，其余厂仍是那次全厂 Run。

`from-mrp-results`：每个 `mrpResultId` 的 `mrpRunId` 必须等于其 `factoryId` 按上式算出的最新 Run，否则整批失败。

SIMULATION 仍不可创建，工作台不必处理。

### 3.3 数量账跨模块 API

废弃整行 `revertMrpResults`（MRP PR 删除路径一起下线）。

`RemoteMrpResultService` 增加：

```text
applyConvertedQuantity(mrpResultId, delta)   // 加锁行；重算 convert_status；不得把数量打成负数或超过 required
findPendingPurchaseItems(...)                // 各厂最新 Run + PURCHASE + remaining > 0
assertLatestOperativeRun(mrpResultId)        // 转单校验
```

SCM 在转 PO、删 DRAFT 行/单、改 DRAFT 行订购量时调用，对标 `PurchaseRequisitionService.updateOrderedQuantity`。

同一请求里同一个 `mrpResultId` 可出现多次：按请求顺序扣 remaining，Σ ≤ 原 remaining。

### 3.4 DRAFT PO 改数量

**允许**改 `ordered_quantity`（与现请购汇入行一致），但必须同步：

1. 改 pegging `pegged_quantity`
2. `applyConvertedQuantity(delta)`
3. 增量不得超过该结果 remaining；减量后行数量 > 0（减到 0 请删行）

`MRP` 类型仍 **禁止手键新增行、禁止汇入 PR**。单价、税率、预计交期可改。

`expected_delivery_date` 生成时必填（默认同需求日）。现网 `findOpenPurchaseOrders` 在收货日为空时 **跳过该行**，空日期等于没占供给。

### 3.5 起订量

来源清单 `min_order_quantity > 0` 时：`convertQuantity < MOQ` 且 `convertQuantity < remaining` → 拒绝该行。  
`convertQuantity == remaining`（尾数）允许低于 MOQ。

### 3.6 模块边界

| 动作 | 归属 |
|------|------|
| 工作台查询、`from-mrp-results`、`from-pr-items`、PO 明细工具栏 | SCM |
| 结果 remaining / convert_status / 最新 Run | PP，经 `RemoteMrpResultService` |
| 建 PO | SCM；**不要**让 PP 依赖 SCM 实体 |
| 计划员入口 | 前端跳转 `/scm/purchase-orders?tab=mrp`（可带 `factoryId`），不强制做 PP `convert-to-purchase-orders` |

权限：工作台、转单、计划员「前往采购工作台」均用现有 `/scm/purchase-orders:create`（跨页须显式 `pathName`）。来源清单另挂 `/scm/material-suppliers:*`（标准 CRUD）。  
**不要**再挂独立菜单 `/scm/purchase-proposals`、`/scm/pr-proposals`。

### 3.7 清理时禁止误删 pegging

`cleanupPreviousRunArtifacts` 现网会对 `resultsToDelete` 执行：

- `deleteByDemandTypeAndDemandIdIn(MRP_RESULT)` → 会拆掉 Result→PO
- `deleteBySupplyTypeAndSupplyIdIn(MRP_RESULT)` → 会拆掉 FO→Result

因此 **PARTIAL/CONVERTED 不得进入该列表**。停掉 `findOldMrpRequisitionItemIds` / `deleteOldMrpRequisitions`。

供给：`RemoteMrpSupplyServiceImpl.OPEN_PO_STATUSES` 加入 `DRAFT`。PR 侧仍只要 `APPROVED`/`PARTIAL`。
