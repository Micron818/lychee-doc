# 01. 客户退货现状与问题（As-Is）

> 依据当前代码与 schema：`lychee-erp-sd` / `lychee-erp-wm` / `lychee-erp-fi` / `lychee-doc`。  
> 采购侧反向链已落地，见 [采购退货](../采购退货/README.md)、[应付贷项](../应付贷项/README.md)、[供应商退款-主流程V1](../供应商退款-主流程V1/README.md)。

---

## 1. 业务缺口

O2C 已落地：

```text
SO ─► 交货单(RELEASED/DELIVERED) ─► 领料 SALES_DELIVERY（过账：库存 − / COGS）─► AR（从交货开票）─► 收款
```

内部领用已有反向单：`stock_issue_returns`（退料），且 **明确排除** `SALES_DELIVERY`。  
采购收货已有反向单：`purchase_returns`。  
**销售出库没有反向业务单。** 错发只能整单冲销领料；质量退回、部分退客户没有单据。

`WM_schema_design.md` 已划清：退料不是客户退货；流水账预留了 `CUSTOMER_RETURN`，但没有表、没有 API、没有页面。

---

## 2. 现有单据各管什么

| 单据 | 模块 | 方向 | 现网能力 |
|------|------|------|----------|
| `deliveries` | SD | 商业出货 | 从 SO 行汇入；`issued_quantity` 由领料回写；`invoiced_quantity` 由 AR 占用（含草稿） |
| `stock_issues`（`SALES_DELIVERY`） | WM | 出库存 + COGS | 仓/批号在领料行；过账写 `STOCK_ISSUE`；`issueCallback` 回写交货已发与 SO 已交 |
| `stock_issue_returns` | WM | 入库存 | 仅内部领料；一对一原领料；**不含**销售出库 |
| `purchase_returns` | WM | 出库存 | 一对一采购收货；与客户退货无关 |
| 领料冲销 | WM | 对调进出 | 原领料有草稿/已过账退料则禁止；**不**检查交货已开票、**不**检查客户退货 |
| AR 发票 | FI | 从交货开正数票 | 无贷项；`source_doc_type` 为 `SHIPMENT` / `SALES_ORDER` |

与采购的关键不对称：库存过账单是领料，不是交货。交货行 **没有** 仓、批号、`stock_type`。财务开票挂交货行。

## 3. 已占位、未实现

### 3.1 流水账 `CUSTOMER_RETURN`

`StockTransactionType.CUSTOMER_RETURN`、`stock_transactions.transaction_type` 注释已列出。  
语义是客户退货入库，但**没有任何单据过账写入**。`StockTransactionType.DELIVERY` 同样从未被 Java 使用——销售出库走 `STOCK_ISSUE`。

### 3.2 收货来源 `CUSTOMER_RETURN_ITEM`

`GoodsReceiptSourceDocType.CUSTOMER_RETURN_ITEM` 与已删除的 `PURCHASE_RETURN_ITEM` 曾经并列。  
`GoodsReceiptGenerationServiceImpl` 对该类型抛 `UnsupportedOperationException`。

`StockTransactionLedgerServiceImpl.typeForGoodsReceiptLine`：

```text
CUSTOMER_RETURN_ITEM → CUSTOMER_RETURN
```

采购退货文档已说明：客户退货经收货入库「说得通」，但收货主档带供应商、AP 可开票、GR/IR，不适合客户退货。本波 **删除** 该来源，独立建 `customer_returns`。

### 3.3 收货冲销回取列表仍含 `CUSTOMER_RETURN`

`GoodsReceiptServiceImpl.reverseGoodsReceipt` 回取单价时包含 `CUSTOMER_RETURN`。没有客户退货走收货单时不会命中。本波退货不再走收货，回取列表 **删除** `CUSTOMER_RETURN`。

### 3.4 交货类型 `RETURN`

`DeliveryType` 有 `NORMAL` / `RETURN` / `SAMPLE`。代码从未按 `RETURN` 作业。本波 **不启用**，避免交货单身兼正向出货与退货。

## 4. 销售出库过账今天做什么

`StockIssueServiceImpl.postStockIssue`（`SALES_DELIVERY`）：

1. 解析标准成本（数量记账政策下可跳过凭证）
2. `applyStockIssue`（`STOCK_ISSUE`，−）
3. `remoteDeliveryService.issueCallback(+transaction_quantity)` → 交货行 `issued_quantity`、行状态 `DELIVERED`；SO 行 `delivered_quantity`，满则 `DELIVERED`
4. COGS 凭证：借 COGS、贷存货；`journal_entry_id` 挂在领料单
5. 状态 → `POSTED`

冲销：反向库存、`issueCallback(−qty)`、冲 COGS。  
**不看** 交货 `invoiced_quantity`，**不看**下游客户退货（尚不存在）。

领料行已有 `returned_quantity`，语义是 **已过账内部退料** 基本单位合计。`SALES_DELIVERY` 不能走退料，该列在销售出库行上恒为 0。

`issueCallback` 减量时：

- 交货已发不得为负、不得超过 `transaction_quantity`
- SO `delivered_quantity` 会减少
- **不会**把已 `DELIVERED` 的 SO 行/表头退回 `CONFIRMED`
- 表头刷新只在订单当前为 `CONFIRMED` 时运行

因此现网冲销销售出库后，SO 可能仍显示 `DELIVERED`。本波退货必须补这个守卫（见 `02` §3.6）。

## 5. 交货开票占用

`ArInvoiceDeliveryQuantityHelper` 在 AR 行新增 / 改数量 / 删除（含 **DRAFT**）时调用 `RemoteDeliveryServiceImpl.updateInvoicedQuantity`。

语义 = **已被 AR 行占用（含草稿）**，不是「已过账发票」。

```text
newInvoiced ≥ 0
newInvoiced ≤ delivery_item.transaction_quantity     // 不看已退（尚无已退）
billableQty = transaction_quantity − invoiced_quantity
```

从交货生成发票走 `getDeliveryForBilling` 的 `billableQty`，发票行仍可手改数量。没有 `returned_quantity`。

`ArInvoiceLineSourceDocType.SHIPMENT` 的 `source_line_id` 指向 `delivery_items.id`（表是 `deliveries`，枚举名仍是历史 `SHIPMENT`）。

## 6. 采购退货已验证的模式（应对齐）

`purchase_returns`：

- 一张退货单只对一张已过账库存原单
- 明细必须挂原库存行；同单内一行对一行
- 仓、批号锁定；`stock_type` 可改
- 原单行 `returned_quantity`（基本单位）；可退 vs 开票用单据单位求和
- 已被发票占用（含草稿）不可退
- 过账写独立流水账类型；成本取原单流水
- 冲销退货回减 `returned_quantity`；原单有退货则禁止冲销
- 状态 `DRAFT` / `POSTED` / `REVERSED`

客户退货对齐这套，原单换成 `SALES_DELIVERY` 领料；开票占用读交货行。

## 7. 应收现状（约束退货数量）

```text
出库：借 COGS / 贷 存货
发票：借 应收 / 贷 收入 + 销项税
收款：借 银行 / 贷 应收
```

- 无 AR 贷项，无负向 `quantity`（独立专题：[应收贷项](../应收贷项/README.md)）
- 已开票后再退货且只冲库存 / COGS → 应收仍在，账不平
- 从交货开票已按未开票剩余计算，退货后必须同步压低可开票量（本波用「只退未开票」保证）

## 9. 若继续用「负交货 / 收货转换 / 退料扩展」会错什么

| 方案 | 问题 |
|------|------|
| `deliveries.delivery_type = RETURN` | 交货行无仓/批；开票、已发回写都按正向出货假设；与已落地独立反向单不一致 |
| `goods_receipts` + `CUSTOMER_RETURN_ITEM` | 收货主档供应商 / AP 占用 / GR/IR；客户退货会污染采购入口 |
| 扩展 `stock_issue_returns` 覆盖 `SALES_DELIVERY` | 退料文档与菜单是内部退料；无客户、币别、单价；AR 占用对不上 |

结论：独立 `customer_returns`，流水账写 `CUSTOMER_RETURN`，一对一已过账销售出库领料。
