从会计实务看，**成本分摊**和**成本计算（期末结算）产生的分录不同：前者主要是费用在成本对象/部门之间的重分类**；后者是**把本期实际成本定到存货与销货成本，并处理差异**。下面按规范制造业（吸收成本法）说明，并对照你们 `cost_allocations`、`cost_calculations` 的设计含义。

---

## 一、先分清两类业务


| 类型                        | 会计本质                           | 在你们系统里                                                            |
| ------------------------- | ------------------------------ | ----------------------------------------------------------------- |
| **费用分摊 (Allocation)**     | 间接费从「费用池/辅助部门」摊到「生产成本部门/产品」    | `cost_allocations`                                                |
| **成本计算/结算 (Costing Run)** | 按本期收发存算出单位成本，调整存货账面，并把差异认到 P&L | `cost_calculations` → `cost_calculation_items` → `material_costs` |


Cost Run 过账时，`journal_entries.source_module = 'COSTING'`，通常不是一张分录，而是**一组分录**。

---

## 二、费用分摊会转什么分录？

分摊解决的是：**电费、折旧、厂务人工等已进 GL，但还没准确归到产品/生产部门**。

### 典型场景 1：服务部门 → 生产部门

例如：厂务部电费 10 万，按机器工时摊到生产一部、生产二部。

```
借：制造费用—生产一部（或直接进 5101 生产成本-制造费用）  60,000
    制造费用—生产二部                                   40,000
贷：制造费用—厂务部（或 5102 制造费用-厂务）           100,000
```

**会计含义**：费用**仍在制造费用/成本类科目内流转**，一般**不进损益**，只是从「费用池」转到「可吸收到产品的成本中心」。

对应 `cost_allocations`：

- `gl_account_id`：被分摊的费用科目（如电费）
- `source_department_id`：厂务部
- `target_department_id`：生产一部
- `amount` + `allocation_basis` / `allocation_ratio`



### 典型场景 2：公司级费用池 → 各部门

若 `source_department_id` 为 NULL，表示公司级共同费用：

```
借：制造费用—各生产部门（按分摊比例）     xxx
贷：制造费用—共同费用 / 待分摊制造费用   xxx
```



### 注意

- **分摊本身通常不碰存货科目**，除非你们设计为「分摊完立刻吸收进 WIP/FG」。
- 规范 ERP 常见两步：
  1. **分摊**：部门间/费用池间重分类
  2. **吸收 (Absorption)**：制造费用按标准或实际工时摊进 WIP/FG（在 Cost Run 或生产报工环节）

## 三、成本计算（期末 Cost Run）会转什么分录？

取决于 `cost_method`（`STANDARD_COST` / `MOVING_AVERAGE` / `ACTUAL_COST`）。日常收货、发料若已即时凭证，期末 run 主要是**调整与差异**，不是从零重做全部收发。

---



### 1. 实际成本法（ACTUAL_COST）— 月末结算最常见



#### （1）制造费用吸收进在产品/产成品

把已分摊到生产部门的制造费用，按本期产量/工时吸收进成本：

```
借：生产成本—在产品 (WIP) / 库存商品 (FG)     xxx
贷：制造费用—已吸收 (Overhead Applied)        xxx
```

若实际制造费用与已吸收有差额，还要做：

```
# 少吸收（实际 > 已吸收）
借：制造费用差异 / 少吸收制造费用差异          xxx
贷：制造费用                                    xxx

# 或多吸收时方向相反
```



#### （2）存货账面调整到计算出的实际单位成本

`cost_calculation_items` 算出 `calculated_unit_cost` 后，若与账面 provisional 成本有差：

```
# 存货被低估（应调高）
借：原材料 / 在产品 / 库存商品                  xxx
贷：存货成本调整 / 生产成本结算差异            xxx

# 存货被高估（应调低）则借贷相反
```



#### （3）已销售部分：调整销货成本

若本期发料/出货按临时成本入账，期末按实际成本重算：

```
借：主营业务成本 (COGS)                        xxx
贷：库存商品                                    xxx
```

或差异单独走差异科目：

```
借：主营业务成本
贷：销货成本差异
```

**要点**：Cost Run 要同时处理**期末库存**和**本期已销**两部分，否则账料会对不上。

本系统实现口径（标准成本主路径）：

- 汇总自 `stock_transactions`：本期收发**排除**内部调拨；`startRun` 以流水 WAC 写入 `materialCost`
- `completeRun`：本 run 的 `cost_allocations` 按 `cost_element` 拆池——`LABOR` 吸收进 `labor_cost`，`OVERHEAD` 吸收进 `overhead_cost`（份额基数 `(opening_qty + receipt_qty)`）；`calculated_unit_cost = material + labor + overhead`
- `variance_amount = (calculated_unit_cost − standard) × (issue_qty + closing_qty)`
- `postRun`：结存差异 → `INV_STOCK`（通配 `140702` 存货成本调整）vs `PRICE_VAR`（`140701`）；发出差异 → `COGS`（`6401`）vs `PRICE_VAR`；费用分摊仍做 Dr WIP（`5101`）/ Cr 来源制造费用重分类。日常收发货的 `INV_STOCK` 仍按评估类映射 `1401/1403/1405`，与 Cost Run 通配行分离
- 采购价差在收货时已记 `PRICE_VAR`，不在此重复计算
- 工时模块未上线前：人工总额可由作业单位 Excel 按工时计算后，以 `cost_element=LABOR` 录入分摊行

### 2. 标准成本法（STANDARD_COST）— 差异认到损益

日常按标准价入账；期末 `variance_amount` 认差异。

#### 常见差异类型与分录方向


| 差异           | 典型原因          | 分录倾向                    |
| ------------ | ------------- | ----------------------- |
| **材料价格差异**   | 实际采购价 ≠ 标准价   | 借/贷：材料价格差异；对应 GR/IR、原材料 |
| **材料用量差异**   | 实际耗用 ≠ 标准 BOM | 借/贷：材料用量差异；对应 WIP       |
| **人工效率差异**   | 实际工时 ≠ 标准工时   | 借/贷：人工效率差异              |
| **制造费用开支差异** | 实际 OH ≠ 预算 OH | 借/贷：制造费用开支差异            |
| **制造费用产量差异** | 实际产量 ≠ 标准产量   | 借/贷：制造费用产量差异            |




#### 示例：材料价格差异（采购时或发票校验时）

```
借：原材料（标准）              100
    材料价格差异（不利，超支）   10
贷：应付账款 / GRIR              110
```



#### 示例：期末汇总 unfavorable 差异进损益

```
借：材料用量差异
    人工效率差异
    制造费用差异
贷：主营业务成本调整 / 或保留在差异科目后结转
```

`cost_calculation_items.variance_amount` 在标准成本下，主要就是这类**标准 vs 实际**的差异汇总。

**实务**：差异可先留在资产负债（WIP/FG）上，期末按政策摊到 COGS 和期末库存。

---



### 3. 移动平均法（MOVING_AVERAGE）— 日常已算，期末偏对账

每次收货会更新平均价，分录多在**交易时点**：

```
收货：
借：原材料 / 库存商品              xxx（按移动平均或本次更新后成本）
贷：应付账款 / GRIR               xxx

发料：
借：生产成本—直接材料 / WIP       xxx
贷：原材料                         xxx
```

期末 Cost Run 若仍有差异（例如盘点、尾差、四舍五入），可能只有**微调分录**：

```
借/贷：库存商品
贷/借：库存成本差异 / 成本调整      小金额
```

移动平均下，`cost_calculations` 更多是**归档、对账、写 material_costs**，不一定有大额 settlement 凭证。

## 四、按成本要素看：料 / 工 / 费 各转什么？

对照 `material_cost`、`labor_cost`、`overhead_cost`：


| 要素    | 日常已发生的分录（举例）       | 期末 Cost Run 可能补的分录      |
| ----- | ------------------ | ----------------------- |
| **料** | 借 WIP/生产成本，贷原材料    | 实际耗用 vs 账面调整；价格/用量差异    |
| **工** | 借 WIP/生产成本，贷应付职工薪酬 | 实际工时成本 vs 已入账调整；效率差异    |
| **费** | 借制造费用，贷应付/折旧等      | 分摊 → 吸收进 WIP/FG；开支/产量差异 |

## 五、完整月结分录顺序（规范 ERP）

以**实际成本 + 先分摊后结算**为例：

```
Step 1  费用分摊 (cost_allocations)
        借：制造费用—生产部门
        贷：制造费用—辅助/共同部门

Step 2  费用吸收 (Cost Run 一部分)
        借：WIP / 库存商品
        贷：制造费用—已吸收

Step 3  制造费用结算（实际 vs 已吸收）
        借/贷：制造费用差异
        贷/借：制造费用

Step 4  完工结转（若按订单/批次）
        借：库存商品
        贷：WIP

Step 5  存货成本调整（按 calculated_unit_cost）
        借/贷：原材料 / WIP / 库存商品
        贷/借：存货成本调整 / 生产成本结算

Step 6  销货成本调整（本期已销部分）
        借/贷：主营业务成本
        贷/借：库存商品 或 销货成本差异

Step 7  （标准成本）差异结转
        借/贷：各类差异科目
        贷/借：COGS / 期末库存（按政策分摊）
```

实际系统里，Step 1–7 可能合并成 1–3 张 `journal_entries`，但**会计逻辑**仍是这些步骤。

## 六、和你们表结构的对应关系


| 数据                                            | 可能产生的 GL 影响                                     |
| --------------------------------------------- | ----------------------------------------------- |
| `cost_allocations`                            | 制造费用科目间、部门辅助核算维度间的**重分类**                       |
| `cost_calculation_items.calculated_unit_cost` | 驱动存货科目**金额调整**                                  |
| `cost_calculation_items.variance_amount`      | 标准成本下进**差异科目**                                  |
| `material_costs`                              | 结算结果快照；本身不直接过账，是下次出库计价依据                        |
| `cost_calculations.journal_entry_id`          | 指向上述 settlement 凭证（可能含多行 `journal_entry_lines`） |


`journal_entry_lines` 上通常需要：

- `gl_account_id`：原材料、WIP、FG、制造费用、差异、COGS 等
- `department_id`：成本中心
- `debit_amount` / `credit_amount`

## 七、实务上必须明确的三个会计政策

否则「Cost Run 过账」无法唯一确定分录：

1. **计价方法**：标准 / 移动平均 / 全月加权平均 / 实际成本
2. **差异处理**：期末全部进 COGS，还是按期末库存比例分摊
3. **吸收基准**：按工时、机时、产量还是材料成本比例吸收制造费用

### 本系统已锁定（制造）

见 [08.成本方法实现计划.md](08.成本方法实现计划.md)：

1. 日常计价 = **标准成本**（`fi_costing_policies.default_cost_method = STANDARD_COST`）
2. 差异 = **全额进当期损益**（`FULL_TO_PL`）
3. 吸收基准 = **直接人工工时**（`LABOR_HOURS`；工时主数据就绪前以分摊 + 差异结转简化）

移动平均仅作物料级后续扩展，不作为公司默认。

## 八、一句话总结

- **费用分摊**：主要是 **借/贷 制造费用（及成本中心重分类）**，把间接费摊到可进产品的部门；一般**不直接进损益**。  
- **成本计算**：主要是 **借/贷 存货（原材料/WIP/FG）+ 制造费用吸收 + 差异/成本调整 + 主营业务成本**，把本期真实成本定到**期末库存**和**已销商品**；标准成本下差异单独进**差异科目**再结转到 COGS。
