这两组字段服务于**不同层面**，不是重复设计。

## 对比

| 字段 | 层面 | 含义 | 谁定义 | 典型用途 |
|------|------|------|--------|----------|
| `account_code` | **ERP 内部** | 系统内短编码 | 财务/IT 维护 | 下拉选择、批处理、唯一标识 |
| `account_name` | **ERP 内部** | 业务友好显示名 | 财务维护 | UI 展示、报表、出纳选账户 |
| `account_no` | **银行外部** | 真实银行账号 | 银行开户 | 网银转账、银企直联、对账 |
| `account_holder` | **银行外部** | 开户法定户名 | 银行登记 | 付款文件、收款验证 |

## 为什么需要两套？

**1. 内部标识 ≠ 银行账号**

一家公司可能有多个账户，银行账号很长、不便记忆，也不适合作为 ERP 业务键：

```
account_code:  CMB-CNY-01          ← 短、稳定、可人工维护
account_name:  招行基本户-人民币    ← 出纳一眼能看懂
account_no:    622588xxxxxxxx1234  ← 真实账号，可能变更或销户重开
account_holder: 深圳某某科技有限公司 ← 银行登记的法定名称
```

**2. 现金账户（`account_type = CASH`）没有银行账号**

总部备用金、门店零用金通常没有 `account_no`，但仍需要在 ERP 里维护：

```
account_code:  CASH-HQ
account_name:  总部出纳现金
account_no:    NULL
account_holder: NULL
```

若只有 `account_no` / `account_holder`，现金类账户就不好建模。

**3. 与 `partner_bank_accounts` 的设计差异**

对方账户表只有银行侧字段，没有 `account_code`，因为：

- 归属已由 `partner_id` 确定
- 通常按「银行 + 账号」识别即可，不需要 ERP 内部编码

```9:12:c:\WorkSpace\WorkSpace\lychee\lychee-backend\docs\database\sql\schema_tables\FI\partner_bank_accounts.sql
	bank_name varchar(100) NOT NULL,        -- 银行名称 (如: 招商银行)
	bank_branch varchar(100) NULL,          -- 支行/分行名称
	account_no varchar(50) NOT NULL,        -- 银行账号
	account_name varchar(100) NOT NULL,     -- 账户户名
```

我方 `company_bank_accounts` 是 **Treasury 主数据**，要参与：
- 付款批处理选账户
- 按公司维护默认账户（`is_default`）
- 绑定 GL 科目（`gl_account_id`）

所以需要额外的 `account_code` 作为 `(tenant_id, company_id, account_code)` 唯一键。

**4. 命名注意：`account_name` 在两表含义不同**

| 表 | `account_name` 含义 |
|----|---------------------|
| `partner_bank_accounts` | 银行户名（= 户名） |
| `company_bank_accounts` | ERP 显示名称 |
| `company_bank_accounts.account_holder` | 银行户名 |

我方表把「显示名」和「银行户名」拆开了，避免和 partner 侧语义混用。

## 实际业务场景

出纳做付款单时：
- **选账户**：看 `account_name`（「招行基本户-人民币」）
- **系统引用**：用 `account_code` 或 `id`
- **生成网银文件**：用 `account_no` + `account_holder` + `bank_name`
- **过账**：用 `gl_account_id`

`payments` 里的快照字段也体现了这种分层——过账后保留当时银行信息，而不只留内部编码：

```28:33:c:\WorkSpace\WorkSpace\lychee\lychee-backend\docs\database\sql\schema_tables\FI\payments.sql
	internal_bank_account_id bigint NULL,
	internal_bank_name varchar(100) NULL,
	internal_bank_branch varchar(100) NULL,
	internal_account_no varchar(50) NULL,
	internal_account_name varchar(100) NULL,
```

这里的 `internal_account_name` 快照更接近 **显示名/户名**，不是 `account_code`。

---

**一句话**：`account_code` / `account_name` 是 **ERP 怎么管这个账户**；`account_no` / `account_holder` 是 **银行眼里这个账户是谁**。两者职责不同，所以都需要。
