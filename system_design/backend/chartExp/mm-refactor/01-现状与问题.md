# 01. 物料变体现状与问题（As-Is）

> 依据当前代码与文档：`lychee-erp-mm` / `lychee-erp-basis` / `lychee-frontend` / `schema_tables/MM`。  
> 尺码排序 Phase 1 已用 `PrefixedCode` 修好，**不是**本专题的缺口。

---

## 1. 业务缺口

鞋服成品不是「一个物料」，而是 **款号 × 颜色 × 尺码** 的笛卡尔积（再扣掉不生产的格子）。一款 5 色 × 8 码 = 40 个 SKU。

现网只能：

```text
物料资料 → 新建（手填全部字段）
物料资料 → 复制一行 → 改颜色/尺码/编码/名称 → 保存
（重复 N 次）
```

后果：

- 编码容易撞号或漏改（复制后编码仍是上一笔，保存即 `validation.material.code.duplicate`）
- 同一款同一色同一码可以建两笔（无变体唯一键）
- 衣服可以选鞋码、童装可以选成人码（颜色/尺码是全域字典，与款号无约束）
- 工厂订单 / 销售订单矩阵列靠 SKU 上的 `product_size_id` 联集；SKU 建错码，报表列就错

原料、包材、不带型体的物料**没有**这个痛点，应继续单笔维护。

## 2. 现网各管什么

| 对象 | 路径 | 现网能力 | 对变体的含义 |
|------|------|----------|--------------|
| `product_models` | MM 可编辑表 | `code/name/description/status` | 只有「抽象款号」，无尺码组、无本款色 |
| `colors` | MM | `PREFIX-serial` 编码 + `PrefixedCode` 列表序 | 全域色卡，不隶属某款 |
| `product_sizes` | MM | 同上，另有 `sequence` 覆盖组内序 | 全域尺码，**没有**「成人上衣 / 欧码女鞋」分组 |
| `materials` | MM | SKU 主档；`product_model_id/color_id/product_size_id` 可空 | 变体关系只靠三个可空 FK |
| `MaterialForm` | `pages/mm/materials` | 分类或款号变更时 `code = categoryCode + modelCode` | **不含**色码、尺码；多 SKU 会建议出同一编码 |
| 复制 | `index.tsx` `handleCopy` | 去掉 `id` 回填抽屉 | 编码/名称/色码都要人手改 |
| `uk_materials_tenant_code` | DDL | 仅 `(tenant_id, code)` | 变体维度不唯一 |
| `material_images` | 挂在 SKU | 无款号/颜色图 | 40 个 SKU 要各传一次，或生成后补 |
| `material_factories` | 挂在 SKU | `(factory, material)` 唯一 | 生成 40 个 SKU 后还要分配 40 次工厂 |
| BOM | `bill_of_materials.product_material_id` | 按 SKU | 生成不带 BOM；尺码耗用差异本波也不自动处理 |
| FO/SO 报表 | `sizeColumns` by `ProductSize.sequence` + `PrefixedCode` | 列序已可用 | 前提是 SKU 挂对 `product_size_id` |

成品入口约定（前端，非库约束）：`materialType.isSold && isManufactured` 才允许选款号；其它类型禁用并清空 `productModelId`。

## 3. 编码与唯一性为什么不够

### 3.1 物料编码（现场规则 vs 系统误拼）

现场成品编号是 **款号 + 分隔符 + 可选色号 + 两位流水**，不是把色卡/尺码主数据 `code` 拼进去：

```text
区分颜色：materials.code = 款号.code + "-" + 本款色号(A–Z) + 尺码流水(01–99)
          例：12345-A01     （该款黑色、该色最小码）
不分颜色：materials.code = 款号.code + "-" + 尺码流水(01–99)
          例：12345-01
```

| 段 | 规则 | **不是** |
|----|------|----------|
| 款号 | `product_models.code` | 物料分类 `code` |
| 分隔符 | 固定 `-`（与现网 `PrefixedCode` 一致） | 无分隔 / 其它符号 |
| 色号 | **1 字母 A–Z**，挂在**该款**；不区分颜色则**整段省略** | `colors.code` |
| 尺码 | **2 位 01–99**，按 **该款 + 该色（不分色则仅该款）** 从最小码编 01 | `product_sizes.code`；尺码组档位号 |

因此：

- `materials.code` **保持 varchar(50)**。区分色：`len(款号)+4≤50`；不分色：`len(款号)+3≤50`。
- 同一物理尺码 40：A 色可以是 `01`（该色最小），不必是组里的第 6 档。
- 黑/白若尺码集合相同，则两边都是 01=最小、02=次小；流水按色各记一份，互不借用组号。
- `PrefixedCode` 只给色卡/尺码主数据排序。

现网表单建议 `分类.code + 款号.code`，与现场规则冲突，Wave A 必须改掉。

### 3.2 变体不唯一

现网允许：

| 数据 | 能否保存 |
|------|----------|
| 两笔 `POLO-RED-M`，编码不同 | **能**（只验 code） |
| 两笔编码相同 | 不能 |
| 成品只填款号、色/码为空 | 能 |
| 不分色成品：同款同码两笔、`color_id` 皆空 | **能**（现网无「款+码」唯一） |
| 原料三维度皆空 | 能（应保持） |

报表按 `productSizeId` 透视时，重复变体会把数量拆到两个 SKU，或矩阵出现重复列语义。

PostgreSQL 单一 `UNIQUE (model, color, size)` 不够：原料常有 NULL；不分色成品 `color_id` 也为 NULL（NULL 互不相等）。To-Be 用 **两条部分唯一索引**（有色三列 / 无色款+码），见 `03`。

## 4. 若继续只做「更好的复制」会错什么

| 方案 | 问题 |
|------|------|
| 只优化复制抽屉 | 仍是 N 次保存；矩阵漏格、撞码无法预览 |
| Excel 一次导入物料 | 能批量，但无「已存在格子跳过」、无色×码预览；导入中心另题，不替代生成器 |
| 把款号做成物料 `parent_id` | 与现网 `product_model_id` + BOM 重叠，库存层语义混乱 |
| 只在前端循环调 `POST /materials` | 半成功、无变体唯一、无统一编码规则 |
| Wave A 不建唯一索引 | 生成器与手建仍能造出重复变体 |
| 用 `款号-色卡code-尺码code` 当 SKU | 超长、与现场「- + 可选字母 + 两位流水」不符 |
| 尺码流水挂在尺码组（同组 40 永远 06） | 与「按款+色、最小码从 01」不符 |
| 按勾选顺序现算 A/01 却不落库 | 下次加码会重号 |
| 先做生成器、后做本款色号/流水表 | 没有稳定 token |
| 生成时强制复制 BOM | 不同尺码耗用往往不同 |

结论：Wave A 同时落地 **变体唯一（含不分色）+ 尺码组（只定序）+ 本款色号 + 款×色流水 + 预览生成**。Wave B 打印列序与 copy-from。Wave C 从属复制。
