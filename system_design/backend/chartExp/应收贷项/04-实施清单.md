## 3. 实现约定

### 3.1 可贷数量

与应付贷项同一计算器。过账：`qty ≤ creditableQty` 且 `total ≤ total − credited`。税走现有 `FiInvoiceTaxSupport`。

### 3.2 过账模板

复制 `ArInvoicePostingServiceImpl`，借贷对调：贷伙伴 GL、借行收入 GL、借销项税。禁止 `findActiveUnitCost`。

### 3.3 占用

仅 `SHIPMENT` 且 `source_line_id != null`。只在 POST / VOID 调。`updateInvoicedQuantity` 须对交货行悲观锁。

### 3.4 VOID vs 退货

```text
RemoteCustomerReturnService.existsPostedByDeliveryItemIds(Set<Long> deliveryItemIds)
```

WM 查 POSTED 客户退货行的 `delivery_item_id`。FI 不得直接依赖 WM 实体。

### 3.5 收款 remaining

`applyAr` / `restoreAr`：

```text
remaining = total − received − applied_credit_amount
if remaining < 0 → ValidationException
```

改为 `findByIdForUpdate`。未识别的核销类型必须抛错。锁序：贷项 POST 为 CM → AR；收款为 Payment → AR。客户退款落地后与 CM→AR 对齐，见退款目录。

### 3.6 命名

i18n / 测试 / 权限用 `ar_credit_memo` / `arCreditMemo`。不要「红字」。

## 6. 验收

1. AR 100 未收，贷 40 过账：凭证贷应收 40、借收入/税；原票 `credited=40`、`applied=40`、`remaining=60`；交货 `invoiced` −40。
2. 随后客户退货最多可退「原未占用 + 40」。
3. AR 已收 100 仍可贷（有可贷数量）；`applied=0`、`refundable=贷项总额`，原票 remaining 仍 0。
4. AR 收 60 剩 40：贷 70 → `applied=40`、`refundable=30`。待退款超过剩余实收现金则拒绝。
5. AR 草稿不能生成贷项。交货被 AR **草稿**占用时退货仍拒绝。
6. 两张贷项草稿抢同一 AR 行：数量占用互斥。
7. 提交时 `tax_credit_note_no` 仍为 `PENDING-` → 拒绝。
8. 贷项过账后原 AR VOID 失败。
9. 贷项过账 + 该交货行已有 POSTED 客户退货 → 贷项 VOID 失败；冲销退货后成功。
10. 只贷不退：占用下降后可再从交货开 AR。
11. 收款在贷项之后：`remaining = total − received − applied_credit`，不会把贷项冲掉的剩余写回去。
12. 数量记账政策下贷项仍有应收凭证。
13. 期间内未过账贷项挡住关帐。
14. 全文无负向 AR 发票方案残留。
