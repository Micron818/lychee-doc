## 2. 接口设计与技术规格（API Contracts）

### 2.1 获取物料分类的有效编码策略
* **端点**：`GET /api/mm/material-categories/{id}/effective-policy`
* **说明**：自动执行向上递归继承，返回该分类实际生效的编码策略。
* **响应报文示例**：
  ```json
  {
    "success": true,
    "data": {
      "categoryId": 105,
      "categoryCode": "TSHIRT",
      "strategy": "FASHION_VARIANT",
      "sourceCategoryId": 10,
      "sourceCategoryName": "成衣大类",
      "prefix": "APP",
      "numberRuleId": null,
      "allowManualOverride": false
    }
  }
  ```

---

### 2.2 物料保存接口请求适配（`POST /api/mm/materials`）
* **接口路径**：`POST /api/mm/materials`
* **行为变化**：
  - 当分类策略为 `SEQUENTIAL` 时，前端**允许传空 `code`**，后端自动分配后在响应中返回正式 `code`；
  - 当分类策略为 `FASHION_VARIANT` 时，后端执行 V1 既有逻辑（验款号、本款色、尺码组并写流水表）；
  - 当分类策略为 `MANUAL` 时，前端必填 `code`，后端仅做格式与防重校验。

```text
  │           ├── FashionVariantCodeGenerator.java     <-- 封装鞋服款色码逻辑
  │           ├── SequentialCodeGenerator.java         <-- 封装分类前缀流水号
  │           └── ManualCodeGenerator.java             <-- 封装手工录入校验
  └── service
        └── impl
              ├── MaterialCategoryServiceImpl.java     <-- 包含向上继承解析
              └── MaterialServiceImpl.java             <-- 保存时路由调用
```

### 核心接口签名

```java
public interface MaterialCodeGenerator {
    /**
     * 所支持的策略枚举
     */
    CodingStrategyEnum getStrategy();

    /**
     * 在落库前分配/确定正式的物料编码
     * @param request 物料入参
     * @param policy 当前生效的策略配置
     * @return 最终确定的物料编码
     */
    String allocateCode(MaterialRequest request, EffectiveCodingPolicy policy);

    /**
     * 前端输入校验
     */
    void validate(MaterialRequest request, EffectiveCodingPolicy policy);
}
```

## 4. 前端 MaterialForm 重构方案

利用本次 V2 重构契机，彻底解决前述 `MaterialForm.tsx` 831 行过长、逻辑混杂的问题：

```text
src/pages/mm/materials/components/MaterialForm/
├── index.tsx                         # 抽屉容器与主表单骨架 (~150 行)
├── hooks/
│   ├── useCategoryCodingPolicy.ts    # 分类策略异步解析与缓存
│   └── useMaterialVariantSuggest.ts  # 抽离款色码变体预览与建议状态机
└── fields/
    ├── TypeInfoFields.tsx            # 类型、分类、科目选择
    ├── VariantFields.tsx             # 款式、颜色、尺码（仅在 FASHION_VARIANT 时渲染）
    └── BasicInfoFields.tsx           # 编码（依据策略动态只读/手填）、名称
```
