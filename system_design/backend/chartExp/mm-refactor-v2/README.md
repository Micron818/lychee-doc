# MM 重构 V2：基于分类树的多策略物料编码体系

> 关联前序设计：`../mm-refactor-v1`（款号 × 颜色 × 尺码变体矩阵生成）。  
> 本设计（V2）解决 V1 的核心局限：**打破鞋服变体公式的硬编码，通过「物料分类（Material Category）树 + 继承机制 + 策略路由」，实现同租户下多产品性质、跨行业物料的灵活自适应编码。**

---

## 1. 设计背景与问题本质

在 V1 阶段，系统成功建立了鞋服成品「款号 × 颜色 × 尺码（A12345-A01）」的变体生成矩阵。但在深化应用中暴露了以下结构性矛盾：

1. **同租户下多产品形态冲突**：
   - 企业的「成衣/鞋靴」需要走 `款号-色号-尺码流水`（Fashion Variant）；
   - 同一企业的「配件周边（帆布袋、雨伞、袜子）」是单一成品，不具备尺码组和款色，强行套用变体逻辑导致数据畸变；
   - 「原料（面料、辅料、线材、包材）」多为连续流水或按供应商规范编码；
   - 「OEM 客供来料 / 贴牌定制成品」要求直接录入品牌商指定料号（Manual）。
2. **`material_types`（物料类型）粒度过粗**：
   - `material_types`（如 成品 FERT、半成品 HALB、原材料 ROH）仅表征财务核算与单据行为（是否可售、是否自制、是否管库存），一个租户通常只有 4~6 个大类；
   - 若将 `code_strategy` 绑定在 `material_types` 上，将导致「同为成品的所有商品只能使用同一种编码逻辑」，无法区分成衣与标品配件。
3. **前端表单与业务规则重度耦合**：
   - 前端 `MaterialForm` 内部包含了 120+ 行变体推导与状态机判断，导致页面臃肿且容易产生时序竞态；
   - 编码生成与校验逻辑必须收敛至后端统一策略服务。

---

## 2. 核心设计结论

| 决策点 | 选型与设计 | 核心理由 |
| :--- | :--- | :--- |
| **策略配置载体** | **`material_categories`（物料分类表）** | 分类树直击业务品类（成衣 vs 配件 vs 原料），支持细分到任意层级。 |
| **规则传递机制** | **向上继承与号池自适应** | 策略向上继承；流水号参数（前缀、位宽）支持逐级覆盖；支持独立号池与共享大类号池灵活切换。 |
| **核心编码策略** | **`FASHION_VARIANT` / `SEQUENTIAL` / `MANUAL`** | 覆盖「款色码变体矩阵」、「分类序列流水号」、「外部手工录入」三大企业主流场景。 |
| **前端交互表现** | **依策略动态自适应表单** | `SEQUENTIAL` 时编码只读（允许传空）、款色码收折为可选；`FASHION_VARIANT` 时开放款式色码必填并支持矩阵生成；`MANUAL` 时开放手填，并支持折叠填入版型尺码（赋能 OEM 代工）。 |
| **物理约束处理** | **物化策略标记（`is_fashion_variant`）+ 条件唯一索引** | 随波次 2 后端业务策略同批次落地，保留数据库层级变体三维硬防线，彻底消除对 OEM 客供料号与配件标品的误伤。 |
| **后端生成架构** | **策略模式 + 工厂路由（`MaterialCodeGeneratorFactory`）** | 保存时根据物料所属分类自动匹配生成器，与 Excel 导入、EDI 接口共用同一逻辑。 |
| **全生命周期覆盖** | **包含创建、修改（编码只读）、复制清空、向导强拦截** | 闭环物料主档全生命周期操作，确保主数据资产不可变性与单据链条稳定。 |
