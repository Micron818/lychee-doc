## 1. 审查结论（设计阶段）

| 问题 | 结论 |
|------|------|
| 一期自由百分比能否保留为唯一真相 | **否**；百分比只作快照 |
| 税码能否做成 option_values | **否**；有税率档、方向、科目 |
| 物料直接挂默认税码是否更简单 | **否**；用税分类 + 矩阵，对标评估类 |
| 找不到税码写 0 | **否**；与采购「无供应商则失败」同级 |
| 含税价 | **否** |
| 本波做申报/电子票 | **否** |

编码从本文件 §5 按模块推进。未改业务代码前先合入 Liquibase + 空 CRUD 亦可，但不要分两个上线窗口。

## 3. 实现约定

### 3.1 `RemoteTaxDeterminationService`

```text
resolve(TaxResolveRequest) → TaxResolveResult

Request:
  companyId, direction,          // 必填
  partnerTaxClassId,             // 无物料杂项行可仍填往来分类
  materialTaxClassId,            // 杂项可空
  documentDate,                  // 必填
  taxCodeId                      // 可选覆盖

Result:
  taxCodeId, code, taxType, direction, isDeductible,
  taxRate, inputGlAccountId, outputGlAccountId
```

覆盖路径：不走矩阵，仍校验税码启用、国家=公司国家、方向兼容，并取税率档。  
匹配顺序严格按 `02` §3.2。同层唯一已由 DB 保证。  
无税率档、分类 scope 错误、税码停用 → `ValidationException`（i18n key）。

SCM/SD 不要自己 join 四张税表。

### 3.2 共享计税

抽一个无状态方法（common 或 FI，SCM/SD/FI 都用同一套，避免三处 `divide(100)` 漂移）：

```text
subtotal = qty × price          scale 2 HALF_UP
tax      = subtotal × rate/100  scale 2 HALF_UP
total    = subtotal + tax
```

AP/AR：`taxAmountOverridden == true` 时不重算 `tax`，只 `total = line + tax`。  
改税码时把 `taxAmountOverridden` 打回 `false` 再按公式算。

现网 `PurchaseOrderItemServiceImpl` / `OutsourceOrderItemServiceImpl` / `ArInvoiceServiceImpl` / `ApInvoiceServiceImpl` 的本地公式 **换成调用该工具**。

### 3.3 转单

`PurchaseOrderGenerationServiceImpl`：删 `.taxRate(BigDecimal.ZERO)`。每行 `resolve` 后写入 `taxCodeId`+`taxRate` 再 `applyItemAmounts`。  
工作台 DTO 可选 `taxCodeId`。  
`SalesOrderServiceImpl` 两处写死 0 同样改为判定。

### 3.4 复制快照

| 从 | 到 | 复制栏 |
|----|-----|--------|
| PO/委外行 | GR 行 | `tax_code_id`, `tax_rate`（现网已 copy rate，补 code） |
| SO 行 | 发货行 | 同上 |
| GR/PO 行 | AP 行 | 同上；`tax_amount_overridden = false` |
| 发货/SO 行 | AR 行 | 同上 |

WM 建 GR 时读来源 DTO，Remote 契约要带出 `taxCodeId`。

### 3.5 过账

`ApInvoicePostingServiceImpl`：

```text
税行 GL：
  amount=0 → skip
  code.isDeductible → coalesce(inputGl, resolve(INPUT_TAX))
  !deductible → inputGl 必有，否则 ValidationException
                禁止 resolve(INPUT_TAX)
```

`ArInvoicePostingServiceImpl`：

```text
amount=0 → skip
GL = coalesce(outputGl, resolve(OUTPUT_TAX))
```

缺税码的历史测试行（`tax_code_id` 空且税额>0）：V1 **拒绝过账**（未上线无历史包袱）。不要静默走通配，否则免税/漏配会再次混在一起。

### 3.6 主数据校验

- 物料保存：若带 `taxClassId`，scope 必须 `MATERIAL`。
- 供应商/客户：scope `PARTNER`。
- 税码保存：`is_deductible=false` 必须有 `input_gl_account_id`。
- 税率档保存：与同税码其他档日期不重叠；`ZERO/EXEMPT/NON_TAXABLE` 的 rate 必须为 0。
- 判定保存：分类 scope、税码国家/方向。
- 公司改 `country_code`：存在非关闭 SO/PO/委外/AP/AR 则拒绝。

删除税码：`exists` 判定或任何单据行 → 拒绝。

### 3.7 权限

| 资源 | 建议 |
|------|------|
| `/fi/tax-classes:*` `/fi/tax-codes:*` `/fi/tax-determinations:*` | 财务主数据角色 |
| `resolve` | 开单权限即可调用（内部 Remote）；若暴露 HTTP，给 SO/PO/发票 `:create` |
| 物料/往来税分类 | 现有主数据 update |
| 单据改税码 | 现有 DRAFT 更新 |

菜单挂在 FI 主数据，靠近科目/评估类。

### 5.2 common

- Remote DTO：`TaxResolveRequest` / `TaxResolveResult`
- 计税工具（若放 common，避免 FI↔SCM 循环依赖；**推荐 common**）

### 5.3 BASIS

- `Company` + DTO + 表单：`countryCode`；改国家校验

### 5.4 MD / SCM / SD / WM

- 物料/供应商/客户：栏位、表单校验 scope
- PO/委外/SO 保存与转单调用 `resolve`
- 删除写死 `BigDecimal.ZERO` 税率
- GR/发货 mapping 增加 `taxCodeId`
- Remote GR/SO 来源 DTO 带税码，供 AP/AR 建行

### 5.5 i18n

`messages_*.properties`：无分类、无判定、无税率档、国家不一致、方向不兼容、不可抵扣缺科目、已审不可改税、税率档重叠、票面覆盖说明。

## 8. 明确不做（本波）

- 金税/越南 e-invoice 接口、进项认证、申报底稿  
- 含税价、价税分离倒算（除发票票面税额覆盖外）  
- 税码维度并入 `fi_account_determination`  
- 不可抵扣税额追加存货成本 / 调整 GR 凭证  
- 来源清单或 BP 上的税码  
- PR、表头税率  
- 多国家交货地判定（仍只用公司国家，不按客户地址国重判）  
- 税码名称行上快照  
- 自动从物料类型推税分类（可手工批填，不做映射表）

## 9. 验收反例（必测）

1. 未配矩阵开 PO → 失败，无草稿行。  
2. 旧 PO 税率 10，税码档改为 8 且旧档 `valid_to` 已截止 → 已审 PO 仍 10；新 PO 为 8。  
3. `BP-OVERSEAS` 销项 → 零税率、AR 无税行、应收 = 未税。  
4. `VN-IN-ND` 过账 → 借费用，**试算表 222102 不动**。  
5. 工作台转单不再出现税率为 0 的国内货物行。  
6. 把 CN 税码选到 VN 公司行 → 拒绝。
