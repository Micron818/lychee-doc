# 01. 税率现状与问题（As-Is）

> 依据当前代码与 `schema_tables`：`lychee-erp-scm` / `lychee-erp-sd` / `lychee-erp-wm` / `lychee-erp-fi` / `lychee-frontend`。  
> 委外行的 `tax_rate` / `tax_amount` / `total_amount` 已在 Liquibase `0706-001` 落地，`schema_tables/SCM/outsource_order_items.sql` 尚未同步，以代码为准。

---

## 1. 一期设计

所有业务/财务单据行把税率当成 **可空或必填的百分比数字**（`numeric(5,2)`，`13.00` = 13%）。没有税码、没有有效期、没有进销项方向、没有与科目判定的关联。

单价约定（代码已按此计算，UI 未写死）：

```text
未税金额 = round(数量 × 单价, 2)
税额     = round(未税金额 × tax_rate / 100, 2)
含税合计 = 未税 + 税额
表头     = Σ 明细
```

没有「单价含税」开关。MRP/PR 转 PO、销售开行时税率常为 **0**，要人在草稿单上补。

主数据侧：

| 对象 | 与税相关的栏 |
|------|----------------|
| `companies` | 仅 `tax_id`（税号）；**无国家** |

| `materials` | 无 |

前端：PO/SO/委外/发票行用 `ProFormDigit` 自由输入 `taxRate`，无下拉、无校验合法档位。

## 3. 开单与过账路径

```text
MRP/PR/手键 ──► PO 行（税率常 0，人补）──► GR（复制 tax_rate）──► AP（可改）──► 过账借进项
手键        ──► SO 行（税率常 0，人补）──► 发货（复制）      ──► AR（可改）──► 过账贷销项
手键        ──► 委外行（人补）          ──► GR（复制）      ──► AP
```

过账逻辑（已落地，二期仍用金额，不按「行上填的百分比」重新算税）：

- AP：未税走行快照科目（GRIR/费用/CIP）；`tax_amount > 0` 一律借 **同一个** `INPUT_TAX`。
- AR：未税贷行快照收入科目；`tax_amount > 0` 一律贷 **同一个** `OUTPUT_TAX`。
- `tax_amount = 0`：**不产生税行**。0% 出口、免税、漏填税率，分录上看不出来差别。

## 4. 作业与合规摩擦


| 问题 | 影响 |
|------|------|
| 自由数字 | 同一供应商可能填 10、0.1、10.00；无法约束越南 8%/10%、中国 13%/9%/6% 档位 |
| 转单税率为 0 | 采购员每张 PO 补一次；漏补则 AP 无进项、成本/应付偏小 |
| 无税码 | 税率政策调整（如越南阶段性 8%）只能改历史行或靠人口口相传；无法「以后新单用新税率、旧单冻结」 |
| 0% 语义混淆 | 零税率出口、免税、不征税、漏填，申报口径完全不同，系统视为同一件事 |
| 不可抵扣 | 小规模/招待费等进项不应进 222102，现网只要 `tax_amount > 0` 就进进项税 |
| 无国家 | 公司是纳税主体，`companies` 无 `country_code`，无法按 CN/VN 选税码池 |
| 科目通配 | 进项/销项各一个科目，无法按税码拆子目（若财务以后要按税率申报） |
| 销售新建行税率为 0 | 与采购转单同一类漏填 |


一期在中小 ERP 可接受：表头汇总正确、发票过账借贷平衡。二期要解决的是 **可重复、可审计、可过账到正确税目**，而不是再加一个百分比栏。

---

## 5. 明确一期做对的部分（二期保留）

1. **税率在行、不在头** — 一行 10%、一行 0% 是常态。  
2. **单价按未税算** — 公式已统一，不要改成含税价（二期锁定）。  
3. **GR 复制 PO 税率** — 已是快照思维，只缺 `tax_code_id`。  
4. **税行与货行分科目** — `INPUT_TAX` / `OUTPUT_TAX` 已从货行科目拆出。  
5. **表头税额 = Σ 行** — 不要用表头税率重算。
