# 01. 应付贷项现状与问题（As-Is）

> 依据当前代码与 schema：`lychee-erp-fi` / `lychee-erp-wm` / `lychee-doc`。  
> 采购退货 V1（独立 `purchase_returns` + 未开票断言）已按 [采购退货](../采购退货/README.md) 落地。

---

## 1. 业务缺口

P2P 已落地：

```text
PO ─► GR（过账：库存 + / GR/IR）─► AP（从收货开正数票）─► 付款核销
                         │
                         └─► 采购退货（仅未占用数量）
```

已开票数量要退货或要纠正应付时，现网只有两条路：

1. **作废整张 AP**（`VOID`）：冲全部凭证、回吐全部 `invoiced_quantity`。已有过账付款则禁止。不能部分贷。
2. **先改/删 AP 草稿**再退货：只覆盖未过账占用。

没有「对已过账发票贷回一部分」的单据。采购退货 `RemotePurchaseReturnCreditMemoService.afterPosted` 为空；V1 硬规则是已占用不可退。

---

## 2. 现有单据各管什么

| 单据 | 模块 | 方向 | 现网能力 |
|------|------|------|----------|
| `ap_invoices` | FI | 增加应付 | 正数数量/金额；过账贷伙伴 GL；草稿即占用收货 `invoiced_quantity` |
| `payments`（DISBURSEMENT） | FI | 减少应付（资金） | 核销 `remaining_amount`；金额必须 `> 0`；`remaining < 0` 拒绝 |
| `purchase_returns` | WM | 出库存 + 冲回 GR/IR | `returnableTxn = min(未退, 未占用)`；不写 AP 实体 |
| 发票 VOID | FI | 整单冲回 | 有过账付款则禁止；回吐占用 |

`ApInvoiceLineSourceDocType` 仅 `RECEIPT` / `PURCHASE_ORDER`。  
`DocumentTypeEnum` 有 `AP_INVOICE`，无贷项。

---

## 3. 占用与剩余如何计算

### 3.1 收货 `invoiced_quantity`

`ApInvoiceGoodsReceiptQuantityHelper` 在 AP 行新增 / 改数量 / 删除（含 **DRAFT**）以及发票 VOID 时调用 `RemoteGoodsReceiptService.updateInvoicedQuantity`。

语义 = **已被 AP 行占用（含草稿）**，不是「已过账发票」。

强制上限（采购退货 V1 已改）：

```text
newInvoiced ≥ 0
newInvoiced ≤ transaction_quantity − SUM(POSTED 采购退货行.transaction_quantity)
```

减少占用（负 delta）在现网只发生在：改小数量、删行、VOID 发票。没有「过账贷项回减」这条路径，但 **API 已支持负 delta**。

### 3.2 AP `remaining_amount`

```text
过账发票：remaining = total
付款核销：paid += alloc；remaining = total − paid；remaining < 0 则失败
```

没有「已贷金额」列。若贷项只改 `remaining` 而不改付款公式，下一次付款会按 `total − paid` 把贷项冲掉的剩余写回去。

### 3.3 采购退货可退

```text
uninvoicedTxn = txn − invoiced
returnableTxn = min(unreturnedTxn, uninvoicedTxn)   // FOC：只用 unreturnedTxn
```

`assertReturnableAgainstInvoice` 同样用 `txn − invoiced`。  
**不改这两处公式**的前提下，让已开票可退的唯一办法：先把 `invoiced_quantity` 降下来。

## 4. 凭证方向

```text
收货：借 存货 / 贷 GR/IR
发票：借 GR/IR（或 CIP/费用）+ 进项税 / 贷 应付；价差 PRICE_VAR；汇率 EXCHANGE_DIFF
退货：贷 存货 / 借 GR/IR（数量记账政策下可整单跳过）
付款：借 应付 / 贷 银行
```

`ApInvoicePostingServiceImpl` 固定贷伙伴 GL。付款核销不产生「贷项对发票」的无资金分录。

数量记账（`require_standard_cost_on_stock_post = false`）：收货/退货可无库存凭证；AP 发票仍过账。贷项仍必须冲应付，即使退货侧无 GR/IR 凭证。

## 5. 下游耦合

| 下游 | 假设 |
|------|------|
| 付款挑票 | `remainingAmount > 0` 的已过账 AP |
| 发票 VOID | 无过账付款即可；**不看**是否已有贷项 |
| 固定资产成卡 | `fixed_assets.ap_invoice_line_id`；成卡后发票 VOID / 贷项不调原值（`06.3.固定資產MVP.md`） |
| 财务关帐 | `FiscalPeriod.close`：期间内按单据日期拦 **未过账** AP/AR/付款（`DRAFT` / `PENDING_APPROVAL` / `APPROVED`）。`POSTED` / `VOIDED` 不拦。现网不管贷项 |
| 改公司国家码 | `RemoteFiOpenDocumentService.hasOpenApInvoices` = 该公司存在 **非 VOIDED** AP。与关帐不是同一闸；现网不管贷项 |
| 付款排程 | 按发票 `total_amount` 拆；与剩余脱钩 |
| GR/IR 余额 | `JournalSourceModule.IN` + `AP` 的 GRIR 科目 |

## 7. 若把贷项做成负向 AP 发票会错什么

- `remaining = total − paid ≥ 0`、付款金额 `> 0`、从收货生成 `quantity > 0`、过账固定贷应付
- `external_invoice_no` 按供应商+公司唯一，与贷项号不是同一语义
- 排程、成卡、挑票、关帐都把 `ap_invoices` 当作正数负债
- 采购退货 V1 占用含草稿：负向草稿会立刻改 `invoiced_quantity`，仓库可能在财务过账前就退货

结论：独立 `ap_credit_memos`；数量与金额保持正数；凭证借贷对调。
