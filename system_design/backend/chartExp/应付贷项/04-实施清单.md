## 1. 审查结论

| 问题 | 结论 |
|------|------|
| 能否做成负向 `AP_INVOICE` / 类型位 | **否**；独立 `ap_credit_memos` |
| 数量能否为负 | **否**；正数数量与金额，过账借贷对调 |
| 已开票能否先退货再补贷项 | **否**；先贷项过账回减占用，再退货。WM 公式不改 |
| 退货过账能否自动生成贷项 | **否**；财务先过账贷项 |
| 锚点 | **一对一已过账 AP** |
| 核销 | 过账时全额冲该票 `remaining`；无未分配贷项 |
| 已付部分 | 不可贷；先作废付款。本波无退款 |
| 模块 / 菜单 | **FI**，`/fi/ap-credit-memos` |

编码从本文件 §5 按模块推进。

| 14 | 单号 | `CM` + `yyyyMM` + 4 位月重置 |

## 3. 实现约定

### 3.1 可贷数量

```text
postedCreditedQty = SUM(POSTED 贷项行.qty)   // 同 AP 行，排除 VOIDED
otherDraftQty     = SUM(其他 DRAFT 贷项行.qty)
creditableQty     = ap_line.qty − postedCreditedQty − otherDraftQty
```

过账：`qty ≤ creditableQty` 且表头 `total ≤ remaining`。用 `compareTo`。  
税走现有 `FiInvoiceTaxSupport` / `LineTaxCalculator.calculateInvoice`（正数）。  
草稿只占数量、不占 remaining；可贷金额 UI 不要预扣其他草稿金额。

### 3.2 过账模板

复制 `ApInvoicePostingServiceImpl` 结构，借贷对调：

- 暂估 `source_amount > 0`：贷行 GL（通常 GRIR）
- 价差：与原方向相反的 `PRICE_VAR`
- 税 `> 0`：贷进项科目
- 表头：借伙伴 GL = `total_amount`
- FX：同一套收货汇率 vs 本单汇率（汇率取自原票快照），符号相反

禁止 `findActiveUnitCost`。GL 用原 AP 行上已解析的 `gl_account_id`。

### 3.3 占用

仅 `source_doc_type == RECEIPT` 且 `source_line_id != null`。  
复用 `ApInvoiceGoodsReceiptQuantityHelper` 的 callback 形状，**不要**在草稿 create/update/delete 时调用；只在 POST / VOID 调。  
`updateInvoicedQuantity` 须对收货行悲观锁（`findAllByIdForUpdate`）；优先改 WM 该方法内部。

### 3.4 VOID vs 退货

```text
RemotePurchaseReturnService.existsPostedByOriginalReceiptItemIds(Set<Long> receiptItemIds)
```

`receiptItemIds` = 本贷项 RECEIPT 行的 `source_line_id`。  
WM 查 `purchase_returns.status = POSTED` 且 items.original_receipt_item_id in ids。  
FI 不得直接依赖 WM 实体。  
粗闸通过后，+占用仍可能因后续 AP 占用撞 cap；捕获后抛贷项专用 i18n（先改/删后续发票占用）。

### 3.5 付款 remaining

`PaymentInvoiceClearingSupport.applyAp` / `restoreAp`：

```text
remaining = total − paid − applied_credit_amount
if remaining < 0 → ValidationException
```

`ApInvoicePostingServiceImpl.postInvoice` 置 `remaining = total` 时 `credited_amount` / `applied_credit_amount` 必为 0（尚无贷项）。  
`recalculateInvoiceTotals` 重算 remaining 也要用该公式。严禁再用 `credited_amount` 进 remaining。

### 3.6 成卡

生成可贷行、过账前：`fixed_assets.ap_invoice_line_id` 已占用则拒绝该行。对标 `loadUsedLineIds`。

### 3.7 命名检查

合并前不得残留业务含义上的：负向 AP、`AP_INVOICE` 当贷项、菜单「红字」。

## 6. 验收

1. AP 100 未付，贷 40 过账：凭证借应付 40、贷 GR/IR（及税）；原票 `credited_amount=40`、`remaining=60`；收货 `invoiced_quantity` −40。
2. 随后采购退货最多可退「原未占用 + 40」；退 40 成功。
3. 再贷超过 remaining 拒绝；再贷超过可贷数量拒绝。
4. AP 草稿不能生成贷项。收货被 AP **草稿**占用时退货仍拒绝（改/删草稿）。
5. AP 已付 100（remaining=0）仍可贷（有可贷数量时）；过账后 `applied=0`、`refundable=贷项总额`，原票 remaining 仍为 0。
6. AP 付 40 剩 60：贷 60 后 `applied=60`、`refundable=0`、`payment_status=PAID`，挑票不再出现。贷超过 remaining 的部分记 `refundable`。
7. 两张贷项草稿抢同一 AP 行：数量占用互斥；过账锁 remaining。
8. 贷项过账与采购退货过账并发抢同一收货行：收货行锁生效，一方成功、另一方失败回滚；`invoiced_quantity` 与已退数量不超 cap。
9. 提交时 `external_credit_note_no` 仍为占位符（`PENDING-`）→ 拒绝（对标 AP）。
10. 该 AP 行已成卡 → 生成跳过该行；若手加则过账失败。
11. 贷项过账后原 AP VOID 失败。
12. 贷项过账 + 该收货行已有 POSTED 采购退货 → 贷项 VOID 失败；冲销退货后 VOID 成功：占用加回、`credited_amount` 回 0、凭证冲销。
13. 只贷不退：占用下降后可再从收货开 AP。再开 AP 占用后 VOID 原贷项失败（专用文案）；改/删后续占用后 VOID 成功。
14. 付款在贷项之后：`remaining = total − paid − applied_credit`，不会把贷项冲掉的剩余写回去。
15. 数量记账政策下贷项仍有应付凭证。
16. 期间内未过账贷项挡住关帐；已过账贷项不挡关帐。
17. 全文无负向 AP 发票方案残留。
