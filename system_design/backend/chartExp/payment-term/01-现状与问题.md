# 01. 付款条件现状与问题（As-Is）

> 依据当前代码与 `schema_tables`：`lychee-erp-fi` / `lychee-erp-scm` / `lychee-erp-sd` / `lychee-frontend`。  
> 未上线，无历史包袱；本波直接换模型，不做双写。

---

## 1. 一期设计

付款条件被当成 **ADM 统一选项**（`option_categories.code = PAYMENT_TERM` → `option_values`）。表上只有 `code` / `name` / 排序 / 启停，没有任何计算属性。

到期日不由结构化规则算出，而是：

```text
从 option.code 用正则 (\d+) 取第一组数字
  失败 → 再从 option.name 取
    仍失败 → 静默 DEFAULT_PAYMENT_TERM_DAYS = 30
due_date = invoice_date + days
```

对应代码：`PaymentTermDueDateHelper`（含 TODO：把偏移写进 `option_values` metadata）。  
`option_values` **没有** metadata / jsonb 列，该 TODO 尚未落地，也不应落地——字典塞财务规则会变成 ADM 特例。

---

## 2. 条件落在哪些表

| 表 | 栏位 | 谁写入 | 备注 |
|----|------|--------|------|
| `business_partners` | `payment_term_option_id` → `option_values` | FI 维护 | 财务核准的默认条件 |
| `purchase_orders` | 同上 | 选供应商时从前端带出 BP 条件；MRP/PR 转 PO 从 `RemoteBusinessPartnerFinanceDTO` 带出 | 可改 |
| `sales_orders` | 同上 | 选客户时带出 | 可改 |
| `outsource_orders` | **无** | — | 委外立 AP 只能退回 BP |
| `ap_invoices` / `ar_invoices` | **只有 `due_date`** | 自动立账用 Helper；手工开票前端 +30 | **不存**条件 ID |
| `customers` / `suppliers` | 无列 | 列表/表单只读展示 BP 上的选项 | 保存剥离 `paymentTermOptionId` |
| `ap_invoice_lines` / `ar_invoice_lines` | 无 | — | 到期在表头，这点是对的 |
| `payment_lines` | 已有 `discount_amount` | 收付核销 | 现网没有折扣计算来源 |

主数据侧：

| 对象 | 与付款条件相关 |
|------|----------------|
| `option_values` | 唯一「主档」；code/name 即规则 |
| `companies` | 无默认条件 |
| 发票 | 无排程行；分期/现金折扣无法表达 |

前端下拉一律 `OptionValueSelect categoryCode="PAYMENT_TERM"`：往来、PO、SO、客户/供应商展示。

## 3. 开单与立账路径

```text
FI 维护 BP.payment_term_option_id
         │
         ▼
选供应商/客户 ──► PO / SO 复制 option id（委外没有）
         │
         ▼
GR / 发货 ──► 自动开 AP / AR
              到期日 = Helper(invoiceDate, partner.paymentTermOptionId)
              不读 PO/SO 上的条件
手工开票 ──► 前端 dueDate = today + 30，与 Helper、BP 三套逻辑
```

```text
账龄 / 付款建议（规划中，见 财务/04-01）──► 只认发票 due_date
```

`payment_lines.discount_amount` 已预留现金折扣金额，但没有「在哪一天前付可打几折」的规则，核销时无法自动带出。

## 4. 作业与计算摩擦

| 问题 | 影响 |
|------|------|
| 从文字抓第一组数字 | `2/10 NET 30` → 2 天；`EOM25` / `月结25` 语义错；改显示名会改到期日 |
| `COD` / `PREPAID` / 纯「月结」无数字 | 静默变成 30 天，账龄与合同不符 |
| 只有 `invoiceDate + N` | 做不了月结、固定付款日、次月 25 号 |
| 自动立账只看 BP | PO/SO 已改条件，发票仍用主档 |
| 发票不存条件 ID | 主档改名/改码后无法追溯当初用哪一条 |
| 手工开票写死 +30 | 与 Helper、往来三套默认 |
| 委外无条件 | 委外 AP 只能退回供应商 BP |
| AR/AP 共用同一选项池 | 无法限制「仅应付」或「仅应收」条件 |
| 无排程行 | 30/60/90 分期、2/10 Net 30 无法立多笔到期 |
| Helper 失败兜底 30 | 漏配条件的发票看起来「正常」，账龄错而不报错 |

一期在中小开账可接受：列表能显示条件名称、发票有一个到期日。完整方案要解决的是 **可计算、可审计、可分期、可折扣**，而不是再往选项上挂一个整数。

---

## 5. 明确一期做对的部分（本波保留）

1. **条件由 FI 核准** — SCM/SD 主档不写条件；供应商/客户只展示 BP。  
2. **业务单可覆写** — PO/SO 从往来带出后允许改，不强制永远等于主档。  
3. **到期日在发票表头** — 账龄主索引继续用 `due_date`（本波改为派生值）。  
4. **核销行已有 `discount_amount`** — 现金折扣入账位已在，本波补规则与排程，不另发明扣款栏。  
5. **Remote BP 财务 DTO** — 转 PO 已走 `RemoteBusinessPartnerFinanceDTO`，只换字段名与来源表。
