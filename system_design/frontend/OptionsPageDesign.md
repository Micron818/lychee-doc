# Options页面设计规范

本文档旨在为后续AI开发人员提供Lychee ERP系统中Options页面的设计规范和实现指导。

## 1. 页面概述

Options页面用于管理系统中的选项分类（OptionCategory）和选项值（OptionValue），采用主从表结构设计。选项分类是主表，选项值是从表，两者通过categoryId字段关联。

## 2. 数据结构分析

### 2.1 OptionCategory（选项分类）
字段数量：7个字段
- name（名称）
- code（代码）
- description（描述）
- isSystem（是否系统内置）
- isActive（是否启用）
- defaultValueId（默认值ID）
- createdAt/updatedAt（时间戳）

### 2.2 OptionValue（选项值）
字段数量：9个字段
- categoryId（分类ID）
- name（名称）
- code（代码）
- sortOrder（排序）
- isSystem（是否系统内置）
- isActive（是否启用）
- createdAt/updatedAt（时间戳）
- createdBy/updatedBy（操作人）

## 3. 设计原则

根据ERP系统布局规范：
1. 由于两个实体的字段数都超过5个，新增和编辑操作应使用Drawer形式进行数据维护
2. 主从表结构采用垂直布局，主表在上方，明细表在下方
3. 明细表（OptionValue）适合使用EditableProTable实现行内编辑功能

## 4. 页面布局设计

### 4.1 整体结构
```
+--------------------------------------------------+
| PageContainer                                    |
|  +--------------------------------------------+  |
|  | 主表区域 (OptionCategory)                   |  |
|  |                                            |  |
|  |  [搜索条件]                                 |  |
|  |  [表格数据]                                 |  |
|  |  [操作按钮]                                 |  |
|  +--------------------------------------------+  |
|  +--------------------------------------------+  |
|  | 明细表区域 (OptionValue)                    |  |
|  |                                            |  |
|  |  [表格数据]                                 |  |
|  |  [操作按钮]                                 |  |
|  +--------------------------------------------+  |
+--------------------------------------------------+
```

### 4.2 主表（OptionCategory）设计

#### 4.2.1 组件选型
- 使用ProTable展示数据
- 新增/编辑使用DrawerForm

#### 4.2.2 功能特性
- 支持按名称、代码、启用状态等字段搜索
- 操作列包含编辑、删除按钮
- 选中某行时，自动加载对应的明细数据

#### 4.2.3 字段展示
- 名称（name）- 必填
- 代码（code）- 必填，唯一性校验
- 描述（description）- 可选
- 启用状态（isActive）- 开关形式展示，默认true
- 系统内置（isSystem）- 开关形式展示, 默认false
- 创建时间（createdAt）- 仅展示
- 更新时间（updatedAt）- 仅展示

### 4.3 明细表（OptionValue）设计

#### 4.3.1 组件选型
- 使用EditableProTable实现行内编辑
- 支持多行同时编辑和批量保存

#### 4.3.2 功能特性
- 支持多行同时编辑
- 新增行通过工具栏按钮触发
- 批量操作支持

#### 4.3.3 字段展示
- 名称（name）- 必填
- 代码（code）- 必填，唯一性校验
- 排序（sortOrder）- 数字输入框
- 启用状态（isActive）- 开关形式展示
- 系统内置（isSystem）- 开关形式展示
- 创建时间（createdAt）- 仅展示
- 更新时间（updatedAt）- 仅展示

## 5. 交互设计

### 5.1 主从表联动
- 主表选中某行时，自动加载对应的明细数据
- 主表切换时，清空明细表的编辑状态
- 删除主表记录前需要确认，并提示将同时删除相关明细记录

### 5.2 数据操作流程
1. 主表新增：
   - 点击新增按钮
   - 弹出Drawer表单
   - 填写表单信息
   - 提交保存
   - 刷新主表数据

2. 主表编辑：
   - 点击编辑按钮
   - 弹出Drawer表单，显示当前记录信息
   - 修改表单信息
   - 提交保存
   - 刷新主表数据

3. 明细表新增：
   - 点击新增按钮
   - 在表格中添加新行并进入编辑状态
   - 填写信息
   - 保存单行或批量保存

4. 明细表编辑：
   - 点击编辑按钮或直接点击单元格
   - 进入行内编辑状态
   - 修改信息
   - 保存单行或批量保存

### 5.3 特殊处理
- 代码字段建议添加自动格式化（空格转下划线）
- 提供友好的用户提示和操作反馈
- 添加加载状态和错误处理

## 6. 组件使用规范

### 6.1 主要组件
- PageContainer：页面容器
- ProCard：区域分割
- ProTable：主表展示
- EditableProTable：明细表展示和编辑
- DrawerForm：表单维护

### 6.2 表单组件
- ProFormText：文本输入
- ProFormSwitch：开关
- ProFormDigit：数字输入

## 7. 样式和主题

### 7.1 一致性要求
- 遵循系统统一的主题色（拂晓蓝 #1890ff）
- 使用系统默认的间距和布局规范
- 保持与其他管理页面一致的视觉风格

### 7.2 特殊标识
- 系统内置记录使用蓝色标签标识
- 启用状态使用绿色标签，停用状态使用红色标签
- 必填字段使用红色星号标识

## 8. 性能优化建议

### 8.1 数据加载
- 主表支持分页加载
- 明细表根据分类ID按需加载
- 提供搜索功能减少数据量

### 8.2 用户体验
- 添加加载状态提示
- 提供友好的错误处理和重试机制
- 合理使用缓存减少重复请求

## 9. 安全性和权限控制

### 9.1 数据保护
- 系统内置(is_system=true)记录只有ADMIN的角色能异动
- 删除操作需要二次确认

### 9.2 权限控制
- 根据用户权限显示不同的操作按钮
- 无权限时禁用相关功能
- 提供权限不足的友好提示

## 10. 错误处理和异常情况

### 10.1 网络异常
- 提供网络异常提示
- 支持手动刷新重试

### 10.2 数据校验
- 前端表单校验
- 提供详细的错误信息提示

### 10.3 异常处理
- 统一的错误边界处理
- 用户友好的错误提示页面

## 11. Service调用

### 1.1 查询操作（R）
- 在ProTable或EditableProTable的request属性中直接调用service方法
- 使用分页和搜索参数进行数据查询
- 示例：
  ```typescript
  <ProTable
    request={getTenantsPage}
  />
  ```

### 1.2 增删改操作（CUD）
- 使用useRequest Hook封装CRUD操作
- 为每个操作设置成功和失败的回调处理
- 示例：
  ```typescript
  // 删除操作
  const { run: delRun, loading: deleteLoading } = useRequest(deleteTenant, {
    manual: true,
    onSuccess: () => {
      messageApi.success('删除成功');
      actionRef.current?.reloadAndRest?.();
    },
    onError: () => {
      messageApi.error('删除失败，请重试');
    },
  });
  ```
