# 基础资料多语言

公司的名称、地址需要按语言取值。以后其他主档沿用同一套做法。这次只做存储和公司维护，不改打印模板，也不改公司下拉。

界面文案（后端 `messages` / `entities` / `enums`，前端 `locales`）与业务数据分开。名称和地址是用户录入的内容，不写入 properties。

## 源语言

`companies.name`、`companies.address` 是源语言的内容。

公司主档增加 `source_locale varchar(10) NOT NULL DEFAULT 'en'`。取值 `en`、`zh_CN`、`vi`。已有公司在迁移中写成 `en`，栏位不留空。数据库默认值也是 `en`，避免插入时为空。

列表列、排序、模糊查询、公司下拉、`BasisCacheService.getAllCompanies` 和 `findCompanyById` 仍只用主表的名称和地址，不看文本表，也不随界面语言切换。`RemoteCompanyDTO` 本次不加 `source_locale` 和译文。列表展开行仍只显示主表地址。

编码、税号、电话、邮箱不翻译。更改 `source_locale` 只改变主表文字被认定的语种，不翻译，也不把文字搬进文本表。

## 文本表

每种要多语言的主档单独一张文本表。公司用 `company_texts`，实体继承 `AuditableEntity`。文本表只存源语言以外的语言。

| 列 | 说明 |
|---|---|
| `id` | `bigserial` 主键 |
| `tenant_id` | 非空，`@TenantId` |
| `company_id` | 非空，外键到 `companies` |
| `locale` | `varchar(10)` 非空，`en`、`zh_CN`、`vi`，且不得等于该公司的 `source_locale` |
| `name` | `varchar(100)` 非空 |
| `address` | `text`，可空 |
| `created_at` / `updated_at` / `created_by` / `updated_by` | 与其他子表相同 |

约束对齐 `product_size_group_items`：

- 唯一键 `uk_company_texts_company_locale (tenant_id, company_id, locale)`。该键已能按租户和公司查询，不再另建 `(tenant_id, company_id)` 索引。
- 索引 `ix_company_texts_company (company_id)`。
- 外键 `fk_company_texts_tenant`、`fk_company_texts_company`、`fk_company_texts_created_by`、`fk_company_texts_updated_by`。都是 `NO ACTION`，不用数据库级联删除。
- 删除公司前，先按公司 id 删除其文本行（`@Modifying(flushAutomatically = true)`），再删公司。子级公司一并处理。
- 请求里的 `texts` 不得包含与 `sourceLocale` 相同的语言，否则 `validation.company.text.locale.same_as_source`。因此改源语言后，原语言若还在请求里会被拒绝；前端提交前去掉该项，后端就按缺失的 `locale` 删掉该行。主表名称、地址不动。

语言码与 `MessageSource` 的库存值一致，不用前端的 `zh-CN`、`vi-VN`。

不做按语言加列，不做主表 `jsonb`，也不做 `entity_type + field + locale` 的通用翻译表。

落地时同步：Liquibase `v2` 增量、`companies` 与 `company_texts` 的 `schema_tables/BASIS` 脚本、`BASIS_schema_design.md`。`companies` 不在租户开通白名单里，这两处变更也不加入 `provision-tenant.sql`。

## 语言码

`lychee-erp-common` 增加枚举 `DataLocale`：`ZH_CN("zh_CN")`、`VI("vi")`、`EN("en")`。

实体和 `CompanyResponse` 用该枚举。数据库用 JPA `AttributeConverter` 存括号里的代码。响应用 `@JsonValue` 输出 `en` / `zh_CN` / `vi`，不输出枚举名 `ZH_CN`。

`CompanyRequest.sourceLocale` 和 `CompanyTextRequest.locale` 用 `String`。服务里调用 `DataLocale.fromCode`：空白是 `required`，认不出的代码是 `invalid`。不为该枚举写 `@JsonCreator`。请求字段若是枚举，非法字符串会在进入校验前变成无法读取的请求体，现有异常处理会返回 500，而不是上述 key。

从 `java.util.Locale` 归一化时只看 `getLanguage()`，不用 `toString()`：

| `getLanguage()` | 结果 |
|---|---|
| `zh`（含 `zh_CN`、`zh_TW`、`zh`） | `ZH_CN` |
| `vi`（含 `vi_VN`） | `VI` |
| `en`（含 `en_US`） | `EN` |
| 其他 | 空，调用方改读主表 |

## 解析

不带语言参数，或请求的语言等于 `source_locale`：只读主表，不读文本表。

请求的是另一种语言：`name`、`address` 各自判断。译文经 `hasText` 为真就用译文，否则用主表该字段。空白视为没有译文。不改用第三种语言。

因此源语言为 `en`、越南文行只有名称时：取越南文则名称用越南文，地址用主表地址。

双语并印：某一语等于源语言时，该行用主表；否则只用该语言的非空译文，没有则不印该行。

`lychee-erp-common` 的 `DataLocaleTexts` 按一个栏位计算：`resolve` 随一种语言取值，`bilingual` 取双语并印的一个栏位，`includeBilingualLine` 判断整行是否保留。调用方按该主档的栏位各调一次。公司名称、地址这样组合；物料只有名称时只调名称。各实体的文本表留在所属模块。本次不为此改 `BasisCacheService`。

## 公司接口

Request / Response 增加 `sourceLocale` 和 `texts: [{ locale, name, address }]`。`name`、`address` 仍是源语言的内容。

`getCompany`、`getCompanyPage`、`createCompany`、`updateCompany`、`uploadLogo`、`deleteLogo` 的 `CompanyResponse` 都带这两项。公司页面编辑直接使用分页行，不另调详情；分页漏返回 `texts` 时，再次保存会把译文清空。分页按公司 id 批量装载（`findByCompanyIdIn`）。`getCompanyList` 不带译文。

`texts` 只含源语言以外的语言，请求里没有的 `locale` 会删掉。保存时按 `locale` 比对已有行：有则更新，无则插入，缺失的 `deleteAllInBatch`。禁止先按公司删光再插入同一唯一键。写路径用内存中的结果组装 Response，保存后不对文本行做 `JOIN FETCH`。

校验：

- `sourceLocale` 必填，且是上述三种。
- `texts.locale` 必须是上述三种，不得等于 `sourceLocale`，同一请求不可重复。
- 出现该元素则 `name` 必填，最长 100；`address` 可空。`name` 为空白时拒绝，即使 `address` 也空白，不把这种元素当成删除。
- 校验文案走 `messages*.properties` 三语：`validation.company.source_locale.required`、`validation.company.source_locale.invalid`、`validation.company.text.locale.invalid`、`validation.company.text.locale.duplicate`、`validation.company.text.locale.same_as_source`、`validation.company.text.name.required`、`validation.company.text.name.size`。

## 公司表单

主表单仍是一组名称、地址，并增加源语言选择。不在名称、地址下面再排中文、越南文或英文。选项为 `en`、`zh_CN`、`vi`。编辑已有公司时带出库里的值（迁移后为 `en`）。新建预选 `en`，与数据库默认值一致。

「多语言」打开小窗口。窗口只读显示当前名称、地址和源语言，只编辑另外两种语言。源语言下拉和小窗口里的语言名称用前端文案，不把 `DataLocale` 放进 `EnumController`。`EnumController.getCode` 对普通枚举取 `name()`，会变成 `ZH_CN`。

- 某一语的名称和地址都空白：不提交该 `locale`。
- 只填了地址、没填名称：拦住，不丢弃地址。
- 主表单组装请求时，无论小窗口是否打开过，都去掉 `locale` 等于当前 `sourceLocale` 的项。用户只改源语言、未打开小窗口就保存时，同样去掉。后端仍拒绝直接传入与源语言相同的 `locale`。
- 小窗口确定后，译文写进主表单状态。外层抽屉的 `useFormOpenChangeHandler` 用 `customHasChanges` 比较当前 `texts` 与打开时的 `texts`。否则小窗口已确定、主表单尚未保存时，关抽屉会被当成没有修改。
- 小窗口字段与 `texts` 用 `toFormValues` 双向转换。参考 `ProductSizeGroupForm`。

前端标签三语：`pages.basis.companies.sourceLocale`、`pages.basis.companies.text.action`、`pages.basis.companies.locale.en`、`pages.basis.companies.locale.zh_CN`、`pages.basis.companies.locale.vi`，以及三种语言的名称、地址标签。

## 以后的主档

物料、客户等需要时，在该主档增加 `source_locale`，并另建 `material_texts`、`customer_texts`。列按该实体实际要翻译的字段定。已有行同样写成 `en`，栏位不留空。列表和缓存仍读主表。

## 打印

本次不改模板。存储可以支持两种印法，由具体打印任务决定：

1. 随本次打印语言取一条。等于源语言用主表；否则文本表按栏位退回主表。
2. 抬头同时印中文和越南文。等于源语言的那一行用主表；另一行只用非空译文，没有则不印。与当前界面语言无关。

打印需要译文时，在所属模块读取 `source_locale` 和 `company_texts`，再按栏位调用 common 的归一化和回退函数。不要把译文塞进 `RemoteCompanyDTO`。
