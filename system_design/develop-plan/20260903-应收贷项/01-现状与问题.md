# 01. 应收贷项现状与问题（As-Is）

> 依据当前代码与 schema：`lychee-erp-fi` / `lychee-erp-sd` / `lychee-erp-wm` / `lychee-doc`。  
> 客户退货设计见 [客户退货](../客户退货/README.md)。应付侧对照 [应付贷项](../应付贷项/README.md)。

---

## 1. 业务缺口

O2C 已落地：

```text
SO ─► DN ─► 领料 SALES_DELIVERY ─► AR（从交货开正数票）─► 收款核销
```

已开票数量要退货或要纠正应收时，现网只有两条路：

1. **作废整张 AR**（`VOID`）：冲全部凭证、回吐全部 `invoiced_quantity`。已有过账收款则禁止。不能部分贷。
2. **先改/删 AR 草稿**再退货：只覆盖未过账占用。

没有「对已过账发票贷回一部分」的单据。客户退货 V1 硬规则是已占用不可退。

应付贷项 + 供应商退款已落地，证明独立贷项表、正数数量、过账拆 applied / refundable、收款公式必须改 remaining 这一套可行。应收应对齐，不要重走「先只贷未收」的弯路。

---

## 2. 现有单据各管什么

| 单据 | 模块 | 方向 | 现网能力 |
|------|------|------|----------|
| `ar_invoices` | FI | 增加应收 | 正数数量/金额；过账借伙伴 GL、贷收入/销项税；草稿即占用交货 `invoiced_quantity` |
| `payments`（RECEIPT + CUSTOMER） | FI | 减少应收（资金） | 核销 `remaining = total − received`；金额必须 `> 0` |
| `customer_returns`（设计中） | WM | 入库存 + 冲 COGS | `returnable = min(未退, 未占用)`；不写 AR 实体 |
| 发票 VOID | FI | 整单冲回 | 有过账收款则禁止；回吐占用 |

`ArInvoiceLineSourceDocType` 仅 `SHIPMENT` / `SALES_ORDER`。  
`DocumentTypeEnum` 有 `AR_INVOICE`，无贷项。  
`ar_invoices` 无 `credited_amount` / `applied_credit_amount`。

## 3. 占用与剩余如何计算

### 3.1 交货 `invoiced_quantity`

`ArInvoiceDeliveryQuantityHelper` 在 AR 行新增 / 改数量 / 删除（含 **DRAFT**）以及发票 VOID 时调用 `RemoteDeliveryService.updateInvoicedQuantity`。

语义 = **已被 AR 行占用（含草稿）**。

客户退货设计将把上限改为 `issued`（实发净额；`issueCallback` 已净减退货）。减少占用（负 delta）在现网只发生在：改小数量、删行、VOID 发票。没有「过账贷项回减」这条路径，但 **API 已支持负 delta**。

### 3.2 AR `remaining_amount`

```text
过账发票：remaining = total
收款核销：received += alloc + discount；remaining = total − received；remaining < 0 则失败
```

`PaymentInvoiceClearingSupport.applyAr` 用 `findById`，**没有行锁**，也没有已贷金额。若贷项只改 `remaining` 而不改收款公式，下一次收款会按 `total − received` 把贷项冲掉的剩余写回去。

`restoreAr` 现网用 `.max(ZERO)` 静默截断 `received` / `remaining`。本专题必须删掉，对不齐就失败。

应付侧已改为 `remaining = total − paid − applied_credit` 且 `findByIdForUpdate`。应收必须同样改。

### 3.3 客户退货可退

```text
remainingUninvoiced = delivery.txn − invoiced − 该交货行已退与其他草稿
returnableTxn = min(领料未退, remainingUninvoiced)
```

**不改这两处公式**的前提下，让已开票可退的唯一办法：先把 `invoiced_quantity` 降下来。

## 4. 凭证方向

```text
出库：借 COGS / 贷 存货
发票：借 应收 / 贷 收入 + 销项税
退货：借 存货 / 贷 COGS（数量记账政策下可整单跳过）
收款：借 银行 / 贷 应收
```

`ArInvoicePostingServiceImpl` 固定借伙伴 GL、贷行 GL（收入）、贷销项税。收款核销不产生「贷项对发票」的无资金分录。

数量记账：出库/退货可无库存凭证；AR 发票仍过账。贷项仍必须冲应收，即使退货侧无 COGS 凭证。

AR 发票 **没有** AP 那套收货暂估 / `PRICE_VAR` / 收货汇率 vs 发票汇率。贷项凭证就是发票的借贷对调。

## 5. 下游耦合

| 下游 | 假设 |
|------|------|
| 收款挑票 | `remainingAmount > 0` 的已过账 AR |
| 发票 VOID | 无过账收款即可；**不看**是否已有贷项 |
| 财务关帐 | 期间内拦未过账 AR/付款。现网不管贷项 |
| 改公司国家码 | 现网有开放 AR 检查则对齐应付：不把贷项并进 `hasOpenArInvoices` |
| 收款排程 | 按发票 `total_amount` 拆；与剩余脱钩 |
| 固定资产 | AR 行不成卡；本专题无成卡闸 |

## 7. 若把贷项做成负向 AR 发票会错什么

- `remaining = total − received ≥ 0`、收款金额 `> 0`、从交货生成 `quantity > 0`、过账固定借应收
- `tax_invoice_no` 与贷项税务号不是同一语义
- 排程、挑票、关帐都把 `ar_invoices` 当作正数债权
- 客户退货占用含草稿：负向草稿会立刻改 `invoiced_quantity`，仓库可能在财务过账前就退货

结论：独立 `ar_credit_memos`；数量与金额保持正数；凭证借贷对调。
