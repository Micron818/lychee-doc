# 产品主站

`lycheetech.com` 与 `www.lycheetech.com` 提供产品介绍和帮助。它们不属于任何栈。`khh-prod` 切换当天起，根域不再作为 ERP 入口，也不跳进任何租户 Host。栈的划分见 [多租户运行栈](../20261022-多租户运行栈/02-目标架构.md)。

主站放在阿里云 OSS，前面加 CDN。不挂到 `khh-prod`、`khh-test`、`demo` 的 Nginx，也不把 `lycheetech.com` 的 DNS 交到 Cloudflare。

## 仓库

`lychee-doc` 仍是一个仓库。

| 路径 | 作用 |
|------|------|
| `system_design/` | 研发设计与库表。不编译，不发布 |
| `site/` | 主站，唯一的 VitePress 项目 |
| `site/intro/` | 系统介绍 |
| `site/user_training/` | 用户训练。中文为源，`vi/` 与 `zh/` 路径镜像 |

构建只在 `site/` 执行 `pnpm docs:build`。产物是 `site/.vitepress/dist`。对象键从桶根开始，`index.html` 就是网站根，不放进 `dist/` 前缀。

`site/.vitepress/config.mts` 的 `srcExclude` 排除 `README.md`、`**/assets/**`、`user_training/00-conventions.md`。写作约定和截图说明留在仓库里阅读。

## 地址

不开启 `cleanUrls`。普通页的链接带 `.html`，与桶里的对象键相同。`index.md` 的地址以 `/` 结尾，对应目录下的 `index.html`，例如 `/intro/`、`/user_training/`、`/user_training/zh/00-overview/`。

导航和侧栏的路径是手写的。新增普通页时写成 `.html`。新增目录首页时以 `/` 结尾。正文里的相对链接由 VitePress 在构建时改写。

不显示 Git 的最后更新时间。训练正文自己写版本日期。构建不读取 Git 历史，CI 的检出深度保持默认。

站点语言是 `zh-CN`。用户训练不维护英文。越南文按中文目录补齐；导航保留 `Tiếng Việt` 入口。

## 公开内容

首页说明产品范围，并链到系统介绍和用户训练。

已有账号使用贵司专属地址。页面不列出客户 Host。演示入口是 `https://footwear-demo.lycheetech.com`，数据是虚构的。这个名字按 `{标签}-demo.lycheetech.com` 放在 `demo` 栈，不在主站桶上。

主站没有登录，没有 `/api`、`/oidc`。不写 Cookie，尤其不写 `Domain=.lycheetech.com`。根域和各租户 Host 同属 `lycheetech.com` 这个站点。业务令牌在租户 Host 的 `localStorage`，Keycloak 会话写在 issuer 那个 Host 上。

## 桶

桶名 `lycheetech-site`，地域 `oss-ap-southeast-1`。读写权限私有，阻止公共访问。不开静态网站的公网入口。可以开版本控制，用于回退一次上传。

这个桶与各栈的业务桶、备份桶分开。上传用的 AccessKey 只能对该桶 `ListObjects`、`GetObject`、`PutObject`、`DeleteObject`。CDN 回源使用控制台的「私有 Bucket 回源」服务角色，与上传密钥分开。

发布时同步 `dist` 的内容，并删除桶里这次产物没有的对象。`--delete` 只用于这个桶。

缓存头：

| 对象 | `Cache-Control` |
|------|-----------------|
| `*.html`、`vp-icons.css`、`hashmap.json` | `no-cache` |
| `assets/` 下的 js、css、woff2 | `public, max-age=31536000, immutable` |

`Content-Type` 按扩展名设置：`text/html`、`text/css`、`application/javascript`、`font/woff2`。

## CDN

加速域名是 `lycheetech.com` 和 `www.lycheetech.com`。加速区域不含中国内地。源站是 `lycheetech-site`，回源 Host 用桶域名。

证书在 CDN 上申请，名称包含这两个域名。`*.lycheetech.com` 盖不住根域。通配证书的私钥仍只放在各栈，不拷到 CDN。

HTTP 跳转到 HTTPS。打开 HTTP/2，并对 HTML、JS、CSS 压缩。

缓存规则：

- `/assets/` 缓存一年。
- 无后缀路径、以 `/` 结尾的路径、`*.html`、`/vp-icons.css` 不缓存，或缓存很短并遵循源站的 `no-cache`。
- 404 的缓存时间设短。

回源 URI 改写，命中后停止：

1. 路径已有扩展名（`/assets/...`、`*.html`、`*.css`）保持原样。
2. 路径是 `/`，回源 `/index.html`。
3. 路径以 `/` 结尾，回源「原路径 + `index.html`」。`/intro/` 回源 `/intro/index.html`。

不把无后缀路径改成 `.html`。普通页的链接已经带扩展名。

`www` 整站 301 到 `https://lycheetech.com`，路径和查询串保持不变。规范名是根域。

状态码 404 时正文返回 `/404.html`，HTTP 状态仍是 404。

响应头加上 `X-Content-Type-Options: nosniff`。页面含内联脚本，先不加严格的 Content-Security-Policy。

## 解析

切换前先看根域 `@` 上已有的 MX、TXT、SPF。

- `www` 用 CNAME 指向 CDN 分配的地址。
- 根域没有邮件和 TXT 时，`@` 用 CNAME 指向 CDN。
- 根域已有 MX 或 TXT 时，CNAME 与它们冲突。使用云解析 ALIAS（旗舰版或尊享版），或者把规范名改成 `www`，根域用显性 URL 301 到 `https://www.lycheetech.com`。

只加这两条精确记录。不做 `*.lycheetech.com`。不指向任何栈的 ECS。

证书校验用的 TXT 可以先加上。CDN 上 HTTPS 和回源改写都测通之后，再把根域和 `www` 指到 CDN。在此之前用 hosts 或 `curl --resolve` 访问 CDN 节点。

## 发布

工作流是 `lychee-doc/.github/workflows/site.yml`。与前后端的镜像构建、ACR 和 SSH 部署分开，不选择 `khh-test`、`demo`、`khh-prod`。

| 触发 | 动作 |
|------|------|
| 拉取请求，且变更涉及 `site/**` | 在 `site/` 执行 `pnpm install --frozen-lockfile` 和 `pnpm docs:build`。失败则不能合并。不上传 |
| 推送到 `main`，且变更涉及 `site/**` | 同样构建，再把产物同步到 `lycheetech-site`，写上缓存头，并刷新 CDN 上的 HTML |

`system_design/**` 不触发这条工作流。Node 满足 `site/package.json` 的 `>=18`，包管理器使用其中的 `pnpm@9.15.0`。

两次发布串行：concurrency 分组固定为这一条发布，不取消已经开始的一次，避免两份带删除的同步同时写桶。

GitHub Secret 是 `ALIYUN_ACCESS_KEY_ID` 与 `ALIYUN_ACCESS_KEY_SECRET`。这把密钥只能读写 `lycheetech-site`，并能刷新 `lycheetech.com`、`www.lycheetech.com`。不用各栈的 SSH 密钥，也不用业务桶的 AccessKey。

`assets/` 的文件名带哈希，新文件不必刷新。回退时把上一版 `dist` 再同步一次并刷新 HTML；桶开了版本控制时，也可以按对象版本找回。

CDN 的回源改写、证书和解析在阿里云控制台做一次，不放进工作流。

## 上线核对

- `/`、`/intro/`、`/user_training/` 返回 200。
- `/user_training/glossary.html` 返回 200，`Content-Type` 是 HTML。
- `/user_training/zh/01-getting-started/01-system-overview.html` 返回 200，流程图能出来。
- `/assets/` 下某个带哈希的 `.js` 返回 200，`Content-Type` 是 JavaScript，缓存时间为长期。
- `/vp-icons.css` 返回 200，`Content-Type` 是 CSS。
- 不存在的路径返回 404，正文是站点的 404 页。
- `/system_design/` 返回 404。
- `http://` 跳到 `https://`。
- `https://www.lycheetech.com/intro/` 跳到 `https://lycheetech.com/intro/`。
- 响应里没有 `Set-Cookie`，页面不请求任何栈的 `/api/` 或 `/oidc/`。

## 不做

- 不把主站挂到任何栈，不把根域证书放回栈上。
- 不使用 Cloudflare Workers，也不迁移 `lycheetech.com` 的 NS。
- 不开启 `cleanUrls`，不在页脚显示 Git 更新时间。
- 不发布 `system_design/`、写作约定和截图目录。
- 不在主站列出客户 Host，不做统一登录。
- 不维护英文用户手册。
- ERP 里的帮助入口以后再链到本站的训练页。本次不做。
