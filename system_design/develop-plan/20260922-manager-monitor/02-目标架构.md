# 02. 目标架构

> 原则：report 是跨模块只读出口；口径和查询留在拥有该数据的模块。  
> 导出框架见 [../20260818-report/02-导出框架总体设计.md](../20260818-report/02-导出框架总体设计.md)。本专题不扩展 `DataExportHandler`。

---

## 1. 模块

```text
lychee-erp-common
  HealthIndicator          各模块可注册的健康卡片
  HealthContext / HealthCard
  ProductionDailyProgressQuery
                           仅 pp 实现的当日进度查询

lychee-erp-report          只依赖 common
  MonitorController / MonitorService
  收集 HealthIndicator
  调用 ProductionDailyProgressQuery
  不写 JPQL，不注入其他模块的 Repository

lychee-erp-pp
  ProductionDailyProgressQuery 的实现
  只读事务内用本模块 Repository 汇总 ProductionReport

其他业务模块（P2 起）
  各自一个 @Component implements HealthIndicator
```

`lychee-erp` 启动类已经同时加载 report 与各业务模块，Spring 能收集到全部 `HealthIndicator` Bean。这和 `ExportJobServiceImpl` 收集 `DataExportHandler` 相同，不需要 report 去依赖 pp。

P0 就把 `ProductionDailyProgressQuery` 和请求 / 响应类型放进 common，report 的 POST 能编译。pp 的实现类放到 P1。P0 容器里没有这个 Bean 时，进度接口返回「未启用」，健康页仍可打开。

## 2. 页面

一个菜单、一个路由：`/report/monitors`。

```text
管理监测
├─ 系统健康          默认收起。展开后才 GET /health
│    卡片网格。无注册指标时显示空状态，不报错
└─ 今日生产进度      默认收起。展开后才 POST 进度
     日期（默认今天）、工厂（可选，可清空）
     合计：良品、返工、报废、产出、良品率
     多种计量单位时合计数量旁提示混合单位，合计良品率留空
     明细表：见 03 的行维度（含单位）
     行上链接到报工列表。未选厂的行带该厂；已选厂的行再带工单号。状态固定 POSTED
```

以后新增的区块同样默认收起，展开才请求自己的接口。交互见 [05 §7](./05-物料变体检核.md)。

窄屏下两区上下排列，卡片一列，表格 `scroll.x`。不另做移动端路由。

前端目录：

```text
src/pages/report/monitors/index.tsx
src/services/report/monitor/
```

文案走 `zh-CN` / `en-US` / `vi-VN`。页面标题、列名、空状态使用 `FormattedMessage`。

## 3. 请求形态

打开 `/report/monitors` 不发业务请求。使用者展开哪个区块，才同步读取那个区块。接口本身仍是一次请求、一次响应。

- 健康：展开「系统健康」后 `GET`，一次返回当前用户可见的全部卡片。本批不按卡片拆请求。
- 进度：展开「今日生产进度」后 `POST` 查询体（日期默认今天、可选工厂），与现网列表筛选的 `ProPageRequest` 分开。本接口不分页；一天、一个租户的已过账报工按组合并后行数有限。若上线后单日行数过大，再在 pp 内改为分页，report 的路径不变。
- 新区块：展开才调用该区块自己的接口，不在页面挂载时追加查询。
- 使用 `@Transactional(readOnly = true)`，事务开在 **实现查询的模块**。report 的拼装方法不必包大事务。
- 不进入 `exportTaskExecutor`，不写 `export_jobs`。

单个健康指标抛错时，该卡片状态为 `UNKNOWN`。文案 key 取 `HealthIndicator.titleKey()`，不依赖 `evaluate` 的返回值。其余卡片照常返回。进度查询失败则整段进度按现网业务异常返回，不影响健康区（前端分两次请求）。

## 4. 权限

菜单与动作为运行时数据（本专案惯例，无 Liquibase 种子）。

| 权限 | 谁用 | 作用 |
|------|------|------|
| `/report/monitors:read` | 管理者 | 打开监测页、调用两个 API |
| 各指标自己的 `requiredAuthority()` | 该指标的读者 | 没有该权限且不是 `ROLE_ADMIN` 时，卡片不出现 |
| `/pp/production-reports:read` | 要点进报工列表的人 | 只保护下钻。没有它仍可看进度合计 |

监测权限不等于单据的 `read` / `export`。进度接口只返回汇总数、定位字段（工厂、工单号、物料、单位），以及已选工厂时的工单计划量、累计完工量、计划起止日、工单单位。不返回报工备注等明细正文。

健康页缺少某个指标权限时跳过该卡片，整页不 403。角色 code 为 `ADMIN` 时，权限串里有 `ROLE_ADMIN`（`AuthenticationCacheServiceImpl` 加前缀），但不会因此自动拥有每个菜单的 `read`。卡片是否可见：`requiredAuthority()` 为空，或当前用户拥有该权限，或拥有 `ROLE_ADMIN`。`ROLE_ADMIN` 不代替 `/report/monitors:read`：没有监测页读取权时，菜单不可见，API 403。

## 5. 当日进度口径

查询在 pp，只统计：

```text
tenant = 当前租户（Repository 上的租户过滤，禁止在 params 里手写 tenantId）
reportDate = 请求日期
reportStatus = POSTED
factoryId = 请求有值时等值过滤
```

数量在 pp 内汇总，前端不做 `BigDecimal` 相加或相除。

| 字段 | 算法 |
|------|------|
| 良品 / 返工 / 报废 | 组内已过账报工对应字段之和 |
| `outputQuantity` | 三者之和。对齐日报行的派生产出 |
| `yieldRate` | 良品 / 产出，产出为 0 则 null。格式对齐日报 `percentText`（一位小数加 `%`） |
| 单位 | 组内 `unitId` 只有一种时填写 `unitId` / `unitCode` / `unitName`；多于一种则三个单位字段为 null，该行 `mixedUnits = true`，该行良品率 null |
| 合计 `mixedUnits` | 响应里出现多于一种单位，或任一行自身混合，则为 true。为 true 时合计数量仍返回，合计良品率为 null |

日报 Excel 在混合单位时仍写出合计良品率，并另标 `{mixedUnitLabel}`。监测合计在 `mixedUnits` 时不给良品率：不同量纲的数量相除不能当指标。行内只有一种单位时仍给该行良品率。

状态口径和日报 Excel 不同。Excel 跟列表筛选走，选草稿就导出草稿。监测页固定已过账。两套规则都写在 pp，report 不复制查询。

行维度：

| 请求 | 一行代表 |
|------|----------|
| 未选工厂 | 一个工厂的合计 |
| 已选工厂 | 一张生产工单在该日的合计（工单号、成品物料、单位、三个数量、产出、良品率），并带出该工单的计划量、累计完工量、计划起止日 |

行顺序是契约的一部分。`GROUP BY` 之后数据库不保证顺序，pp 必须显式排序后再返回：未选厂按 `factoryId` 升序；已选厂按工单 `orderNo` 升序，相同单号再按 `productionOrderId`。刷新页面时行不许跳动。

下钻到报工列表（现网列字段名，搜索提交前的值）：

| 行 | URL |
|----|-----|
| 未选工厂 | `/pp/production-reports?reportDate={date}&factoryId={factoryId}&reportStatus=POSTED` |
| 已选工厂 | 上式再加 `&productionOrderNo={no}` |

`production-reports` 今天不会读这些 query。P1 要让该页用它们初始化搜索，第一笔列表请求就带上筛选。没有 `/pp/production-reports:read` 时监测页不渲染链接。

已选工厂时，工单计划量、累计完工量、计划起止日来自工单表头，不参与合计，也不用来计算完成率。累计完工是历次过账良品之和，计划量是整单总量。未选工厂的行这些字段为 null。

第一版不做相对计划量的完成率，不按产线拆（报工实体上没有独立产线字段）。这些若以后要做，仍加在 pp 的这个查询上，并单独改契约。

## 6. 租户与性能

统计必须走所属模块的 Spring Data 查询，让 `@TenantId` 过滤生效。report 不对 `production_reports` 或其他业务表写原生 SQL。

健康指标实现要一次计数或小范围查询，避免在卡片计算里分页扫全表再在内存过滤。P0 没有指标，没有这个成本。某个指标变慢时，只改该指标的实现，可以加短缓存；缓存键带租户。本设计不引入指标结果表。
