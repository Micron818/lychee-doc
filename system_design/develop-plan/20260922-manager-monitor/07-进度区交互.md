# 07. 进度区交互

> 读者是管理多家工厂的人，用手机浏览器打开同一页 `/report/monitors`。  
> 进度接口不改。行维度仍以 [03-契约设计.md](./03-契约设计.md) 为准：不带 `factoryId` 时一行一厂，带 `factoryId` 时一行一工单。  
> 区块展开与收起仍以 [05 §7](./05-物料变体检核.md) 为准。本节替换工厂下拉、查询按钮，以及工厂行跳进报工列表。

---

## 1. 四条决定

| # | 决定 | 做法 |
|---|------|------|
| 1 | 去掉工厂选项 | 不放工厂下拉，不读取用户主数据的 `factoryId`（那是建单用的厂别，不是监测范围）。首次展开的请求不带 `factoryId`，一行一个当天有已过账产量的工厂 |
| 2 | 点一厂看工单 | 内层 `Collapse` 开 `accordion`。点工厂行，用该行 `factoryId` 再查一次，工单卡片铺在该行面板里。同时只展开一厂。再点这一行则收起。不进入报工列表，也不整页换成工单 |
| 3 | 日期 | 默认今天。控件在进度面板内部、合计上方。`allowClear={false}`，今天之后的日期不可选。选出完整日期后按当前展开状态查询。选择过程中的中间值不发请求 |
| 4 | 刷新 | 与健康区相同的手动刷新，放在外层「今日生产进度」标题栏。状态在 `useMonitorProgress`，不放在 `ProgressPanel` 内部。没有查询按钮，也不定时刷新 |

页顶合计始终来自不带 `factoryId` 的响应，展开某一厂时合计仍是全部工厂。工厂行就是该厂合计，展开区里不再放一块该厂合计。

没有已过账产量的工厂不出现在列表里。当天全部没有产量时，合计为 0。汇总 `rows` 为空时不渲染内层 `Collapse`（没有任何面板），合计下方用 `Empty`：

```tsx
<Empty
  image={Empty.PRESENTED_IMAGE_SIMPLE}
  description={<FormattedMessage id="pages.report.monitors.progress.empty" />}
/>
```

某一厂的工单响应 `rows` 为空时，该面板内用同一个 `Empty`。加载中用 `Spin`，不要把还没返回的数据画成这个空状态。未启用用 `pages.report.monitors.progress.disabled`，不用这一条。

多种单位是常态。合计或工厂行 `mixedUnits == true` 时不显示良品率，数量仍显示。页面不展示 `pages.report.monitors.progress.mixedUnitsNotice`。

## 2. 状态

外层 `Collapse` 的 `extra` 由 `MonitorsPage` 渲染。进度的日期、展开的厂和加载中不能关在 `ProgressPanel` 里面，否则标题栏刷新看不到，面板未挂载时也无法重查。

比照 `useMonitorHealth`，在 `src/pages/report/monitors/useMonitorProgress.ts` 提供 `useMonitorProgress(open: boolean)`。`MonitorsPage` 调用它，把结果传给标题栏和 `ProgressPanel`。`ProgressPanel` 不自己请求。

Hook 交出：

| 字段 | 用途 |
|------|------|
| `reportDate` / `setReportDate` | 当前日期。面板内的日期控件写入它 |
| `expandedFactoryId` / `toggleFactory` | 当前展开的厂。`null` 表示全部收起 |
| `summary` | 不带 `factoryId` 的响应。页顶合计和工厂行用它 |
| `orders` | 当前厂的工单响应。只属于 `expandedFactoryId` |
| `loading` | 汇总或工单任一请求进行中。标题栏刷新按钮用它 |
| `ordersLoading` | 工单请求进行中。展开区用 `Spin`，合计在汇总已返回后保持可见 |
| `disabled` | 收到 `validation.monitor.production_progress.not_enabled` |
| `refresh(event, ensureOpen)` | 与健康区同一个签名。先 `stopPropagation` |

`open` 从收起变为展开、且还没有成功的汇总、也不是未启用时，Hook 用今天查一次，不带 `factoryId`。收起后再展开不自动重查。标题栏在面板收起时触发的那次刷新，自己把区块展开，并跳过这次展开带来的自动请求，避免打两次。做法与 `useMonitorHealth` 的 `skip` 标记相同。

同一日期已经取回的工单可以按 `reportDate + factoryId` 留在内存里，来回点同一厂不必再请求。更改日期或手动刷新后整份缓存丢掉，按 §5 重查。

展开中的工厂只留在这份状态里，不写进 URL。浏览器整页刷新后，仍按 [05 §7](./05-物料变体检核.md) 用当天、不带 `factoryId` 重新载入全厂汇总。

## 3. 呈现

窄屏和桌面同一套组件，不另做移动端路由，也不做「全部展开」。360px 宽的屏幕排不下「工单号、产品、累计完成、产出、良品率」同一行。

进度面板内部自上而下：

1. 日期。一个 `DatePicker`，宽度随面板，不放进外层折叠标题。
2. 页顶合计。沿用现在的两列（窄屏）统计项：良品、返工、报废、产出；`mixedUnits` 不为真时再加良品率。
3. 工厂列表。Ant Design `Collapse`，`accordion`。每一项的标题就是工厂行，内容是该厂的工单卡片。用组件自带的展开图标，不再手写一套箭头。厂名过长时省略。标题上同时能看到厂名、产出、良品率。

工厂行的 `mixedUnits` 为真时不显示良品率。良品、返工、报废留在页顶合计和工单卡片上，不单列在工厂行。

工单是小卡片，跟在该厂面板里面，不放到整张汇总的最底下。一张卡片三层：

| 层 | 内容 |
|----|------|
| 头部 | 左侧工单号（下钻链接）；右侧累计完成。进度条吃掉剩余宽度，不设 `minWidth` |
| 次行 | 产品编码与名称，允许换行 |
| 卡体 | 统计网格。窄屏两列，更宽时三列：产出、良品率、单位、良品、返工、报废、计划量、累计完工量、计划开始、计划结束 |

字段规则仍按 [04](./04-实施清单.md) P1 第 3 条：累计完成用进度条；计划量为 0 时留空；超过 100% 时条铺满、文字保留实际比例；`mixedUnits` 时单位为空、该卡不显示良品率；工单单位与当日报工单位不一致时，计划量和累计完工量后标工单单位代码。

不用横向滚动的 `ProTable`，也不在宽表里做行展开。卡片是普通 CSS，收起面板时的 `display: none` 不会把布局量成 0。删掉 `ProgressPanel` 里为表格列宽写的 `progressTableMounted` 和 `requestAnimationFrame` 测宽，不要等容器宽度大于 0 再挂内容。

两层列表分开取键，不再用 `productionOrderId ?? factoryId` 打平：

| 列表 | 键 |
|------|----|
| 工厂 | `factoryId` |
| 工单 | `productionOrderId` |

不要写成 `id`。

## 4. 日期

控件是 `DatePicker`，放在面板内、合计上方。

- `allowClear={false}`。清空会把 `reportDate` 变成空，后端抛 `validation.monitor.production_progress.report_date.required`。
- `disabledDate`：晚于今天的日期不可选。未来日期没有已过账报工。
- 只有选出一个完整日期、且与当前 `reportDate` 不同时，才调用 `setReportDate`。面板打开、滚动到某一月、尚未点中某一天，都不发请求。

未启用时不渲染这个控件，只留 §6 的空状态。

---

## 5. 请求与时序

一次进度请求仍是一种行。汇总 1 次；展开着一厂时再加该厂工单 1 次。不按每个有产量的厂各查一次工单。

| 动作 | 请求 |
|------|------|
| 首次展开进度 | `reportDate` 为今天，不带 `factoryId` |
| 更改日期，没有展开的厂 | 立刻丢掉当前汇总。新日期，不带 `factoryId` |
| 更改日期，有展开的厂 | 立刻丢掉当前汇总和工单，展开区进入加载，工厂仍记着。新日期不带 `factoryId`。该厂仍在新汇总里，再查新日期加该 `factoryId`。该厂已不在汇总里，收起展开区，不再要工单 |
| 点未展开的厂 | 当前日期加该行 `factoryId`。上一厂收起。没有这份缓存时，展开区先是 `Spin`，不显示上一厂的工单 |
| 点已展开的厂 | 收起，不请求 |
| 手动刷新，面板收起 | 这次点击负责展开。当前日期，不带 `factoryId`。若状态里还有展开的厂且该厂仍在汇总里，再查该厂 |
| 手动刷新，面板已展开 | 保持展开，不先把画面清空。当前日期不带 `factoryId`；有展开的厂再查该厂。不把日期改回今天，也不清掉当前厂。响应回来后替换 |
| 收起后再展开 | 不自动重查 |
| 定时、推送 | 不做 |

日期一变，画面上不能留下上一个日期的合计或工单。手动刷新是同一日期的替换，可以等到响应再换掉数字。

每次发出的汇总请求、工单请求各自记下递增序号，并带上当时的 `reportDate`；工单请求再带上当时的 `factoryId`。回调同时满足下面两条才写入状态，否则静默丢掉，不提示、不改日期、不改展开的厂：

1. 序号仍是这一类请求的最新一次。
2. 响应里的 `reportDate` 等于当前 `reportDate`。工单响应的 `factoryId` 还要等于当前 `expandedFactoryId`。

汇总失败（不是未启用）时提示。若这次失败来自更改日期，合计与工单保持清空，不把上一日的数据填回来。若这次失败来自同一日期的刷新，保留刷新前已经显示的同一日期数据。工单请求失败时收起该厂并提示，页顶合计仍在。`factoryId` 来自刚返回的工厂行，不另走「未知工厂」。

## 6. 刷新与未启用

进度面板标题栏 `extra` 提供刷新，文案 key 为 `pages.report.monitors.progress.refresh`（刷新 / Refresh / Làm mới），写入 `src/locales/{zh-CN,en-US,vi-VN}`。`onClick` 调用 Hook 的 `refresh`。加载中的状态用 Hook 的 `loading`。

面板收起时，这次点击自己展开并按 §5 请求。已展开时只重查，保持展开。

接口返回 `validation.monitor.production_progress.not_enabled` 时，`disabled` 为真，汇总和工单清空，展开的厂收起。面板只显示 `pages.report.monitors.progress.disabled` 的空状态，不渲染日期和工厂列表，不弹错误通知。标题栏刷新仍可点，一次点击只发一次请求。结果仍是未启用时，停在这个空状态，不连续提示。下一次请求成功后，空状态撤掉，按正常进度渲染。

## 7. 报工列表

点工厂行只在本页展开，只要求 `/report/monitors:read`。

工单号在有 `/pp/production-reports:read` 时进入报工列表：

```text
/pp/production-reports?reportDate={date}&factoryId={factoryId}&productionOrderNo={no}&reportStatus=POSTED
```

`factoryId` 用数字。`productionOrderNo` 用该行工单号全文。没有该权限时工单号是纯文本。卡片其余区域不跳转。

报工列表用这些 query 初始化搜索，仍按 [04](./04-实施清单.md) P1 第 5 条。第一笔列表请求就要带上条件。

## 8. 不要做的事

- 不要把 `reportDate`、`expandedFactoryId`、请求和 `loading` 关在 `ProgressPanel` 内部。
- 不要读取用户主数据的 `factoryId` 作为进度范围。
- 不要放工厂下拉，也不要放查询按钮。
- 不要让日期可以被清空，也不要让今天之后的日期可选。
- 不要把日期控件放进外层折叠标题。
- 不要定时刷新，不要为这一屏做推送或快照表。
- 不要一次展开全部工厂。那会为每个有产量的厂各打一次工单查询，刷新和改日期都会重做这一组。
- 不要整页换成工单，再提供「全部工厂」。收起当前行就是回到汇总。
- 不要把工单放在整张汇总的最底下。
- 不要在展开区再画一块该厂合计。
- 不要把工单号、产品、累计完成、产出、良品率排进同一行。
- 不要用横向滚动的表做工厂行或工单行。
- 不要用 `requestAnimationFrame` 测量容器宽度，也不要等宽度大于 0 再渲染进度内容。
- 不要用 `productionOrderId ?? factoryId` 充当同一列表的行键。
- 不要在合计或工厂行旁边展示混合单位提示。混合单位时只是不显示良品率。
- 不要在日期已经改变后，仍把上一个日期的工单留在画面上。
- 不要把过时响应写进状态。
- 不要在未启用时弹出错误通知，也不要让刷新连着自动重试。
- 不要改进度接口的请求或响应形状。

## 9. 验收

- 展开进度区后只发一次进度请求：`reportDate` 为今天，体里没有 `factoryId`。用户主数据上的工厂不参与。
- 页面没有工厂下拉，没有查询按钮。日期在面板内部、合计上方，不能清空，不能选今天之后。标题栏有刷新，点刷新不会把已展开的面板收起。刷新按钮的加载状态跟着 Hook 的 `loading`。
- 工厂列表是带展开图标的 `Collapse`（`accordion`）。标题是厂名、产出、良品率。点一行后，工单卡片出现在该行面板里，监测页地址仍是 `/report/monitors`。再点该行，工单卡片消失且不发请求。
- 工单卡片头部只有工单号和累计完成。产品在次行。其余数量在两列或三列的网格里。窄屏不出现横向滚动。
- 同时只有一厂展开。点另一厂时上一厂收起。没有缓存时展开区是加载，不显示上一厂的工单；并只为新厂再发一次带 `factoryId` 的请求。
- 页顶合计在展开前后都是全部工厂。展开区没有第二块合计。`mixedUnits` 为真时没有良品率，也没有混合单位提示。
- 选出另一个完整日期后，旧合计和旧工单立即消失，再查汇总。当时展开的厂在新日期仍有产量时，工单区保持加载并按新日期重查；没有产量时展开区收起。慢返回的旧日期响应不覆盖新日期。
- 点刷新沿用当前日期。有展开的厂时汇总和该厂各查一次，展开保持。后返回的旧请求不覆盖新结果。
- 收起进度区再展开，不自动重查。面板尚未展开时点标题栏刷新，会展开并只查一次。
- 接口返回未启用时，面板是空状态文案，没有错误通知。再点刷新仍是未启用时，不连续弹出通知。
- 无报工 `read` 时工厂行仍可展开，工单号不可点。有该 `read` 时点工单号，报工列表搜索栏已是该日、该厂、该工单号、`POSTED`。
- 当天没有任何已过账产量时，合计为 0，合计下方是 `pages.report.monitors.progress.empty` 的 `Empty`，没有内层 `Collapse`。进度内容不依赖容器宽度测量。
