## 2. P0 — 空壳

目标：管理者能打开监测页，看到健康区空状态和进度区占位。进度区可展开；在 P1 完成前，后端按 03 §3.2 返回「未启用」。common 里的进度类型已经冻结。

1. `lychee-erp-common`：`HealthIndicator`（含 `titleKey()`）、`HealthContext`、`HealthCard`、`HealthResponse`、`HealthStatus`。P0 没有任何实现类。
2. 同模块放入 03 §2 的 `ProductionDailyProgressRequest`、`ProductionDailyProgressResponse`、`ProductionDailyProgressTotals`、`ProductionDailyProgressRow`、`ProductionDailyProgressQuery`。P0 不在 pp 写实现。
3. `lychee-erp-report`：`GET /health` 返回 `ApiResponse<HealthResponse>`。注入 `List<HealthIndicator>`（允许空列表）。可见性：`requiredAuthority()` 为空，或 `CurrentTenant.authorities()` 含该串，或含 `ROLE_ADMIN`。通过后才 `evaluate`。捕获异常时用 `code()` 与 `titleKey()` 组装 `UNKNOWN` 卡片。
4. 同控制器 `POST /production-progress`，入参 `ProductionDailyProgressRequest`。`ObjectProvider<ProductionDailyProgressQuery>` 没有 Bean 时抛 `validation.monitor.production_progress.not_enabled`。不要在 report 写临时查询充数。
5. 后端三语 messages 写入 §6 的 `validation.monitor.production_progress.*`。前端三语写入页面 key 与 `menu.report.monitors`。
6. 前端：`src/pages/report/monitors`、`src/services/report/monitor`。健康区与进度区分开请求。日期默认当天。进度区不设工厂下拉。呈现、状态提升、展开和刷新见 [07-进度区交互.md](./07-进度区交互.md)。工厂列表与工单列表的行键见 §1。
7. 上线前在系统管理新增菜单 `/report/monitors`（父级报表），locale `menu.report.monitors`，动作 `read`，授给需要看监测的角色。

验收：无指标时健康区为空状态且 HTTP 200，`data.cards` 为数组；无进度 Bean 时进度区显示未启用文案；无 `read` 权限的用户看不到菜单且 API 403；report 工程在没有 pp 进度 Bean 时可以编译。

## 3. P1 — 当日生产进度

目标：进度区显示选定日期的已过账报工合计。查询只存在于 pp。common 的类型不再改形状；若实现时发现字段不够，先改 03 再改代码。

1. pp 新增 `ProductionDailyProgressQuery` 实现：只读事务；`reportDate` 必填；未知工厂走 §6 的 not_found；状态固定 `POSTED`；按 03 的行维度分组；分组后按 03 的顺序排序（未选厂 `factoryId`，已选厂工单 `orderNo` 再 id）；工厂名、物料、单位在 pp 内填充；`outputQuantity`、`yieldRate`、`mixedUnits` 按 03 的表计算。
2. report 的 POST 改为调用该 Bean。「未启用」只留在 Bean 缺失的分支，测试可覆盖。
3. 合计绑定不带 `factoryId` 的响应。工厂行与工单卡片的呈现见 [07-进度区交互.md](./07-进度区交互.md)。工单卡片上的字段规则：累计完成用进度条展示 `completionRate`；计划量为 0 时留空；超过 100% 时条铺满、文字保留实际比例。`mixedUnits` 的行单位为空。工单计划量与累计完工量在工单单位和当日报工单位不一致（含该行 `mixedUnits`）时，数量后标工单单位代码。合计不含工单计划字段和累计完成。合计 `mixedUnits == true` 时不显示合计良品率。混合单位提示以 [07](./07-进度区交互.md) 为准：不渲染 `pages.report.monitors.progress.mixedUnitsNotice`。数量沿用现有数量格式。行键使用 §1：工厂 `factoryId`，工单 `productionOrderId`。
4. 工厂行点击只在本页展开，不要求 `/pp/production-reports:read`。有该权限时工单号按 07 的 URL 下钻。没有该权限时工单号为纯文本，合计与卡片其余内容仍可见。
5. 改造 `src/pages/pp/production-reports/index.tsx`：挂载时读取 `reportDate`、`factoryId`、`productionOrderNo`、`reportStatus`，写入 ProTable 搜索表单的 `initialValues`（字段名用列的 `dataIndex`）。第一笔 `request` 就要带上这些条件。不要等表格请求完再 `setFieldsValue`，否则第一屏仍是未筛选列表。
6. 文案使用 §6，三语对齐。

验收：

- 仅有草稿或已冲销的日期，合计为 0，行表为空，`mixedUnits` 为 false，`yieldRate` 为 null。
- 同一天同时有草稿和已过账时，数量只含已过账。
- 未选厂的行数等于有产量的工厂数，且按 `factoryId` 升序；点一厂后的工单数等于该厂有产量的工单数，按工单号升序，且不会混入其他工厂。收起该厂后仍是各厂汇总。
- 选厂后每一行带得出单位；该行产出 = 良品 + 返工 + 报废；产出为 0 时良品率为 null；产出大于 0 且单位唯一时良品率有值。
- 同一响应当中单位多于一种：合计 `mixedUnits` 为 true，合计良品率为 null，页面不展示混合单位提示。数量合计仍显示。
- 点工厂行在该行下展示工单，不离开监测页。点工单号进入报工列表，搜索栏已是该日、该厂、该工单号、`POSTED`。进度区交互的其余验收见 [07 §9](./07-进度区交互.md)。
- 换租户看不到对方报工。
- `lychee-erp-report/build.gradle` 仍然没有业务模块依赖。
- 日报 Excel 的筛选规则不变：仍要求单厂、单日、单一状态，且不会被改成强制 `POSTED`。

## 4. P2 — 每加一个健康指标

一次只加一个，单独提交。步骤固定：

1. 在所属模块写 `HealthIndicator`，`code` 全局唯一。
2. `requiredAuthority()` 用该资料已有的 `read`（或更窄的现成权限）。不为健康卡片新造一套动作，除非该数字不能给原列表的读者看。
3. 计数查询放在该模块，走自己的 Repository。
4. 文案 key 用 `titleKey()`。默认即 `monitor.health.{code}`。写入 `lychee-erp/src/main/resources/i18n/` 的三语 messages，位置对齐。`evaluate` 成功时 `HealthCard.titleKey` 返回同一个 key。
5. `detailPath` 指向已有列表。列表若无法用 query 表达该缺口，`detailPath` 留空，卡片只显示数量。
6. 不修改 report 的收集代码。

验收：有权限的用户看到这一张新卡片；没有指标权限、且不是 `ROLE_ADMIN` 的用户打开同一页看不到这张，其他卡片还在；故意让 `evaluate` 抛错时，这一张为 `UNKNOWN`，标题仍是 `titleKey()` 的译文，页面其余部分仍在。

第一批三张物料变体卡片的口径、查询、文案、区块载入和排查脚本见 [05-物料变体检核.md](./05-物料变体检核.md)。卡片仍一次提交一张。区块载入先于第一张卡片。

这三张卡片的排查抽屉见 [06-物料变体排查.md](./06-物料变体排查.md)。该批会给 `HealthCard` 增加 `inspectionKind`，并在 report 增加一个只读 GET。收集健康卡片的循环仍不写业务 SQL。

## 5. 实现时不要做的事

- 不要让 `lychee-erp-report` 依赖 `lychee-erp-pp` 或其他业务模块。
- 不要在 report 里对业务表写原生 SQL，也不要在监测参数里塞 `tenantId`。
- 不要把 `ProductionDailyExportHandler` 的查询原样拿来当进度 API。导出允许草稿和已冲销，监测不允许。
- 不要在前端把良品、返工、报废相加得到产出，也不要在前端算良品率。
- 不要在混合单位时仍展示合计良品率，也不要为此再展示混合单位提示。
- 不要用当日良品或产出除以计划量。累计完成只用工单累计完工 / 计划量，且不进合计。不要在本页做齐套。
- 不要把进度行的键写成 `id`，也不要在同一列表里用 `productionOrderId ?? factoryId`。
- 不要为 P0/P1 建指标结果表、定时快照或独立移动工程。
- 不要用用户主数据的 `factoryId` 当作进度范围，也不要为进度区做定时刷新。
- 不要一次展开全部工厂的工单。
