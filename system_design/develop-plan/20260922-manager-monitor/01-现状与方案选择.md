# 01. 现状与方案选择

> 编写日期：2026-09-22  
> 状态：设计。依据现网模块边界与已落地的报工、导出框架。

---

## 1. 现网能给管理者看什么

报工已经在生产模块落地。`ProductionReport`（界面 MOR）记录工厂、报工日、生产工单、良品 / 返工 / 报废数量，状态为 `DRAFT` / `POSTED` / `REVERSED`。

管理者要看「这一天做了多少」，今天只能：

- 打开报工列表自己筛日期、工厂、状态；或
- 从报工列表导出 [生产日报表](../20260818-report/11-示例-生产日报表.md) Excel。该导出强制单一工厂、单一报工日、单一状态，一行一张报工单，状态跟操作者所选，草稿和已冲销都能导出。

工单进度 Excel 看的是 `ProductionOrder` 的计划与完工、齐套，不是当日报工汇总。

系统没有跨模块的健康页。资料齐不齐、单据有没有卡住，要进各个主数据或单据列表才能发现。

## 2. report 模块现在的职责

`lychee-erp-report` 只依赖 `lychee-erp-common`。它持久化导入 / 导出作业，异步生成文件并上传存储。业务数据怎么查，由各模块实现 `DataExportHandler`，report 按 `ExportJobType` 分发。

因此 report 今天看不到 `ProductionReport`，也没有同步汇总 API。这是边界，不是缺一张表。

## 3. 三种做法

| 做法 | 结论 |
|------|------|
| 现有 Web 增加监测页，手机浏览器打开同一地址 | **采用** |
| 新建手机专案 | 用户测试阶段不采用。登录、租户、权限、发版都要再做一套；健康指标和进度口径还会改 |
| 让 report 依赖 pp 等业务模块，自己查实体 | 不采用。模块图会被打破；Hibernate 租户过滤挂在各模块自己的 Repository 上；日报 Excel 与页面会各写一套数量口径 |

推送、离线、车间扫码不在本阶段。进度页被稳定使用、并且管理者明确需要这些能力之后，再评估薄客户端。届时只调本专题的汇总 API，计算仍留在后端。

## 4. 本阶段交付边界

| 纳入 | 不纳入 |
|------|--------|
| `/report/monitors` 只读页：健康区 + 当日生产进度 | 新的手机工程、PWA、消息推送 |
| 健康区空壳；指标以后按一个卡片一个实现注册 | 本波列出并实现一批健康指标 |
| 当日进度：已过账报工的笔数、良品 / 返工 / 报废、产出、单位、良品率；多种单位时合计标明混合单位 | 改报工单、改过账、改工单完成率（相对计划量） |
| 查询放在所属模块；report 只拼装和转发 | report 的 Gradle 依赖增加业务模块 |
| 响应式布局（窄屏卡片纵排、表格横向滚动） | 图表库、导出作业、新数据库表、指标快照表 |
