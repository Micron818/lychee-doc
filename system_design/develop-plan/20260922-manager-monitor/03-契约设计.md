# 03. 契约设计

> 无 Liquibase，无新表。  
> 下面的类型放在 `lychee-erp-common`，供 report 依赖、供各模块实现。名称以落地时的包名为准，职责不要拆散到别的模块。  
> **这些类型全部在 P0 落地**（含进度查询接口）。P0 可以没有 pp 的实现类。

---

## 1. 健康指标 SPI

```java
public interface HealthIndicator {

    /** 稳定编码，同一应用内唯一，如 "mm.material.missing-unit"。 */
    String code();

    /**
     * 与菜单权限串一致，如 "/mm/materials:read"。
     * 空白表示凡能打开监测页的人都可见。
     * 否则仅当用户拥有该权限，或拥有 ROLE_ADMIN 时，report 才调用 evaluate。
     */
    String requiredAuthority();

    /**
     * 卡片文案 key。evaluate 抛错时 report 仍要能显示标题，所以不能只放在 HealthCard 里。
     * 默认 monitor.health.{code}。与 code 不一致时覆盖本方法，并在三语 messages 登记同一 key。
     */
    default String titleKey() {
        return "monitor.health." + code();
    }

    /**
     * 排查抽屉的种类。null 表示这张卡片没有排查。
     * 成功时 HealthCard.inspectionKind 必须等于本方法的返回值，不要在 evaluate 里另写一份字面量。
     */
    default String inspectionKind() {
        return null;
    }

    HealthCard evaluate(HealthContext context);
}
```

```java
public record HealthContext(Locale locale) {}

public record HealthCard(
    String code,
    HealthStatus status,
    Long count,
    String titleKey,
    String detailPath,
    String inspectionKind
) {}

public record HealthResponse(List<HealthCard> cards) {}

public enum HealthStatus {
    OK,
    ATTENTION,
    UNKNOWN
}
```

约定：

| 项 | 规则 |
|----|------|
| 租户 | `evaluate` 内需要租户时用 `CurrentTenant.tenantId()`。`HealthContext` 不传 `tenantId`，避免调用方伪造 |
| 文案 | 成功时 `HealthCard.titleKey` 必须等于 `titleKey()`。前端用这个 key 取三语文案，卡片上不写死中文 |
| 数量 | 无数量的指标 `count` 为 null。有缺口时 `ATTENTION` 且 count 为缺口数；没有缺口时 `OK` |
| 下钻 | `detailPath` 是前端路由（可带 query）。没有安全的列表入口则为 null。`inspectionKind()` 默认 null。成功时卡片上的 `inspectionKind` 等于 `inspectionKind()`。非空时，卡片在 `ATTENTION` 且 `count > 0` 时打开抽屉，不走路由。两者不要同时有值。种类与抽屉见 [06](./06-物料变体排查.md) |
| 可见 | `requiredAuthority()` 空白则任何能打开监测页的人都可见。否则 `CurrentTenant.authorities()` 含该权限串，或含 `ROLE_ADMIN`，才调用 `evaluate`。管理员角色不会自动带上各业务菜单的 `read`，不放行就会看不到卡片。这不放宽控制器上的 `/report/monitors:read` |
| 失败 | `evaluate` 未捕获异常时，report 记日志，自行组装卡片：`status=UNKNOWN`，`count` / `detailPath` / `inspectionKind` 为 null，`titleKey` 取 `indicator.titleKey()`，`code` 取 `indicator.code()`。不读取抛错前可能不存在的 `HealthCard` |
| 排序 | 响应按 `code` 字典序，保证刷新顺序稳定 |
| 空 | 没有任何可见指标时，`cards` 为空数组，HTTP 200 |

P0 不注册任何 `HealthIndicator`。P2 每加一个指标，只在所属模块新增一个 Bean 和文案，不改 report 的收集逻辑。

## 2. 当日生产进度查询

接口在 common，唯一实现在 pp（P1 才提供 Bean）：

```java
public interface ProductionDailyProgressQuery {

    ProductionDailyProgressResponse query(ProductionDailyProgressRequest request);
}
```

```java
public record ProductionDailyProgressRequest(
    LocalDate reportDate,
    Long factoryId
) {}

public record ProductionDailyProgressResponse(
    LocalDate reportDate,
    Long factoryId,
    ProductionDailyProgressTotals totals,
    List<ProductionDailyProgressRow> rows
) {}

public record ProductionDailyProgressTotals(
    long reportCount,
    BigDecimal goodQuantity,
    BigDecimal reworkQuantity,
    BigDecimal scrapQuantity,
    BigDecimal outputQuantity,
    String yieldRate,
    boolean mixedUnits
) {}

public record ProductionDailyProgressRow(
    Long factoryId,
    String factoryName,
    Long productionOrderId,
    String productionOrderNo,
    Long productMaterialId,
    String productMaterialCode,
    String productMaterialName,
    Long unitId,
    String unitCode,
    String unitName,
    boolean mixedUnits,
    long reportCount,
    BigDecimal goodQuantity,
    BigDecimal reworkQuantity,
    BigDecimal scrapQuantity,
    BigDecimal outputQuantity,
    String yieldRate
) {}
```

| 字段 | 未选工厂 | 已选工厂 |
|------|----------|----------|
| `factoryId` / `factoryName` | 有值 | 有值，且与请求工厂相同 |
| `productionOrderId` / `productionOrderNo` | null | 有值 |
| 物料三字段 | null | 有值。名称编码用 pp 内已有的物料关联，不在 report 里填 |
| `unitId` / `unitCode` / `unitName` | 该厂当日已过账报工只有一种单位时有值，否则 null | 该工单当日只有一种单位时有值，否则 null |
| `mixedUnits` | 该厂单位多于 1 种 | 该工单单位多于 1 种（报工上的 `unitId` 允许各行不同） |
| 数量 | 该厂当日已过账合计 | 该工单当日已过账合计 |
| 顺序 | `factoryId` 升序 | `productionOrderNo` 升序，再 `productionOrderId` 升序 |

派生规则（pp 内计算，对齐日报 Assembler 的产出与良品率；混合单位时的合计良品率比 Excel 更严）：

| 字段 | 规则 |
|------|------|
| `outputQuantity` | `goodQuantity + reworkQuantity + scrapQuantity`，精度 18,6。行和合计都有，包括混合单位 |
| 行 `yieldRate` | 该行 `mixedUnits == false` 且产出 > 0 时，良品 / 产出，一位小数加 `%`（与 `ProductionProgressRowAssembler.percentText` 相同）。否则 null |
| 合计 `mixedUnits` | 所有参与行的 `unitId` 去重后多于 1 个，或任一行 `mixedUnits == true` |
| 合计 `yieldRate` | 合计 `mixedUnits == false` 且产出 > 0 时才计算。混合单位时为 null，数量仍返回 |

`reportDate` 为空时 pp 抛 `ValidationException`（`validation.monitor.production_progress.report_date.required`）。工厂 id 在本租户不存在时抛 `validation.monitor.production_progress.factory.not_found`，不返回空表冒充「当天没有产量」。当天没有已过账报工时，数量合计为 0，`yieldRate` 为 null，`mixedUnits` 为 false，`rows` 为空数组。

工厂显示名沿用 pp 现有基础资料缓存（日报 Excel 已使用 `BasisCacheService`）。单位编码名称同样在 pp 内按 `unitId` 填充。这些不在 report 里做。

分组查询结束要按上表排序再放进 `rows`。用 JPQL 时：未选厂 `ORDER BY r.factoryId ASC`；已选厂按工单号 `ORDER BY productionOrder.orderNo ASC, productionOrder.id ASC`。在内存里排也可以，顺序必须与上表一致。

## 3. HTTP

控制器：`lychee-erp-report`，`@RequestMapping("/api/v1/report/monitors")`。  
两个方法都是 `@PreAuthorize("hasAuthority('/report/monitors:read')")`。  
成功时 `ApiResponse.success(body)`，业务字段在 `data` 里，不把 `cards` 或进度字段摊在信封外面。

### 3.1 健康

```java
@GetMapping("/health")
public ApiResponse<HealthResponse> health()
```

`GET /api/v1/report/monitors/health`

```json
{
  "code": 200,
  "success": true,
  "data": {
    "cards": [
      {
        "code": "mm.material.missing-unit",
        "status": "ATTENTION",
        "count": 3,
        "titleKey": "monitor.health.mm.material.missing-unit",
        "detailPath": "/mm/materials",
        "inspectionKind": null
      }
    ]
  }
}
```

P0 的 `data.cards` 为 `[]`。示例卡片不是本波要做的指标。不要返回 `ApiResponse<List<HealthCard>>`：外层对象固定为 `HealthResponse`，以后加字段不用改列表形态。

### 3.2 当日进度

```java
@PostMapping("/production-progress")
public ApiResponse<ProductionDailyProgressResponse> productionProgress(
    @Valid @RequestBody ProductionDailyProgressRequest request)
```

`POST /api/v1/report/monitors/production-progress`

请求：

```json
{ "reportDate": "2026-09-22", "factoryId": 1 }
```

`factoryId` 可省略。成功时 `data` 即 `ProductionDailyProgressResponse`。

容器里没有 `ProductionDailyProgressQuery` 时，report 抛 `ValidationException`（`validation.monitor.production_progress.not_enabled`），健康接口不受影响。P1 提供实现后，这条路径只在测试里出现。P0 已经能编译这个方法，因为请求和响应类型在 common。

## 4. 前端

`src/services/report/monitor` 手写上述请求和响应类型，字段与本节一致。本接口不从单据 OpenAPI 批量生成里推导业务公式。若用 `pnpm openapi` 覆盖 `services`，生成后仍以本节字段为准核对。

进度表没有实体 `id`。`ProTable` 的 `rowKey` 固定为：

```tsx
rowKey={(record) => record.productionOrderId ?? record.factoryId}
```

同一次响应里，未选厂时行键是 `factoryId`（`productionOrderId` 为 null）；已选厂时行键是 `productionOrderId`。不要写 `rowKey="id"`。

下钻 query 使用报工列表搜索栏的字段名（`dataIndex`，不是 `*_eq` / `*_like`）：

| 行 | 路径 |
|----|------|
| 未选工厂 | `/pp/production-reports?reportDate={date}&factoryId={factoryId}&reportStatus=POSTED` |
| 已选工厂 | 再加 `&productionOrderNo={productionOrderNo}` |

`factoryId` 用数字。`productionOrderNo` 用该行工单号全文；列表该列的搜索是 `like`，全文能落到这一张工单。

监测页工厂控件必须 `allowClear: true`。清空后请求体不带 `factoryId`（或为 null），回到未选厂的行维度。不要保留上一次选中的工厂。
