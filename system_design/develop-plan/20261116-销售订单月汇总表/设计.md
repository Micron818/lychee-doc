## 1. 两张报表

销售订单列表保留两张预览，互不替代。

| | 销售明细表 | 销售订单月汇总表 |
|--|------------|------------------|
| 是什么 | 现有 `POST .../sales-orders/report/pdf` | 本设计新增 |
| 条件 | 勾选订单，或单一客户 + `orderDate` 闭区间 | 单一公司 + 订单年月 |
| 明细 | 尺码矩阵（型号、色号、单价、原币未税金额、样图、签核） | 订单号码、订单状态、客户名称、产品代号、单位、订单数量、本位币含税金额 |

| 引擎 | Thymeleaf + openhtmltopdf。P2 第 11 张才迁 | `lychee-pdf`，模板 `sd/sales-order-monthly` |
| 归档 / Excel | 无 | 无 |

销售明细表只改用户看得见的名称。查询、矩阵、模板文件、类名、URL、i18n **key** 不动。见 §11。

## 3. 已锁定的决定

| # | 决定 |
|---|------|
| 1 | 条件只有两个，都必填：`companyId`、`yearMonth`（`yyyy-MM`）。不读取列表上的客户、日期、勾选或其他筛选项 |
| 2 | 月份是 `orderDate` 的闭区间：该月 1 日到该月最后一天。`orderDate` 是 `LocalDate`，没有时区换算 |
| 3 | 表头 `orderStatus = CANCELLED` 的订单整单排除。明细 `orderStatus = CANCELLED` 的行排除。`DRAFT`、`CONFIRMED`、`DELIVERED`、`CLOSED` 都纳入，与销售明细表现有的订单集合一致 |
| 4 | 打印行不是订单一行，也不是订单一料号一行。合并键是 `salesOrderId + productModelId + unitId`。同一订单里同型号、同单位的颜色和尺码加在一起。月汇总没有色号和尺码列；那些留在销售明细表 |
| 5 | 物料没有 `productModelId` 时，产品代号为空，单独成组，不并进有代号的行，金额和数量仍计入合计 |
| 6 | 客户名称取 `Customer.name`。订单头上的 `customerName` 快照不参与打印 |
| 7 | 单位显示 `MaterialUnit.name`；name 为空时用 `code`，行与合计用同一个显示值 |
| 8 | 金额先按行换成本位币并按该币小数位四舍五入，再按合并键相加。表尾各状态金额等于该状态打印行金额之和，总合计等于各状态金额之和 |
| 9 | 汇率用订单头快照，不回查 `exchange_rates`。折算方向与主档相同：`本币金额 = 原币金额 × exchangeRate` |
| 10 | 单据币别等于公司 `localCurrencyId`，或单据币别为空时，汇率按 1，忽略头上偏离 1 的快照。外币汇率缺失、空或 ≤ 0 时整表拒绝，规则同 `DocumentExchangeRates.require` |
| 11 | 数量合计按 `unitId` 分列。金额不按单位拆开。总合计金额之前，按 `SalesOrder.orderStatus` 各印一行本位币金额，只印本表出现过的状态 |
| 12 | 无明细、超过 5000 条源明细、公司不存在、本位币代码缺失、无权限：在 Java 结束，不调用 PDF 服务 |
| 13 | 公司数据权限仍走 `SalesOrder` 上的 company filter。选了范围外的公司时结果为空，与该月没有订单用同一条「无可打印明细」，不另外说明原因 |
| 14 | 纸张 A4 纵向。`measure: false`。页码用 Playwright 页脚。不印 Logo、样图。公司名称只出现在信息区，不进标题。信息区最右是列印时间。表尾签核与销售明细表相同：主管、审核人留白，制表人印当前用户 |
| 15 | 订单号码后印 `SalesOrder.orderStatus` 的三语文案。颜色按枚举名写在模板 CSS 里，四种在表状态各用一色。不印行状态 |


关联按 id 批量装入 Map。租户由 `@TenantId` 过滤，模型里不出现 `tenantId`。

入选订单的源明细（未按型号合并之前）超过 5000：`validation.salesOrder.monthlySummary.tooManyItems`。  
没有可打印行：`validation.salesOrder.monthlySummary.noPrintableItems`。

## 5. 明细合并与排序

对每一条入选的 `SalesOrderItem`：

```text
localAmount = round(totalAmount × rate, fractionDigits(本位币代码), HALF_UP)
```

`rate` 见 §6。`fractionDigits` 用 `MoneyFormatSupport.fractionDigits`（VND 为 0，USD 为 2）。乘法保留中间精度，最后再收位。

然后按 `(salesOrderId, productModelId, unitId)` 相加 `quantity` 与 `localAmount`。`productModelId` 为空的行，空值本身是键的一部分。状态不进合并键：键里已有 `salesOrderId`，同一订单的打印行共用表头 `orderStatus`。

打印行排序：

```text
orderDate ASC
→ orderNo ASC
→ productCode ASC（空串在后）
→ unitCode ASC
```

同一合并键只出一行，所以行内不再排 `itemNo`。

## 6. 本位币

标识与换算都用条件公司的 `Company.localCurrencyId`。

1. 用 `dictionaryCacheService` 取该选项的 `code`，作为表头币别、金额列标题和 `MoneyFormatSupport.formatMoney` 的币别。格式跟币别，不跟界面语言。
2. 每一条源明细调用 `DocumentExchangeRates.require(order.exchangeRate, order.currencyOptionId, localCurrencyId)`：
   - 币别相同或单据币别为空 → `1`
   - 外币且汇率无效 → `validation.exchange_rate.rate.required`，整表失败
3. 不因为范围内订单币别不同而拒绝。换算之后只有一种币。

例：公司本位币 VND。

| 订单 | 单据币别 | 汇率 | 型号 | 单位 | 数量 | totalAmount | 本位币 |
|------|----------|------|------|------|------|-------------|--------|
| SO001 | USD | 25450 | A | 双 | 10 | 100.00 | 2,545,000 |
| SO002 | VND | 1 | A | 双 | 4 | 200,000 | 200,000 |
| SO002 | VND | 1 | A | 双 | 6 | 300,000 | 300,000 |
| SO002 | VND | 1 | B | 件 | 2 | 80,000 | 80,000 |

SO002 的两行型号 A、单位「双」合并。打印：

| 订单号码 | 状态 | 客户名称 | 产品代号 | 单位 | 订单数量 | 金额 (VND) |
|----------|------|----------|----------|------|----------|------------|
| SO001 | 草稿 | … | A | 双 | 10 | 2,545,000 |
| SO002 | 已确认 | … | A | 双 | 10 | 500,000 |
| SO002 | 已确认 | … | B | 件 | 2 | 80,000 |

数量合计：双 20，件 2。状态金额：草稿 2,545,000，已确认 580,000。金额合计：3,125,000。

外币中间值先乘再收位。`10.01 × 25450.123456 = 254766.7359…`，VND 收成 `254,767`。同一合并键里先收位再相加，避免合并后再舍入和行上数字对不上。

## 7. 合计

表尾按 `unitId` 各一行：单位显示名 + 该单位数量合计。顺序按 `MaterialUnit.code`，再按显示名。

数量之后、总合计金额之前，按表头 `orderStatus` 各一行本位币金额。金额是该状态各打印行已经收位的金额之和。状态顺序固定为 `DRAFT`、`CONFIRMED`、`DELIVERED`、`CLOSED`。本表没有的状态不印，不印 0。各状态金额之和等于总合计。

状态行的名称和金额用 §9 的同一字色。总合计金额保持黑色，币别与明细相同。

数量格式与销售明细表相同：`#,##0.######`，符号用 `Locale.US`。整数不带小数。模型里数量和金额都已经是字符串。

## 9. 版式

A4 纵向。`pdf`：

```ts
{
  width: "210mm",
  height: "297mm",
  margin: { top: "12mm", right: "12mm", bottom: "16mm", left: "12mm" },
  footer: true,
  measure: false,
}
```

`@page { size: 210mm 297mm; margin: 12mm 12mm 16mm 12mm; }` 与上面一致，给 Chrome 打印预览用。页脚只放 ASCII 页码 `pageNumber / totalPages`。字体 `Noto Sans`、`Noto Sans SC`，`@font-face` 指向本服务 `/fonts/`。

标题只印报表名。公司名称已经在信息区，不再在标题上方重复一行。

```text
销售订单月汇总表
公司: {companyName}    订单年月: {yearMonth}    币别: {currencyCode}          打印时间: {printedAt}

订单号码 | 状态 | 客户名称 | 产品代号 | 单位 | 订单数量 | 金额 (VND)
...行...

合计
单位 | 数量
双   | 20
件   | 2
草稿                           2,545,000
已确认                           580,000
合计金额                       3,125,000

主管 ____________    审核人 ____________    制表人: {preparedByName} ____________
```

信息区一行四段。前三段靠左：公司、订单年月、币别。打印时间靠该行最右，`white-space: nowrap`。

表头用 `thead { display: table-header-group }`，跨页重复列名。公司、年月、币别和打印时间只在第一页，不进每页重复的 `thead`。合计块与签核各自 `break-inside: avoid`。签核在合计之后，只出现一次。

签核三等分，对齐销售明细表 `sign-table`：主管、审核人只有标签和横线；制表人标签后印 `preparedByName`，下面同样一条横线。不印样图，不印 Logo。

订单号码、状态、产品代号、数量、金额 `white-space: nowrap`。客户名称允许换行。数量与金额右对齐。文本一律走会转义的渲染，备注和名称里的 `<` 不能变成标签。

状态只改字色，不加底色。`page.pdf` 已开 `printBackground`，字色会进 PDF。类名只接受枚举名：

| orderStatus | 在表中 | 字色 | 对照 |
|-------------|--------|------|------|
| `DRAFT` | 印 | `#595959` | 列表 Default，灰 |
| `CONFIRMED` | 印 | `#237804` | 列表 Success，绿 |
| `DELIVERED` | 印 | `#0958d9` | 列表 Processing，蓝 |
| `CLOSED` | 印 | `#531dab` | 列表把已关闭也画成绿；这里用紫，和已确认分开 |
| `CANCELLED` | 不印 | `#cf1322` | 红。过滤已排除，类仍写上 |

模板按 `orderStatus` 套 `status-DRAFT` 这一类名，文字用 `orderStatusLabel`。

不设 `data-pdf-row` / `data-pdf-repeat`。本地 Chrome 预览就是版式验收。

`pnpm dev` 与 `pnpm pdf` 目前写死 `sample/hello`。预览路由 `GET /preview/<templateId>` 已经按注册表和 `fixtures/<id>.json` 工作。实施时两个命令接受可选模板 id，缺省仍是 `sample/hello`：

```text
pnpm dev
pnpm dev sd/sales-order-monthly
pnpm pdf sd/sales-order-monthly
```

`pnpm pdf` 把斜线换成横线，写出 `out/sd-sales-order-monthly.pdf`。

## 10. 接口与入口

```text
列表 [销售订单月汇总表]
  → 条件弹层：公司、订单年月
  → 前端校验两者都有
  → PdfPreviewSession
       POST /api/v1/sd/sales-orders/monthly-summary/pdf
       Authorization，/sd/sales-orders:read
       Content-Disposition: inline
  → SalesOrderMonthlySummaryPdfRenderer
       1. Service 校验、查询、换算、合并
       2. 格式化成 §8 的模型
       3. ChromiumPdfClient.render(
            "sd/sales-order-monthly", model, PREVIEW, out)
  → blob → iframe → print()
```

请求体：

```json
{ "companyId": 1, "yearMonth": "2026-11" }
```

显式 Request，不复用明细表那份筛选 Map，也不复用 `/report/pdf`。

Renderer 的方法接收 `PdfRenderMode`。本期只有预览，传入 `PREVIEW`。不建 `ExportHandler`，不增加 `export` 权限。以后要归档时，同一个 Renderer 传 `EXPORT`，模板 id 不变。

文件名：`{fileName}-{companyCode}-{yyyyMM}.pdf`，例如 `销售订单月汇总表-KHH-202611.pdf`。

前端：

- `endpoints.salesOrders.monthlySummaryPdf`
- `postSalesOrderMonthlySummaryPdfBlob`
- `src/pages/sd/sales-orders/print/SalesOrderMonthlySummaryPdfPreviewModal.tsx`  
  只包 `PdfPreviewSession`，`depsKey` 为 `companyId + yearMonth`
- 条件弹层放在销售订单 `index.tsx` 工具栏，紧挨现有打印按钮。公司用 `getCompanyList`，默认 `initialState.user.companyId`。年月用月份选择器，默认当月，提交值 `YYYY-MM`
- 弹层未填齐时不打开预览。按钮文案用 `pages.sd.salesOrders.monthlySummary.*`（`preview`、`previewTitle`、`company`、`yearMonth`），三语与 §1 一致

空数据与校验失败由后端返回业务错误，预览壳显示错误，不向 PDF 服务发请求。

## 12. 实施清单

对应 [P1](../20261116-单据PDF新架构/04-实施清单.md)。

### Java（`lychee-erp-sd`）

1. §11 的三语标题与按钮。明细表 Renderer、模板、URL 仍走 `PdfRenderSupport`。
2. `SalesOrderMonthlySummaryRequest` / Service：§4 校验，§5 合并，§6 换算，§7 分单位合计。
3. `SalesOrderMonthlySummaryPdfRenderer`：格式化、`labelsByPrefix("print.sales_order_monthly.")`、只调用 `ChromiumPdfClient`。
4. `SalesOrderController` `POST /monthly-summary/pdf`：`read`、inline、不落 OSS。
5. 三语 `print.sales_order_monthly.*` 与 `validation.salesOrder.monthlySummary.*`。
6. 单测：同币别汇率按 1、外币乘快照、VND 收成整数、先收位再合并、作废单与作废行排除、同型号同单位合并、两个单位的数量合计、状态金额之和等于总合计、没有出现的状态不进 `amountTotals`、无明细时不调用客户端。假客户端，不启动 Chromium。

### `lychee-pdf`

1. 模板、类型、脱敏 fixture、注册表。
2. `pnpm dev` / `pnpm pdf` 接受可选模板 id。
3. HTML 断言：关键字段在，客户名中的 `<` 已转义；`DRAFT` 行带 `status-DRAFT` 且文字为样例里的状态文案。沿用现有 Playwright 冒烟方式打出 PDF 文件头即可，不测坐标。

### 前端（`lychee-frontend`）

1. §11 按钮与预览标题三语。
2. 月汇总 endpoint、blob API、薄预览适配、条件弹层。
3. `pnpm tsc` 覆盖改动。

### 不做

- 不改销售明细表的矩阵、样图、分页和 openhtmltopdf。
- 不把 `renderPaginatedPdf` 或续页标记用于月汇总。
- 不新建菜单和 `permissions`。

## 13. 验收

1. 销售订单列表上，原按钮显示「销售明细表」。勾选与「客户 + 订单日期」两条路的预览仍成功，PDF 标题为销售明细表，栏位与改名前一致。
2. 「销售订单月汇总表」只认弹层里的公司和年月。列表上的客户筛选和勾选不改变这张表的结果。
3. 改 `lychee-pdf` 的 CSS 后，刷新 `pnpm dev sd/sales-order-monthly` 的 Chrome 打印预览即可看到结果。再用后端预览接口打出同一版式的 PDF。
4. §6 的数字：合并后三行；双 20、件 2；草稿 2,545,000、已确认 580,000，其后总合计 3,125,000，列标题带 VND。订单号码后是状态，草稿为灰、已确认为绿，表尾这两行金额同色。标题没有公司名。信息区最右有打印时间。表尾有主管、审核人、制表人，制表人是当前用户。
5. 该月只有作废单、或公司不在数据权限内：接口报无可打印明细，PDF 服务无对应渲染日志。
6. 外币订单汇率 ≤ 0：整表拒绝，提示汇率，不打出半份 PDF。
7. 无 `/sd/sales-orders:read` 时 403，请求不到 PDF 服务。
