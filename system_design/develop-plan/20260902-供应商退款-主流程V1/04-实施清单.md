# 04. 实施清单：供应商退款主流程 V1

> **本期开发入口。** 流程以 [02-目标流程.md](./02-目标流程.md) 为准，字段以 [03-schema设计.md](./03-schema设计.md) 为准。  
> 必须一次交付「贷项开放金额 + 退款过账核销 + VOID」。禁止只放开已付贷项而没有退款单。  
> 不要按 [../供应商退款/04-实施清单.md](../供应商退款/04-实施清单.md) 的完整范围施工。

## 1. 审查结论

| 问题 | 主流程 V1 |
|------|-----------|
| 真实退款是否 VOID 原付款 | **否** |
| 新表 `supplier_refunds` | **否**；复用 `payments` |
| 业务组合 | `RECEIPT + SUPPLIER + SUPPLIER_REFUND` |
| 核销对象 | 贷项 `refund_remaining` |
| 贷项超过 remaining | **可以**，不超过尚未贷回总额与可贷数量 |
| 资金先行 | **否** |
| 一单核多张贷项 | **否** |
| 外币 | 同币允许；快照与退款段汇兑按贷项汇率重乘 |
| 普通 AP/AR 汇兑 | **不改** |
| 原票折扣 | 待退款 ≤ 剩余实付现金；不转回折扣 |
| 核销/冲销换日 | **否**；走现网期间规则 |

## 2. 已锁定决策

1. 名称：**供应商退款 / `SUPPLIER_REFUND`**。
2. 只覆盖数量型退货贷项的现金退款。
3. 贷项仍一对一原 AP。退款一对一贷项；一贷项可被多张退款分次退。
4. `credited` 保持总额；`applied_credit` 进 remaining。
5. `applied = min(memo.total, remainingBefore)`；`refundableGross = total − applied`。
6. `refundableGross > 剩余实付现金` 则拒绝过账；通过则 `refundable = refundableGross`。
7. 退款不改原 AP `paid_amount` 与原付款。
8. 过账必须恰好一行 `AP_CREDIT_MEMO` 且 `allocated = amount`。
9. `payment_purpose` 显式存储。DRAFT 无行时可改。
10. 退款 Journal 模块 `AP`。
11. 本位币快照与退款汇兑一律重乘；不读 AP 未结本位币；不接入 `applyAp / applyAr`。
12. 有有效退款则禁止 VOID 贷项。
13. 有 `refundable > 0` 的未作废贷项则禁止撤原付款。
14. 撤销顺序：退款 → 退货 → 贷项 → 原付款。
15. 沿用 Payment 权限与页面。
16. STANDARD 核销 DELETE / VOID 行为不变；不迁 `allocation_status`。
17. 退款 POSTED 禁止追加核销、禁止删行；只整单 VOID。
18. 交叉货币拒绝。
19. 银行账户强校验仅 `SUPPLIER_REFUND`。

## 3. 核心公式

### 3.1 原 AP

```text
credited      = Σ(POSTED 非 VOID 贷项 total)
appliedCredit = Σ(POSTED 非 VOID 贷项 applied)
remaining     = total − paid − appliedCredit
```

严禁 `remaining = total − paid − credited`。

### 3.2 贷项

```text
grossCreditAvailable = invoice.total − invoice.credited
applied              = min(memo.total, remainingBefore)
refundableGross      = memo.total − applied
cashAvailable        = Σ(该 AP 有效付款 allocated) − Σ(其它 POSTED 贷项 refundable)
refundable           = refundableGross    // 仅当 ≤ cashAvailable
refundRemaining      = refundable − refunded

appliedBase      = round(applied × memo.rate, 2)
refundableBase   = round(memo.total × memo.rate, 2) − appliedBase
```

### 3.3 退款

```text
POSTED: unallocated = 0
allocated = payment.amount
fx = round(allocated × payment.rate, 2) − round(allocated × memo.rate, 2)
```

## 5. 后端 FI

### 5.1 实体与 DTO

`ApInvoice.appliedCreditAmount`

`ApCreditMemo`：applied / refundable / 对应 base / refunded / refundRemaining / refundStatus

`Payment.paymentPurpose`

`PaymentLine`：`apCreditMemoId` + 四列汇兑快照

`PaymentLineRequest` 只加 `apCreditMemoId`。汇兑只由后端写。

`ApCreditMemoRefundableResponse`

### 5.2 remaining

`ApInvoiceRemainingSupport`：

```text
remaining = total − paid − appliedCredit
```

查完并改掉所有 `total − paid − credited`：

- `ApInvoicePostingServiceImpl`
- `ApInvoiceServiceImpl.recalculateInvoiceTotals`
- `PaymentInvoiceClearingSupport.applyAp / restoreAp`
- `ApCreditMemoPostingServiceImpl`
- AP VOID / 付款 VOID

### 5.3 贷项过账

`ApCreditMemoPostingServiceImpl`：

1. 保留可贷数量与成卡校验
2. 删除 `memo.total ≤ remaining`
3. `memo.total ≤ total − credited`
4. 锁内拆 applied / refundableGross
5. 重乘 base；校验 §3.2 现金上限
6. `credited += total`，`appliedCredit += applied`，重算 remaining
7. 完整金额写凭证并回减占用

`refundable=0` → `NOT_REQUIRED`，否则 `UNREFUNDED`。

### 5.4 贷项 VOID

有效退款核销存在则拒绝。通过后回滚 credited / appliedCredit，其余现网逻辑。

### 5.5 Payment 用途

`PaymentServiceImpl`：

- 从 BP 回填并校验 `partnerType`
- 校验 purpose + type + partner 组合
- `SUPPLIER_REFUND`：`isPrepayment=false`、单号 `SUPPLIER_REFUND`、银行账户强校验
- purpose 变更规则见 02 §5.1
- 默认 `STANDARD`

前端隐藏不是安全边界。

### 5.6 Payment 过账

```text
STANDARD RECEIPT         → AR
STANDARD DISBURSEMENT    → AP
SUPPLIER_REFUND RECEIPT  → AP
```

退款：`sourceDocType = SUPPLIER_REFUND`；必须有恰好一行拟核销；过账后 `unallocated=0`。

`PaymentInvoiceClearingSupport.applyLine`：按 type 分派。`AP_CREDIT_MEMO` → 新 `SupplierRefundAllocationSupport`。未知 type 抛错。禁止误走 `applyAp` 或折扣/GL 调整凭证。

`SupplierRefundAllocationSupport`：锁、校验、回写贷项、写汇兑快照、必要时出汇兑凭证。

VOID：`restoreLine` 按快照冲汇兑、回滚贷项；再冲银行凭证。STANDARD VOID 路径不改。

### 5.7 原付款闸

`removeAllocation` / `reversePostedPayment`：目标 AP 有非 VOIDED 且 `refundable>0` 的贷项则拒绝。批量按 AP id 查。锁序见 02 §7.3。

`removeAllocation` 对 `SUPPLIER_REFUND` 直接拒绝。

### 5.8 其它入口

- `PaymentAllocationValidator`：退款只接受 `AP_CREDIT_MEMO`；STANDARD 拒绝该 type
- `PaymentServiceImpl.recalculatePaymentAmounts`：STANDARD 不变；退款 POSTED 必须 unallocated=0
- `PaymentPrintServiceImpl` / PDF：退款标题与合计
- OperationLog、凭证跳转（含 `SUPPLIER_REFUND_ALLOC`）
- `ApCreditMemoResponse` 返回拆分字段
- Payment items fetch 增加 `apCreditMemo`

不改：`JournalPostingService.reverseEntry` 签名、Payment VOID 无 body、STANDARD allocations DELETE。

### 5.9 Controller

- CRUD/工作流 DTO 带 `paymentPurpose`
- 草稿 `/items` 支持一行 `AP_CREDIT_MEMO`
- `POST /ap-credit-memos/refundable/page`
- Payment page 可按 purpose 过滤

## 8. 实施顺序

1. 补现网未付贷项与付款 remaining 回归测试
2. Liquibase + 实体 + 枚举
3. 切换 `applied_credit` remaining（迁移后 V1 账面不变）
4. 贷项 POST 拆分 + 现金上限 + VOID 回滚
5. `payment_purpose` + 供应商 RECEIPT 过账
6. 退款一行核销、汇兑重乘、整单 VOID、原付款闸、锁
7. 前端与 locale
8. schema_tables / 应付贷项文档切到已落口径

3–6 必须同一可发布交付。禁止：已付贷项能过账但没有退款；退款过账但不回写贷项；汇兑写出但 VOID 不冲；只拦前端。

## 9. 验收

### 9.1 金额与折扣

1. AP 100 已付 100，贷项 40：`applied=0`、`refundable=40`、原票 remaining=0。
2. AP 100 已付 60，贷项 70：`applied=40`、`refundable=30`。
3. AP 100 已付 20，贷项 30：`applied=30`、`refundable=0`、remaining=50。
4. 累计贷项总额超过原 AP total：拒绝。
5. 数量超过可贷：拒绝。
6. 全额已付仍有可贷数量：可生成并过账贷项；前端入口可见。
7. 实付 98、折扣 2，贷项 40：允许，`refundable=40`。
8. 实付 98、折扣 2，贷项 100：拒绝（超过实付现金）。
9. 同上先贷 40 再贷 60：第二张拒绝。
10. 无折扣时行为与 1–3 相同。

### 9.2 退款资金

11. 退款 40 带一行过账：借银行/贷 AP 40，贷项 `refunded=40`，`unallocated=0`。
12. 无线过账、两行核销、`allocated ≠ amount`：拒绝。
13. 跨公司/供应商/币别：拒绝。
14. 超过 `refundRemaining`：拒绝。
15. STANDARD 使用 `AP_CREDIT_MEMO`：拒绝。
16. `isPrepayment=true`：拒绝。
17. 草稿行不回写贷项；POST 后回写一次。
18. 同一贷项第二张退款 10（第一张已退 30）：成功，`PARTIAL` 再 `REFUNDED`。
19. 两张草稿抢同一余额：第二张 POST 失败。
20. 银行账户跨公司/币别/无效：拒绝。
21. POSTED 追加核销或 DELETE 行：拒绝。
22. 交叉货币：拒绝。

### 9.3 汇兑

23. 退款汇率 = 贷项汇率：无汇兑凭证。
24. 退款汇率更高：local-only 借 AP / 贷汇兑收益。
25. 退款汇率更低：借汇兑损失 / 贷 AP。
26. 缺 `EXCHANGE_DIFF` 且汇差非 0：过账回滚。
27. 本位币与外币（同币）均可过账；不要求普通 AP 付款汇兑已存在。
28. 分次退款重乘累计可与 `refundableBase` 有分位差：不因此失败。

### 9.4 VOID 与依赖

29. VOID 退款：恢复贷项、冲汇兑与银行凭证。
30. 有有效退款时 VOID 贷项：拒绝。
31. 先 VOID 退款、无 POSTED 退货：贷项 VOID 成功（期间按现网）。
32. 退款 + 采购退货：必须先退款后冲退货再 VOID 贷项。
33. `refundable>0` 时撤原付款：拒绝。
34. `refundable=0` 时撤后置付款：remaining 公式正确。
35. STANDARD VOID / DELETE 分配：账务与现网一致。

### 9.5 并发与迁移

36. 两张退款并发最后余额：一成一败，无超退。
37. 付款与贷项并发同一 AP：无丢更新。
38. 贷项 POST 与原付款 VOID 并发：只形成一种合法结果。
39. 普通 RECEIPT→AR、DISBURSEMENT→AP 回归通过。
40. 已过账贷项迁移后 `applied=total`、`refundable=0`，remaining 不变。
