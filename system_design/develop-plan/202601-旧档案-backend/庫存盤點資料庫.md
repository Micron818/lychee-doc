- **盤點的核心意義**：盤點的本質是拿「系統認知的真相 (`book_quantity`)」去和「物理世界的真相 (`counted_quantity`)」碰撞，從而逼出「管理上的黑數 (`difference_quantity`)」。



在 ERP 系統中，庫存盤點 (Stocktaking / Physical Inventory) 是一個非常嚴謹且具有特定流程的作業。它通常不是「直接把庫存改成某個數字」，而是包含三個階段：

1. **建立盤點計畫 (Create Plan)**：決定要盤點哪些倉庫、哪些物料（全盤或抽盤），此時系統會記錄當下的「帳面庫存 (Book Quantity)」，並可能凍結這些物料的異動。
2. **輸入盤點結果 (Enter Count)**：倉管人員拿著盤點單去現場數數量，並將「實盤數量 (Counted Quantity)」輸入系統。
3. **過帳差異 (Post Differences)**：系統計算出「差異數量 (Difference Quantity)」，經主管核准後，產生盤盈 (IN) 或盤虧 (OUT) 的庫存異動流水帳。

為了支援這個完整的流程，我們需要設計 **盤點單 (Physical Inventories)**。

### 💡 核心控制欄位設計與系統邏輯 (inventory_type, block_transactions, snapshot_at)

在盤點模組中，為了確保盤點期間庫存數據的準確性與一致性，特別設計了以下三個關鍵控制欄位。它們的組合決定了系統如何處理「盤點期間的庫存異動（動盤與靜盤）」。

#### 1. `inventory_type` (盤點類型)

- **FULL (全盤)**：通常在月末、季末或年末進行，要求對整個倉庫（或特定庫區）進行全面清點。在全盤模式下，通常會強制要求凍結整個倉庫的交易。
- **CYCLE (循環盤點/抽盤)**：日常營運中，每天抽取一部分物料進行盤點（例如高價值 A 類物料每天盤，C 類物料每季度盤）。此模式下，可以選擇只凍結特定物料，或允許不停機盤點（動盤）。

#### 2. `block_transactions` (凍結交易)

這是 WMS 盤點模組中非常經典的設計，用於解決盤點時「移動的靶子」問題（邊盤點邊收發料導致帳實不符）。

- **當 `block_transactions = true` (靜盤/凍結)**：
  - **系統邏輯**：在業務邏輯層（如收貨過帳、領料過帳等服務中）進行攔截。如果發現當前操作涉及的倉庫/物料/庫位正在被一個未完成（狀態為 `PLANNED` 或 `COUNTED`）的盤點單鎖定，系統將拒絕該庫存交易，提示「該物料/倉庫正在盤點中，禁止交易」。
  - **配合 `inventory_type`**：如果是 `FULL` 全盤，則凍結整個 `warehouse_id`；如果是 `CYCLE` 循環盤點，則僅凍結 `physical_inventory_items` 中列出的特定 `material_id`、`batch_no` 和 `location_code`。
- **當 `block_transactions = false` (動盤/不停機盤點)**：
  - **系統邏輯**：允許在盤點期間繼續進行庫存交易。這需要配合 `snapshot_at` 來追溯盤點期間發生的流水，計算出真正的差異。

#### 3. `snapshot_at` (快照時間)

此欄位記錄了產生盤點明細（抓取 `book_quantity` 帳面庫存）的精確時間點。

- **配合 `block_transactions = true`**：`snapshot_at` 就是庫存被凍結的那一刻。因為後續沒有異動，盤點人員數到的數量直接與快照時的 `book_quantity` 對比即可。
- **配合 `block_transactions = false`**：`snapshot_at` 是計算動盤差異的「時間基準」。如果盤點期間發生了出入庫，過帳時系統可以透過比對 `snapshot_at` 之後的 `stock_transactions` 流水，將盤點期間的增減回溯，從而計算出精確的差異量。

### 💡 盤點單運作邏輯與寫入流水帳 (`stock_transactions`) 的行為

這張單據的生命週期與寫入流水帳的邏輯非常特別，請特別注意以下流程設計：

#### 階段 1：建立盤點單 (`status = 'PLANNED'`)

- **系統動作**：當使用者點擊「產生盤點明細」時，系統會去 `stock_on_hand` 撈取該倉庫下所有符合條件的物料與批號。
- **寫入明細與帳面庫存 (`book_quantity`) 獲取邏輯**：
系統需要根據不同的庫存狀態 (`stock_type`)，從 `stock_on_hand` 映射並計算出對應的帳面數量。同一物料在同一庫位，若同時存在不同狀態的庫存，會產生多筆盤點明細行。
  - **當 `stock_type = 'UNRESTRICTED'` (非限制/可用庫存)**：
  `book_quantity` = `physical_quantity` - `blocked_quantity` - `qa_quantity`
  *(說明：可用庫存為物理總庫存減去被凍結和質檢中的數量。預留數量 `reserved_quantity` 通常不扣減，因為實物仍在庫位上)*
  - **當 `stock_type = 'INSPECTION'` (質檢庫存)**：
  `book_quantity` = `qa_quantity`
  - **當 `stock_type = 'BLOCKED'` (凍結庫存)**：
  `book_quantity` = `blocked_quantity`
  此時 `counted_quantity` 為 `NULL`，`difference_quantity` 為 `0`。
- *(可選)* 如果 `block_transactions = true`，系統可能需要在 `stock_on_hand` 標記這些物料被凍結，禁止其他單據（如領料單、出貨單）扣減。

#### 階段 2：輸入實盤數量 (`status = 'COUNTED'`)

- **人工動作**：倉管人員在畫面上輸入實際數到的數量。
- **系統動作**：當使用者輸入 `**counted_quantity`** 後，系統自動計算並更新 `**difference_quantity**` (`counted_quantity` - `book_quantity`)。
  - 如果 `difference > 0`：代表盤盈 (系統少算，現場多)。
  - 如果 `difference < 0`：代表盤虧 (系統多算，現場少)。
  - 如果 `difference = 0`：代表帳實相符。

#### 階段 3：核准並過帳差異 (`status = 'POSTED'`)

- **人工動作**：主管檢視差異報表，確認無誤後點擊「過帳 (Post)」。
- **系統動作 (寫入流水帳)**：
系統**只針對 `difference_quantity != 0` 的明細**產生 `stock_transactions` (庫存異動流水帳)：
  - **盤盈 (Difference > 0)**：
    - 將 `difference_quantity` 的絕對值寫入流水帳的 `**in_quantity` (入庫)**。
    - `transaction_type` = `ADJUSTMENT`。
  - **盤虧 (Difference < 0)**：
    - 將 `difference_quantity` 的絕對值寫入流水帳的 `**out_quantity` (出庫)**。
    - `transaction_type` = `ADJUSTMENT`。
- **解除凍結**：過帳完成後，解除該倉庫/物料的異動凍結狀態。
