# SO → FO 汇总规则 → UI 提示与禁用逻辑映射

> 目标：把「系统规则」翻译成**用户一看就懂、操作时就被引导**的 UI 行为，
> 避免事后报错、避免业务与系统理解不一致。

---

## 一、SO 选择阶段（SO → FO 汇总入口）

### 1️⃣ 不可汇总的 SO（硬性条件）

| 规则     | UI 表现       | 说明文案示例             |
| ------ | ----------- | ------------------ |
| 客户不同   | Checkbox 禁用 | 不同客户的订单不可汇总为同一张 FO |
| 工厂不同   | Checkbox 禁用 | 订单所属工厂不一致          |
| 交易条件不同 | Checkbox 禁用 | 付款 / Incoterms 不一致 |

**辅助 UI**

* 禁用行整行置灰
* Hover tooltip 显示具体原因

---

### 2️⃣ 可汇总但有风险的 SO（软性条件）

| 情况          | UI 表现           | 提示方式                  |
| ----------- | --------------- | --------------------- |
| 交期差异 > 设定阈值 | 黄色 Warning Icon | Tooltip：交期差异较大，建议拆 FO |
| 数量差异极大      | Tag：数量差异        | Tooltip：数量不平衡，可能影响排产  |

---

## 二、FO Lines 生成阶段（是否合并行）

### 3️⃣ 产品行合并规则

| 条件           | 系统行为    | UI 提示          |
| ------------ | ------- | -------------- |
| 同产品 + 同需求日期  | 自动合并为一行 | 灰字：已合并自 3 笔 SO |
| 同产品 + 不同需求日期 | 自动拆分    | Tag：不同交期       |
| 用户手动合并       | 弹窗确认    | 合并后将以最早交期为准    |

---

### 4️⃣ 来源 SO 追溯显示

* 来源 SO 列显示：`SO-001, SO-003 +1`
* Hover 显示完整清单
* 行展开区显示：

  * SO No
  * SO Line No
  * 原始数量 / 交期

---

## 三、FO Header 层级提示（整体语义）

### 5️⃣ 汇总状态提示条（Header Banner）

| 场景      | UI 样式          | 文案示例            |
| ------- | -------------- | --------------- |
| 多 SO 汇总 | Info Banner    | 本 FO 汇总自 4 笔 SO |
| 交期不一致   | Warning Banner | 存在多组交期，请留意排产    |
| 部分转单    | Info Banner    | 含部分转单 SO        |

---

## 四、Confirm / 执行 MRP 前的防呆

### 6️⃣ Confirm 前检查清单（Blocking Rules）

| 检查项       | 不通过时 UI 行为          | 提示文案           |
| --------- | ------------------- | -------------- |
| 存在不可汇总 SO | Confirm 按钮 disabled | 存在不可汇总订单       |
| 数量超出可转    | 禁止确认                | 转单数量超出 SO 剩余数量 |
| 交期冲突未确认   | 弹确认框                | 是否确认以最早交期排产？   |

---

## 五、操作后即时反馈（Toast / Result）

### 7️⃣ 成功与警告并存的反馈

* ✅ FO 建立成功（汇总 5 笔 SO）
* ⚠️ 提示：存在 2 行不同交期，已拆分处理

---

## 六、设计原则总结（给 UI / 前端 / 产品）

1. **能选 ≠ 一定合理 → 用提示区分风险等级**
2. **禁止要有原因 → 禁用 + Tooltip**
3. **规则前移 → 不等 Confirm 才报错**
4. **汇总语义要处处一致（List / Header / Lines）**
