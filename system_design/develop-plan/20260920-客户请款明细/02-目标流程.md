# 02. 客户请款明细目标流程（To-Be）

> 原则：用户选 **一个客户** 和 **实际出货日闭区间**，系统把该期间已出货行打成一张 PDF。  
> 不落请款单、不改 Delivery / AR / 占用。打印基座对齐销售订单报表（仅预览，禁止前端 HTML 双轨）。

系统未上线：**一次交付**查询组装 + PDF + 出货单列表入口。不做 Excel、邮件、归档 Export、账龄、对账单。

---

## 1. 在作业链上的位置

```text
SO 确认
  → 开 Delivery → 领料发货 StockIssue(SALES_DELIVERY)
  → Delivery 整单出完：status = DELIVERED，actualDeliveryDate 有值
         │
         ├─【本报表】按客户 + actualDeliveryDate 汇总 → 寄客户请款
         │
         └─ 财务从 Delivery 开 AR（可合并）→ 收款核销
```

请款与开票并行：已开票的出货仍进本表（列上标开票状态）。本表 **不** 创建或更新 `ar_invoices`。

```

   │  否则读 ProTable 搜索条件
   │  前端校验：customerId 单一 + actualDeliveryDate between 两端齐全
   │  DeliveryBillingStatementPdfPreviewModal + post blob
   ▼
POST /api/v1/sd/deliveries/billing-statement/pdf     ← read，inline，不建作业、不落 OSS
   │  body: 与列表同源筛选，或 { id_in }
   ▼
DeliveryBillingStatementPdfRenderer.render(params, locale)
    ├─ DeliveryBillingStatementService.getReportData(params)
    │     ├─ requireCustomerAndActualDeliveryDateRange 或 loadByIds
    │     ├─ 查 Delivery：客户、actualDeliveryDate 闭区间、DELIVERED、NORMAL
    │     ├─ 校验币别一致、公司一致（factory → company）
    │     ├─ 查 DeliveryItem（DELIVERED + sourceDocType 空或 SALES_ORDER）→ Fact：净量 / LineTaxCalculator / 备注
    │     ├─ 回追 SalesOrder / SalesOrderItem（PO、内部参号、付款条件）
    │     ├─ Material → Model / Color / Size / Unit
    │     ├─ 按 §3 / 03 §4 分组为尺码矩阵 + rowspan
    │     ├─ 付款条件唯一则 resolveSchedule(dateTo, 含税合计)
    │     ├─ 默认公司银行（companyId + 本表币别，可空）
    │     └─ 抬头 + 区间 + 合计 + 大写 + 制表人
    └─ Thymeleaf templates/print/delivery-billing-statement-pdf.html → PDF bytes
   │
   ▼
前端 blob → objectURL → iframe；工具栏 print()
```

禁止再开 `/print` 深链、前端 HTML 版式、`autoPrint`、对外 `print-data` REST。

## 5. 筛选与纳入规则

### 5.1 表头

| 条件 | 规则 |
|------|------|
| 客户 | `customerId` 等于所选 |
| 实际出货日 | `actualDeliveryDate >= from AND <= to`（闭区间，含两端） |
| 状态 | `DELIVERED` |
| 类型 | `NORMAL` |
| 作废 | `CANCELLED` 永不纳入 |

勾选路径：先按 id 加载。任一条非 `DELIVERED` 或非 `NORMAL` → `validation.delivery.billing_statement.selection.not_printable`（不静默丢掉）。客户/公司/币别从命中单派生，不一致拒绝。前端应先挡住，避免「勾了却打不出」。

### 5.2 明细行

```
纳入：status = DELIVERED
    AND (sourceDocType == null OR sourceDocType == SALES_ORDER)
    AND (issuedQuantity − returnedQuantity) > 0
```

`sourceDocType == null`：手工自建交货行，未挂销售订单，**纳入**。  
`sourceDocType == SALES_ORDER` 但 `sourceDocId` 空：仍纳入；PO / 订单号 / 付款条件留空，不因此整表失败。  
`RETURN_PO` / `TRANSFER_ORDER` / `OTHER`：**排除**（退货、调拨、其它来源不是给客户请款的销售出货）。

### 5.3 数量与金额（先 Fact，再矩阵）

```
netQty = issuedQuantity − returnedQuantity          // ≤ 0 跳过

fact 未税/税/含税 = LineTaxCalculator.calculate(netQty, unitPrice, taxRate)
```

`LineTaxCalculator` 已是 `qty × price` 未税、税率/100 税额、含税 = 未税 + 税，2 位 `HALF_UP`。  
净量等于交易量时，结果与交货行落库值一致（落库也走该计算器）。部分退货后与 `ArInvoiceFromDeliveryService` 开票行同源，不另做比例分摊。

矩阵行金额 = **Σ 组内 Fact 金额**（对齐 09 `rowAmount = Σ subtotalAmount`）。  
**不要**再做「末行吃尾差」：矩阵一行跨多尺码，末行语义不成立。合计以 Σ Fact 为准。

禁止：

- `subtotalAmount.multiply(netQty.divide(transactionQuantity))`（无精度 `divide` 会抛 `ArithmeticException`；先分摊再舍入会与 AR 差 1 分）
- 用销售订单行 `quantity` / `unitPrice` 重算

单价列印交货行 `unitPrice`（4 位）。

`transactionQuantity <= 0` → 该行跳过并记 warn，不抛整表失败。

无型号物料：不另开料号列；型号格印 `materialCode + " " + materialName`，尺码格空，数量仍进行合计。无 `productModelId` 时分组键与 rowspan 都带 `fallbackMaterialId`，避免不同无型号料被合成一行。

### 5.4 抬头派生

| 字段 | 来源 |
|------|------|
| 公司抬头 | 唯一 `companyId` → Company（名称 / 地址 / 电话 / 税号 / logo，对齐 SO 报表） |
| 客户 | `Customer` code + name + 账单地址（有则印） |
| 币别 | 唯一 `currencyOptionId` → 字典 code |
| 付款条件 | 行上来源 SO 的 `paymentTermId` 去重 |
| 到期日 | 条件唯一时：`resolveSchedule(termId, dateTo, 含税合计)` 取排程最晚 `dueDate` |
| 收款账号 | `findDefaultByCompanyId(companyId, currencyOptionId)`：银行名 / 账号 / 户名；无则空 |

## 6. API

```
POST /api/v1/sd/deliveries/billing-statement/pdf
@PreAuthorize("hasAuthority('/sd/deliveries:read')")
Content-Type: application/json
Accept: application/pdf
Content-Disposition: inline; filename="..."
```

Body 与出货单列表 `DynamicSpecifications` 同源，至少：

```
customerId_eq
actualDeliveryDate_between: "yyyy-MM-dd,yyyy-MM-dd"
```

或：

```
id_in: [1, 2, 3]
```

不建 `export_jobs`，不传 OSS。校验失败用现有 `ValidationException` + `messages*.properties`。

前端：`postDeliveryBillingStatementPdfBlob(params)`，Modal 复用 `PdfPreviewSession`。

## 7. 前端（出货单列表）

对齐销售订单报表工具栏（`sales-orders/index.tsx` + `reportParams.ts`），不新建菜单页。

1. 客户搜索改为 **`customerId` Select**（`getCustomerList`），与 SO 列表一致：Select 唯一入口，去掉 `customerName like`。  
2. 增加 **实际出货日** `dateRange` 搜索（`actualDeliveryDate_between`）。计划出货日区间可保留，**不**作为请款条件。  
3. 列表 Response 补只读 `companyId`（后端 `factory → company`，不改 `deliveries` 表）。勾选混公司用 `hasUniformField(rows, 'companyId')`，不要用 `factoryId` 当公司（同公司两厂会被误拒）。  
4. 工具栏「预览/打印」（对标 SO `canPreview`）：  
   - 有勾选：全部 `status = DELIVERED` 且 `deliveryType = NORMAL`，且同一客户 / 公司 / 币别  
   - 否则 tooltip：`deliveredOnly` / `sampleOrReturn` / `customerMixed` / `companyMixed` / `currencyMixed`  
   - 无勾选：必须单一客户 + 实际出货日两端齐全  
5. `rowSelection`：`DRAFT` 与 `DELIVERED` 可勾；`RELEASED` / `CANCELLED` 不可勾。  
   `BatchDeleteButton` 对齐 SO：仅当勾选全部为 `DRAFT` 才可点（`assertBulkStatus(..., 'status', 'DRAFT')` + `disabled={!allDraft}`）。**不得**因放开勾选而删已出货单（后端 `deleteDeliveryBulk` 已拒非 DRAFT，前端仍须挡住）。

## 10. 与销售订单报表的差异

| 维度 | 09 销售订单报表 | 本报表 |
|------|-----------------|--------|
| 数据 | `SalesOrder` / 订购量 | `Delivery` / 净出货量 |
| 日期 | `orderDate` | `actualDeliveryDate` |
| 版式 | 跨单尺码矩阵 + 样图；左起型号 | **同一套尺码矩阵**；左起出货复合格；按出货单+开票状态+型号+色分组；**不印**样图、**不印**料号列、不另开单位列 |
| 备注 | SO 头备注进 PO 复合格；行备注进客户订单号下 | 出货单 `remarks` 进出货复合格；交货行 `remarks` 进客户订单号下（`appendDistinctRemark`） |
| 税 | 不印 | 印未税 / 税率 / 税额 / 含税 |
| 账期 / 账号 | 无 | 有（可空 / 多种） |
| 金额大写 | 无 | 含税合计 |
