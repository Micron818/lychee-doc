## 1. 无新表

请款明细是只读投影。不新增 `billing_statements`、不写打印流水、不改 `invoiceStatus`。

复用：

```
deliveries
delivery_items

materials / product_models / colors / product_sizes / material_units
```

## 2. 查询关联

```
筛选
  ├─ customerId（必填，单一）
  └─ actualDeliveryDate between from..to（必填）

Delivery[]（DELIVERED + NORMAL + 日期内）
  ├─ factoryId → Factory.companyId → Company
  ├─ customerId → Customer
  ├─ currencyOptionId
  ├─ actualDeliveryDate / deliveryNo / invoiceStatus / remarks
  └─ DeliveryItem[]（DELIVERED + SALES_ORDER + 净量 > 0）
        ├─ issuedQuantity / returnedQuantity / transactionQuantity
        ├─ unitPrice / taxRate / subtotalAmount / taxAmount / totalAmount
        ├─ invoiceStatus / remarks
        ├─ transactionUnitId → MaterialUnit
        ├─ materialId → Material → Model / Color / Size
        └─ sourceDocId / sourceDocItemId → SalesOrder / SalesOrderItem
              ├─ customerPoNo / orderNo
              ├─ customerInternalRefNo / customerOrderNo
              └─ paymentTermId
```

无有效明细的 Delivery 不占行；若全部被滤掉 → 无可打印明细。

## 3. 打印数据模型

`DeliveryBillingStatementResponse`（一次性返回、名称已解析）：

```java
public class DeliveryBillingStatementResponse {
    // 公司抬头
    String companyName;
    String companyAddress;
    String companyPhone;
    String companyTaxId;
    String companyLogoDataUri;          // 可空

    // 客户
    Long customerId;
    String customerCode;
    String customerName;
    String customerBillingAddress;      // 可空

    // 查询范围

    LocalDate deliveryDateTo;
    int deliveryCount;                  // 命中出货单张数
    String currencyCode;

    // 账期 / 收款（可空）
    String paymentTermName;             // 多种时为翻译后的「多种」
    boolean paymentTermMixed;
    LocalDate dueDate;                  // 条件唯一才有
    String bankName;                    // 默认户，可空
    String bankAccountNo;
    String bankAccountName;

    List<SizeColumn> sizeColumns;        // 本结果尺码联集，排序对齐 09 §6.3
    List<MatrixRow> rows;

    BigDecimal totalQuantity;
    BigDecimal subtotalAmount;
    BigDecimal taxAmount;
    BigDecimal totalAmount;
    String totalAmountInWords;

    String preparedByName;
    String printedBy;
    LocalDateTime printedAt;
}

public static class SizeColumn {
    Long productSizeId;
    String code;
    String name;
    Integer sequence;
}

public static class MatrixRow {
    Long deliveryId;
    LocalDate actualDeliveryDate;
    String deliveryNo;
    String deliveryRemarks;             // Delivery.remarks；进出货复合格

    String invoiceStatus;               // 交货行
    String invoiceStatusLabel;

    Long salesOrderId;
    String salesOrderNo;
    String customerPoNo;
    String customerInternalRefNo;
    String customerOrderNo;
    String itemRemarks;                 // 组内交货行 remarks 去重拼接

    Long productModelId;
    String productModelCode;            // 纯款号；Renderer 拼 15 的 label
    String productModelName;
    String colorSkuCode;
    String productModelLabel;           // 无型号时 = materialCode + " " + materialName
    Long colorId;
    String colorName;
    String unitName;

    Long fallbackMaterialId;            // 仅 productModelId == null
    BigDecimal unitPrice;
    BigDecimal taxRate;
    Map<Long, BigDecimal> sizeQuantities;
    BigDecimal rowQuantity;
    BigDecimal subtotalAmount;
    BigDecimal taxAmount;

```

**不**建 `materialCode` / `materialName` 独立列。无型号时身份只写在 `productModelLabel`。

Renderer 预格式化日期 / 数量 / 单价（4 位）/ 金额（2 位）/ 税率。模板只做 `th:text` / `th:if` / `th:rowspan`。

## 4. 矩阵组装

对齐 [09 §6](../20260818-report/09-示例-销售订单报表.md) + [15](../20260818-report/15-工厂订单与销售订单型号色号展示.md)。数量改净出货，分组键加上出货单 / 税率 / 开票状态。

### 4.1 平坦事实行（Fact）

每个纳入的 `DeliveryItem` 产出一条 Fact：

- 出货：`deliveryId` / `actualDeliveryDate` / `deliveryNo` / `deliveryRemarks`
- 来源 SO：`salesOrderId` / `salesOrderNo` / `customerPoNo` / 内部参号 / 客户订单号
- 物料：`productModelId` / `colorId` / `productSizeId` / `unitId` / `materialId`
- 计价：`unitPrice` / `taxRate` / 净量 / 已分摊未税·税·含税
- 状态与备注：行 `invoiceStatus`、行 `remarks`

### 4.2 分组键

```
groupKey = (
  deliveryId,
  salesOrderId,                 // 可空
  customerPoNo,
  customerInternalRefNo,
  customerOrderNo,
  productModelId,
  colorId,
  fallbackMaterialId,           // productModelId == null 时 = materialId，否则 null
  unitId,
  unitPrice,
  taxRate,
  invoiceStatus                 // 同行尺码开票进度不同则拆行，避免 rowspan 吃掉状态
)
```

**禁止**把 `materialId` 放进有型号行的键：一色一尺码是不同 Material，放进去就合不成矩阵。

组内：

- `sizeQuantities[sizeId] += netQty`（`productSizeId == null` 只累加 `rowQuantity`，尺码格空）
- `rowQuantity = Σ netQty`
- `subtotal / tax / total = Σ Fact 已分摊金额`
- `itemRemarks`：复用 `SalesOrderReportServiceImpl.appendDistinctRemark` 语义（去空白、去重、多条用分隔拼）
- `deliveryRemarks`：同出货单头备注（组内相同）

### 4.3 动态尺码列

本结果全部 Fact 的 `productSizeId` 去重，排序同 09 §6.3（`PrefixedCode`：prefix ASC、sequence ASC NULLS LAST、name ASC）。

### 4.4 行排序（服务视觉合并）

```
actualDeliveryDate ASC
→ deliveryNo ASC
→ productModelCode ASC
→ salesOrderNo / customerPoNo ASC
→ colorSkuCode / colorName ASC
→ customerInternalRefNo / customerOrderNo ASC
→ unitPrice ASC
```

### 4.5 视觉合并（rowspan）

| 列 | 连续相等键 |
|----|------------|
| 出货复合格 | `deliveryId` + `invoiceStatus`（状态不同不跨行合并，避免一张出货单里部分尺码已开票时状态被吃掉） |
| 型号 | `deliveryId` + `invoiceStatus` + `productModelId` + `colorId`（对齐 15，型号含本款色字母） |
| PO / 销售订单 | `deliveryId` + `invoiceStatus` + `productModelId` + `colorId` + `salesOrderId` |
| 颜色 | 上一项 + `colorId` |

算法同 09 §6.5。内部参号、客户订单号、尺码、数量、价税、开票状态每行都印。

## 5. PDF 版式

模板：`lychee-erp-sd/src/main/resources/templates/print/delivery-billing-statement-pdf.html`  
Renderer：`DeliveryBillingStatementPdfRenderer`  
共用：`PdfRenderSupport`、`MoneyFormatSupport`、`AmountInWordsSupport`、`StorageImageHelper`（仅公司 logo）。

### 5.1 页头（每页重复）

- 左：公司 logo（可空）+ 名称 / 地址 / 电话 / 税号  
- 中：标题「客户请款明细」  
- 右：币别、出货单张数、打印时间

### 5.2 信息区

| 左 | 右 |
|----|----|
| 客户代码 / 名称 | 出货日：from ~ to |
| 账单地址（可空） | 付款条件 / 到期日（可空） |
| | 收款银行 / 账号 / 户名（可空） |

### 5.3 明细表（尺码矩阵）

**不设料号、名称、独立尺码列。** 列结构对齐 09，左侧改为出货复合格，右侧保留请款价税：

| 型号* | 出货日 / 单号 / 开票* | 客户PO / 销售订单* | 颜色* | 内部参号 | 客户订单号 | S | M | … | 数量 | 单位 | 单价 | 未税 | 税率 | 税额 | 含税 |
|-------|----------------------|-------------------|-------|----------|------------|---|---|-----|------|------|------|------|------|------|------|

`*` = rowspan。Size 过多时缩字号（同 09）。

**出货复合格**（对齐 09 的 PO 格）：

```
{actualDeliveryDate}
{deliveryNo}    {invoiceStatusLabel}
备注: {deliveryRemarks}          // 无则整行不印
```

开票状态用该矩阵行的交货行状态（与分组键一致）。同一出货单 rowspan 时，若行间状态不同，分组已拆行，复合格各自显示，不跨状态合并。

**PO / 销售订单复合格**：

```
{customerPoNo}
{salesOrderNo}
```

**客户订单号格**（对齐 09）：主行印 `customerOrderNo`；其下印 `itemRemarks`（组内去重拼接）。

**无型号物料**：型号格 = `materialCode + " " + materialName`；颜色空；尺码格空；数量仍在「数量」列。不另开料号列。

### 5.4 合计与签核

- 合计数量、未税、税额、含税  
- 含税大写一行  
- 签核三栏：制表（已填） / 审核（空） / 客户确认（空）

多页：`thead` 重复；合计与签核只在最后一页（对齐订购单 / 收款单分页习惯）。

### 5.5 文件名

```
{print.customer_billing_statement.fileName}_{customerCode}_{from}_{to}.pdf
```

客户代码做文件名安全截断（同 SO 报表 `safeCustomer`）。

## 7. 校验 key（新增）

写入 `messages.properties` / `_zh_CN` / `_vi`，三语 key 顺序对齐：

| key | 含义 |
|-----|------|
| `validation.delivery.billing_statement.customer.required` | 未选单一客户 |
| `validation.delivery.billing_statement.date_range.required` | 出货日区间不完整 |
| `validation.delivery.billing_statement.date_range.invalid` | from > to |
| `validation.delivery.billing_statement.customer_mixed` | 勾选跨客户 |
| `validation.delivery.billing_statement.company_mixed` | 跨公司 |
| `validation.delivery.billing_statement.currency_mixed` | 跨币别 |
| `validation.delivery.billing_statement.noPrintableItems` | 无已出货明细 |
| `validation.delivery.billing_statement.max_rows` | 超过 5000 行 |

与 SO 报表一样：缺条件是校验错误，不是空 PDF。
