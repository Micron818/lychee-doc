# 04. 实施清单（开发入口）

> 架构以 [02-目标架构.md](./02-目标架构.md) 为准；域名与变量以 [03-环境契约.md](./03-环境契约.md) 为准；数据库基线与开通以 [06-数据库基线与租户开通.md](./06-数据库基线与租户开通.md) 为准。  
> **表结构不变。** Liquibase 以现有库重新生成基线，旧的 `v0/`、`v1/` 退出 changelog。  
> 本波交付：数据库基线与开通函数、khh 测试栈、演示栈、khh 正式栈切换。小租户共用栈只保持契约，不购买机器，不写迁移脚本。

## 1. 审查结论

| 问题 | 结论 |
|------|------|
| 现网机器是什么 | khh 大租户正式栈 `khh-prod` |
| khh 正式入口 | 只有 `khh.lycheetech.com`，issuer 用同一 Host |
| `lycheetech.com` | 产品介绍与帮助站；khh-prod 切换当天停用它的 ERP 入口，不做跳转 |
| khh 测试入口 | 只有 `khh-test.lycheetech.com`，issuer 用同一 Host |
| 是否把 `test.lycheetech.com` 做成登录页 | 否。该名字不创建 |
| 演示 | 独立栈；用户入口 `demo.lycheetech.com`；issuer `auth-demo.lycheetech.com`；租户代码 `demo` |
| 演示数据从哪来 | 空库 + 开通函数 + 虚构资料。不恢复 khh 正式库 |
| 空库能否建起来 | 现在不能：基线被 context 跳过，种子写死租户 1。以现有库重新生成基线 |
| 新租户的配置 | 从模板租户复制；开通函数同时建第一个管理员 |
| 测试栈的数据 | 只从正式恢复业务库；Keycloak 独立建立；恢复后改写 `users.idp_user_id` |
| 小租户 | 将来进 `shared-prod` / `shared-test`，共用库和 Keycloak，issuer 用 `auth` / `auth-test` |
| 大租户 | 一租户一对独享栈，本波只有 khh |
| 小租户升格 | DNS 切到新独享栈后用户重新登录。本波不实施 |
| 镜像 | 各栈同一构建；`pnpm run build`；Spring profile 各栈都是 `prod` |
| 发布 | `main` 只自动到 `khh-test`；`demo` 与 `khh-prod` 手动指定已有标签 |
| 备份目录 | `backup-postgres/${STACK_ID}/` |

## 3. 实现顺序

### 3.0 先行

[05-khh正式issuer切换.md](./05-khh正式issuer切换.md) 在 khh 正式执行完毕。若尚未执行，先做它。

### 3.1 数据库基线（`lychee-backend`）

按 [06](./06-数据库基线与租户开通.md) 实施：

1. 比对本机与正式的 `databasechangelog`，一致后暂停向 `v1/` 合并新脚本。
2. 从本机库生成 `baseline/01-schema.sql`、`baseline/02-template-tenant.sql`，编写 `functions/provision-tenant.sql`。
3. `db.changelog-master.yaml` 改为 baseline + `v2/` + functions；删除 `v0/`、`v1/`。
4. 各 profile 删除 `spring.liquibase.contexts`；删除 `db.changelog-it.yaml` 及其中的外键开关，集成测试改用正式 master。
5. `LiquibaseHarnessIT`：空库跑完全量后开通一个租户，断言配置与模板一致、管理员拥有全部权限。
6. 用本机库启动：基线两项记为 `MARK_RAN`，开通函数建立，表结构不变。

### 3.2 后端配置（`lychee-backend`）

1. `application-prod.yaml` 的 endpoint、bucket、CDN、CORS 改为 [03 §5](./03-环境契约.md) 的占位，不给缺省，并在启动时校验。
2. 新增 `application-sql-log.yaml`；`DataSourceProxyLoggingConfig` 加上 `sql-log` profile。
3. `application-local.example.yaml` 改用 khh 测试栈的 bucket 与 CDN。

### 3.3 基础设施（`lychee-infra`）

1. `.gitignore`：加 `!.env.example`；忽略 `deploy/docker/nginx/conf.d/stack.conf`。
2. `deploy/render-stack-config.sh`（[03 §2](./03-环境契约.md)）。
3. Nginx：新增 `docker/nginx/stack.conf.template`，删除 `conf.d/default.conf`（[03 §6](./03-环境契约.md)）。
4. `docker-compose.yml` 按 [03 §4](./03-环境契约.md) 调整，包括端口只绑定 `127.0.0.1` 与 `KC_HOSTNAME_ADMIN`；`.env.example` 覆盖 [03 §3](./03-环境契约.md) 的全部键，值为占位。
5. `docker/postgres/init.sql` 改为 `init.sh`（[03 §9](./03-环境契约.md)）。
6. 备份脚本按 `STACK_ID` 写前缀。恢复脚本按 [03 §9](./03-环境契约.md) 校验栈名、停启对应服务，`--from-prod` 时只收业务库并改写 `users.idp_user_id`。
7. `deploy/deploy-service.sh`（[03 §12](./03-环境契约.md)）。
8. `README.md`：三台栈的 Host、通配证书文件名、新栈首次启动步骤、共用栈尚未购买。

### 3.4 前端（`lychee-frontend`）

1. `docker-entrypoint.sh` 按 [03 §7](./03-环境契约.md) 写 `env-config.js`。
2. `env.config.ts` 解析 `TENANT_HOSTS`，删除 `KEYCLOAK_REALM` 与运行时 `API_BASE_URL`。
3. `auth/config.ts`、`authService.ts` 按 Host 取 realm，确认有 realm 后才创建 `UserManager`。
4. `app.tsx`：Host 未登记时，在任何 OIDC 调用之前显示未登记页。
5. 测试条、演示条、未登记页，zh-CN / en-US / vi-VN 文案。
6. CDN 预连接改为运行时。
7. 本机开发的 `public/env-config.js` 与 `config.dev.ts`。
8. 构建命令保持 `pnpm run build`。

### 3.5 流水线（前后端各自仓库）

1. 构建与部署拆开，部署抽成可复用工作流（[03 §12](./03-环境契约.md)）。
2. `push` 到 `main`：构建，然后只部署 `khh-test`。
3. `workflow_dispatch`：输入栈（`khh-test`、`demo`、`khh-prod`）与已有标签。
4. 部署调用 `deploy/deploy-service.sh`；先拉镜像，成功后才改 `.env`。
5. 创建三个 Environment。`khh-prod` 设置审核人。现网 SSH 密钥放入 `khh-prod`。

### 3.6 开通 khh-test（人工）

1. 新 ECS（ap-southeast-1），目录 `/home/deployer/lychee`，克隆 `lychee-infra`。安全组只开 22、80、443。
2. OSS bucket、CDN（HTTPS 与 URL 鉴权）、应用与备份账号、备份生命周期（[03 §10](./03-环境契约.md)）。
3. 证书目录放通配证书；DNS `khh-test.lycheetech.com` 指向这台机器。
4. 按 [03 §1](./03-环境契约.md) 写 `.env`，镜像标签取 `main` 上已包含 3.1 至 3.4 的版本。执行 `render-stack-config.sh`，只启动 `postgres` 与 `keycloak`。
5. 经 SSH 隧道打开本栈管理台，新建 realm `kimhiephoa` 与 client `lychee-erp-web`（[03 §8](./03-环境契约.md)），建立测试账号，记下各自的用户 ID。`LYCHEE_PLATFORM_ADMINS` 写测试账号的 ID。
6. 准备映射文件（[03 §9](./03-环境契约.md)）：哪些 ERP 用户对应哪个测试账号。
7. 临时授予备份账号读正式业务库备份；执行 `restore_from_oss.sh --from-prod --idp-map <映射文件> khh-prod/daily/lychee_erp_…`；撤销授权。
8. 启动全部服务。映射文件里的测试账号能登录，看到的是正式数据的副本。
9. 需要附件时，由运维把正式 bucket 同步到测试 bucket。
10. LoongCollector 使用 Project `lychee-khh-test`。
11. crontab 备份；确认对象落在 `backup-postgres/khh-test/`。
12. GitHub Environment `khh-test` 填主机与密钥，推一次 `main` 验证自动部署。

以后刷新测试数据只重复第 7、8 步。不带 `--idp-map` 时，脚本沿用刷新前测试库的设定。

### 3.7 开通 demo（人工）

前提：新基线已经发布（3.1），否则空库建不起来。

1. 另一台 ECS，同样的目录布局与安全组。
2. 单独的 OSS bucket、CDN、应用与备份账号、备份生命周期。
3. 证书目录放通配证书；`demo.lycheetech.com` 与 `auth-demo.lycheetech.com` 的 DNS 指向演示机。
4. `.env` 使用演示列，执行 `render-stack-config.sh`，`docker compose up -d`。Liquibase 在空库上建出结构、模板租户和开通函数。
5. 经 SSH 隧道打开本栈管理台，新建 realm `demo` 与 client `lychee-erp-web`（[03 §8](./03-环境契约.md)），建第一个管理员并记下用户 ID。
6. 执行 `provision_tenant('demo', …)`（[06 §4](./06-数据库基线与租户开通.md)）。用该管理员登录，确认菜单完整。
7. 在页面建立虚构的公司、工厂、仓库、物料、客户、供应商与示范单据。不执行来自 khh 的恢复。
8. 做一次备份，复制到 `backup-postgres/demo/golden/`。
9. LoongCollector 使用 Project `lychee-demo`；crontab 备份落在 `backup-postgres/demo/`。
10. GitHub Environment `demo` 填主机与密钥，手动发布一次当前 khh-test 的标签。

### 3.8 khh 正式栈切换（人工）

前提：3.1 至 3.5 已合并，并在 khh-test 运行过。

1. 提前通知 khh 用户：切换当天起只用 `https://khh.lycheetech.com`，`lycheetech.com` 不再能进入系统。通知管理员：Keycloak 管理台改经 SSH 隧道打开（[03 §8](./03-环境契约.md)「管理入口」）。
2. 确认没有依赖公网 5432、8080、9000、8081 的用法（例如经 5432 同步正式库），这次发布会把它们改为只绑定 `127.0.0.1`。确认 Keycloak 首次启动的临时管理员已经换成正式管理员账号；安全组只放行 22、80、443。
3. 手动执行一次备份。
4. 证书目录放通配证书 `wildcard.lycheetech.com.pem` / `.key`，核对有效期。
5. `.env` 补上新键，旧键暂留：`STACK_ID=khh-prod`、`STACK_PLACEMENT=dedicated`、`LYCHEE_ENV=prod`、`TENANT_HOSTS=khh.lycheetech.com=kimhiephoa`、`ISSUER_HOST=khh.lycheetech.com`、`ALIYUN_OSS_ENDPOINT=oss-ap-southeast-1-internal.aliyuncs.com`、`ALIYUN_OSS_BUCKET_NAME=lychee-erp-assets`、`ALIYUN_CDN_DOMAIN=cdn.lycheetech.com`。缺键时部署会在改动容器之前失败。
6. 用 `workflow_dispatch` 向 `khh-prod` 先发布后端标签，再发布前端标签。后端这次发布带来新的 infra、生成的 Nginx 配置和新基线的 `MARK_RAN`。顺序不能反：新前端要靠新 Compose 传入的 `TENANT_HOSTS`。
7. 低峰时执行 `docker compose up -d`。postgres 与 keycloak 因端口绑定和 `KC_HOSTNAME_ADMIN` 变化会重建，数据库与登录会短暂中断。
8. 从 `.env` 删除 `KC_HOSTNAME`、`KEYCLOAK_URL`、`DOMAIN_NAME`、`API_BASE_URL`、`KEYCLOAK_REALM`。
9. DNS 删除 `lycheetech.com` 与 `www.lycheetech.com` 指向 khh-prod 的记录；产品站上线后再指向产品站。根域证书不再放在 khh-prod。
10. 经 SSH 隧道打开管理台，realm `kimhiephoa` 的 client `lychee-erp-web` 删除 `https://lycheetech.com` 的重定向、登出回跳与 Web Origin。
11. 按 §4 第 3、8、12 条验证。次日确认备份出现在 `backup-postgres/khh-prod/`。
12. 建议同时轮换数据库口令（`init.sql` 里的口令已入库）。

### 3.9 规则与文档同步

1. `lychee-workspace/.cursor/rules/workspace.mdc`：Liquibase 增量路径改为 `v2/<yyyy>/<MMdd>-<序号>-<描述>.sql`。
2. `lychee-backend/.cursor/rules/backend-development.mdc`：写入 [06 §5](./06-数据库基线与租户开通.md) 的增量规则。
3. `lychee-infra/README.md` 与 SLS 文档中新栈的部分。

## 4. 本波验收

1. `https://khh-test.lycheetech.com` 用测试 Keycloak 的账号登录 `kimhiephoa`，页面有测试条，回调是这个 Host。khh-test 与 khh-prod 的 JWKS 没有相同的 `kid`。
2. `https://demo.lycheetech.com` 登录 `demo`，页面有演示条。`https://auth-demo.lycheetech.com/` 显示未登记，不跳转登录；`/oidc/` 到达 Keycloak。
3. `https://khh.lycheetech.com` 登录 `kimhiephoa`，没有测试条或演示条。`lycheetech.com` 不再解析到 khh-prod；即使仍解析过来，443 也拒绝握手。`lycheetech.com` 不在 CORS 中，也不在 Keycloak client 中。
4. khh 测试上传的文件在 khh 测试 bucket，演示上传的文件在演示 bucket，khh 正式 bucket 没有这两份对象。测试机、演示机的 AccessKey 写不进正式 bucket。
5. khh 测试或演示签发的 token 调用 khh 正式 `/api` 被拒绝。
6. 推一次 `main`，只有 `khh-test` 的镜像标签变化。手动把该标签发布到 `demo` 后，演示机标签与之相同，khh 正式机不变。手动发布一个不存在的标签，部署失败，该机 `.env` 不变。
7. 恢复规则：
   - 演示机用 `khh-prod/…` 或旧 `daily/…` 恢复，脚本退出，演示库保留；演示机从 `demo/golden/` 恢复成功。
   - khh-test 不带 `--from-prod` 恢复正式备份被拒绝；带 `--from-prod` 恢复 `keycloak_` 备份被拒绝。
   - khh-test 刷新业务库后，映射文件里的账号能登录，其余正式用户不能登录。
8. Nginx：`/api/` 超时仍为 300s；443 的 `server` 与 location 只有一份；重建 backend 后不 reload Nginx 也没有 502；用 IP 或未登记的名字访问 443 被拒绝握手。
9. 演示机空库由 Liquibase 建成；开通的 `demo` 管理员能打开全部菜单，并走通 公司 → 工厂 → 仓库 → 物料 → 采购单 → 收货 → 应付发票 → 付款 → 凭证。
10. khh 正式与本机库：基线两项为 `MARK_RAN`，切换前后 `pg_dump --schema-only` 只多出开通函数。
11. `.env` 缺少必填键时，部署在改动容器之前失败。
12. 三台栈：从公网连不上 5432、8080、9000、8081；公网访问 `/oidc/admin/` 与 `/oidc/realms/master/` 返回 404；经 SSH 隧道能打开管理台并登录。

## 5. 本波明确不做

- 购买或配置 `shared-prod`、`shared-test`。
- 把小租户数据迁到独享栈的脚本。
- 页面「新增租户」接入开通函数，放到共用栈那一波。
- 产品介绍与帮助站本身，以及根域的跳转。
- 重命名 SLS Project `lychee-prod`。
- 为演示复制 khh 业务数据。
- 共用栈按 Host 只下发当前租户的 `env-config.js`。
