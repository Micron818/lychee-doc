# 01 — 现状与问题

## 1. 现行 PDF 链路

[01 §3](../20260818-report/01-技术选型评估.md) 收敛后的结论仍然是现网行为：单据版式只有一份，在服务端生成 PDF。前端不排版。

```text
业务 Service 组装打印数据
  → *PdfRenderer 把金额、日期、文案格式化进模型
  → PdfRenderSupport
       Thymeleaf（classpath templates/print/*-pdf.html，cacheable=true）
       openhtmltopdf-pdfbox 1.1.40
  → application/pdf
```

预览是同步字节流，例如 `GET /api/v1/scm/purchase-orders/{id}/pdf`（`Content-Disposition: inline`，权限 `:read`，不建作业、不落 OSS）。需要归档的单据另有 `*PdfExportHandler`，与预览共用同一个 Renderer。前端 `PdfBlobViewer` 用 iframe 显示，打印走 `iframe.contentWindow.print()`。

Excel 清单与模板套打走 Apache Fesod，与 PDF 引擎无关。导出作业的建作业、同步/异步分流、OSS、本人可见、`GET /file` 下载都不关心 PDF 字节从哪个库来。

## 2. 继续用 openhtmltopdf 做新报表的成本

引擎是 CSS 2.1 加分页，没有 Flexbox / Grid。现网模板已经为它写过专门规则：表头重复依赖 `-fs-table-paginate`，`overflow-wrap` 不生效，`white-space: nowrap` 按单个 inline 盒计算，图片用背景图居中，WebP 不能嵌入。销售订单报表的跨页 `rowspan` 不能靠 CSS 垂直居中，要在 `renderPaginatedPdf` 里按页拆合并格、再渲染多遍。

模板由 `ClassLoaderTemplateResolver` 从 classpath 读取，并且 `setCacheable(true)`。改 `src/main/resources/templates/print/*.html` 不会进正在跑的进程。Spring 的 `spring.thymeleaf.cache` 也不作用在这条引擎上。格式调整要重新打包资源并重启后端，还要有一笔真实单据数据才能看到分页。

本地单测可以不启 Spring、用样例 DTO 出 PDF，但那是回归手段，不是改版式的回路。浏览器直接打开同一份 HTML 也不能当验收：Chrome 的分页和 openhtmltopdf 不是同一套结果。

## 3. 部署约束

`lychee-infra/deploy/docker-compose.yml` 按约 4GB 主机编写：后端 `mem_limit: 1g`，且 `JAVA_TOOL_OPTIONS` 使用 `MaxRAMPercentage=70`。Chromium 是 JVM 外的进程，算进同一个 cgroup。在这个限额里加浏览器，会和堆抢内存。

因此新引擎不放进 `lychee-erp` 进程。主机先加大，PDF 服务使用自己的内存限额。后端容器维持现有量级。

## 4. 这次不改的部分

| 保持 | 原因 |
|------|------|
| 服务端 PDF 为唯一版式；禁止 `/print` 深链、`window.print()` 版式、`autoPrint` | [01 §3](../20260818-report/01-技术选型评估.md) 已去掉前后端双轨 |
| 预览 API 的路径、权限、`inline` PDF | 前端 `PdfPreview*` 已按 blob 接入 |
| 归档走 `DataExportHandler` + OSS + `GET /file` | [02](../20260818-report/02-导出框架总体设计.md) 与 [导出文件交付](../20260918-export-file-delivery/README.md) |
| Excel：`ExcelWriteSupport` / `ExcelTemplateWriteSupport` | 版式在 xlsx，不经过 HTML |
| 查询、`@TenantId`、混合币别/公司拒绝、空数据 `ValidationException` | PDF 服务看不到数据库 |
| 预览 `:read`、归档 `:export` | 权限模型不变 |
| 三语文案仍由后端 `MessageService` 按请求 locale 解析 | 模板不再各维护一套标签 |

## 5. 存量模板

下列文件仍由 openhtmltopdf 渲染，本设计不要求一次改写：

| 模块 | 模板 |
|------|------|
| scm | `purchase-order-pdf`、`purchase-requisition-pdf`、`outsource-order-pdf` |
| wm | `goods-receipt-pdf`、`stock-issue-pdf`、`physical-inventory-pdf` |
| sd | `delivery-note-pdf`、`delivery-billing-statement-pdf`、`sales-order-report-pdf` |
| pp | `factory-order-pdf` |
| fi | `payment-pdf` |

其中销售订单报表使用 `renderPaginatedPdf`。订购单、委外单、工厂订单的预览与归档共用 Renderer，并且都支持把多张单据合并成一份 PDF（`render(Set<Long> ids, …)`）。迁移时这个共用关系保留，只换渲染调用。委外单不是单张、无归档。
