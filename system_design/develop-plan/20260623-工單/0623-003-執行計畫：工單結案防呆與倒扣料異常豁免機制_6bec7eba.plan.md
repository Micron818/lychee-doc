# 執行計畫：工單結案防呆與倒扣料異常豁免機制

此計畫將實作標準 ERP 的工單結案（Close Order）防呆機制，包含倒扣料異常的豁免、零報工防呆、以及領料/入庫的容差檢核。

## 1. 資料庫與模型擴充 (Model & DB)
*   **`ProductionBackflushExceptionStatus`**: 新增 `CANCELLED` 狀態。
*   **`MaterialFactory`**: 
    *   新增 `under_issue_tolerance` (BigDecimal) 欄位，代表該物料在該工廠的預設發料容差百分比。
    *   新增 `under_delivery_tolerance` (BigDecimal) 欄位，代表該物料在該工廠的預設成品入庫容差百分比。
*   **`ProductionOrder`**: 新增 `under_delivery_tolerance` (BigDecimal) 欄位，代表成品入庫允許少交的容差百分比。
*   **`ProductionOrderComponent`**: 新增 `under_issue_tolerance` (BigDecimal) 欄位，代表發料允許少發的容差百分比。
*   **Liquibase**: 在 `db/changelog` 中新增 SQL 腳本以加入上述欄位。

## 2. 跨模組服務擴充 (Remote Service)
*   **`RemoteMaterialFactoryService`**: 在 `lychee-erp-common` 建立此介面，包含 `getMaterialFactory(Long factoryId, Long materialId)` 方法。
*   **`MaterialFactoryServiceImpl`**: 在 `lychee-erp-mm` 中實作該介面，回傳包含 `under_issue_tolerance` 與 `under_delivery_tolerance` 的 DTO，供生產模組取用預設值。

## 3. 工單與組件建立邏輯 (Defaulting Tolerance)
*   **`PlannedOrderServiceImpl.convertToProductionOrders` (BOM 展開)**: 
    *   建立 `ProductionOrder` 時，透過 `RemoteMaterialFactoryService` 取得母件物料的 `under_delivery_tolerance` 並帶入。
    *   建立 `ProductionOrderComponent` 時，透過 `RemoteMaterialFactoryService` 取得子件物料的 `under_issue_tolerance` 並帶入。
*   **`ProductionOrderServiceImpl.createProductionOrderComponent` (手動新增)**: 新增組件時，同樣取得預設的發料容差並帶入。

## 4. 倒扣料異常「豁免/取消」功能 (Exception Handling)
*   **`ProductionBackflushExceptionService` / `Impl`**: 實作 `cancelExceptions(Set<Long> ids)` 方法。將選定異常的狀態改為 `CANCELLED`，代表現場確實省料，不再追扣庫存。
*   **`ProductionBackflushExceptionController`**: 新增 `PUT /bulk-cancel` API，供前端介面呼叫。

## 5. 結案請求參數擴充 (Close Request)
*   **`ProductionOrderController`**: 將 `PUT /{id}/close` API 調整為接受 `forceClose` 查詢參數（`?forceClose=true`，預設 false），允許高權限人員在檢核不通過時強制結案。
*   **`ProductionOrderService`**: 調整 `closeProductionOrder` 方法簽章，加入 `boolean forceClose` 參數。

## 6. 工單結案核心檢核邏輯 (`ProductionOrderServiceImpl.closeProductionOrder`)
在 `closeProductionOrder` 方法中，依序實作以下防呆檢核（若 `forceClose = true` 則跳過 3 & 4）：

*   **Check 1: 報工單狀態檢核**
    *   查詢 `ProductionReportRepository`，若該工單有狀態為 `DRAFT` 的報工單，拋出例外阻斷結案（確保無在途報工）。
*   **Check 2: 異常佇列檢核**
    *   維持現有邏輯：若有 `PENDING` 的倒扣料異常則阻斷（`CANCELLED` 與 `RESOLVED` 可放行）。
*   **Check 3: 零報工與成品產出容差檢核**
    *   若 `completedQuantity == 0`：
        *   檢查所有 Component 的 `issuedQuantity` 總和。若 `> 0`，拋出例外：「已領用物料但無產出，請先辦理退料或報廢」。若 `== 0`，拋出例外：「無任何生產紀錄，請使用『取消工單』功能」。
    *   若 `completedQuantity > 0` 且 `< plannedQuantity * (1 - underDeliveryTolerance)`：
        *   拋出例外：「完工數量低於容差下限，不允許結案」。
*   **Check 4: 物料發放容差檢核 (Material Issue Check)**
    *   遍歷所有 `ProductionOrderComponent`。
    *   計算動態應發量：`expectedIssue = (completedQuantity / plannedQuantity) * requiredQuantity`。
    *   若 `issuedQuantity < expectedIssue * (1 - underIssueTolerance)`：
        *   拋出例外：「物料領用不足，不允許結案」。
*   **Check 5: 釋放預留 (Clear Allocations)**
    *   結案狀態更新為 `CLOSED` 後，呼叫 `rollbackFactoryOrderAllocation` 釋放 MRP 需求。
