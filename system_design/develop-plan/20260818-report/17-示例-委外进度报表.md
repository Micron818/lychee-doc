# 17 — 示例：委外进度报表（Outsource Order Progress Report）

> 编写日期：2026-11-08  
> 状态：**已实现（2026-11-08）**  
> 前置：导出框架（02）、Excel 模板填充（05）、工单进度模板双 Sheet（10 §7）已落地。本表**只做模板**，不做清单扁平行。

## 1. 目标与范围

从委外加工订单（`OutsourceOrder`）**列表工具栏**发起导出，按当前筛选条件导出该工厂、该供应商、该订单日区间内的委外单，产出带标题区、收回进度与备料明细的固定版式 Excel。

进度不在表头上。`OutsourceOrder` 只有工厂、供应商、订单日、状态和金额；订购 / 已收、需求日在收回件 `OutsourceOrderItem`，需求 / 已发 / 已耗在该行的 `OutsourceOrderComponent`。因此主表一行是一条收回件，备料跟着这条收回件走。

| 纳入 | 不纳入 |
|------|--------|
| 列表筛选驱动的多单 Excel；`ExcelTemplateWriteSupport` + 两张 Sheet | 单据 PDF / 预览打印 / `/print` |
| **强制**：单一 `factoryId` + 单一 `supplierId` + 订单日闭区间（`orderDate`） | 未选厂 / 未选供应商 / 订单日两端不齐时导出 |
| Sheet0：1 收回件 1 行 + 齐套汇总。Sheet1：该收回件的组件发料明细 | 清单类 `ExcelWriteSupport`、第二个「导出清单」按钮、第三张作业 |
| 标题写工厂、供应商、订单日期区间 | 主表再重复工厂列、供应商列；单价 / 税额 / 金额 |
| 逾期按收回件 `requiredDate` 派生，只作列 | 用 `requiredDate` 或 `plannedStartDate` 做筛选；`plannedStartDate` 列 |
| 列头 / 状态 / 是否 / 文件名随 `ctx.locale()` | 统计分析图表、邮件外发；草稿发料数量（`draftIssueQuantity`） |

作业管线（创建 / 同步·异步 / OSS / 导出中心）**零改动**。`ExcelTemplateWriteSupport.fill` 的按 `sheetNo` 重载已存在，本表直接复用。

**报表名称（三语）**

| locale | 名称 |
|--------|------|
| zh-CN | 委外进度报表 |
| en-US | Outsource order progress report |
| vi-VN | Báo cáo tiến độ đơn gia công ngoài |

**与工单进度报表的差异**

| 维度 | 10 工单进度模板 | **17 委外进度** |
|------|-----------------|-----------------|
| 数据 | `ProductionOrder` + 组件 | **`OutsourceOrder` 表头筛选；行 = `OutsourceOrderItem`；明细 = `OutsourceOrderComponent`** |
| 写入 | 清单与模板并存 | **仅模板** |
| 强制范围 | 单一工厂 + 计划开始/结束闭区间（窗口落在区间内） | **单一工厂 + 单一供应商 + 订单日闭区间**（`orderDate` 落在区间内） |
| 行粒度 | 1 工单 1 行 | **1 收回件 1 行**。无收回件的表头不出现 |
| 齐套排除 | 倒冲 `isBackflush`；欠发公差 `underIssueTolerance` | **供应商自备 `isSupplierProvided`**；无公差，`issued ≥ required` |
| 合计 | 计划 / 完工 / 报废加总 + 齐套 / 欠料工单数 | **只计行数**（齐套行、欠料行、逾期行）。订购 / 已收 / 需求 / 已发不加总 |
| 超限去向 | 明细超限时提示改用导出清单 | **无清单**。明细超限提示缩小订单日期区间 |

## 2. 业务决策（已确认）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 报表名词 | **委外进度报表** |
| 2 | 产出 | **只要 Excel 模板**；无 PDF |
| 3 | 入口 | `/scm/outsource-orders` 工具栏 **一个** `ExportButton`；不按勾选。`rowSelection` 仍只服务草稿批量删除 |
| 4 | 清单并存 | **不做**。组件超限时缩小筛选，不另开流式清单 |
| 5 | 强制筛选 | 单一工厂 + 单一供应商 + 订单日闭区间。列表浏览不强制；**仅点导出时**前后端双校验 |
| 6 | 日期字段 | 筛选用表头 `orderDate`。命中一张单则带出其**全部**收回件。逾期列用收回件 `requiredDate`，空需求日逾期为「否」 |
| 7 | 行粒度 | Sheet0：一行 = 一条收回件。同一张单多行时单号、订单日、表头状态重复，不做单元格合并 |
| 8 | 无收回件的表头 | 不出现在 Sheet0。`count == 0` 仍生成仅含标题和列头的空 xlsx |
| 9 | 状态 | 跟列表筛选项走，不硬排除 `DRAFT` / `CLOSED`。行上同时给表头状态和收回件状态：表头 `PARTIAL` 时，其下可以既有 `COMPLETED` 也有未完成行 |
| 10 | 齐套 | 按收回件汇总其组件。`isSupplierProvided = true` 不参与。无 `underIssueTolerance`，达标线为需求量本身 |
| 11 | 备料明细 | 同一 workbook 的 Sheet1，含全部组件（含供应商自备）。另给已耗、在外结存（已发 − 已耗）。结存不参与齐套 |
| 12 | 实物收货 | `requiresPhysicalReceipt` 做成「是/否」列。`false` 的中间半成品仍出一行（已收来自上层收货的虚拟入库） |
| 13 | 金额 | 不导出单价、税额、金额 |
| 14 | `plannedStartDate` | 实体有列，界面未维护。不做筛选、不做列 |
| 15 | 草稿数量 | 不导出 `draftIssueQuantity`；已发以组件上已过账的 `issuedQuantity` 为准 |
| 16 | 比率格式 | 完工率 / 齐套率 / 发料率均为**百分比文本、1 位小数**（`85.0%`）。分母为 0 则空 |
| 17 | 合计 | 齐套行数、欠料行数、逾期行数。禁止合计订购、已收、需求、已发、已耗 |
| 18 | `count` / 上限 | 按**收回件行数**卡 `template-max-rows`（默认 50,000）。组件行另见 §5.4 |
| 19 | 表结构 | **不改表**。无 Liquibase 增量 |

## 4. 数据模型与派生字段

### 4.1 行粒度

```
OutsourceOrder（列表筛选命中，含用户所选状态；工厂 / 供应商 / 订单日已在 params 中）
   └─ 0 条收回件  →  不出现
   └─ N 条收回件  →  Sheet0 N 行
         └─ 0 条组件  →  主表 1 行（备料状态 = 无需备料）；Sheet1 无对应行
         └─ M 条组件  →  Sheet1 M 行（含供应商自备）
```

### 4.2 逾期

收回件同时满足则为「是」，否则「否」：

1. `requiredDate != null` 且 `requiredDate < 导出当日`（`LocalDate.now()`，与工单进度相同）
2. 收回件 `status` 不在 `{COMPLETED, CLOSED}`

不按表头状态、不按 `orderDate`、不按 `plannedStartDate`。需求日为空为「否」。`DRAFT` / `ISSUED` / `PARTIAL` 可以逾期。

### 4.3 齐套（Sheet0，按收回件）

收回件实体没有备料汇总字段，由该行组件派生。禁止 `sum(issued) / sum(required)`。

**需发料组件**：`isSupplierProvided` 不为 `true`（`null` / `false` 计入）。供应商自备不参与齐套状态、齐套率、欠料项数；待发料查询 `pendingExplicitIssueComponentsSpec` 已是同一排除。

单行 **已齐套** 当且仅当：

1. `requiredQuantity` 为 null 或 `≤ 0`，或
2. `issuedQuantity ≥ requiredQuantity`

无欠发公差。`issuedQuantity`、`requiredQuantity` 为 null 时按 0。

收回件 **备料状态**：

| 条件 | 状态 | code |
|------|------|------|
| 需发料组件数 = 0（无组件，或全部供应商自备） | 无需备料 | `NONE` |
| 全部需发料行已齐套 | 已齐套 | `READY` |
| 存在需发料行，且没有任何一行 `issued > 0`，且并非全部已齐套 | 未备 | `NOT_STARTED` |
| 其他 | 部分 | `PARTIAL` |

判定顺序：无需备料 → 已齐套 → 未备 → 部分。需求量为 0 的行视为已齐套，故「全是 0 需求」归已齐套。

| 列 | 口径 | 无需备料时 |
|----|------|------------|
| kittingStatus | 上表四态 | 无需备料 |
| kittingRate | 已齐套需发料行数 / 需发料行数；百分比文本 1 位小数 | 空 |
| shortageLineCount | 需发料且未达 `issued ≥ required` 的行数 | 空 |

### 4.4 Sheet 列定义

**Sheet0 — 收回进度**（列表名 `items`）

标题已声明工厂和供应商，主表不含这两列。订单日仍在行上：标题是区间，各单的订单日不同。

| 列 | 来源 | 说明 |
|----|------|------|
| orderNo | `OutsourceOrder.orderNo` | |
| headerStatus | 表头 `status` 枚举翻译 | `enum.OutsourceOrderStatus.*` |
| orderDate | `orderDate` | `yyyy-MM-dd` |
| itemNo | `OutsourceOrderItem.itemNo` | |
| productMaterial | 收回件 `material.code - name` | |
| unit | 收回件 `unit.code - name` | |
| itemStatus | 收回件 `status` 枚举翻译 | 与表头状态分开 |
| orderedQuantity | `orderedQuantity` | |
| receivedQuantity | `receivedQuantity` | 含虚拟入库 |
| completionRate | 派生 | `received / ordered`；订购为 0 则空 |
| remainingQuantity | 派生 | `ordered - received` |
| requiredDate | `requiredDate` | `yyyy-MM-dd`；可空 |
| overdue | §4.2 | 是/否 |
| requiresPhysicalReceipt | 是/否 | `false` = 中间半成品，不入库 |
| kittingStatus / kittingRate / shortageLineCount | §4.3 | |
| remarks | 收回件 `remarks` | |

**Sheet1 — 备料明细**（列表名 `components`）

含该批收回件的**全部**组件（含供应商自备）。无组件的收回件不出现。

| 列 | 说明 |
|----|------|
| orderNo / itemNo / itemStatus / productMaterial | 关联键。`itemNo` 是收回件项次 |
| componentItemNo / componentMaterial / issueUnit | 组件项次、物料 `code - name`、发料单位 |
| requiredQuantity / issuedQuantity | 已过账数量 |
| issueRate | `issued / required`；需求为 0 则空 |
| pendingIssueQuantity | `required - issued`（超发为负，原样写出） |
| consumedQuantity | 收货按收回比例回写的已耗 |
| vendorBalanceQuantity | `issued - consumed`。供应商自备行常见已发为 0、已耗 > 0，结存为负，仍写出 |
| isSupplierProvided | **第一列**。列头「供应商自备」，红字。单元格是/否：是为红字，否为蓝字 |
| componentRemarks | |

明细 Sheet 不重复订购、已收、完工率、剩余、需求日、逾期、是否实物收货、齐套汇总。

供应商自备行的已耗仍会随上层收货按比例增加；在外结存只说明这一行的已发与已耗之差，不拿来判断齐套。

### 4.5 合计（仅 Sheet0）

只扫主表行：

| 合计 | 口径 |
|------|------|
| readyItemCount | `kittingStatus = READY` 的收回件行数 |
| shortageItemCount | `kittingStatus` 为 `NOT_STARTED` 或 `PARTIAL` 的收回件行数 |
| overdueItemCount | 逾期为「是」的收回件行数 |

`NONE` 既不算齐套行，也不算欠料行。Sheet1 不做数量合计。

### 5.2 查询规格

表头 spec 与 `OutsourceOrderServiceImpl.getOutsourceOrderPage` **同源**：

```java
Specification<OutsourceOrder> buildSpec(ExportContext ctx) {
    Specification<OutsourceOrder> spec =
        DynamicSpecifications.build(OutsourceOrder.class, ctx.params());
    Specification<OutsourceOrder> fetch =
        DynamicSpecifications.fetch("supplier");
    return spec.and(fetch);
}
```

- 强制条件已在 params 里，由 `DynamicSpecifications` 生效。`require*` 只负责「能否解析出单一工厂、单一供应商、两端订单日」，不另写一套 Specification。
- 单号、表头状态等其余列表条件照常叠加。
- 不按 `requiredDate` 过滤收回件。命中的表头带出全部收回件。
- 数据权限仍走 `OutsourceOrder` 上的工厂 `@Filter`，导出与列表可见范围一致。
- 无 `sort` 时与列表对齐：`orderNo DESC, id ASC`。收回件在单内 `itemNo ASC`，组件在收回件内 `itemNo ASC`。

### 5.2.1 强制导出条件

实现放在 `OutsourceProgressQuerySupport.requireFactorySupplierAndOrderDate`。`count` 与 `export` 都调用。解析规则对齐工单进度 `singleLong`：缺失、多值、逗号拼接均视为不单一。

| 维度 | 必填 | params 约定（与列表 `field_op` 一致） | 说明 |
|------|------|--------------------------------------|------|
| 工厂 | 是 | `factoryId` 或 `factoryId_eq`，单一值 | |
| 供应商 | 是 | `supplierId` 或 `supplierId_eq`，单一值 | |
| 订单日下界 | 是 | `orderDate_gte`（或 `orderDate_ge` / `orderDate` 的 between 下界） | `from` |
| 订单日上界 | 是 | `orderDate_lte`（或 `orderDate_le` / `orderDate` 的 between 上界） | `to` |

区间规则：

- `from`、`to` 都必须能解析；缺任一端 → 拒绝。
- `from > to` → 拒绝。
- 查询语义：`orderDate >= from` 且 `orderDate <= to`。这是**同一个字段**的闭区间。表头 `orderDate` 非空，不存在「日期为空被排除」的分支。

校验文案：

1. **前端** `beforeExport`：不满足 → `message.warning`（`pages.scm.outsourceOrders.export.requireFactorySupplierAndOrderDate`），不调用 `createExportJob`。
2. **后端**抛 `ValidationException`：
   - 工厂缺失或非单一：`validation.export.outsource_progress.factory.required`
   - 供应商缺失或非单一：`validation.export.outsource_progress.supplier.required`
   - 日期两端不齐或无法解析：`validation.export.outsource_progress.order_date.required`
   - `from > to`：`validation.export.outsource_progress.order_date.invalid_range`

列表搜索 UI：工厂列、供应商列保持现有单选（`buildFactoryColumn` / `buildSupplierColumn`）。新增搜索专用 `valueType: 'dateRange'`、`hideInTable` 的「订单日期」，`transform` 写出 `orderDate_gte` 与 `orderDate_lte`。表格内现有 `orderDate` 列保留展示，`search: false`，避免与区间控件并存。浏览列表不强制这三项。

### 5.3 `count`

```
templateCount = COUNT(OutsourceOrderItem)
    WHERE outsourceOrderId IN (列表 spec 命中的 OutsourceOrder.id)
```

按收回件行数，不按表头数。无收回件的表头贡献 0。用 Criteria 子查询一次 count，禁止先把全部表头 id 载入内存。

- 先 `requireFactorySupplierAndOrderDate`，再 count。
- `count == 0`：仍生成空模板（两 Sheet 均可无数据行），不报业务错误。
- `templateCount > template-max-rows`：抛 `validation.export.outsource_progress.template.rows.exceeded`，提示缩小订单日期区间或其它筛选。

### 5.4 写入、上限与明细截断

分页对象是表头（`batchSize` 按表头，默认 1000）。每批：`findAll` 表头 → `findAllByOutsourceOrderIdIn` 收回件 → `findAllByOutsourceOrderItemIdIn` 组件 → Assembler。

不包长 `@Transactional`。`SpecificationSliceQuery` 每批短只读事务；收回件和组件在同批内加载。接受批间微小不一致。

- 导出过程中收回件累计超过 `template-max-rows`：整单 FAILED，同一条 `template.rows.exceeded`。
- **组件行**累计超过 `template-max-rows`：**不**失败整份作业。Sheet0 照常；Sheet1 不填充数据行；标题区 `{componentOverflowLabel}` = 备料明细超过上限，请缩小订单日期区间。此后的批不再往明细列表追加。
- `ExportResult` 的行数报 **收回件行数**。

组件 fetch：`material`、`unit`。收回件 fetch：`material`、`unit`。表头 fetch：`supplier`。

标题在结果为空时也要能写出名称：工厂用 `BasisCacheService` 按 `factoryId` 解析 `code - name`；供应商按 `supplierId` 查 `Supplier` 得 `code - name`。有数据行时与列表显示一致。

### 5.5 Handler 行为

- `count` / `export` 入口先 `requireFactorySupplierAndOrderDate`。
- 每条收回件：`toItemRow(...)` → `items`；`toComponentRows(...)` → `components`（无组件则只有主表行）。
- 合计只扫 `items`（§4.5）。
- header：`factoryName`、`supplierName`、`dateRange`（`yyyy-MM-dd ~ yyyy-MM-dd`）、导出人、导出时间。标题区只放在 Sheet0。Sheet1 使用 `{componentSheetTitle}`，超限时另写 `{componentOverflowLabel}`。
- `fileName`：`export.outsource_progress.fileName` + `_yyyy-MM-dd.xlsx`。

```java
ExcelTemplateWriteSupport.fill(
    out,
    "excel/outsource-progress",
    header,
    List.of(
        new SheetFill(0, sheetName, Map.of("items", itemRows)),
        new SheetFill(1, componentSheetName, Map.of("components", componentRows或空))));
```

填充只按 `sheetNo`。fill 完成后由既有 Support 按 locale 改页签名（≤31 字符，禁止 `:*?/\[`）。

### 6.3 交互验收

1. 无 `export` 权限时按钮不渲染。
2. 未选单一工厂、未选单一供应商或订单日区间不齐：前端 warning，不发请求。直调 API 由后端 `ValidationException` 拒绝。
3. 三项齐全后导出：表头集合与列表在同一筛选下翻完的总集一致；每张命中表头的全部收回件都在 Sheet0；无收回件的表头不出现。
4. 只筛 `DRAFT`（且已满足三项）：导出这些草稿，不因状态被丢掉。
5. 表头 `PARTIAL`、其下收回件状态不一致：行上表头状态与收回件状态分别显示。
6. 无组件收回件：Sheet0 有行，备料状态为无需备料；Sheet1 无该行。
7. 供应商自备组件：不进欠料项数；Sheet1 仍有该行。该列在第一栏，列头红字；「是」红字，「否」蓝字。
8. 需求日为空：行仍在（只要表头订单日在区间内），逾期为「否」。
9. 收回件数超 `template-max-rows`：FAILED。组件数超限：主表有行，Sheet1 无数据行并出现缩小区间的文案。
10. 切换语言后列头、状态、是/否、备料状态、文件名随语言变化。

## 8. 测试要点

- `requireFactorySupplierAndOrderDate`：缺工厂、多工厂、逗号工厂、缺供应商、多供应商、缺日期一端、`from > to` 各抛对应 i18n。单一工厂 + 单一供应商 + 合法区间通过，并带回 `from` / `to`。
- Assembler 齐套：无组件 → 无需备料、齐套率空、Sheet1 无行；全部供应商自备 → 无需备料，明细仍含这些行；三行非自备均 `issued ≥ required`（含需求 0）→ 已齐套、欠料项数 0；一行已发 > 0、一行未发 → 部分；全部已发 = 0 且需求 > 0 → 未备。自备行不进欠料项数。
- 逾期：需求日为今天 → 否；昨天且 `ISSUED` → 是；`COMPLETED` / `CLOSED` 即使过期 → 否；需求日 null → 否。`DRAFT` 过期 → 是。
- 完工率：订购 0 → 空。剩余 = 订购 − 已收。发料率：需求 0 → 空。在外结存 = 已发 − 已耗，自备行已发 0、已耗 > 0 时为负。
- 无收回件的表头不产生主表行。`count` 等于收回件行数，不等于表头数。
- `usesExcelTemplate() == true`。收回件数超 `template-max-rows` 失败。组件数超限时主表有行、Sheet1 无数据行且 overflow 文案出现，作业仍成功。
- 主表无工厂列、无供应商列、无金额列、无 `plannedStartDate`。`requiresPhysicalReceipt = false` 的行仍在，且该列为「否」。
- 合计：两张各 3 个组件的收回件，齐套行数按收回件计（0/1/2），不按组件数乘。合计区没有订购或已收的加总。
- 集成：租户隔离；权限 `/scm/outsource-orders:export`；工厂数据权限外的单不出现。
