# 15 — 工厂订单 / 销售订单报表：型号列展示本款色字母 + 样图按色拆开

> 编写日期：2026-09-14

## 1. 目标与范围

接单确认 PDF（FO / SO）的 Model 列目前只印 `product_models.code`（如 `Z01139`），同款多色被 rowspan 合成一格。业务需要在型号列区分本款色字母，并让页脚样图与之对齐：

```text
现网：  Z01139          （同款 Black / White 共用一格、一张图）
目标：  Z01139-B        （Model 列 + 样图标签；尺码流水仍只在矩阵 Size 列）
```

| 纳入 | 不纳入 |
|------|--------|
| FO PDF、SO 报表 PDF 的 Model 列标签 | 改 `materials` DDL / 快照 `sku_code` |
| 同款多色不再跨色合并 Model 格 | 从 `materials.code` 拆码（`-B01`） |
| 页脚样图按 `(productModelId, colorId)` 各出一框 | 把尺码流水 `01` 拼进 Model |
| basis 共用拼码 / 取图 Helper | 改矩阵 `GroupKey`、改「先色后 PO」排序 |
| | 前端物料详情 / BOM 展开 / Excel 版 |
| | 改 HTML 模板列结构（仍打 `productModelLabel`） |

**推荐交付方式：同期一波上线（一个 PR）。** 型号列与样图共用本款色批量查询、同一套拼码、同一对 FO/SO 服务；拆成两波会把这两处各改两遍。若必须拆 PR，见 §7 备选分期。

## 2. 已锁定决策

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 色字母来源 | 读时 join `product_model_colors.sku_code`，键 `(product_model_id, color_id)` |
| 2 | Model 展示码 | `model.code` + 可选 `-" + sku_code`；再拼款名（沿用现网 `code + " " + name`） |
| 3 | 不分色 | 本款 0 行颜色，或行上 `colorId` 为空 → 仍为 `Z01139` |
| 4 | 有 `colorId` 但不在本款色池（OEM / 标品） | **不加**字母，避免伪造 `A–Z` |
| 5 | `productModelCode` DTO 字段 | **保持纯款号**；另加 `colorSkuCode`（可空）。Renderer 再拼 label |
| 6 | 矩阵分组 `GroupKey` | **不改**（现网已含 `colorId`，一色一行） |
| 7 | 行排序 | **不改嵌套**：款 → PO/订单 → 色。可在 `colorName` 前加 `colorSkuCode` 作稳定序 |
| 8 | Model rowspan | 由 `productModelId` 改为 `productModelId + colorId` |
| 9 | PO / 订单 / Color rowspan | **不变** |
| 10 | 样图粒度 | 由「每款一张」改为「每款每色一张」；无图仍空框 |
| 11 | 样图选图 | 该 `(model, color)` 下、本单出现过的 material 中，取 `materialId` 最小且 `isPrimary=true` 者（与现网同款策略一致，仅作用域缩到色） |
| 12 | 样图顺序 | 按**已排序矩阵行**首次出现的 `(productModelId, colorId)`，与表格阅读序一致 |
| 13 | 模板 | FO / SO HTML **零改**（label / `imageRows` / 每行 5 张 chunk 契约不变） |
| 14 | 模块边界 | 拼码与取图放 `lychee-erp-basis`；**不**让 PP/SD 依赖 `lychee-erp-mm.MaterialSkuCodes` |

版式示意（排序仍先 PO 后色；Model 不再跨色合并）：

```text
│ Z01139-A 款名 │        │ Black │ … │
│ Z01139-B 款名 │  PO-1  │ White │ … │
│ Z01139-A 款名 │  PO-2  │ Black │ … │
```

页脚：`[图 Z01139-A 款名] [图 Z01139-B 款名]`，不再一张 `Z01139` 代表全款。

## 4. 技术规格

### 4.1 basis：`ProductModelLabels`

新建 `com.lychee.erp.basis.support.ProductModelLabels`（纯函数，无 Spring）：

```text
SEP = "-"   // 与 MaterialSkuCodes.SEP 同值；此处只拼「款+色」，不含尺码

modelColorCode(modelCode, colorSku):
  blank(modelCode) → null
  blank(colorSku)  → modelCode
  else             → modelCode + "-" + colorSku

displayLabel(modelCode, colorSku, modelName):
  code = modelColorCode(modelCode, colorSku)
  若 code、name 皆有 → code + "\n" + name
  否则取非空者
```

两处 PdfRenderer 删除私有 `formatModelLabel`，改为 `ProductModelLabels.displayLabel(...)`。

单测（`lychee-erp-basis`）：

| 入参 | `modelColorCode` | `displayLabel` |
|------|------------------|----------------|
| `Z01139`, `B` | `Z01139-B` | `Z01139-B` 换行 `款名`（name 有值时） |
| `Z01139`, null/`""` | `Z01139` | `Z01139` 换行 `款名` |
| null, `B` | null | 仅 name |

### 4.2 本款色批量加载

两服务在已有 `productModelIds` 之后：

```text
if productModelIds 非空:
  rows = productModelColorRepository.findFetchedByProductModelIdIn(productModelIds)
  letterByModelColor = (productModelId, colorId) → skuCode
```

组装 `MatrixRow` 时：

```text
colorSkuCode = (productModelId != null && colorId != null)
    ? letterByModelColor.get(productModelId, colorId)
    : null
productModelCode = model.code          // 仍为纯款号
```

查找键建议用 record `ModelColorKey(Long productModelId, Long colorId)`（`colorId` 允许 null），FO/SO/Helper 共用，避免 `"id:id"` 字符串。

### 4.3 rowspan / 排序

FO `applyRowspans`（SO 把 `customerPoNo` 换成 `salesOrderId`）：

| 列 | 连续相等键（改后） |
|----|-------------------|
| productModel | `productModelId` **+ `colorId`** |
| customerPoNo / orderRef | 现网不变 |
| colorName | 现网不变 |

排序在 `colorName` 前插入 `colorSkuCode`（空串垫底）。**禁止**把色提前到 PO/订单之前。

同款同色、因交期 / 内部参号拆开的多行：Model 仍可 rowspan。同款不同色：各印 `Z01139-A` / `Z01139-B`。

### 4.4 样图：Helper 泛化 + 按色出框

将

```java
Map<Long, String> resolvePrimaryImageDataUris(Map<Long, List<Long>> productModelToMaterialIds)
```

改为（或等价重载后删除 Long 版；现网仅 FO/SO 两处调用）：

```java
<K> Map<K, String> resolvePrimaryImageDataUris(Map<K, List<Long>> keyToMaterialIds)
```

语义保持：按 map **插入序** 输出；每键在候选 materialId 中取最小且有 primary 者；无图 `null`；`filePath` 级 data URI 缓存去重。

调用方改为：

```text
keyToMaterials = LinkedHashMap<ModelColorKey, List<materialId>>
遍历 已排序 rows（非原始 facts）：
  skip productModelId == null
  key = ModelColorKey(productModelId, colorId)
  首次出现 → 登记候选顺序 + 空 list
  该行对应 facts 的 materialId 追加（去重）
```

注意：矩阵行本身不含 `materialId`。两种做法择一，推荐 **B**（少改 DTO）：

- **A**：`MatrixRow` 增加 `List<Long> materialIds`（组装分组时收集）
- **B**：分组阶段另建 `Map<GroupKey, List<Long>>` / 直接 `Map<ModelColorKey, List<Long>>`，排序后按 row 的 `(productModelId, colorId)` 取出并 **稳定合并**（同一色多 PO 共用一张图、material 并集后再选最小 id）

`ProductImage` 扩展：

```text
productModelId
colorId                 // 可空
colorSkuCode            // 可空
productModelCode        // 纯款号
productModelName
imageDataUri
```

Renderer 样图 `label` 与矩阵同一函数：`displayLabel(code, colorSkuCode, name)`。`chunk(..., 5)` 不变。

同款 8 色 → 最多 8 框（约 2 行）。可接受。OSS 图按 `filePath` 缓存，同色多 SKU 共用文件时不重复解码。

### 4.5 明确不做

- 不解析 `materials.code` 末位（不分色 `-01` vs 分色 `-A01`，款号还可能含 `-`）
- 不把 `product_size_group_items.sequence` / `product_model_size_codes.sku_code` 写入物料或 Model 列
- 不改 08/09 的入口、权限、纸张、数量口径


**可独立上线：否（相对现网）。** 没有中间态开关；不涉及 Liquibase。

## 7. 备选分期（仅当需要拆 PR）

| 波次 | 内容 | 单独上 | 代价 |
|------|------|--------|------|
| **P1** | Labels + 本款色加载 + Model 列 + rowspan + Renderer 矩阵 label | 可以 | 页脚仍是「每款一张、标签无 `-B`」，和表格短暂不一致 |
| **P2** | Helper 泛型 + 样图按色 + ProductImage 字段 + Renderer 图 label | 依赖 P1（需 `colorSkuCode` / Key） | FO/SO 服务再改一轮收集逻辑 |

不建议 P1 先改 `productModelCode` 为 `Z01139-B` 再在 P2 拆回：DTO 语义会抖。两波都走「纯款号 + `colorSkuCode`」。

若拆 PR：P1 合入后必须在发布说明写明「样图仍按款」，避免业务以为图也按色了。

## 9. 风险

| 风险 | 对策 |
|------|------|
| 样图从「每款 1 张」变为「每色 1 张」，PDF 变大、页数增加 | 按色才是业务目标；`filePath` 缓存；chunk=5 已换行 |
| Helper 签名变更漏改调用方 | 现网仅 2 处；改泛型后编译器兜住 |
| FO/SO 再次分叉 | Labels / Key / Helper 强制单点；禁止在 Renderer 里手拼 `code + "-" + sku` |
| 占用锁外改了本款字母 | 报表读当前主数据；已有变体物料时 V1 禁止改字母；单据链认的是物料 `code` 不是本列 |
