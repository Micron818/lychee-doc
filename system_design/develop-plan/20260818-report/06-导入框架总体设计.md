# 06 — Excel 资料导入框架总体设计

> 编写日期：2026-08-07  
> 前置：导出框架（[02](./02-导出框架总体设计.md)）已落地；Fesod 已引入（写路径成熟，读路径本专案启用）  
> 首例：[07 — 物料标准成本导入](./07-示例-物料标准成本导入.md)

目标：一次性建好可复用的「导入作业」基础设施，之后每个新主数据/配置类导入只需：后端加一个 Handler、前端加一个按钮 + 下载模板。

## 1. 需求边界

### 1.1 本期做

| 范围 | 说明 |
|------|------|
| **主数据 / 期间配置类 Excel 批量导入** | 用户下载系统模板 → 填数 → 上传 → 校验落库 |
| 统一作业模型 | 小文件同步、大文件异步；OSS 存源文件与错误报告 |
| 部分成功 | 成功行提交；失败行进错误报告，可下载修正后再导 |
| 权限 | `{menuPath}:import`（权限模型已内建 `import` action） |

### 1.2 本期不做

| 排除 | 理由 / 去向 |
|------|-------------|
| 单据 Excel 导入（PO/SO 等） | 关联校验更重，二期按需扩展同一 SPI |
| 前端解析 xlsx 再逐条调 create API | 绕过统一校验/审计/批处理 |
| 改写现有 `ImportButton` 语义 | 现有按钮服务「从他单/资料导入行」（FO←SO、AP←GR 等），与 Excel 主数据导入分流 |
| 整文件原子回滚 | 主数据导入更适合部分成功；财务原子导入可后续加 `ImportMode.ATOMIC` |

## 2. 总体流程

```
前端列表页 [Excel导入] (canAction(path,'import'))
   │  （可选）GET /api/v1/report/import-jobs/templates/{jobType} → 下载空模板
   │  Upload xlsx
   │  POST /api/v1/report/import-jobs  multipart: file + jobType + options
   ▼
ImportJobService.create()
   ├─ 权限校验（Handler.requiredAuthority）
   ├─ 文件校验：扩展名 .xlsx、Content-Type、大小 ≤ max-file-size
   ├─ 落库 PENDING 作业 + 上传源文件 → OSS {tenantCode}/imports/.../_src.xlsx
   ├─ 轻量预扫行数（或创建时暂估；超 max-rows 直接 FAILED）
   ├─ ≤ sync-threshold：请求内同步执行 → 响应 COMPLETED（含成功/失败计数）
   └─ >  sync-threshold：发布 ImportJobCreatedEvent（tenantId + Authentication）
                      │
                      ▼  @Async("importTaskExecutor") + @TransactionalEventListener(AFTER_COMMIT)
                 ImportJobEventListener
                      ├─ 设置 TenantContextHolder / SecurityContext
                      ├─ status → RUNNING
                      ├─ 从 OSS 拉源文件 → Handler.importData(ctx, in)
                      │     ├─ ExcelReadSupport 流式读 + 批处理
                      │     ├─ 行映射 / 校验 / 调领域 Service
                      │     └─ 失败行写错误报告 xlsx → OSS
                      ├─ status → COMPLETED（success/failed/total + 路径）
                      ├─ 异常：status → FAILED（error_message 截断 500）
                      └─ finally 清理两个上下文
   ▲
前端 useImportJob：同步完成 → Modal/通知展示结果；有失败则提供错误报告下载
                 异步 → 通知「处理中」+ 轮询；完成后同样展示；可到「导入中心」查看历史
```

与导出的对称点：作业表、SPI、同步/异步分流、租户/安全上下文、OSS + 签名 URL、本人可见。  
差异点：入口是 **上传文件**；结果物是 **计数 + 可选错误报告**（不是业务数据导出文件）。

## 5. Handler SPI

```java
package com.lychee.erp.common.dataimport;

public interface DataImportHandler {

    ImportJobType type();

    /** 权限串，与前端菜单路径对齐，如 "/fi/material-costs:import" */
    String requiredAuthority();

    /** 导出行 DTO 类型（Fesod 注解绑定） */
    Class<?> rowType();

    /**
     * 写入空模板（仅列头 + 可选说明 Sheet / 示例行）。
     * 列头按 locale 经 MessageService 解析 i18n key。
     */
    void writeTemplate(OutputStream out, Locale locale);

    /**
     * 从 source 流式导入。实现应委托 ExcelReadSupport，避免整表进内存。
     * 返回成功/失败计数；若有行失败，应通过 ImportResult 携带错误报告字节或由框架根据错误列表统一写报告。
     */
    ImportResult importData(ImportContext ctx, InputStream source);
}

public record ImportContext(
    Map<String, Object> options,   // mode=UPSERT|CREATE_ONLY 等
    Locale locale,
    Long tenantId,
    String tenantCode,
    int batchSize,
    int maxRows
) {}

public record ImportResult(
    int totalRows,
    int successRows,
    int failedRows,
    List<ImportRowError> errors     // 框架据此生成错误报告 xlsx；空则无报告
) {}

public record ImportRowError(
    int rowIndex,                   // Excel 行号（含表头时从 2 起）
    String businessKey,             // 便于用户定位，如物料编码
    String message                  // 已按 locale 翻译或 i18n key 解析后文本
) {}

public enum ImportMode {
    CREATE_ONLY,
    UPSERT
}
```

### 5.1 `ExcelReadSupport` 骨架

```java
public final class ExcelReadSupport {
    /**
     * 流式读取 sheet0：校验列头与期望列一致 → 每批 batchSize 行调用 consumer。
     * 超 maxRows 抛 ValidationException。
     * consumer 返回本批行级错误（可空）；Support 汇总后交给框架写错误报告。
     */
    public static <T> ImportResult readPaged(
        InputStream in,
        Class<T> rowType,
        List<String> expectedHeaders,          // 已按 locale 解析的列头文本
        ImportContext ctx,
        BatchConsumer<T> consumer
    );
}
```

要点：

- 使用 `FesodSheet.read(in, rowType, listener).sheet().doRead()` + `PageReadListener` / 自管批缓冲。
- **列头校验**：模板下载与导入使用同一套 i18n key → `MessageService` 按作业 `locale` 解析；用户改列名/删列 → 作业级 FAILED（非行级）。
- **列序绑定**：行 DTO 使用 `@ExcelProperty(index = n)`，不依赖用户改过的列名做字段映射；列头校验只保证「模板未被破坏」。
- 空行跳过；全空文件 → FAILED（`validation.import.empty_file`）。

### 5.2 错误报告生成

框架层（report）在 Handler 返回后：

1. 若 `errors` 非空：用 Fesod 写 `错误报告.xlsx`——复制源文件关键业务列（或按同一 Row DTO 回写失败行）+ 追加「错误信息」列；上传 OSS。
2. 一期简化：**仅输出失败行 + 错误信息**（不必整表回写），文件名如 `{原名}_errors.xlsx`。
3. `ImportJob.error_report_file_*` 填值；前端提供下载。

### 5.3 领域落库约定

- Handler **必须**调用领域 `*Service.create/update`（或专门的 `importUpsert`），禁止直接 `repository.save` 绕过校验。
- 若现有 create/update 对批量不友好（如每次 reload 富化），可在 Service 增加包内/接口级 `upsertForImport(...)`，仍集中业务规则。
- 每批短事务（`batchSize` 默认 100）：单行失败不回滚整批已成功行；批内可用 `REQUIRES_NEW` 按行提交，或收集异常后继续——由 Handler 选择，框架不强制。

## 6. 异步执行与上下文传递

与 [02 §5](./02-导出框架总体设计.md) / MRP 逐字对齐：

```java
// ImportJobServiceImpl.create —— 事务内保存作业 + 上传源文件后
if (estimatedRows <= importProperties.getSyncThreshold()) {
    executeImport(jobId);   // 同请求线程
} else {
    eventPublisher.publishEvent(
        new ImportJobCreatedEvent(jobId, CurrentTenant.tenantId(), authentication));
}

// ImportJobEventListener
@Async("importTaskExecutor")
@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
public void handle(ImportJobCreatedEvent event) {
    SecurityContextHolder.getContext().setAuthentication(event.authentication());
    try {
        TenantContextHolder.setTenantId(event.tenantId());
        importJobService.markRunning(event.jobId());
        importJobService.executeImport(event.jobId());
    } catch (Exception e) {
        importJobService.markFailed(event.jobId(), e.getMessage());
    } finally {
        TenantContextHolder.clear();
        SecurityContextHolder.clearContext();
    }
}
```

线程池独立：`importTaskExecutor`（建议 core=2, max=4, queue=20, AbortPolicy），**不与** `exportTaskExecutor` 共用，避免导出/导入互相挤占。

同步快路径：行数 ≤ `lychee.import.sync-threshold`（默认 **500**，低于导出——写库更重）时请求内执行完，响应即 `COMPLETED`。

## 7. REST API（`/api/v1/report/import-jobs`）

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/templates/{jobType}` | Handler.`requiredAuthority` | 生成空模板；`Content-Disposition` 附件下载（可同步直出，或上传临时 OSS 签发 URL；一期 **同步直出字节流** 即可，模板很小） |
| POST | `/` | Handler.`requiredAuthority` | `multipart/form-data`：`file` + `jobType` + `options`（JSON 字符串，含 `mode`） |
| GET | `/{id}` | `/report/import-jobs:read` | 轮询；默认仅本人（ADMIN 全租户） |
| POST | `/page` | `/report/import-jobs:read` | 导入中心列表 |
| GET | `/{id}/source-url` | `/report/import-jobs:read` + 重验业务 import 权限 | 源文件签名 URL（5 分钟） |
| GET | `/{id}/error-report-url` | 同上 | 错误报告签名 URL；无报告则 404/业务错误 |
| DELETE | `/bulk-delete` | `/report/import-jobs:delete` | 删记录 + OSS 源文件/错误报告；RUNNING 不可删 |

访问控制对齐导出中心加固策略：默认仅创建人可见；下载前按 `jobType` 重验 Handler 业务 `import` 权限；下载留审计日志。

## 9. 配置项

```yaml
lychee:
  import:
    sync-threshold: 500          # 同步/异步分流行数
    max-rows: 50000              # 单作业行数上限
    max-file-size-mb: 10         # 上传文件大小
    batch-size: 100              # 写库批大小
    retention-days: 30           # expires_at + OSS 生命周期
    download-url-expiration-seconds: 300
    executor:
      core-size: 2
      max-size: 4
      queue-capacity: 20
```

基础设施（`lychee-infra`）：OSS 生命周期规则为前缀 `*/imports/`（或统一 `imports/` 二级前缀）配置 30 天过期，与 `retention-days` 对齐。

Spring 上传限制需同步放宽（若全局默认过小）：

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 10MB
      max-request-size: 12MB
```

## 10. 列头国际化约定（强制）

| 规则 | 说明 |
|------|------|
| 模板列头 | `@ExcelProperty` / 模板生成时使用 **i18n key**，经 `MessageService` 按 locale 解析 |
| 导入校验 | 作业记录 `locale` = 用户上传时的 UI 语言；用同一 locale 解析期望列头并与文件首行比对 |
| 字段绑定 | **按 index**，不按列名字符串匹配业务字段 |
| 跨语言 | 用户须使用「当前语言下下载的模板」；用英文模板在中文界面上传会因列头校验失败——产品文案需提示 |

说明 Sheet（可选）：第二 sheet 写字段说明、枚举取值、业务键规则（纯文本，不参与解析）。

## 11. 安全与多租户

1. 异步线程显式传递 `tenantId` + `Authentication`，`finally` 双清理。  
2. Handler 内查询/写入一律走带 `@TenantId` 的 JPA / 领域 Service。  
3. 创建与下载均校验业务 `import` 权限。  
4. 作业默认仅本人可见（`ROLE_ADMIN` 例外）。  
5. 源文件与错误报告均短时效签名 URL，不落长效链接。

## 13. 风险与对策

| 风险 | 对策 |
|------|------|
| 大文件内存溢出 | Fesod 流式读 + 批处理；`max-rows` / `max-file-size` 双上限 |
| 部分成功导致数据不一致观感 | 结果明确展示成功/失败数；错误报告可修正重导（UPSERT 幂等） |
| 模板列头被用户改坏 | 严格列头校验，失败信息指向「请重新下载模板」 |
| 导入写库拖垮 DB | 独立线程池 + 小 batchSize + 行数上限 |
| 与单据 ImportButton 混淆 | 组件命名分流 + 文档/文案使用「Excel 导入」 |
| 异步租户串数据 | 复制导出/MRP 上下文传递范式；集成测试覆盖 |
