# 03. 数据模型与版式

> 本波 **不建表、不改** `outsource_orders` / `outsource_order_items` / `outsource_order_components`。只定义打印 DTO 与 PDF 版式。  
> 改版式、列宽、分页、样品区时以本章为准，尤其是 [§6](#6-版式维护)。

一份 PDF 对应一张 `order_no`。读者是加工厂商。纸上是订购约定：收回什么、加工价、本厂送来哪些料、厂商自己备哪些料、成品长什么样、表头备注。执行中的已收、已发、已耗不印在这张单上。

---

## 1. 无新表

委外加工单是委外订单的只读打印投影。

复用：

```
outsource_orders
outsource_order_items
outsource_order_components
factories / companies / company_texts     // 抬头
suppliers                                 // 加工厂商
fi_payment_terms                          // 付款条件，有值才印
materials / material_units
product_models / product_model_colors / product_model_images
material_images                           // 无型号时的样品图回退
users                                     // 制单 createdBy
```

预览 `GET /api/v1/scm/outsource-orders/{id}/pdf`（`/scm/outsource-orders:read`，inline，不建作业）。  
归档下载对齐采购订单：`ExportJobType` + `*PdfExportHandler`（`/scm/outsource-orders:export`）。打印件与归档件走同一个 Renderer。  
前端：列表操作列 + 详情抽屉「打印」，原页 `PdfPreviewModal`。禁止 `/print` 深链、前端 HTML 版式、`autoPrint`、对外 `print-data`。

## 2. 查询关联

```
OutsourceOrder（id）
  ├─ factoryId → Factory.name + companyId → Company / CompanyText
  ├─ supplierId → Supplier（code / name / addressLocal|addressEn / contact*）
  ├─ currencyOptionId → 币别 code
  ├─ paymentTermId → 付款条件名称（可空）
  ├─ orderNo / orderDate / status / remarks / createdBy
  ├─ billingAddress                     // 开单快照；信息区整行
  ├─ shippingAddress                    // 开单快照；与工厂同一行，不回退工厂地址
  ├─ subtotalAmount / taxAmount / totalAmount
  └─ OutsourceOrderItem[]（按 item_no）
        ├─ materialId → Material（code / name / specification / productModelId / colorId）
        ├─ unitId → Unit
        ├─ orderedQuantity / unitPrice / taxRate / subtotalAmount / requiredDate / remarks
        └─ OutsourceOrderComponent[]（按 item_no）
              ├─ materialId → Material（code / name / specification）
              ├─ unitId → Unit
              ├─ requiredQuantity / isSupplierProvided / remarks
              └─ issuedQuantity / consumedQuantity   // 读出来也不进模板
```

无收回件 → 校验错误，不渲染空表。组件可以没有。

## 3. 打印数据模型

`OutsourceOrderPrintResponse`（一次性返回、名称已解析；不对外 REST）：

```java
    // 规则与 PurchaseOrderPrintServiceImpl.letterheadField 相同。
    String companyName;                 // 没有则不印
    String companyNameVi;              // 没有则不印
    String companyAddress;             // 仍组装，模板不印
    String companyAddressVi;           // 仍组装，模板不印
    String companyPhone;
    String companyEmail;                // 可空；有值才印
    String companyTaxId;                // 仍组装，模板不印
    String companyLogoDataUri;          // 可空

    Long id;
    String orderNo;
    LocalDate orderDate;
    String status;                      // 仍组装，模板不印
    String statusLabel;                 // 仍组装，模板不印
    boolean draft;                      // status == DRAFT → 水印
    String factoryName;
    String shippingAddress;             // outsource_orders.shipping_address；空白收成 null
    String billingAddress;              // outsource_orders.billing_address；空白收成 null
    String currencyCode;                // 页眉币别；金额格式也用它

    String remarks;                     // 表头备注；空白收成 null

    String supplierCode;
    String supplierName;

    String supplierContactPerson;
    String supplierContactPhone;        // contactPhone，空则 phone
    String supplierContactEmail;        // contactEmail，空则 email

    BigDecimal subtotalAmount;

```

```java
public static class Item {
    int itemNo;                         // outsource_order_items.item_no 原值
    String materialCode;
    String materialName;
    String materialSpec;                // 可空
    String unitName;
    BigDecimal orderedQuantity;
    BigDecimal unitPrice;
    BigDecimal taxRate;                 // 可空
    BigDecimal subtotalAmount;          // 行不含税金额，模板上的「金额」
    LocalDate requiredDate;             // 可空
    String remarks;                     // 行备注；空白收成 null
}

public static class SupplyBlock {
    int itemNo;
    String materialCode;
    String materialName;
    List<SupplyLine> issueLines;        // isSupplierProvided = false 且 requiredQuantity > 0
    List<SupplyLine> vendorLines;       // isSupplierProvided = true 且 requiredQuantity > 0
}

public static class SupplyLine {
    int itemNo;                         // 组件 item_no 原值，不重编
    String materialCode;
    String materialName;
    String materialSpec;
    String unitName;
    BigDecimal requiredQuantity;
    String remarks;
}

public static class ProductImage {
    String label;                       // 已含换行，模板只 th:text
    String imageDataUri;               // 可空
    boolean hasImage;
}
```

Renderer 预格式化日期、数量、单价、金额、税率。模板只做 `th:text` / `th:if` / `th:each` / `th:style`。  
数量：`new DecimalFormat("#,##0.######", DecimalFormatSymbols.getInstance(Locale.US))`。  
单价：`MoneyFormatSupport.unitPriceFormat(currencyCode)`。金额：`MoneyFormatSupport.moneyFormat(currencyCode)`。跟单据币别，不跟界面语言。  
税率印成 `12%` 这种文本；`taxRate == null` 时格子留空。

**不进模板的字段**（Service 可以不组装进上述列表）：`exchangeRate`、`receivedQuantity`、`issuedQuantity`、`consumedQuantity`、草稿发料量、可发量、`plannedStartDate`、`requiresPhysicalReceipt`、超收容差、行状态、仓库、批次、成本、组件图。

## 4. 明细与样品组装

### 4.1 收回件

一行 = 一条 `OutsourceOrderItem`，按 `item_no` 升序。不按物料、型号、颜色合并。项次印表上的 `item_no`，不从 1 重编。

行备注印在物料名称下方，不并进表头备注栏。

### 4.2 本厂发料

`is_supplier_provided = false` 且 `required_quantity > 0` 的组件。这是订购约定的应发数量，不是已经发出的数量。

同一收回件的发料行按组件 `item_no` 升序。应发量为 0 或空的行跳过。一个收回件若跳完后没有发料行，就不产出发料小表。

### 4.3 厂商自备

`is_supplier_provided = true` 且 `required_quantity > 0`。数量是厂商应自行备齐的量，不写成「应发」。没有这样的行就不产出自备小表。

自备行禁止写进发料小表。两张小表标题不同，避免被看成我方送料。

### 4.4 样品图

样品只取收回件，不取组件。

| 收回件物料 | 一张图的键 | 标签 |
|------------|------------|------|
| `productModelId != null` | `(productModelId, colorId)`，同一型号同一色只留一张，按收回件首次出现 | `ProductModelLabels.displayLabel(型号, 色号 sku, 型号名称)`，两行 |
| `productModelId == null` | 该 `materialId` 单独一张 | `{materialCode}\n{materialName}` |

取图调用 `MaterialImageHelper.resolvePrimaryImageDataUris`：型号色先 `product_model_images` 主图，没有再退回候选物料里 id 最小的那张 `material_images` 主图。无型号的收回件用 `materialId` 做 key。禁止用 `ModelColorKey(null, null)`，否则没有型号的收回件会并成一张图。

没有图也输出空框和标签（`hasImage = false`）。图片在 Service 里转成 data URI。OpenHTMLToPDF 不抓外链。WebP 嵌不进 PDF 时该格留空框，标签仍印。

### 4.5 表头备注

`outsource_orders.remarks` 去掉空白后为空则视为没有备注。它只出现在样品区右侧，不在合计下面再印一行。

## 5. PDF 版式

模板：`lychee-erp-scm/src/main/resources/templates/print/outsource-order-pdf.html`  
Renderer：`OutsourceOrderPdfRenderer`  
共用：`PdfRenderSupport`、`StorageImageHelper`（公司 logo）、`MaterialImageHelper`（样品图）。

纸张 **A4 纵向**，对齐采购订单：

```css
@page {
    size: A4 portrait;
    margin: 14mm 12mm 16mm 12mm;
}
```

可用内容宽约 186mm（约 527pt）。字体 `Noto Sans`, `Noto Sans SC`。正文 9pt。页码在 `@bottom-center`：`counter(page) ' / ' counter(pages)`，8pt。不印列印账号。

`DRAFT` 水印对齐采购订单：约 `top: 45mm; left: 25mm`，文案 `print.outsource_order.draftWatermark`。其他状态无水印，仍可补打；补打的数量仍是订购量与应发量。

阅读顺序固定为下面八块。调整时不要改这块的先后，除非同时改 [§6](#6-版式维护)。

### 5.1 页眉

对齐采购订单抬头，不印公司地址、公司税号、单据状态。

- 左：logo（可空，有值才占 `logo-cell`）。公司名称先中文、下一行越南文，各一行。某一语等于该公司 `source_locale` 时用主表；否则只用 `company_texts` 里该语言的非空译文，没有则不印该行。与本次打印的界面语言无关
- 右：标题 `print.outsource_order.docTitle`，约 14pt、`letter-spacing: 2pt`、`white-space: nowrap`。其下单号（加粗）、订单日
- 底行：左侧电话、邮箱，有值才印。右侧币别与打印时间（`yyyy-MM-dd HH:mm`）同一行靠右。标签和值放进同一个 `white-space: nowrap` 的元素里，不要拆成相邻 `<span>` 再套 nowrap（OpenHTMLToPDF 按每个 inline 盒子算最小宽度，会把「打印时间」和时刻拆成两行）

### 5.2 信息区

四列网格对齐采购订单信息区。可空项用 `th:if` 摘掉。

| 行 | 内容 |
|----|------|
| 1 | 加工厂商 `code - name`（占左半）｜联系人（占右半） |
| 2 | 电话｜邮箱 |
| 3 | 厂商地址，整行 |
| 4 | 账单地址，整行。对齐采购订单 |
| 5 | 付款条件。无值则整行不出现 |
| 6 | 工厂约 1/4，配送地址约 3/4。同一行，对齐采购订单 `.factory-inline` |

账单地址只印 `outsource_orders.billing_address`，配送地址只印 `outsource_orders.shipping_address`。空白时标签仍印、值留空，不回退公司地址、工厂主数据或厂商地址。工厂名 `white-space: nowrap`，右侧留白后接配送地址；两处地址都允许换行。

不印厂商税号、汇率。

### 5.3 收回件表

一张 `table.items-table`。列序：

| 项次 | 物料编码 | 物料名称 | 数量 | 单位 | 单价 | 税率 | 金额 | 需求日 |
|------|----------|----------|------|------|------|------|------|--------|

- 项次、单位、需求日居中。数量、单价、税率、金额右对齐
- 物料名称格：主行 `materialName`；其下 `materialSpec`（class `item-sub`，可空）；再其下 `remarks`（class `item-remarks`，可空）
- 金额 = 行 `subtotalAmount`（不含税）
- `-fs-table-paginate: paginate`，`thead` 每页重复
- `tbody tr { page-break-inside: avoid; }`，给每行稳定的 `id`（例如 `oo-item-{itemNo}`），避免一行被从名称中间切开
- 表内只有收回件。发料行、自备行、样品图都不进这张表

### 5.4 合计

紧跟收回件表，右对齐小表，三行：小计、税额、合计。合计行加粗。  
合计用表头金额，不在模板里对行金额求和。  
这一块放在用料附录之前。用料很长时，价税仍留在收回件表后面，不要被发料行推到文末。

### 5.5 用料附录

放在合计之后、样品区之前。按收回件 `item_no` 顺序。一个收回件的发料与自备都空时，整段不出，也不印「无需发料」。

每一段两张小表，各自独立，标题只写在该表 `thead` 里，不要在表外再放一行相同文字。

1. 发料小表 `table.issue-table`，仅 `issueLines` 非空时输出。`thead` 第一行 colspan：`{issueTitle} · 项次 {itemNo} {materialCode} {materialName}`。第二行是列名：项次、物料编码、物料名称、单位、应发数量。名称下印规格与备注，样式同收回件
2. 自备小表 `table.vendor-table`，仅 `vendorLines` 非空时输出。`thead` 第一行 colspan：`{vendorTitle} · 项次 {itemNo} {materialCode} {materialName}`。列与发料相同，但数量列表头是 `print.outsource_order.vendorQuantity`（数量），不是「应发数量」

两张小表都：

- `-fs-table-paginate: paginate`。标题行留在 `thead`，续页重复，才能看出这是哪一条收回件的料
- 标题行 `page-break-after: avoid`，避免只剩标题落在页尾
- 数据行 `tr { page-break-inside: avoid; }`
- 字号可以降到 8pt，线用 0.5pt 实线
- 不要对小表设 `page-break-inside: avoid`。组件很多时整表高过一页，设在 table 上会把行从中切开或顶出页边

### 5.6 样品图与表头备注

结构对齐工厂订单 `factory-order-pdf.html` 的 `.media-row`：有图或有表头备注才输出整张表；缺的一侧整列不出现。

```html
<table class="media-row" th:if="${hasImages or hasRemarks}">
  <tr>
    <th th:if="${hasImages}">产品样图</th>
    <th th:if="${hasRemarks}" class="media-remarks-side">备注</th>
  </tr>
  <tr>
    <td class="media-cell" th:if="${hasImages}">…图…</td>
    <td class="media-cell remarks-text" th:if="${hasRemarks}">表头备注</td>
  </tr>
</table>
```

外层 `hasImages` / `hasRemarks` 由 Renderer 放进模型（boolean）。模板里不要写 `${a or b}` 这种把可能为 null 的字符串放进 SpEL `or`。

图区是内嵌 `table.images-table`（`width: auto`，不要 `table-layout: fixed`）。Renderer 按 **每行 3 张** 切 `imageRows`。单元格宽 96pt，图框 90pt × 70pt。

```css
.media-row tr,
.images-table tr { page-break-inside: avoid; }

.media-remarks-side { width: 180pt; }

.remarks-text {
    white-space: pre-wrap;
    word-wrap: break-word;
    vertical-align: top;
}

.img-box {
    width: 90pt;
    height: 70pt;
    border: 0.5pt solid #999999;
    background-repeat: no-repeat;
    background-position: center center;
    background-size: contain;
}

.img-label {
    width: 90pt;
    margin-top: 2pt;
    font-size: 7pt;
    white-space: pre-line;
    word-wrap: break-word;
}
```

图本身用 div 的背景，不用 `<img>`：

```html
<div class="img-box"
     th:style="${img.hasImage} ? 'background-image:url(' + ${img.imageDataUri} + ')' : ''"></div>
<div class="img-label" th:text="${img.label}"></div>
```

`<img>` 配 `line-height` 做垂直居中时，高图会被裁掉；`table-layout: fixed` 且列宽没写死时，背景图会塌成 0 宽。

备注栏 180pt 是按纵向 A4 算的。3 × 96pt = 288pt，加上备注 180pt，仍落在约 527pt 的内容宽里。工厂订单是横向，备注栏 260pt、每行 5 张，不要把那两个数字抄到本模板。

只有备注、没有图时，备注格占满整行，不保留 180pt。只有图、没有备注时，仍然每行 3 张，不临时改成 4 张或 5 张。

### 5.7 签核

样品区之后。从左到右：核准（空线）、审核（空线）、制单（`createdByName` + 线）。对齐采购订单。  
`page-break-inside: avoid` 设在签核表上。不印列印账号，不在签核行再印打印时间（已在页眉）。

### 5.8 文件名

```
{print.outsource_order.fileName}_{orderNo}.pdf
```

`orderNo` 做文件名安全截断（同销售订单报表的字符过滤）。`fileName` 与 `docTitle` 分开，标题可以带字距，文件名不要带空格。

| locale | docTitle | fileName |
|--------|----------|----------|
| zh-CN | 委外加工单 | 委外加工单 |
| en-US | OUTSOURCE ORDER | OutsourceOrder |
| vi-VN | ĐƠN GIA CÔNG NGOÀI | DonGiaCongNgoai |

## 6. 版式维护

改模板前先对一下下面几条。这些是 OpenHTMLToPDF 1.1.40 上已经踩过的坑，不是风格偏好。

| 想改的地方 | 要一起看的地方 |
|------------|----------------|
| 纸张改为横向，或改页边距 | 重算内容宽。样品每行张数 × 96pt + 备注栏宽必须小于内容宽。纵向现在是 3 张 + 180pt |
| 图框改尺寸 | 同步改 `.img-box`、`.images-table td`、`.img-label` 的宽度，再重算每行张数 |
| 每行改成 4 张或 5 张 | 纵向 A4 放不下「4 × 96pt + 180pt 备注」。要么减备注栏，要么改纸张，要么改成上下堆叠并在这里写明 |
| 把发料行嵌进收回件表的同一个 `<tr>` 或 `rowspan` | 不要。续页重复的 `thead` 会变成单价表头；`rowspan` 跨页时字会沉到底部或被裁掉。发料保持独立小表，标题放进该表 `thead` |
| 给 `.issue-table` / `.supply-block` / `.images-table` 加 `page-break-inside: avoid` | 不要加在 table 上。只加在 `tr` 上。表高过一页时，加在 table 上会把图或行从中间切开 |
| 样品改回 `<img>`，或给图区 `table-layout: fixed` | 图会顶对齐、被裁，或整格宽度变成 0。保持 div 背景 + `background-size: contain` + 内表 `width: auto` |
| 备注改成「标签 `<span>` + 正文 `<span>`」并给外层 nowrap | 打印时间、币别会折行。整段不可断的文字放进一个元素 |
| 表头备注同时印在合计下方和样品区 | 只留样品区右侧。没有样品时右侧备注格自动拉满，不需要第二处 |
| 补上已发、已耗、已收、仓库、批次 | 那是进度报表和发料单的口径。写进本 PDF 后，补打会和已交给厂商的约定数量不一致 |
| 厂商自备并进发料表，只加一个勾 | 自备会被看成我方送料。保持两张小表、两个标题 |
| 在 Thymeleaf 里写 `${remarks or hasImages}` | `remarks` 是字符串时 SpEL 直接失败。布尔先在 Renderer 算好 |

收回件表、发料小表的列宽用 `colgroup` 写死百分比或 pt，不要靠内容把「金额」列撑开后把「需求日」挤出页边。物料名称列允许换行（`word-wrap: break-word`）。编码列可以略窄，长编码换行，不要 `nowrap`。

## 8. 文案 key

前缀 `print.outsource_order.`，三语同步，至少：

`docTitle` / `fileName` / `draftWatermark` / `orderNo` / `orderDate` / `currency` / `printedAt` / `phone` / `email` / `supplier` / `contactPerson` / `address` / `billingAddress` / `factory` / `shippingAddress` / `paymentTerm` / `itemNo` / `materialCode` / `materialName` / `quantity` / `unit` / `unitPrice` / `taxRate` / `amount` / `requiredDate` / `subtotal` / `tax` / `total` / `supplyTitle` / `issueTitle` / `issueQuantity` / `vendorTitle` / `vendorQuantity` / `productImages` / `remarks` / `authorized` / `approvedBy` / `preparedBy`

`amount` 是收回件不含税金额。`issueQuantity` 是应发数量。`vendorQuantity` 是厂商自备数量。  
样品图、备注的中文与工厂订单一致即可（产品样图、备注），key 仍用本前缀，不要复用 `print.factory_order.*`。
