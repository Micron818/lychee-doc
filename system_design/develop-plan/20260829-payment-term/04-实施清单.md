## 3. 实现约定

### 3.1 `PaymentTermScheduleService`

无状态展开（纯函数，便于单测）：

```text
expand(term + lines, baseDate, totalAmount) → List<ScheduleDraft>
  + headerDueDate
```

写库：

```text
rebuild(invoice, mode)
  REPLACE_ALL     // 改条件
  RESPREAD_AMOUNT // 改合计；overridden 行保留 due_date
```

`java.time.LocalDate` + `YearMonth.lengthOfMonth()`。金额 `BigDecimal` scale 2 `HALF_UP`。  
最后一行吃尾差。`percent` 合计用 `compareTo(100.00)`。

删除 `PaymentTermDueDateHelper` 及所有注入。

### 3.2 `RemotePaymentTermService`

```text
get(id) → header + lines（不存在 / 停用 → 空或异常，由调用方决定）
requireForDocument(id, PartnerType) → 校验 scope + active，否则 ValidationException
resolveSchedule(termId, baseDate, total) → expand 结果
listOptions(scope, activeOnly) → List<OptionValueDTO>
```

SCM/SD 保存 PO/委外/SO：`requireForDocument`。不要 join 条件行来算日期。

### 3.3 BP / 公司

- 新建 BP：请求未带 `paymentTermId` 时填 `company.default_payment_term_id`（仍可空）。  
- 保存 BP：若有值，`partner_scope` 与 `CUSTOMER`/`SUPPLIER` 兼容。  
- `RemoteBusinessPartnerFinanceDTO` 字段改名为 `paymentTermId`；全仓库同步。

### 3.4 转单与开业务单

`PurchaseOrderGenerationServiceImpl`：写入 `paymentTermId`，无则整批回滚。  
委外生成/手键：与 PO 相同带出逻辑。  
`SalesOrder` 选客户：与现网带 `paymentTermOptionId` 相同，改字段名。  
DRAFT 改供应商/客户：重带条件，除非请求显式含 `paymentTermId`。

### 3.5 AP/AR

| 入口 | 条件 | 基准日 |
|------|------|--------|
| 从 GR | PO/委外 → BP | `SOURCE_DATE` 则 min(收货日)，否则发票日 |
| 从发货 | SO → BP | `SOURCE_DATE` 则发货日，否则发票日 |
| 手工 | 必填（UI 可先带 BP） | 默认发票日；`SOURCE_DATE` 无来源时 = 发票日 |

`create` / `update` / `recalculateInvoiceTotals` 之后调用 `rebuild`。  
`ApInvoiceRequest.dueDate`、`ArInvoiceRequest.dueDate`：**从必填请求移除**。响应仍返回。

前端 `handleAdd` 去掉 `dayjs().add(30, 'day')`。

过账：无排程或 `payment_term_id` 空 → `ValidationException`。  
排程金额之和必须等于 `total_amount`（过账再断言一次）。

### 3.6 主数据校验

- 条件保存：§3 应用层规则 + 至少一行。  
- 已被引用的条件行：禁止从 PUT 全量替换中删除（与税码档「相交则拒删」同类）；只能改未引用行或停用整份条件。未上线测试可清库。  
- 删除头：`exists` BP/公司/PO/委外/SO/发票 → 拒绝。  
- 公司改默认条件：无额外单据校验（只影响以后新建 BP）。

### 3.7 权限

| 资源 | 建议 |
|------|------|
| `/fi/payment-terms:*` | 财务主数据角色 |
| `/fi/payment-terms/options`、`resolve-schedule` | 开单/往来权限 |
| 单据改条件 | 现有 DRAFT 更新 |
| 公司默认条件 | 现有公司 update |

菜单：FI 主数据，靠近评估类。

## 9. 验收反例（必测）

1. 无条件转 PO → 失败，无草稿。  
2. 名称从「Net 30」改成「月结」→ 已开票到期日不变。  
3. `2/10 NET 30` 不再被 parse 成 2 天。  
4. PO 为 `EOM30`、BP 为 `NET30` → AP 到期按月结。  
5. 手工开票不出现默认 +30。  
6. `SPLIT3070` 过账：两行金额之和 = 含税合计，表头 due = 第二期。  
7. 把 `GR-NET30`（SUPPLIER）选到 SO → 拒绝。  
8. 已过账 AR 改条件 → 拒绝。  
9. API/前端搜索 `PAYMENT_TERM` / `paymentTermOptionId` → 零命中。
