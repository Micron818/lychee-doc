付款流程（Procure-to-Pay 的付款阶段）在财务/应付（AP）和资金（Treasury）模块中提供以下几个核心的作业功能（UI 界面和后台逻辑）：

### 1. 应付发票管理功能 (Invoice Management)

虽然发票管理属于前置步骤，但它是付款流程的基石。

*   **应付发票工作台 (AP Invoice Workbench)**：
    *   用于录入、编辑、作废、审核 `ap_invoices`。
    *   提供“三单匹配（3-Way Match）”的界面：用户输入收货单号，系统自动抓取收货明细生成发票明细。
    *   发票状态管理（草稿、待审批、已审核/已过账）。
*   **发票到期预警与账龄分析表 (AP Aging & Due Date Report)**：
    *   出纳或财务经理每天查看的报表。系统根据发票的 `due_date`（到期日），将欠款按时间段分组（例如：0-30天内到期、逾期 1-30天、逾期 30天以上）。
    *   这是决定“今天要付哪些款项”的主要依据。

### 2. 付款申请与审批功能 (Payment Request & Approval)

很多公司要求付款前必须有内部申请和审批过程。

*   **付款申请单据维护 (Payment Request Entry)**：
    *   员工或会计在此选择要申请付款的发票。
    *   可以申请全额或部分金额付款。
*   **付款审批工作流 (Approval Workflow)**：
    *   系统提供多级审批流引擎。根据金额大小、部门不同，自动路由给不同的主管或总监审批。
    *   支持移动端审批是非常常见的需求。

### 3. 付款排程与准备功能 (Payment Proposal / Preparation)

这是出纳管理资金的核心工具，尤其在有多张发票需要支付的情况下。

*   **付款建议书生成 (Payment Proposal / Batch Run)**：
    *   **核心功能**：出纳可以在这个界面设定过滤条件（例如：到期日 <= 下个月初，供应商 = A 公司，金额 > 0）。
    *   系统会**自动检索**所有符合条件且已审批的待付款发票，生成一个批次的付款建议清单。
*   **付款资金分配与账户选择 (Fund Allocation & Bank Account Selection)**：
    *   在这个列表中，出纳可以看到总共需要付多少钱。
    *   出纳在此指定使用公司的哪个“自有银行账户（House Bank Account）”来支付这笔批次的款项。
    *   如果发现账户余额不足，出纳可以在这个界面临时取消某些发票的付款（即本批次先不付）。

### 4. 付款执行与核销功能 (Payment Execution & Clearing / Allocation)

这是真正记录资金流出和冲减应付账款的动作。

*   **手动付款录入 (Manual Payment Entry)**：
    *   用于处理非批量的、零散的付款。出纳在网银转账后，在 ERP 中记录一笔付款单（`payments`）。
*   **发票核销/结算 (Payment Allocation / Clearing)**：
    *   **极其重要**：如果出纳使用“付款建议书”功能生成付款，系统通常会自动完成核销（因为是勾选发票生成的付款）。
    *   如果是收到供应商对账单后手动打款一笔总数，系统需要提供一个“核销界面”。界面左侧显示这笔“未分配的付款（Unallocated Payment）”，右侧列出该供应商所有“未结清的发票（Open Invoices）”。出纳通过打勾，将这笔付款金额分配给具体的发票，直至付款金额分配完毕。
    *   此动作会更新 `ap_invoices` 的 `paid_amount`、`remaining_amount` 和 `payment_status`。

### 5. 银企互联功能 (Host-to-Host / Bank Integration) - 进阶功能

中大型企业 ERP 的标配功能，极大提高效率并减少舞避风险。

*   **付款指令生成与发送 (Payment File Generation)**：
    *   出纳在 ERP 确认付款后，系统不要求出纳去网银手工录入，而是自动生成符合银行要求的付款文件（如 XML, TXT, 或直接调用银行 API）。
*   **付款状态回执 (Bank Status Feedback)**：
    *   银行处理完转账后，ERP 接收回执状态（成功/失败），自动更新 ERP 中的付款单状态。

### 6. 财务抛转功能 (Accounting / Journal Generation)

*   **自动凭证生成引擎 (Subledger Accounting Engine)**：
    *   当付款单确认并完成核销后，系统后台默默工作的功能。它会自动从付款单抓取数据，并根据配置好的会计科目映射规则，生成财务凭证（`journal_entries`）。
    *   借：应付账款（冲销发票对应的科目），贷：银行存款（对应出纳选择的银行账户）。

总结来说，在付款流程中，ERP 必须提供 **发票选择 -> 资金统筹（选银行/看余额）-> 付款记录 -> 发票核销 -> 自动记账** 的一套完整的闭环功能界面。
