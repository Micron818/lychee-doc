# 02. 送货单打印目标流程（To-Be）

> 原则：用户打开 **一张交货单**，系统打出一张 **送货单 PDF**，给司机跟车、客户点货签字。  
> 不落送货单主档、不改 Delivery / 领料 / AR、不记 POD。打印基座对齐收货单（单张 `GET /{id}/pdf`，禁止前端 HTML 双轨）。

系统未上线：**一次交付**单张查询组装 + PDF + 列表/详情入口。不做 Excel、邮件、归档 Export、批量多单、三联纸、价税客户联、装箱单、电子签收。

---

## 1. 在作业链上的位置

```text
SO 确认
  → 开 Delivery → 下达 RELEASED
         │
         ├─【本打印】送货单 PDF → 跟车 → 客户签收（纸质回签，系统不回写）
         │
         └─ 领料 SALES_DELIVERY 过账 → DELIVERED
                ├─ 客户请款明细（期间汇总）
                └─ 开 AR → 收款
```

打印可在下达后、出库前（主路径），也可在已出货后补打。纸面数量认交货行计划量，不随领料/退货改口径（见 §3 #11）。

## 2. 命名（三语，锁死）

现网菜单已经是 `交货单(DN)` / `Delivery Notes(DN)` / `Phiếu giao hàng(DN)`，页面标题 `交货单` / `Delivery` / `Phiếu giao hàng`。本波 **不改菜单**。

| 角色 | zh-CN | en-US | vi-VN |
|------|-------|-------|-------|
| 系统单据 / 菜单 / 单号标签 | 交货单（维持现状） | Delivery / Delivery Notes(DN)（维持现状） | Phiếu giao hàng(DN)（维持现状） |
| **本 PDF 标题 / 文件名** | **送货单** | **Delivery Note** | **Phiếu giao hàng** |
| 期间对账件 | 客户请款明细 | Customer billing statement | Bảng kê đề nghị thanh toán |

中文必须拆开：作业叫交货单，跟车纸叫送货单。英文、越南文菜单已接近 Delivery Note，打印标题与菜单同族即可，不要另造 `Dispatch Note` / `Biên bản giao nhận`。

i18n key 前缀：`print.delivery_note.*`、`pages.sd.deliveries.print.*`。

禁止：

- 把菜单 `menu.sd.deliveries` 改成「送货单」
- 中文打印标题写成「交货单」「出货单」「发货单」
- 英文打印标题写成 `Delivery`（用 `Delivery Note`）
- 与收货单字段 `deliveryNoteNo`（供应商送货单号）共用文案 key
- 把术语表 DN 从「交货单」改名；只在说明列注明打印件标题为送货单

## 3. 已锁定决策

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 产出物 | **PDF 预览 + 浏览器打印**；无 `ExportJobType` / `ExportButton` |
| 2 | 纸张 | **A4 landscape**（尺码动态列，对齐 09；本单无价税列，仍横向以免码列挤爆） |
| 3 | 版式 | **尺码矩阵**（对齐 09 / 15：型号本款色字母、rowspan）。一单无「出货复合格」。**不是**「型号 → PO → 颜色」左到右树；见 [03 §4.5](./03-数据模型与版式.md)。**不印**料号/名称列、**不印**样图、**不印**单价/税/金额/币别/汇率/开票状态。交货行 `remarks` 必须印。数量列带单位，不另开单位列 |
| 4 | 入口 | 交货单 **列表操作列 + 详情抽屉**「打印」（对齐收货单）。**不**占用请款工具栏「预览/打印」 |
| 5 | 数据范围 | **一张** `Delivery` + 可打印明细。禁止 `id_in` 跨打成一张 |
| 6 | 表头可打 | `DRAFT` / `RELEASED` / `DELIVERED`。**`CANCELLED` 拒绝** |
| 7 | 交货类型 | `NORMAL` / `SAMPLE` 可打。**`RETURN` 拒绝**（未启用；退货走客户退货单） |
| 8 | 行范围 | 行状态 ≠ `CANCELLED`，且 `sourceDocType` 为 **`null` 或 `SALES_ORDER`**。排除 `RETURN_PO` / `TRANSFER_ORDER` / `OTHER` |
| 9 | 空明细 | 过滤后无行或数量皆 ≤ 0 → `validation.delivery_note.noPrintableItems` |
| 10 | DRAFT | **允许打印**，整页「草稿」水印（对齐收货单） |
| 11 | 数量 | **一律 `transactionQuantity`**（交货行计划量）。不用 `issuedQuantity`，不扣 `returnedQuantity`。≤ 0 跳过该行。签收件口径稳定，不随后续领料/退货改数 |
| 12 | 金额 | **不展示、不组装、不合计**。主档价税仍留在交货单，供请款/开票 |
| 13 | 样图 | **不印** |
| 14 | 开票状态 | **不印** |
| 15 | 送货地址 | `Delivery.shippingAddress`；空则回退 `Customer.addressShipping`；仍空则留空，**不拒绝** |
| 16 | 签核 | 三栏：**制单** = `createdBy` 姓名 + 签字线；**送货人** 留白；**客户签收** 留白（含签收日期线）。制单不是当前打印人 |
| 17 | 水印 | 仅 `DRAFT`。`RELEASED` / `DELIVERED` 无水印（下达后跟车是正式件） |
| 18 | 权限 | `/sd/deliveries:read` |
| 19 | 模块 | **`lychee-erp-sd`** 直读 Delivery / SO / Customer / Factory→Company。**不**复用 `DeliveryBillingStatementService`（价税、跨单、开票状态会污染） |
| 20 | 矩阵算法 | 对齐 09 / 15 / 请款的分组 + rowspan；分组键**不含** `deliveryId` / `invoiceStatus` / 单价 / 税率。字符串键 **`nullToEmpty`**（对齐请款 / SO 报表）。rowspan 用请款的 `modelKey`，**不要**抄 SO 报表只比 `productModelId`（无型号辅料会误合并） |
| 21 | 手工自建行 | **纳入**（`sourceDocType` 空）；PO / 内部参号可空。`salesOrderId` 全空时 PO 列允许 rowspan 成空格，模板必须保底高度（[03 §4.2](./03-数据模型与版式.md) / [03 §5.3](./03-数据模型与版式.md)） |
| 22 | 赠样 | 表头印交货类型标签；数量规则同 NORMAL |
| 23 | 三联 / 多联 | **不做**；同一 PDF，需要几份就打几份 |
| 24 | 价税客户联 | **不做**；要对账用请款明细 |
| 25 | POD | **不做**签收人、签收时间、附件回写 |
| 26 | 装箱单 | **不做** |
| 27 | 批量打印 | **本期不做**列表勾选多单；Renderer 可按收货单预留 `render(Set)`，UI 只调 `renderOne` |
| 28 | 归档 Export | **否** |
| 29 | 抽屉打印 | **`DeliveryForm` 自包含 Modal**（对标 `GoodsReceiptForm`）。列表 `index.tsx` 另挂一份给操作列。禁止抽屉通过 props 把打印抬到父级 |
| 30 | 未保存打印 | **DRAFT 且表单脏：提示先保存，不打开预览、不自动保存**。PDF 只读库。`RELEASED` / `DELIVERED` 只读，无此路径 |

## 4. 总体流程

```
前端交货单列表操作列 / 详情抽屉 [打印]
   │  CANCELLED 或 RETURN 隐藏按钮
   │  DeliveryNotePdfPreviewModal + getDeliveryNotePdfBlob(id)
   ▼
GET /api/v1/sd/deliveries/{id}/pdf     ← read，inline，不建作业、不落 OSS
   ▼
DeliveryNotePdfRenderer.renderOne(id, locale)
    ├─ DeliveryNotePrintService.getPrintData(id)
    │     ├─ 加载 Delivery；CANCELLED / RETURN → 业务错误
    │     ├─ 抬头：factory → company（logo / 名 / 址 / 电话 / 税号）
    │     ├─ 客户：code / name / taxId / phone / contactPerson / contactPhone
    │     ├─ 地址：shippingAddress，空则 customer.addressShipping
    │     ├─ 承运 / 运单 / 计划日 / 实际日 / 类型 / 状态 / 备注
    │     ├─ 行：非 CANCELLED + source 空或 SALES_ORDER + transactionQuantity > 0
    │     ├─ 回追 SalesOrder / SalesOrderItem（PO、内部参号、客户订单号）
    │     ├─ Material → Model / Color / Size / Unit
    │     ├─ 按 §3 / 03 分组为尺码矩阵 + rowspan
    │     └─ 制单人 = createdBy；printedBy = 当前用户
    └─ Thymeleaf templates/print/delivery-note-pdf.html → PDF bytes
   ▼
前端 blob → objectURL → iframe；工具栏 print()
```

禁止再开 `/print` 深链、前端 HTML 版式、`autoPrint`、对外 `print-data` REST。  
禁止把请款 `POST /billing-statement/pdf` 改成单张入口。

## 5. 筛选与纳入规则

### 5.1 表头

| 条件 | 规则 |
|------|------|
| 存在 | 租户内按 id 加载；无则现有 404 |
| 状态 | `CANCELLED` → `validation.delivery_note.cancelled` |
| 类型 | `RETURN` → `validation.delivery_note.return_type` |
| 其余 | `DRAFT` / `RELEASED` / `DELIVERED` × `NORMAL` / `SAMPLE` 可打 |

### 5.2 明细行

```
纳入：status != CANCELLED
    AND (sourceDocType == null OR sourceDocType == SALES_ORDER)
    AND transactionQuantity > 0
```

`sourceDocType == null`：手工自建行，**纳入**。  
`sourceDocType == SALES_ORDER` 但 `sourceDocId` 空：仍纳入；PO / 订单号留空。  
`RETURN_PO` / `TRANSFER_ORDER` / `OTHER`：**排除**。

过滤后零行 → `validation.delivery_note.noPrintableItems`（不出空白 PDF）。

### 5.3 数量

```
printQty = transactionQuantity     // ≤ 0 已在纳入时跳过
```

禁止：

- 用 `issuedQuantity`（领料实发）替换计划量
- 用 `issuedQuantity − returnedQuantity`（请款净出货）——签收件不应被事后退货改掉
- 用销售订单行 `quantity`

矩阵行数量 = **Σ 组内 printQty**。合计 = Σ 行数量。

### 5.4 抬头派生

| 字段 | 来源 |
|------|------|
| 公司抬头 | `factoryId` → Factory → Company（名称 / 地址 / 电话 / 税号 / logo，对齐请款 / SO 报表） |
| 单号 | `deliveryNo`（标签用「交货单号」，标题仍是「送货单」） |
| 客户 | `Customer` code + name + taxId + phone + 联系人 / 联系电话（可空） |
| 送货地址 | Delivery 上有则用；否则客户送货地址 |
| 承运 / 运单 | `carrierName` / `trackingNumber`（可空） |
| 日期 | 计划交货日必印；实际交货日有值才印该 **div**（信息区一行两 `td` 流式，见 [03 §5.2](./03-数据模型与版式.md)） |
| 类型 / 状态 | 枚举三语标签；SAMPLE 必须可见 |
| 工厂 | Factory 名称 |
| 备注 | 表头 `remarks`（可空） |

## 6. API

```
GET /api/v1/sd/deliveries/{id}/pdf
@PreAuthorize("hasAuthority('/sd/deliveries:read')")
Accept: application/pdf
Content-Disposition: inline; filename="..."
```

不建 `export_jobs`，不传 OSS。校验失败用现有 `ValidationException` + `messages*.properties`。

前端：`getDeliveryNotePdfBlob(id)`，Modal 复用 `PdfPreviewSession`（对标 `GoodsReceiptPdfPreviewModal`）。

与请款并存：

| | 请款明细 | 送货单 |
|--|----------|--------|
| 方法 | `POST /billing-statement/pdf` | `GET /{id}/pdf` |
| 范围 | 多张已出货 | 一张 |
| 入口 | 列表工具栏 | 操作列 + 抽屉 |

## 7. 前端（交货单）

对齐收货单，不新建菜单页。Modal **两处各挂一份**，互不回调：

```
src/pages/sd/deliveries/
  print/DeliveryNotePdfPreviewModal.tsx     // 共用薄适配
  index.tsx                                 // 列表操作列 → 本页 previewOpen + Modal
  components/DeliveryForm.tsx               // 抽屉工具栏 → 抽屉自己的 previewOpen + Modal
```

对标 `goods-receipts/index.tsx` + `GoodsReceiptForm.tsx`。禁止只在 `index.tsx` 挂 Modal、再让 Form `onPrint` 通知父级。

1. 列表操作列「打印」：`CANCELLED` 或 `deliveryType = RETURN` 不渲染按钮。  
2. 详情抽屉工具栏「打印」：已保存（有 `id`）且非 `CANCELLED` / `RETURN`；新建未保存不显示。  
3. **脏数据**：`status === DRAFT` 且 `compareFormValues` 相对上次载入的详情为脏 → `message.warning(pages.sd.deliveries.print.unsavedChanges)`，**不** `setPreviewOpen(true)`，**不**自动 `save`。未保存的地址/备注不会进 PDF（接口只读库）。  
4. `RELEASED` / `DELIVERED` 表单只读，打印直接开预览。  
5. 请款工具栏逻辑 **零改动**。  
6. `rowSelection` / 批量删除规则不因本波改变。

## 9. 与相邻打印件的差异

| 维度 | 收货单 (12) | 客户请款明细 | **本送货单** |
|------|-------------|--------------|--------------|
| 对象 | 一张 GR | 多张已出货 Delivery | **一张 Delivery** |
| 对象方 | 供应商 | 客户（对账） | **客户（点货）** |
| 数量 | GR 行交易量 | 净出货 | 交货行计划量 |
| 价税 | 不印 | 印 | **不印** |
| 矩阵 | 否（扁平行） | 是，出货格在左 | **是，无出货格** |
| 签核 | 制单 / 仓管 | 制表 / 审核 / 客户确认 | **制单 / 送货人 / 客户签收** |
| 水印 | 草稿 / 已冲销 | 无 | 仅草稿 |
| 入口 | 操作列 + 抽屉 | 列表工具栏 | **操作列 + 抽屉** |
