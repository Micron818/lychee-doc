# 01. 送货单打印现状与问题（As-Is）

> 依据当前代码与文档：`lychee-erp-sd` / `lychee-erp-wm` / `lychee-erp-report` / `lychee-frontend` / 请款明细与报表专案。  
> 本文件只说明「现在有什么、差在哪」。To-Be 见 [02-目标流程.md](./02-目标流程.md)。

---

## 1. 业务缺口

工厂出货常见动作：司机把货送到客户，客户按箱/按款点货，在纸上签字或盖章，回签联带回。  
这张纸回答「**这一车、这一单发了什么**」，不是「这个月一共多少钱」。

现网销售出货作业能跑完，但没有这张跟车件：

```text
SO → Delivery → StockIssue(SALES_DELIVERY) → Delivery.DELIVERED
                                              → 客户请款明细（期间汇总，已实现）
                                              → ArInvoice（可合并多张 Delivery）
                                              → Payment(RECEIPT)
```

业务只能：

- 打开交货单画面给客户看系统，或
- 把客户请款明细当送货单用（跨多日出货、带价税，司机无法按车点货），或
- 到采购收货单去看「送货单号」字段（那是**供应商**送来时我方填写的对方单号）

客户现场拿不到「本张交货单：款号 / 色 / 码 / 数量 / 送货地址」的套打件。

## 2. 现网各管什么

| 单据 / 报表 | 模块 | 现网能力 | 对送货签收的含义 |
|-------------|------|----------|------------------|
| `deliveries` / items | SD | 表头客户、配送地址、承运/运单、计划/实际交货日、类型、状态；行上计划量 / 已出库量 / 价税 | **送货数据在这里**；无 `/{id}/pdf` |
| `StockIssue` `SALES_DELIVERY` | WM | 从 Delivery 导入、过账后回写 `issuedQuantity`，整单出完写 `actualDeliveryDate` | 仓内出库事实；**不是**给客户签字的纸 |
| 客户请款明细 | SD | 强制客户 + `actualDeliveryDate` 闭区间；跨多张已出货 Delivery 一张价税矩阵 | 月结对账；[请款设计](../20260920-客户请款明细/02-目标流程.md) §9 明确不做单张打印 |
| 销售订单报表 | SD | 强制客户 + 订单日；订购量矩阵 | 接单确认，不是实发 |
| 收货单 PDF | WM | 采购入库套打；抬头有供应商 **送货单号**；不印金额 | 进项对称物：记录**对方**送货单；本方销售侧没有对等打印 |
| `ar_invoices` | FI | 从已出货 Delivery 开票 | 立账，无套打 |
| 客户退货 | WM | 已出货后的退回 | 反向单，不是正向送货 |

交货单列表工具栏「预览/打印」只打请款明细。操作列无「打印」。详情抽屉无「打印」。

`DeliveryController` 仅有 `POST /billing-statement/pdf`，没有 `GET /{id}/pdf`。  
已有单据类 PDF：订购单、请购单、收货单、收付款单、盘点单、工厂订单、销售订单报表、客户请款明细。**交货单不在其中。**

## 3. 数据已够、缺的是单张打印

交货单头已有跟车所需字段：

- `deliveryNo`、`deliveryType`、`status`
- `customerId`、`shippingAddress`（选客户时会带出 `Customer.addressShipping`）
- `carrierName`、`trackingNumber`
- `plannedDeliveryDate`、`actualDeliveryDate`（仅整单行全部 `DELIVERED` 时由领料回写）
- `factoryId` → Company 抬头、`remarks`

行上已有：

- `transactionQuantity` / `issuedQuantity` / `returnedQuantity`
- `materialId` → 型号 / 色 / 码 / 单位
- 来源 SO：`customerPoNo`、内部参号、客户订单号
- 行 `remarks`

**没有**签收人、签收时间、回签附件字段。本波不补这些列。

缺口是：

1. 没有「一张交货单 → 一张客户签收 PDF」
2. 请款明细不能替代（跨单、带价税、只纳入已整单出完）
3. 收货单上的「送货单号」是进项字段，不能当本方打印件
4. `DELIVERED` 表示仓内领料出完，**不是**客户已签收

## 4. 容易用错的现网对象

| 对象 | 为什么不能当送货单 |
|------|-------------------|
| 客户请款明细 | 多张已出货单汇总；带价税、账期、账号；底部「客户确认」是对账签核 |
| 销售订单报表 | 数量是订购量；日期是订单日 |
| `StockIssue` | 仓内出库凭证；无客户签收栏；无打印 |
| 收货单 PDF | 采购入库；「送货单号」= 供应商单据号 |
| `ArInvoice` | 立账；无套打 |
| 交货单画面 | 内部作业 UI，不是跟车纸 |
| `deliveryType = RETURN` | 未启用；客户退货是独立单据 |

## 5. 命名现状（必须拆开）

| 用语 | 现网用法 | 问题 |
|------|----------|------|
| 交货单(DN) | 菜单、页面、术语表 | 系统作业对象，应保留 |
| 出货单 | 请款明细文案里常与 Delivery 混称 | 不是打印标题 |
| 送货单号 | 收货单字段 `deliveryNoteNo` | 进项：供应商的单号 |
| Delivery Note | 术语表把 DN 译成 Delivery Note | 国际惯例里 Delivery Note 多指**打印输出** |

本专题锁定见 [02 §2](./02-目标流程.md)：作业=交货单，打印标题=送货单，期间件=客户请款明细。

## 6. 与请款、POD、装箱单的边界

| 件 | 口径 | 本波 |
|----|------|------|
| **送货单** | 一单交货单 + 数量矩阵 + 客户签收栏 | **做** |
| 客户请款明细 | 期间已出货 + 价税 | 已有；不改 |
| 电子签收 POD | 签收人 / 时间 / 扫描件回写 | 不做 |
| 装箱单 Packing List | 箱唛、毛净重、件数 | 不做 |
| AR 发票打印 | 一票一张 | 不做 |
| 领料单打印 | `SALES_DELIVERY` 套打 | 不做 |
