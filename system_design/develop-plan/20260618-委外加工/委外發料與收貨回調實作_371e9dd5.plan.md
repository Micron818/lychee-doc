# 委外加工系統：發料與收貨回調實作計劃

本計劃根據分析結果，先擴充必要的 Enum 定義，調整 SCM 回調 DTO 降低與 Order ID 的耦合，最後在 WM 模組的收貨與領料過帳流程中，整合 SCM 的回調通知與追溯 (Pegging) 機制。

## 1. 調整類別定義 (Enum)
為了讓 WM 模組能識別委外單據並記錄追溯，需要擴充以下列舉：
*   修改 `lychee-erp-common/src/main/java/com/lychee/erp/common/enums/StockIssueType.java`，新增 `OUTSOURCE`。
*   修改 `lychee-erp-common/src/main/java/com/lychee/erp/common/enums/StockIssueSourceDocType.java`，新增 `OUTSOURCE_ORDER_COMPONENT`。
*   修改 `lychee-erp-common/src/main/java/com/lychee/erp/common/enums/GoodsReceiptType.java`，新增 `OUTSOURCE`。
*   修改 `lychee-erp-common/src/main/java/com/lychee/erp/common/enums/GoodsReceiptSourceDocType.java`，新增 `OUTSOURCE_ORDER_ITEM`。
*   修改 `lychee-erp-common/src/main/java/com/lychee/erp/common/enums/PeggingOrderType.java`，新增 `OUTSOURCE_ORDER`。

## 2. 調整 DTO 與 SCM 回調實作
移除 DTO 中的 `outsourceOrderId`，改為直接從 Item/Component 反查，增強靈活性。
*   修改 `RemoteOutsourceOrderIssueCallbackRequestDTO.java` 與 `RemoteOutsourceOrderReceiptCallbackRequestDTO.java`：
    *   刪除 `outsourceOrderId` 欄位。
*   修改 `RemoteOutsourceOrderServiceImpl.java` (`issueCallback` 與 `receiptCallback`)：
    *   調整邏輯：從傳入的 `outsourceOrderComponentId` 或 `outsourceOrderItemId` 查詢出對應的 `OutsourceOrder`。
    *   若一次回調包含多筆不同訂單的明細，需將更新後的訂單狀態 (`ISSUED`, `PARTIAL`, `COMPLETED`) 進行批量處理與儲存。

## 3. 實作 WM 模組：委外收貨 (Goods Receipt)
在收貨過帳與反過帳流程中加入 SCM 委外單連動與 Pegging。
*   修改 `GoodsReceiptServiceImpl.java` 的 `postGoodsReceipt`：
    *   在迴圈中攔截 `sourceDocType == GoodsReceiptSourceDocType.OUTSOURCE_ORDER_ITEM` 的 `GoodsReceiptItem`。
    *   將這類項目組裝成 `RemoteOutsourceOrderReceiptCallbackRequestDTO` 呼叫 `remoteOutsourceOrderService.receiptCallback`（傳入正數數量）。
    *   建立 `OrderPegging` 紀錄：`demandType = OUTSOURCE_ORDER`，`demandId = item.getSourceDocId()`。
*   修改 `GoodsReceiptServiceImpl.java` 的 `reverseGoodsReceipt`：
    *   攔截委外收貨項目，組裝並呼叫 `receiptCallback`（傳入負數數量，即 `transactionQuantity.negate()`）以扣回數量與反向 Backflush。
    *   刪除對應的 `OrderPegging` 紀錄。

## 4. 實作 WM 模組：委外發料 (Stock Issue)
在領料過帳與反過帳流程中加入 SCM 委外發料連動。
*   修改 `StockIssueServiceImpl.java` 的 `postStockIssue`：
    *   在迴圈中攔截 `sourceDocType == StockIssueSourceDocType.OUTSOURCE_ORDER_COMPONENT` 的 `StockIssueItem`。
    *   將這類項目組裝成 `RemoteOutsourceOrderIssueCallbackRequestDTO` 呼叫 `remoteOutsourceOrderService.issueCallback`（傳入正數數量）。
*   修改 `StockIssueServiceImpl.java` 的 `reverseStockIssue`：
    *   攔截委外發料項目，呼叫 `issueCallback`（傳入負數數量）以扣回發料數量。
