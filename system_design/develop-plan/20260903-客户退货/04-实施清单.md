## 1. 审查结论

| 问题 | 结论 |
|------|------|
| 能否做成负交货 / `delivery_type = RETURN` | **否**；独立 `customer_returns` |
| 能否做成收货转换 `CUSTOMER_RETURN_ITEM` | **否**；删除该枚举 |
| 能否扩展 `stock_issue_returns` | **否**；内部退料保持排除 `SALES_DELIVERY` |
| 已开票能否先退货再补贷项 | **否**；只退未被 AR 占用（含草稿）。已开票须先过账 [应收贷项](../应收贷项/README.md) |
| 锚点对交货还是领料 | **一对一已过账 `SALES_DELIVERY` 领料** |
| 模块 | **WM**，菜单 `/wm/customer-returns` |
| 退货后是否自动关 SO | **否**（退货路径不关单）。`DELIVERED` 可回 `CONFIRMED`；`CLOSED` 只改已交。现网 `CONFIRMED`→`CLOSED` 正向分支保留 |
| AR 闸门 | `getDeliveryForBilling` **和** `updateInvoicedQuantity` 都以 `issued` 为上限；`RELEASED` 只能对已出净额开票 |

编码从本文件 §5 按模块推进。

## 3. 实现约定

### 3.1 数量

与采购退货同一计算器风格（`CustomerReturnQuantityCalculator`）：

```text
unreturnedTxn       = issue.txn − postedReturnedThisLine − otherDraftThisLine
unreturnedBase      = issue.base − issue.returned − otherDraftBase
remainingUninvoiced = delivery.issued − delivery.invoiced − otherDraftOnDI
returnableTxn       = min(unreturnedTxn, remainingUninvoiced)
```

过账：`txn ≤ returnableTxn` 且 `base ≤ unreturnedBase`。  
用户改数量时 txn→base 走现有单位服务。最后一笔退完该领料行（`txn = unreturnedTxn`）时 `base = unreturnedBase`。用 `compareTo`。

过账回写交货已发用 **单据单位** `−transaction_quantity`。

### 3.2 库存

对标 `applyStockIssueReturn` 入库，类型 `CUSTOMER_RETURN`。只对 `isInventoried` 且有仓的行调库存（对标采购退货，不要照搬现网 `applyStockIssue` 不过滤）。  
成本：`findPostedUnitCostsBySourceDocItem(STOCK_ISSUE, originalIssueId, STOCK_ISSUE)`。  
非库存物料：不过 `stock_on_hand`、不写流水、不进 COGS 行；仍回写已退与交货/SO。

数量记账政策：与领料相同，跳过评价分录。

### 3.3 凭证

新 `RemoteCustomerReturnFinanceService.postCustomerReturn`：销售出库 COGS 的反向（借存货、贷 COGS）。  
请求字段见 `03` §6.1：每行冻结 `unitCost` + WM 算好的 `cogsAmount`；FI **禁止**再查当前标准成本、禁止重算金额。  
该领料行退完时 WM 用剩余未冲填 `cogsAmount`。非库存 / `unitCost == null` 的行不要放进 `lines`。冲销走现有 journal reverse。`postDate` = `return_date`。

### 3.4 贷项预留

```text
com.lychee.erp.common.service.RemoteCustomerReturnCreditMemoService

void assertReturnableAgainstInvoice(Long deliveryItemId, BigDecimal returnTxnQty);
void afterPosted(Long customerReturnId);
void afterReversed(Long customerReturnId);   // V1 no-op
```

V1 实现放在 FI，对标 `RemotePurchaseReturnCreditMemoServiceImpl`：

```text
qty = RemoteDeliveryService.findItemQuantity(deliveryItemId).orElseThrow(...)
if returnTxnQty ≤ qty.issued − qty.invoiced → 通过
否则按 AR 行区分：DRAFT 占用 → occupied.draft；POSTED 占用 → occupied.posted
```

**不要**让 FI 查客户退货草稿。草稿池只在 WM 计算器。  
**禁止**用 `// TODO` 代替类型。测试：已被占用的数量调用 `assert*` 抛 `ValidationException`。

### 3.5 可开票

两处都改：

1. `getDeliveryForBilling`：`billableQty = issued − invoiced`；剩余 ≤ 0 跳过。**取消必须 `DELIVERED`**，改为非 `CANCELLED`/`DRAFT` 且有剩余行
2. `updateInvoicedQuantity`：`newInvoiced ≤ issued`（替换现网只比 `transaction_quantity`）；交货行悲观锁；改占用后仍按 `issued` 刷新状态
3. `issueCallback`（`+qty` / `−qty`）每次改完 `issued` 后：`resolveItemStatus(issued, invoiced)` 刷新行与表头。正向销售出库过账必须走这里，否则部分出货开满后再出库会卡在 `FULLY_INVOICED`
4. 新 `updateReturnedQuantity`：只写 `returned_quantity` 审计列，**不**刷新 `invoice_status`

### 3.6 原领料冲销

`StockIssueServiceImpl.reverseStockIssue` 在 `SALES_DELIVERY` 开头：

1. 存在 `customer_returns` 且 `original_stock_issue_id` 匹配、`status ∈ {DRAFT, POSTED}` → 拒绝
2. 所涉交货行任一 `invoiced_quantity > 0` → 拒绝

内部退料的 `has_returns` 闸保持不变，不要混用文案。

### 3.7 `issueCallback` 负向（本波 SD 必改）

`RemoteDeliveryServiceImpl.issueCallback`：

- 交货行：保持现网已发上下限；出货状态按已发 vs 应发重算
- **每次 `issued` 变化后**刷新该行与表头 `invoice_status`（`resolveItemStatus(issued, invoiced)`）。正负向都刷
- SO 行 `CLOSED` / `CANCELLED`：只改 `delivered_quantity`（不得为负），不改状态
- 其它 SO 行：减量后未交满且当前为 `DELIVERED` → `CONFIRMED`；加满 → `DELIVERED`
- SO 表头：`CLOSED` / `CANCELLED` 不改；`DELIVERED` 且不再全交 → `CONFIRMED`
- 表头仍为 `CONFIRMED`：**保留**现网全行 `CLOSED`/`DELIVERED` → 自动 `CLOSED`

销售出库过账 / 冲销已走此回调，本波修完出库与退货一起对。交货取消不加退货闸。

### 3.8 命名检查

合并前不得残留：

- `CUSTOMER_RETURN_ITEM` 作为收货来源
- 菜单 / 正式文案「销售退货」
- 把客户退货做成 `delivery_type = RETURN` 或 `stock_issue_returns`

测试类名、i18n key 用 `customer_return` / `customerReturn`。

## 6. 验收

1. 已过账销售出库 100，未开票 → 退 40 过账：库存 +40，领料 `returned_quantity=40`，交货 `returned_quantity=40`，`issued` −40，SO 已交 −40，流水账 `CUSTOMER_RETURN`，有冲回凭证（成本启用时）。
2. 再退 60 成功（最后一笔：`base` 取剩余、COGS 用剩余金额）；再退拒绝。
3. 交货 100 已开票 60（含 AR **草稿**占用）→ 最多退 40；退 50 被拒。草稿占用提示改/删发票行，已过账提示先过账应收贷项。
3b. 出 100 退 40 后（`issued=60`），AR 草稿把行数量改成 100 → `updateInvoicedQuantity` 拒绝；改成 60 可通过。
3c. 出 100 退 40 后再从交货开 AR：表头已回 `RELEASED` 仍可开，可开票 60；已退满且未占用 → 无剩余行（不要报 `already_invoiced` / `not_delivered`）。
3d. `RELEASED` 交货行 txn=100、只出 50、未退未开票 → 可开票 50；开 60 拒绝。再退 20 后可开票 30。
3e. 出 50 并开满 50（行/表头 `FULLY_INVOICED`）后再出 50 → `invoice_status` 回到 `PARTIALLY_INVOICED`，可再开 50。不要钉死在 `FULLY_INVOICED`。
4. 同一交货行被领料 A 出 60、领料 B 出 40，未开票 30：A 退 20 后 B 最多再退 10；两张草稿合计超过 30 时第二张过账失败。
5. 原仓原批入库成功；改 `stock_type` 为 `INSPECTION` 后进待检。
6. 仓 / 批号 API 传入与原行不一致 → 拒绝。
7. 原领料有草稿或已过账客户退货 → 领料冲销失败。
8. 所涉交货行已开票 → 领料冲销失败。
9. 冲销客户退货单：库存、已退、已发、SO 已交恢复；原领料仍为 `POSTED`。
9b. 出 100 → 退 40 → 再出 40（已发回 100）→ 冲销该退货：交货已发将超 100 则拒绝。
9c. SO 行/表头 `CLOSED` 时退货成功、已交减少，状态仍为 `CLOSED`。
9d. SO 全交为 `DELIVERED` 后部分退货 → 行与表头回 `CONFIRMED`。
10. 混客户的销售出库领料不出现在 `returnable-issues`。
11. 删除 DRAFT 退货后，可退数量立即恢复。
12. 全文无 `CUSTOMER_RETURN_ITEM` / 「销售退货」作为正式名。
13. `from-source` 不再出现 `CUSTOMER_RETURN_ITEM` 分支；`StockTransactionLedgerServiceImplTest` 对应用例删除或改写。
14. 内部领料不出现在 `returnable-issues`；退料单仍排除 `SALES_DELIVERY`。
15. 非库存物料：库存与 COGS 跳过，已退 / 已发 / SO 仍回写。
16. `existsPostedByDeliveryItemIds`：有 POSTED 退货行返回 true，REVERSED 返回 false。
