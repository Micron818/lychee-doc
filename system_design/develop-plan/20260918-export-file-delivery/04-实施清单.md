## 1. 审查结论

方向正确，可以开工：这是把作业文件的 **交付 hop** 从 CDN 收回应用，**不是**改报表生成、不是弃 OSS。

| 问题 | 结论 |
|------|------|
| OSS 还要不要 | **要**。异步作业与 30 天导出中心仍靠它 |
| CDN 还要不要给报表 | **不要** |
| 图片是否一起改 | **否**，继续签名 URL |
| 是否保留 download-url 降级 | **否**，与前端切换同一交付删除 |
| 浏览器能否 `<a href=/file>` | **否**，必须 Bearer；走 blob |
| 整文件读进 `byte[]` | **否**（模板除外） |
| 新权限 / 新菜单 | **否** |
| 成功 toast 时机 | blob `downloadBlob` 之后；4xx 必须 throw，禁止与错误弹窗并存 |
| `exporting` 是否含传输 | **是**（列表按钮）；中心页靠 `downloadApiFile` 的 `message.loading` |
| Nginx 超时 | 两个 host 的 **通用** `location /api/` 提到 300s；**禁止**正则拆 location |
| 改 Handler SPI | **否** |
| blob 请求是否 skipErrorHandler | **必须 true**（对齐 `requestPdfBlob`） |
| 响应体类型 | **仅** `StreamingResponseBody` |
| `open()` 失败 | 先 `shutdown`，再抛；`NoSuchKey` → `validation.storage.object.missing` |
| Spring 异步超时 | **必须** `spring.mvc.async.request-timeout: 300000`，与 Nginx/前端对齐 |

未改业务代码。编码从 §5 按模块推进。

## 3. 实现约定

### 3.1 后端开流

`ExportJobServiceImpl` / `ImportJobServiceImpl` 把现网 `getDownloadUrl` 三段校验 **原样搬** 到 `open*`，最后 `storageService.open` 替代 `generateSignedUrl`。组装 `StoredFileDownload.fileName` 时：

```text
String fallback = job.getJobType() + handler.fileFormat().getExtension();
String targetFileName = StringUtils.hasText(job.getFileName()) ? job.getFileName() : fallback;
```

```text
不要：InputStreamResource
不要：先 return 头再 open（失败只能截断）
不要：Controller 在 return 前 close(in)
不要：IOUtils.toByteArray(open())
不要：ContentDisposition.filename(null 或 "")
```

Controller 锁定 `StreamingResponseBody` + `in.transferTo(out)`，`try-with-resources` 关流。`fileSize == null` 则不要调用 `.contentLength`。

`AliyunStorageService.open` **必须**改（泄漏 + 业务错误收口都在这里，report 不要再包一层）：

```java
OSS ossClient = new OSSClientBuilder().build(...);
try {
    var ossObject = ossClient.getObject(bucket, path);
    InputStream content = ossObject.getObjectContent();
    return new InputStream() { /* close → content.close + ossClient.shutdown */ };
} catch (Exception e) {
    ossClient.shutdown();
    if (isNoSuchKey(e)) {
        throw new ValidationException("validation.storage.object.missing");
    }
    throw e;
}

private static boolean isNoSuchKey(Exception e) {
    if (e instanceof com.aliyun.oss.OSSException ossEx) {
        return "NoSuchKey".equalsIgnoreCase(ossEx.getErrorCode())
                || ossEx.getStatusCode() == 404;
    }
    return false;
}
```

只认阿里云 `OSSException` 的 errorCode / HTTP 404。不要用 `e.getMessage().contains("NoSuchKey")`。

`generateSignedUrl` 行为不变。

Content-Type：导出用 `requireHandler(job.getJobType()).fileFormat().getContentType()`；导入固定 `ExportFileFormat.XLSX.getContentType()`。

### 3.2 前端 `downloadApiFile`

建议签名：

```text
downloadApiFile(url: string, fallbackFileName: string): Promise<void>
```

对齐 `src/utils/request-pdf-blob.ts`，**不是**导入模板当前那版未 skip 的 `request`。

实现顺序：

1. **按 URL 去重**：模块级 `Map<string, Promise<void>>`。同一 URL 已在飞则 `return` **同一个 Promise**（调用方继续 await 真实结束）。**禁止** `if (set.has(url)) return;` 空返回——`useExportJob` 会当成成功并打绿色 toast。
2. `message.loading({ content: formatMessage(component.export.downloading), key: 'job-file-download', duration: 0 })`
3. `request<Blob>(url, { method:'GET', responseType:'blob', getResponse:true, timeout:300_000, skipErrorHandler:true })`
4. 失败：见下方 catch；提示后 **throw**
5. 成功：`parseFileNameFromContentDisposition` → `downloadBlob`
6. `finally`：`message.destroy`；从 Map 删除该 URL

catch（无 HTTP 响应时 `error.response` 为 undefined，如 Axios `ECONNABORTED`、断网）：

```text
let errorMessage = error.message
if (error.response?.data instanceof Blob) {
  try {
    const json = JSON.parse(await error.response.data.text())
    errorMessage = json.message || errorMessage
  } catch {
    // 网关 502 HTML 等，保留 error.message
  }
}
message.error(errorMessage || formatMessage(component.export.downloadFailed))
throw error
```

**禁止** `await error.response.data.text()` 不带可选链。

`useExportJob`：

```text
await downloadExportJobFile(job.id)
message.success(component.export.success)  // 仅 await 成功
```

`catch`：只 `notification.destroy(processingKey)`，**禁止** success。注释改为「`downloadApiFile` 已提示」，不要再写「全局 errorHandler 已提示」。

`setExporting(false)` 只放 `finally`。

导出/导入中心 `handleDownload` 必须 `try/catch`（避免 unhandled rejection）。loading + in-flight Map 已在 `downloadApiFile`，不必行级 `downloadingId`。

JSON-in-blob：复用 `src/utils/blob.ts` 读 JSON；不要 `assertPdfBlob`。

**禁止**省略 `skipErrorHandler`：现网 `errorHandler` 弹窗后 `return`，`await` 会当成功，成功 toast 与错误通知并存。

### 3.3 Nginx

`deploy/docker/nginx/conf.d/default.conf` 两个 server 里 **已有的** `location /api/` 增加：

```text
proxy_read_timeout 300s;
proxy_send_timeout 300s;
```

`khh.lycheetech.com` 与 `lycheetech.com` 各一份。

**禁止**再写 `location ~ ^/api/v1/report/...`。正则 location 搭配现网 `proxy_pass http://backend:9000/api/;`（带 URI）会 `nginx -t` 失败，容器起不来。不强制 `proxy_buffering off`。

### 3.3.1 Spring MVC 异步超时（必须）

`StreamingResponseBody` 会 `request.startAsync()`。Spring Boot 未配时沿用 **Tomcat 异步默认约 30s**（`spring.mvc.async.request-timeout` 默认 `-1` = 容器默认）。Nginx 300s、Axios 300s 都救不了：大文件或越南慢网会在约 30s 被 `AsyncRequestTimeoutException` 掐断。

在 `lychee-erp/src/main/resources/application.yaml` 的现有 `spring:` 下增加（毫秒，与 Nginx/前端对齐）：

```yaml
spring:
  mvc:
    async:
      request-timeout: 300000
```

不要只写在 `application-local`；prod 同样生效。不要依赖 `server.tomcat.connection-timeout` 替代（那是连接建立，不是异步写出）。

### 3.4 i18n（三语）

前端成功/超时文案可不动（成功时机变了，语义已正确）。`en-US` / `vi-VN` / `zh-CN` 新增：

| key | 中文参考 |
|-----|----------|
| `component.export.downloading` | 正在下载文件… |
| `component.export.downloadFailed` | 下载失败（无 HTTP body 时的 fallback，如超时/断网） |

后端新增（`messages.properties` / `zh_CN` / `vi`）：

| key | 中文参考 |
|-----|----------|
| `validation.storage.object.missing` | 文件在存储中不存在或已被清理，请重新导出或导入 |

不要为「CDN 失败」加文案，这条路径应消失。

### 3.5 测试

后端：

- COMPLETED 作业 `GET /file` → 200，Disposition 含 `fileName`，有 `Content-Length`（fixture 有 size 时），body 与 fixture 字节一致
- `fileName` 空 → 200，Disposition 含 `{jobType}.xlsx`（或对应副档名），不是 500
- PENDING / 过期 → 400，body JSON 非空
- 他人 `createdBy` → 404
- 权限回收 → 与现网签发相同断言
- `getObject` 抛 NoSuchKey（errorCode 或 status 404）→ `validation.storage.object.missing`；并断言异常路径会 `shutdown`
- 导入 `/source`、`/error-report` 各一条 happy path + missing report

现网若 `getDownloadUrl` 已有测试，改为测 `open*`；不要留签发 URL 断言。

前端：有单测则断言 `downloadApiFile` 带 `skipErrorHandler: true`；400 路径不调用 `downloadBlob`。至少手工看 Network。

## 5. 提交顺序

1. 后端：`open*` + 新 GET + 删旧 URL 端点 + `spring.mvc.async.request-timeout` + 测试 + messages  
2. 前端：`downloadApiFile`（skip / catch 无 response / in-flight Promise）+ 四处调用点切换 + 删旧 api 函数  
3. Nginx 超时  
4. 文档勘误  

前后端必须 **同一交付** 上线：旧 download-url 删除后，旧前端会 404。不要先发后端再隔一周发前端。

Infra Nginx 与 Spring 异步超时可同发或略早，避免大文件被 30s/60s 切断。
