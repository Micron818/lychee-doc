## 1. 设计初衷与实际流量

导出框架把「OSS 上传 + CDN 签名 URL」选为唯一交付，理由是当时系统没有任何字节流下载端点，图片已经走 `StorageService.generateSignedUrl`，希望下载不占应用连接、多实例无状态。

那套模型是为 **物料图片** 建的：同一 `file_path` 被列表反复读，CDN 有缓存命中。作业文件不是这种流量。

| | 物料图片 | 导出 xlsx / 导入源文件与错误报告 |
|--|----------|----------------------------------|
| 对象 | 长期、可重复读 | `{tenant}/exports|imports/.../{jobId}_{ts}.xlsx`，一作业一对象 |
| 访问 | 多用户、多次 | 创建人下载 1～3 次，30 天过期 |
| CDN 命中 | 高 | 接近 0（首次必回源） |
| 鉴权形态 | `<img src>` 不能带 Bearer，必须签名 URL | 前端 `request` 本来就带 Bearer |
| 失败代价 | 裂图，业务可继续 | 报表下不来，作业中断 |

OSS **存储** 对异步作业、导出中心、多实例仍是对的。错在把图片的 **CDN 分发** 套到一次性私密文件上。

## 2. 现行主流程

```text
列表页 ExportButton
        │
        ▼
POST /api/v1/report/export-jobs     // 同步 COMPLETED 或 PENDING
        │
        ├─ PENDING：notification「处理中」+ 每 3s GET /{id}，上限 5 分钟
        │
        ▼ COMPLETED
GET /api/v1/report/export-jobs/{id}/download-url
        │  服务层：本人（ADMIN 例外）+ Handler.requiredAuthority 重验 + 审计日志
        │  返回 https://cdn.lycheetech.com/{path}?auth_key=...   时效 300s
        ▼
downloadByUrl(url)
        ├─ 立刻 message.success「导出完成，文件已开始下载」
        ├─ 隐藏 iframe.src = CDN URL（避免顶层导航到 chrome-error）
        └─ 60s 后移除 iframe
        │
        ▼
浏览器直连 CDN →（miss）回源 OSS
```

导入对称：

- 空模板：`GET /import-jobs/templates/{jobType}` **已经是同源字节流** + `downloadBlob`（对照正确路径）
- 源文件 / 错误报告：`GET /{id}/source-url`、`GET /{id}/error-report-url` → 同一套 CDN + `downloadByUrl`

单据打印预览 `GET /{id}/pdf` 也是同源 blob，与作业文件无关，本专题不改。

## 3. 各步骤在代码中的行为

### 3.1 签发 — `ExportJobServiceImpl.getDownloadUrl`

- 作业须 `COMPLETED`、未过期、有 `filePath`
- 越权按现网约定 404（不暴露存在性）
- 不读对象内容，只 `storageService.generateSignedUrl(path, downloadUrlExpirationSeconds)`
- 审计打在「签发」而非「传完」

导入 `getSourceUrl` / `getErrorReportUrl` 同构。

### 3.2 CDN 签名 — `AliyunStorageService.generateSignedUrl`

Type A：`auth_key = timestamp-rand-uid-md5(path-timestamp-rand-uid-key)`。  
域名固定 `aliyun.cdn.domain`（prod：`cdn.lycheetech.com`）。  
`open(path)` 已能从 OSS 拉流（导入执行、图片处理在用），下载路径没用它。  
现网实现：先 `new OSSClientBuilder().build`，再 `getObject`；**只有**返回的 wrapper 在 `close()` 时 `shutdown`。`getObject` 抛 `OSSException`（如生命周期删掉后的 `NoSuchKey`）时 client 不会关，连接池泄漏。本专题修 `open`，见 [04](./04-实施清单.md) §3.1。

### 3.3 前端点火 — `downloadByUrl`

```text
preconnect CDN → 隐藏 iframe.src = url → 60s 后 iframe.remove()
```

同步函数，不等待、不监听 onload/onerror。  
`useExportJob.downloadJobFile` 在 `downloadByUrl` 返回后立刻成功 toast，然后 `finally` 关掉按钮 `loading`。

`src/requestConfig.tsx` 的全局 `errorHandler`：弹窗后 `return`，**不 re-throw**（仅 `skipErrorHandler: true` 时 `throw error`）。因此未 skip 的 blob `request` 在 4xx/5xx 时会 **resolve 成 `undefined`**。单据 PDF 已用 `requestPdfBlob` + `skipErrorHandler: true` 避开；作业下载若照抄普通 `request` 会再假成功。

设计注释已承认：顶层 `<a>` 在 CDN 超时会把 SPA 打成 `chrome-error`。改 iframe 保住了页面，代价是 **CDN 失败对用户不可见**。

### 3.4 现场已发生的分裂

实测：

1. `POST report/export-jobs` 成功  
2. `GET report/export-jobs/19/download-url` 成功，`data` 为合法 CDN URL  
3. 浏览器对 CDN 一直 pending

即：**用户 → ERP 通，用户 → CDN 不通。** 控制面在业务域名（`lycheetech.com` / `khh.lycheetech.com`），数据面在另一条国际链路上。时区 `Asia/Ho_Chi_Minh`、越南语、VCB 汇率，使用侧在东南亚；阿里云 CDN 边缘质量不保证这条工厂网。

## 4. 摩擦点

| # | 问题 | 影响 |
|---|------|------|
| 1 | 成功信号绑在「拿到 URL」而非「文件落地」 | 假成功；用户以为浏览器会下完 |
| 2 | 隐藏 iframe 无超时/失败回调 | 无 toast、无 errorHandler、无重试入口 |
| 3 | 60s 拆 iframe | 可能 abort 慢下载，页面仍无说明 |
| 4 | 导出中心同一条 CDN | 引导「去导出中心」救不了同一故障 |
| 5 | 签名 URL 5 分钟 | CDN 卡住后再点，可能过期或再撞坏链路 |
| 6 | 签名 URL 可转发 | 5 分钟内谁持有谁下；真正 GET 不经应用 |
| 7 | 零缓存收益 | 多一跳纯开销 |
| 8 | 按钮 `loading` 不含传输 | 用户立刻再点，重复建作业 |
| 9 | 导入错误报告同样走 CDN | 导入失败后的自救文件也下不下来 |
| 10 | `errorHandler` 弹窗后 `return` 不 throw | 未 `skipErrorHandler` 时 `await request` 当成功，成功 toast 仍会执行 |
| 11 | `AliyunStorageService.open`：`getObject` 失败不 `shutdown` | 对象被生命周期删除时 OSS client 泄漏 |
| 12 | 导出/导入中心操作列无 loading | 改同源拉取后传输要数秒，用户会连点 |

## 5. 明确不是问题（本专题不改）

- 作业表、SPI、同步阈值、异步线程池、租户/安全上下文：不改
- OSS 作为落地存储、路径约定、生命周期 30 天：不改
- 图片 / 公司 logo 的 CDN 签名 URL：不改
- 单据 PDF 预览（`GET /{id}/pdf` + Modal iframe）：不改
- 导入空模板同源直出：已正确，保持
- 新报表 Handler / 新导入类型：不在范围
- 上 OSS 传输加速、换海外 Bucket、修 CDN 覆盖：可作为运维并行，**不替代**交付路径纠偏
