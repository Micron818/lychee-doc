# 01. 按款生成 BOM 现状与问题（As-Is）

> 依据当前代码与文档：`lychee-erp-pp` / `lychee-erp-mm` / `lychee-erp-basis` / `lychee-frontend` / `lychee-doc`。  
> V1 `copyBom` 字段 **不是** To-Be 依据，见 [03-schema设计.md](./03-schema设计.md) §1。本文件只说明「现在有什么、差在哪」。

---

## 1. 业务缺口

物料侧已闭环变体矩阵：

```text
款号 × 本款色 × 尺码组
  → VariantGenerateModal 预览
  → generateVariants（1～200 NEW SKU / 事务）
  → materials（is_fashion_variant = true）
```

BOM 没有对等入口。业务只能：

```text
BOM 列表 → 新建表头（选一个 SKU）→ 保存
  → 切明细页 → 逐行开抽屉加组件
  → 下一 SKU 再来一遍
```

一款 5 色 × 8 码 = 40 个自制 SKU。每份 BOM 十几二十行用料时，是几百次头/行往返。  
鞋服面料 / 填充棉等 **同料不同码用量不同**；现网 `bom_items.quantity` 是单值，没有按码表。若生成只写同一用量，业务仍要逐份打开 DRAFT 改米数——只解决「子件对」，不解决「用量对」。  
`SEQUENTIAL` / `MANUAL` 物料没有色码矩阵痛点，应继续单笔。

## 2. 现网各管什么（生成必须对齐的部分）

| 对象 | 模块 | 现网能力 | 对生成的含义 |
|------|------|----------|--------------|
| `materials` 变体三键 | MM / BASIS | `product_model_id` + `color_id` + `product_size_id`；`is_fashion_variant` 条件唯一 | 父件目标格 = 已存在的自制变体 SKU，**不**在本波建料 |
| `VariantGenerateModal` | MM 前端 | 款 → 色码 → 预览 → 公共主数据；坏格整批拒 | BOM 向导应对齐这套预览语义，不要另做 Excel |
| `bill_of_materials` | PP | 一表头 = 一 `product_material_id` + `version`；`uk_bom_product_version` | 生成结果必须是 SKU 表头，版本号本批共用 |
| `bom_items` | PP | 一子件一料号 + 固定用量；`uk_bom_items (bom_id, component_material_id)` | 解析后同一 SKU 不能落两条相同子件 |
| BOM API | PP | `POST /` 只建头；`POST /{id}/items` 再建行 | 前端循环这两步 = 半成功；生成必须单事务头+行 |
| `BomItemForm` | PP 前端 | 子件限 `materialType.isInventoried`，排除父件自身 | 生成解析后同样守这两条 |
| MRP | PP | `findActiveBomsByDate(materialId, date, APPROVED)` | **不**改种子；未批准的生成结果不算需求 |
| 工单 | PP | `production_orders.bom_id` 锁定版本，展开复制到 components | 执行链继续吃 SKU BOM，禁止运行时解款号 |
| 批准 | PP | `bulk-approve` 后 `LowLevelCodeService.recalculate` | 生成只出 DRAFT，**不**碰 LLC |
| V1 `copyBom` | MM DTO | `MaterialVariantGenerateRequest.copyBom` 有字段；`generateVariants` **未写 BOM** | 本波不补这个开关 |

`RemoteMaterialDTO` 目前只有 id/code/name/单位/计价税务，**没有**款色码。PP 已直接用 `MaterialRepository`（MRP / LLC / 工厂订单打印），生成解析走同一条，不要为了对色去扩扁 DTO。

表头 `description` 列在库里、Request 有字段，**Entity 未映射**。与本波无关的历史漂移；生成若写描述，一并补映射，不改列。

## 3. 已占位、不能当生成原语的东西

### 3.1 头行分步 API

| 区域 | 路径 |
|------|------|
| 头 CRUD | `pp/.../BillOfMaterialController`：`/page`、`POST`、`PUT /{id}`、`bulk-delete`、批准族 |
| 行 CRUD | `/{id}/items/page`、`POST /{id}/items`、`PUT /{id}/items/{itemId}`、`items/bulk-delete` |
| 服务 | `BillOfMaterialServiceImpl.createBillOfMaterial` 只 `save` 头；行是另一次调用 |

**没有**：预览、按款查询缺 BOM 的 SKU、一次写入头+行、按色/码解析子件、按尺码换算用量。

### 3.2 V1 Wave C `copyBom`

`20260911-mm-refactor-v1` 写过「复制模板物料当前有效 BOM 头行到新 SKU」。问题：

- 现网没有「读一头+其行、写 N 头+N 行」的服务，只能在 MM 生成循环里调 PP 分步 API，或 MM 直接写 PP 表（模块越权）
- 面料对色、大码加量时，原样复制是错料/错量（V1 `01` 已否决「生成时强制复制 BOM」）
- 物料生成与 BOM 生成生命周期不同：SKU 往往先批量存在，BOM 后补

**本专题明确不做复制。** DTO 上的 `copyBom` / `copyFactoryAssignments` / `copyImages` 保持默认关、不实现。

### 3.3 执行链没有款号 BOM

- MRP / `RemoteBomServiceImpl` 只按 `product_material_id` 取生效 APPROVED
- 计划单转工单按该 SKU 的 `bom_id` 展组件
- 没有 `product_model_id` 上的 BOM 表，也没有运行时继承

## 4. 若继续逐笔 / 复制 / 款号执行会错什么

| 方案 | 问题 |
|------|------|
| 前端对 N 个 SKU 循环 `POST` 头再循环 `POST` 行 | 中途失败留下无行头或半套行；无预览；对色要人肉选 N 次 |
| 实现 V1 `copyBom`（同源整份复制） | 所有色码共用同一 `component_material_id` **和同一用量**；对色面料/对码配件错，大码加量也错；还是头行两次 IO |
| 生成只写全码同量、上线后再逐份改 | 面料主工厂仍要打开几十份 DRAFT；与「按款一次建完」目标矛盾 |
| 把款号做成物料 `parent_id` 当 BOM | 与 `product_model_id` + 现网 BOM 重叠，库存层语义混乱（V1 已否） |
| MRP 执行时解「款号模板」 | 要改 MRP、LLC、工单冻结、审计「当时用了哪张 BOM」；本波不可接受 |
| 先落 `bom_templates` 再生成 | 多一套 CRUD/版本/同步；生成器还没跑通就做 Super BOM，范围膨胀 |
| 覆盖已有 APPROVED / 已被工单引用的版本 | 改执行中结构；与现网「非 DRAFT 不可改头」冲突 |
| 生成时自动 APPROVED | 错料立刻进 MRP 并重算 LLC |
| 缺 SKU / 缺对色子件时自动建料 | 编码策略、号池、工厂分配都在 MM；BOM 向导会变成第二套变体生成器 |
| 只对 `SEQUENTIAL` 父件做批量 | 无色码矩阵，不是本痛点 |
| Excel 一次导入 BOM | 能批量，但无色×码预览、无「已存在版本跳过」、无匹配规则；导入中心另题 |

结论：对齐物料变体向导，在 PP 新增 `preview` / `generate`；模板行在请求内按规则解析子件，并按父件尺码换算用量；**单事务**写入现网两表的 DRAFT（每行仍是一个 `quantity`）；执行链零改。
