## 3. 实现约定

### 3.1 解析函数

`BomGenerateServiceImpl.resolve(request) → BomGeneratePreviewResponse`。preview 与 generate 都走它。

```text
1. 载款号（`ProductModelRepository`）+ 本款色（`ProductModelColorRepository.findFetchedByProductModelId`）+ 尺码组档位（`ProductSizeGroupItemRepository.findFetchedBySizeGroupId`）；无尺码组 → 400
2. distinguish = 本款颜色行 ≥ 1
   distinguish 且 colorIds 空 → 400
   !distinguish 且 colorIds 非空 → 400
3. 校验模板（generate 必有；preview 有则校验）
4. 展开格：
   preview 且 cells 空 → colorIds（或 [null]）× productSizeIds
   否则用 cells[]（generate 可省略 colorIds/productSizeIds，从 cells 去重推导）
5. 一次查出该款全部 fashion variant SKU + `findAllByProductMaterialIdInAndVersion`，入 Map
6. 一次查出所有种子料；非 FIXED 把种子 `productModelId` 并入 `findByProductModelIdInAndActiveStatusFetchTypeAndUnit`，入内存分组
7. 校验每行 `sizeQuantities` → `Map<sizeId, qty>`（重复 / 组外 / ≤0 → 400）
8. 逐格判定 §2 / 02§3.5；逐行按模式过滤家族 List
9. 格内已 RESOLVED 的 componentId 放 Set，撞到 → DUPLICATE
10. 行用量：`resolvedQty = sizeMap.getOrDefault(parent.productSizeId, item.quantity)`
```

家族预取按 `productModelId`，**不要**每格每行打一枪 SQL。200 格 × 50 行只允许常数次查询 + 内存过滤。

`quantity` / `sizeQuantities.quantity` / `scrapRate`：`compareTo(BigDecimal.ZERO)`。`scrapRate == null` 落库 0（对标现网列默认）。`resolvedQty` 写入 `bom_items.quantity`，不要把 `sizeQuantities` 原样落库。

### 3.2 生成事务

类级或方法 `@Transactional`。顺序：

```text
1. preview = resolve(request)
2. 将 request.cells 对到 preview.cells
3. 任一勾选格为坏格 → withErrorData 400
4. newCount ∉ [1,200] → 400
5. saveAll(headers) + flush 一次
6. 填 bomId 后 saveAll(items)
7. 返回 created + skippedExisting（勾选中的 EXISTS 数）
```

不要先 `save` 头再在循环里 `createBomItem`（会触发 APPROVED 才走的 LLC 旁路；DRAFT 虽不重算，仍是分步语义）。  
不要 `REQUIRES_NEW` 按格提交。不要每格 `flush`。`DataIntegrityViolationException` 转业务 400，不要落到全局 409。

`DocumentItemNoAllocator`：模板已给齐项次则原样；有空项次则对**该请求模板**一次性分配，各 SKU 共用同一套项次。禁止每格自己 `findMaxItemNo`。

### 3.3 款色模式

与 `MaterialVariantService` 一致：本款颜色行数 ≥ 1 为区分色。不要读分类 `code_strategy` 来决定父件能不能进向导——父件准入看 `isFashionVariant` + 自制。某 SKU 若被标成变体却挂在 `SEQUENTIAL` 分类，仍允许作为父件（主数据已存在）；向导不负责纠分类。

### 3.4 前端

复制 `VariantGenerateModal` 的步骤机，容器改 `Drawer width="90%"`：

- `StepsForm` 四步
- preview 后默认勾 `NEW`
- 提交 `cells` 只含勾选格
- 成功 `message` 带 created / skipped（对标物料 `variantGenerate.success`）
- 分类策略 Alert **不要**出现（BOM 不选分类）

`useRequest` + `refreshDeps` 拉 `variant-setup`（仅前端）：`productModelId == null` 时 `Promise.resolve(undefined)`，不要 `/undefined/`。

模板行用 `EditableProTable`，`rowKey` 临时 id；提交 `normalize` 掉临时键（含把尺码列收成 `sizeQuantities`，空单元格不要提交）。脏检查走 `useFormOpenChangeHandler` + `customHasChanges`。

按码列数据源：步骤 2 已勾尺码 ∩ `variant-setup.sizes`，排序 `sequence, productSizeId`。可选「按 % 填」用 Popover 只改这些列的绝对数字，不往 API 加字段、不铺百分比列。

## 6. 验收

1. 款号无尺码组：preview / generate 400，库无新 BOM。
2. 区分色不传 `colorIds`：400。不分色传了 `colorIds`：400。
3. 本款 2 色 × 2 码均已有自制变体、无 BOM；1 行 `FIXED` 种子吊牌、用量 1、无 `sizeQuantities`：generate 4 头 4 行，皆 DRAFT，子件都是该吊牌，用量都是 1。
4. 同上但其中一个色码组合无 SKU：该格 `MISSING_SKU`；只勾 NEW 则生成 3 份；勾上缺料格 → 400，一份都不写。
5. 某 SKU 已有同 `version` 的 APPROVED：该格 `EXISTS`，skipped=1，不改该头、不改其行。
6. 某 SKU 已有同版本 DRAFT：仍 `EXISTS`，不覆盖。
7. 换一个 `version`：同一 SKU 可再生成第二份 DRAFT。
8. `COLOR_MATCH`：种子面料款 F、色空、无尺码；另有 F+海军、F+黑色 两料。父件海军/黑色各一码 → 各格解析到对应色面料。缺「F+白色」的父白格 → `UNRESOLVED`，整批 400。
9. 种子面料无 `productModelId` 且模式为 `COLOR_MATCH`：模板级 400，不进格子。
10. 种子带 `productSizeId` 且模式 `COLOR_MATCH`：模板级 400。
11. `SIZE_MATCH`：种子配件款 G、色空、码 40；另有 G/42。父 40 / 42 → 对到对应码；父 41 无配件 → `UNRESOLVED`。
12. `COLOR_SIZE_MATCH`：半成品款 H 已按色码生成；父件同色同码 → 命中该 HALB；缺格 `UNRESOLVED`。
13. 同一格两行 `FIXED` 同一料：`DUPLICATE`，400。
14. 种子 = 某格父件且 `FIXED`：该格 `SELF_REF`，400；其它格若种子≠父件仍不算过（整批拒绝）。
15. `COLOR_MATCH` 命中 2 条同款同色无尺码 ACTIVE 料：`CONFLICT`，400。
16. 种子 `INACTIVE`：模板级 400。
17. 种子非库存类：模板级 400。
18. 父件存在但是采购件（`isManufactured=false`）：`INELIGIBLE`。
19. `quantity = 0` 或负：400。`scrapRate` 空 → 落库 0。
20. 模板 0 行 generate：400。preview 0 行仍返回格子状态。
21. 勾选 0 个 NEW：400。勾选 201 个 NEW：400。
22. generate 中途模拟唯一键冲突：整批回滚，列表无新头、无孤儿行。
23. 生成后现网 `GET /{id}/items` 行数=模板行数，项次 10/20/… 或请求项次。
24. 生成后 `bulk-approve` 成功，MRP `findActiveBomsByDate` 能取到该 SKU；生成当刻 MRP 取不到 DRAFT。
25. 前端无「复制 BOM」文案；物料向导无新的复制 BOM 开关。
26. `POST /bill-of-materials` 单笔头仍可建，行为与现网一致。
27. 不分色款：preview 一行无色；`COLOR_MATCH` 查找 `color_id IS NULL`。
28. `isBackflush = null` 落库 null（不是 false），工单展开仍走工厂默认。
29. 同请求 preview 两次结果稳定（同数据）。preview 后再人手插同版本，generate 对该格 400 或按「状态与 preview 不一致」拒绝整批，**不得**覆盖。
30. 全文无 MM 模块 import PP BOM repository；无 `lychee-erp-pp` import `com.lychee.erp.mm`；无 `lowLevelCodeService` 出现在 generate。
31. `FIXED` 面料 `quantity=1.20`，`sizeQuantities`：S=1.10、XL=1.40，M 未列；勾选 S/M/XL 各一色：S 行 1.10 且 `usedDefaultQuantity=false`，M 行 1.20 且 `usedDefaultQuantity=true`，XL 行 1.40；同码另一色用量相同。
32. `COLOR_MATCH` + 同上按码表：海军蓝 XL 与黑色 XL 子件不同色、用量都是 1.40。
33. `sizeQuantities` 含本款尺码组外的 `productSizeId`：模板 400，不落库。
34. 同一行两个相同 `productSizeId`：模板 400。
35. 按码 `quantity=0` 或负：模板 400。
36. 请求带 `percent` / `scalePercent` 字段：忽略或不进 DTO，不得按 % 算（契约只有绝对量）。
37. 生成后 `GET /{id}/items`：S 的 SKU 该行 `quantity=1.10`，M 的 SKU 该行 `1.20`；`scrap_rate` 未因按码表改变。
38. preview `RESOLVED` 行带 `baseUnitCode` / `baseUnitName`（与子件基本单位一致）。
39. 步骤 2 只勾 4 个尺码：步骤 3 只出现这 4 列；组内未勾尺码不出现、也不因缺列变坏格。
40. 向导是 90% Drawer，不是 70% Modal。
