# 01. 现状与问题（As-Is）

> 依据现网：`MaterialServiceImpl`、`FashionVariantCodeGenerator`、`MaterialVariantServiceImpl`、`material_images`、`MaterialImageHelper`、FO/SO 打印、V1/V2 设计。

---

## 1. 注记写入已经对齐分类，本期不再拆开

V2 落库：

```text
create/update 物料
  policy = 分类树向上解析的 code_strategy
  is_fashion_variant = (policy == FASHION_VARIANT)
```

`MaterialRequest` 没有该字段；`MaterialMapper` `ignore`。矩阵生成走 `createMaterial`，分类已拦截为 `FASHION_VARIANT`，生成行一定是 `true`。

`MANUAL` 发号器只验 code 非空 / 长度 / 租户内不重复，**不进** `validateVariantDimensions`。这是 OEM「挂同一版型、不占格」的正确行为，不能改成「有 `productModelId` 就 true」。

曾评估过第三条路：MANUAL 料号 + 用户勾选 `is_fashion_variant`，让客供号占正品格。`MaterialForm` 已按分类策略分叉（编码、款色码必填/折叠、建议码、尺码组缺失、三维锁定）；再加开关还要切换颜色/尺码组件、防止建议码冲掉手工号、隐藏后重置字段。**复杂度和回归面不划算，本期明确不做。** 要占格、要挡住组合生成，只能进变体分类并接受公式码。

---

## 2. `is_fashion_variant` 现网已经是切面钥匙

写入抄分类，**读取**按行标记：

| 行为 | 是否只看 `true` |
|------|-----------------|
| 部分唯一索引 `uk_materials_tenant_fashion_variant_*` | 是 |
| `findVariant` / `assertVariantUnique` / 组合生成 `EXISTS` | 是 |
| 尺码组锁定、本款色 `in_use`、色字母不可改、色模式锁定 | 是 |
| 保存后款/色/码不可改（`existing.isFashionVariant`） | 是 |
| BOM 按款生成父件准入 | **否**（有意不看） |

列保留。查询语义不变。本期不改写入公式，只补变体保存时的尺码组硬校验。

---

## 3. 变体尺码可以游离在尺码组外

`FashionVariantCodeGenerator` 已要求 `productModelId`、`productSizeId` 必填，然后调用 `validateVariantDimensions`。现网：

```text
if (productSizeId != null && model.sizeGroupId != null)
    才检查尺码 ∈ 尺码组
```

款号**未绑尺码组**时整段跳过。结果：变体 SKU 可以带着组外尺码落库。之后该款绑组、向导发号或 `SizeSkuAllocator` 都会踩 `size.notInGroup`。前端 `fashionSizeGroupMissing` 只挡 UI，API 可绕过。

## 4. 图片挂在 SKU 上，和 FO/SO 消费粒度不一致

```text
material_images.material_id → 单一尺码 SKU
OSS：{tenant}/material/{materialCode}/...
上传入口：物料保存之后，MaterialForm 内 MaterialImageManager
列表主图：fillPrimaryImages 只认本 SKU 的 is_primary
删除：现网 deleteImage(imageId) 未校验路径上的 materialId
```

一款 5 色 × 8 码要传 40 次，或只传在某一个码上。同色其它码列表显示缺图。删图会删 OSS；若按 Wave C 复制同一 `file_path`，删一个尺码会打掉整色文件。

FO/SO 已按 `(productModelId, colorId)` 出样图框，再在本单 SKU 里挑 `min(materialId)` 的 primary——**消费按款色，存储按尺码**。V1 Wave C「同款同色复制到新 SKU」会把错误粒度再复制 N 份，本专题明确不作。

现网没有 `code_strategy = FASHION_VARIANT` 的分类资料，也没有需要补刷的变体注记。旧图全部在 `material_images`。若「变体只读款色、不回退」且不做迁图，列表和打印会集体缺图。

---

## 5. 本专题要修什么 / 不修什么

修：

1. 变体保存：尺码必填、款号必须已绑尺码组、尺码必须在组内。
2. 新建 `product_model_images`；款号 / 本款色抽屉独立上传。
3. 物料图 API 保持 SKU 粒度，补属主校验；**不做**门面改写款色表。
4. 列表 / 详情 / FO/SO：有款号则款色 primary 优先，没有再回退 SKU 图。

不修：

- 用户改 `is_fashion_variant`；`MaterialRequest` 不增加该可写字段。
- 存量注记打标、OSS 迁图、运行时 SKU→款色 copy。
- BOM、工厂物料、库存仍 SKU。
- 分类 `code_strategy` 继承、号池、组合生成仍只允许变体分类。
- 跨变体/非变体改分类的 `strategyMismatch`（本期维持）。
- 把 `product_models` 并进物料、给物料加 `parent_id`。
