# 04. 实施清单（开发入口）

> 流程以 [02](./02-目标流程.md) 为准；DDL 以 [03](./03-schema与数据模型.md) 为准。

建议两波交付：Wave 1 尺码组硬校验可单独上。Wave 2 款色图不依赖注记语义，但 Helper 要同时能读两张表。

| 波次 | 内容 | 可否单独上 |
|------|------|------------|
| 1 | `validateVariantDimensions` 尺码组必填且尺码在组内；单测 | 可以 |
| 2 | `product_model_images`、款色 API、Helper 优先回退、本款色抽屉、物料图属主校验 | 可以（不依赖 1） |

禁止在 `generateVariants` 上实现 `copyImages`。禁止物料图 API 改写 `product_model_images`。

## 1. 审查结论（未确认项已锁定）

对话已确认：不做用户改注记、不做组合 ③、图不跟注记走、两套 API 各自管、不做存量打标与迁图、变体尺码必须在已绑尺码组内。实现不得再分叉回「表单 Switch / 物料门面 / ETL」。

## 3. API

### 3.1 物料保存

`POST/PUT /api/v1/mm/materials` **不增加** `isFashionVariant`。变体分类走现网发号器；`validateVariantDimensions` 按 02 §2.2 收紧尺码组。更新：`code` 仍不可变、仍不发号。

### 3.2 物料图片（仅 SKU，路径不变）

`/api/v1/mm/materials/{materialId}/images` 现网动词不变，**只**读写 `material_images`。

| 方法 | 校验 |
|------|------|
| GET / POST upload | 物料存在；OSS 写入 `{tenant}/material/{materialCode}/...` |
| DELETE `/{imageId}` | 服务 `deleteImage(materialId, imageId)`；行存在且 `image.materialId` 相等，否则 404；只删该行 OSS |
| POST `/{imageId}/set-primary` | 现网已传 `materialId`；目标行必须属于该物料 |

禁止用物料路径的 `imageId` 去删 `product_model_images`。

### 3.3 款色图（新）

权限：`/mm/product-models:read` / `:update`。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/mm/product-models/{modelId}/images?colorId=` | `colorId` 省略表示不分色键（NULL）。分色款必须传本款色 |
| POST | `.../images/upload?colorId=` | multipart，规则同物料图（含前端 100KB） |
| DELETE | `.../images/{imageId}` | `deleteImage(modelId, imageId)`；属主不符 404 |
| POST | `.../images/{imageId}/set-primary` | 先 `clearPrimary` + Flush，再设目标 `true`（见决策 28） |

上传前校验：款号存在；**与本款色池一致**——分色则 `colorId` 必须在 `product_model_colors`；不分色则禁止传 `colorId`（键为 NULL）。池外色 400，不落库。OSS 只写 `product-model/` 前缀。

## 4. 改动面

### 4.1 后端

| 点 | 做 |
|----|----|
| `MaterialVariantServiceImpl.validateVariantDimensions` | `productSizeId != null` 时：无 `sizeGroupId` → `sizeGroup.required`；否则尺码必须 ∈ 组。**不要**保留 `&& sizeGroupId != null` 短路 |
| `FashionVariantCodeGenerator` | 发号不变；校验已要求尺码，组检查放在 `validateVariantDimensions` 即可 |
| `MaterialRequest` / Mapper / `MaterialServiceImpl` 注记写入 | **不改** |
| `ProductModelImage` 实体仓储 | Wave 2。须有 `clearPrimary(modelId, colorId)`（`colorId` 可空） |
| `ProductModelImageService.setPrimaryImage` | **禁止** `saveAll` 同时改多行。`clearPrimary` + Flush → 目标 `true` + `save` |
| `MaterialImageService` | 签名改为 `deleteImage(Long materialId, Long imageId)`；实现校验属主。Controller 把 path 上的 `materialId` 传下去。**不**按注记分流 |
| `MaterialImageHelper.fillPrimaryImages` | 增加提取器重载（`materialId` + `productModelId` + `colorId`）。`getMaterialPage` / `getMaterialResponse` 用 `MaterialResponse` 已有字段，**禁止** Helper 内再按 id 查物料。流程：① 批量查款色 primary（`productModelIdIn`）按 `(model, color)` 入 Map；② 未命中的 `materialId` 再批量查 SKU primary。最多 2 次查询 |
| `resolvePrimaryImageDataUris` | Wave 2：每个 `ModelColorKey` 先查款色 primary，没有再 `min(materialId)` SKU 图 |
| `ProductModelServiceImpl.replaceProductModelColors` | 去掉的色有款色图则 400（`images.in_use`），先于落库；**不**删图 |
| 删款号 | 有款色图则 400，不级联 |
| 单测 | 见 §6 |

旧三参 `fillPrimaryImages(tenantId, items, materialIdExtractor, ...)` 可保留给没有款色字段的调用方（只走 SKU）。有款号的列表必须走新重载。**不要**用 `isFashionVariant` 决定走哪张表。

款色设主图：

```java
productModelImageRepository.clearPrimary(modelId, colorId); // UPDATE is_primary = false；colorId 可 null
productModelImageRepository.flush();
targetImage.setIsPrimary(true);
productModelImageRepository.save(targetImage);
```

`fillPrimaryImages` 新重载（`getMaterialPage` 已有 `MaterialResponse.productModelId` / `colorId`，直接传入）：

```java
public <T> void fillPrimaryImages(Long tenantId, List<T> items,
        Function<T, Long> materialIdExtractor,
        Function<T, Long> productModelIdExtractor,
        Function<T, Long> colorIdExtractor,
        BiConsumer<T, String> urlSetter,
        BiConsumer<T, String> thumbnailUrlSetter)
```

删图：`MaterialImageService.deleteImage(Long materialId, Long imageId)`；属主不符抛 `NotFoundException`。Controller 现有 path `materialId` 必须传进服务，禁止继续只调 `deleteImage(imageId)`。

## 7. 明确不做

- 用户改 `is_fashion_variant`（表单 Switch、请求可写字段、true↔false 可逆）
- 变体分类允许 `is_fashion_variant = false`
- 按 `productModelId` 自动 true
- MANUAL / SEQUENTIAL 勾选占正品格
- 物料图 API 门面到 `product_model_images`
- 按注记或分类策略决定读写哪张图表
- 存量注记打标、OSS 迁图、运行时 SKU→款色 copy
- Wave C `copyImages`
- 图挂 `product_model_colors.id`
- 多态一张 `owner_type` 图片表
- 指定「规范 SKU」当图主人
- 从 `SizeSkuAllocator` 排除已占格变体尺码（会导致后续码重排）
- 本期开放跨 `FASHION_VARIANT` 改分类
- 把 BOM / 工厂物料提升到款色
- 本款删色 / 删款号时级联删图或 OSS
- 款色设主图用 `saveAll` 同时翻转多行
- Helper 按 `materialId` 回表物料再取款色
- 方案 B：款号列表操作列另开「款图」按钮
