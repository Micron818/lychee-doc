## 1. 审查结论

方向正确，可以开工：这是把生产转单作业对齐采购工作台 + 销售订单智能批量，**不是**改 MRP 算法，也不是算完自动转单。

| 问题 | 结论 |
|------|------|
| 会不会变成计算后自动转 PLO | **否**。待转仍要人勾选提交 |
| 要不要跳过 PLO 出 MO | **否** |
| 结果页是否保留「转计划单」POST | **否**，只跳转，与 PURCHASE 对称 |
| 旧 `convert-to-planned-orders` | **删除**，只留 `from-mrp-results` |
| 待转是否跨历史 Run | **否**，与采购同一套最新 Run |
| `hasProtectedOrder` 静默 skip | **改为**列表禁用 + 提交整批失败 |
| firm/unfirm 静默忽略 | **改为**整批校验失败 |
| 转 MO 是否必须先 FIRMED | **否**，维持现网 PROPOSED 可转；只改 tooltip |
| PROPOSED+FIRMED 混选转 MO | **允许** |
| 新权限 / 新菜单 | **否** |
| 与采购工作台共用组件 | **否**（无供应商/部分转）；只抄 PageContainer Tab 与最新 Run 查询 |
| Tab 是否抄采购 `useState(workspace)` | **否**。从 URL 派生，否则结果页跳转会脱节 |
| 空选时 `every` 算出可转 MO / 可删 | **否**。必须先 `hasSelected` |
| 待转分页逐行查保护 | **否**。Pegging 一次 + 保护对一次，固定 2 次 SQL |
| 待转 `factoryId` 初值 | 工作台 `key={factoryId ?? 'all'}`，换厂要重挂载 |
| `from-mrp-results` 加锁顺序 | **id 升序**；最新 Run 按厂缓存 |
| 行内是否保留 MoreActions | **否**，删除组件；`buildActions({ onEdit, onPegging })` |
| 转单响应是否二次 fetch | **否**，只保证 `id` / `orderNo` |
| 删除按钮空选 tooltip | **不传** forbidden；对齐销售订单 `emptyTooltip` |

未改业务代码。编码从 §5 按模块推进。

## 3. 实现约定

### 3.1 最新 Run 与加锁

复用 `MrpServiceImpl.findLatestCoveringOperativeRunId` / `findCoveringOperativeRuns`，**不要**复制第三套定义。待转分页的 subquery 与 `findPendingPurchaseItems` 同构，仅动作类型与状态不同。

fetch 必须写点路径（`baseUnit` 为 LAZY）：

```text
DynamicSpecifications.fetch("material.baseUnit", "factory", "mrpRun")
```

`from-mrp-results`：

1. `mrpResultIds` **升序**后再 `findByIdForUpdate`（防交叉勾选死锁）
2. 与采购 `lockAndValidateForConvert` 对等的生产校验（PRODUCTION、最新 Run、remaining>0、非保护）
3. 同事务 `Map<Long, Long>` 按 `factoryId` 缓存最新 Run，跨厂一批提交时也不要每行重查

### 3.2 保护行

待转分页出数后，对当前页计算 `convertible` / `blockReason`。语义同现网 `hasProtectedOrder`（FO + 同物料 + FIRMED/CONVERTED）。无 FO pegging 的组件层建议：视为可转。

`hasProtectedOrder` 留给转单逐条校验。分页在 `MrpServiceImpl.findPendingProductionItems` 里固定两跳（契约见 [03](./03-schema设计.md) §4）：

1. `orderPeggingRepository.findBySupplyTypeAndSupplyIdIn(MRP_RESULT, 本页 ids)`
2. `plannedOrderRepository.findProtectedFoItemMaterialPairs(foItemIds, materialIds, {FIRMED, CONVERTED})`  
   `foItemIds` 为空则跳过本步

禁止对本页循环 `hasProtectedOrder`。`IN` 空集合不要发给 JPQL。

### 3.3 前端批量启用

不要只抄销售订单的「全部同一状态」。PLO 用行规则聚合。  
**空数组 `.every()` 为 true**，转 MO / 删除必须先挡空选：

```text
hasSelected  = (selectedRows?.length ?? 0) > 0
allProposed  = hasUniformStatus(..., 'PROPOSED')
allFirmed    = hasUniformStatus(..., 'FIRMED')
canConvertMo = hasSelected && selectedRows.every(r => getPlannedOrderRowActions(r).canConvertToMo)
canDelete    = hasSelected && selectedRows.every(r => getPlannedOrderRowActions(r).canDelete)
```

`ExecuteButton.disabled` / `tooltipId` 按上表；execute 内仍 `assertBulkStatus`（仅 firm/unfirm）或手写 `canConvertMo` / `canDelete` 失败提示。  
`BatchDeleteButton` 在 `!canDelete` 时也要 `disabled`。`tooltipId` 对齐销售订单，**空选不要传** `bulkDeleteConvertedForbidden`（组件优先用传入值，会倒挂成「不能删已转单」）：

```text
emptyTooltip    = !hasSelected ? 'pages.common.noRowsSelected' : undefined
deleteTooltipId = canDelete ? undefined : (emptyTooltip ?? 'pages.pp.plannedOrders.bulkDeleteConvertedForbidden')
```

`tableAlertRender` **打开**（现网是 `false`）。

### 3.3.1 计划工单页 Tab

```text
const currentTab = resolveWorkspace(searchParams.get('tab'))
```

不要 `useState(() => resolveWorkspace(...))`。`onTabChange` 只改 URL；结果页 `history.push(?tab=mrp)` 必须立刻切到待转。

`ProTable` 的 `form.initialValues` 只在挂载时生效。待转工作台必须带动态 key，换 `factoryId` 时重挂载，避免搜索工厂残留：

```text
<MrpProductionWorkbench key={factoryId ?? 'all'} factoryId={factoryId} />
```

### 3.6 测试

- `convertToPlannedOrders`：最新 Run 才转；旧 Run 400；保护行 400；成功建 PLO+pegging+CONVERTED；返回含 `orderNo`
- 待转分页：只含最新 Run PRODUCTION OPEN；保护行 `convertible=false`；组件层无 FO peg 仍 `convertible=true`；单位字段有值（`material.baseUnit` 已 fetch）；保护判定不循环 `hasProtectedOrder`
- firm：混入 FIRMED → 失败且库不变
- 前端：结果页 PRODUCTION 无 convert POST（单测或 e2e 能做再做；至少手工验收）
- 手工：空选时转 MO / 删除禁用，删除按钮 tooltip 为「请先选择」而非「不能删已转单」；`?tab=mrp` 深链切到待转

现网若无 `MrpConversionService` 测试，本波补关键路径，不要只靠 UI。

1. 后端：pending 查询 + from-mrp-results（含校验）+ 删除旧 convert 端点 + firm/unfirm 收紧 + 测试
