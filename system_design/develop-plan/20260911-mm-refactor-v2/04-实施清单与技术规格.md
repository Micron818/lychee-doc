### 2.2 物料保存与批量生成接口规格适配

#### A. 单笔物料保存接口（`POST /api/mm/materials`）
* **接口契约调整**：
  - DTO `MaterialRequest.code` 字段移除非空约束（允许前端传空），保留 `@Size(max = 50)`；
  - 必填性由业务策略层校验：
    - `SEQUENTIAL`：在前端界面交互中，编码输入框强制只读置灰且传空，由 `SequentialCodeGenerator` 原子发号并写入，接口响应实体返回正式生成的 `code`；仅当通过外部 API、数据迁移或未来批量导入等集成通道显式提供了非空 `code` 时，系统才原样校验唯一性并落库；
    - `FASHION_VARIANT`：前端通过款式色码动态回填建议编码，保存时由 `FashionVariantCodeGenerator` 严格核验公式并写入流水；
    - `MANUAL`：前端必填 `code`，后端校验唯一性与长度。

#### B. 变体向导批量生成接口（`POST /api/mm/materials/variant-generate`）
* **强安全拦截**：
  - 后端在接收到请求时，首先根据 `request.getCommon().getMaterialCategoryId()` 调用分类策略解析服务；
  - 若 `policy.getStrategy() != CodingStrategyEnum.FASHION_VARIANT`，直接抛出 400 业务异常（`validation.material.variant.generate.notFashionVariantCategory`），彻底杜绝非变体物料被向导批量生成。

### 3.2 序列号发号器（`SequentialCodeGenerator`）与手工生成器实现要点

```java
@Service
@RequiredArgsConstructor
public class SequentialCodeGenerator implements MaterialCodeGenerator {

    private final SysDocSequenceRepository sequenceRepository;
    private final MaterialRepository materialRepository;

    @Override
    public CodingStrategyEnum getStrategy() {
        return CodingStrategyEnum.SEQUENTIAL;
    }

    @Override
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public String allocateCode(MaterialRequest request, EffectiveCodingPolicy policy) {
        // 1. 若外部接口显式提供了编码（如数据迁移/外部集成），直接采用并校验唯一性
        if (StringUtils.hasText(request.getCode())) {
            return request.getCode().trim();
        }

        Long tenantId = CurrentTenant.tenantId();
        String seqKey = "MATERIAL_CAT:" + policy.getSeqScopeCategoryId();
        int length = policy.getSeqLength() != null ? policy.getSeqLength() : 5;
        String prefix = StringUtils.hasText(policy.getEffectivePrefix()) 
                ? policy.getEffectivePrefix() 
                : policy.getCategoryCode();
        String datePart = "";
        if (StringUtils.hasText(policy.getDateFormat())) {
            try {
                datePart = LocalDate.now().format(DateTimeFormatter.ofPattern(policy.getDateFormat())) + "-";
            } catch (IllegalArgumentException ex) {
                throw new ValidationException("validation.material.code.datePattern.invalid");
            }
        }

        // 2. 循环自增取号 (最多重试 3 次，防止手工输入料号偶然占用了未来流水号)
        for (int retry = 0; retry < 3; retry++) {
            Long nextVal = sequenceRepository.incrementAndGetSequence(seqKey, tenantId);
            String paddedSeq = String.format("%0" + length + "d", nextVal);
            String candidateCode = prefix + "-" + datePart + paddedSeq;

            if (candidateCode.length() > 50) {
                throw new ValidationException("validation.material.code.overflow");
            }
            if (!materialRepository.existsByCode(candidateCode)) {
                return candidateCode;
            }
        }

        throw new ConflictException("validation.material.code.duplicate");
    }

    @Override
    public void validate(Material existing, MaterialRequest request, EffectiveCodingPolicy policy) {
        if (StringUtils.hasText(request.getCode())) {
            if (request.getCode().length() > 50) {
                throw new ValidationException("validation.material.code.size");
            }
            Long excludeId = existing != null ? existing.getId() : null;
            boolean duplicate = excludeId == null
                    ? materialRepository.existsByCode(request.getCode())
                    : materialRepository.existsByCodeAndIdNot(request.getCode(), excludeId);
            if (duplicate) {
                throw new ValidationException("validation.material.code.duplicate");
            }
        }
    }
}
```

@Service
@RequiredArgsConstructor
public class ManualCodeGenerator implements MaterialCodeGenerator {

    private final MaterialRepository materialRepository;

    @Override
    public CodingStrategyEnum getStrategy() {
        return CodingStrategyEnum.MANUAL;
    }

    @Override
    public String allocateCode(MaterialRequest request, EffectiveCodingPolicy policy) {
        // 手工录入模式：原样返回用户键入并经过 trim 的编码
        return request.getCode() != null ? request.getCode().trim() : null;
    }

    @Override
    public void validate(Material existing, MaterialRequest request, EffectiveCodingPolicy policy) {
        if (!StringUtils.hasText(request.getCode())) {
            throw new ValidationException("validation.material.code.required");
        }
        if (request.getCode().length() > 50) {
            throw new ValidationException("validation.material.code.size");
        }
        Long excludeId = existing != null ? existing.getId() : null;
        boolean duplicate = excludeId == null
                ? materialRepository.existsByCode(request.getCode())
                : materialRepository.existsByCodeAndIdNot(request.getCode(), excludeId);
        if (duplicate) {
            throw new ValidationException("validation.material.code.duplicate");
        }
        // 注意：MANUAL 策略允许可选填入 productModelId 与 productSizeId (OEM代工场景)，
        // 但绝不触发变体尺码组强制与排他校验，落库时 is_fashion_variant 标记为 false
    }
}

### 3.3 变体策略门面（`FashionVariantCodeGenerator`）与变体服务切面改造

现网 `MaterialServiceImpl` 中对所有新增和修改物料**无条件调用** `materialVariantService.validateAndAllocateOnSave`，导致所有带款号尺码的物料都被当作变体处理。
**核心改造**：
1. `MaterialServiceImpl` 移除对变体服务的直接依赖，全部委托给 `MaterialCodeGeneratorFactory`；
2. 仅在策略为 `FASHION_VARIANT` 时由 `FashionVariantCodeGenerator` 触发变体服务；
3. `MaterialVariantService` 内部所有变体查重与状态机（`findVariant`, `assertVariantUnique`, `assertColorModeForSave`, `persistAllocatedTokens`）全部收敛于 `is_fashion_variant = true` 切面：

```java
@Service
@RequiredArgsConstructor
public class FashionVariantCodeGenerator implements MaterialCodeGenerator {

    private final MaterialVariantService materialVariantService;

    @Override
    public CodingStrategyEnum getStrategy() {
        return CodingStrategyEnum.FASHION_VARIANT;
    }

    @Override
    public String allocateCode(MaterialRequest request, EffectiveCodingPolicy policy) {
        // 委托变体服务：分配款×色×尺码流水 Token 并拼接标准变体编码 (如 A12345-A01)
        return materialVariantService.resolveOrAllocateCode(request);
    }

    @Override
    public void validate(Material existing, MaterialRequest request, EffectiveCodingPolicy policy) {
        // 委托变体服务：校验款号必填、尺码组有效性、本款颜色、模式锁定以及变体排他查重 (仅排他 is_fashion_variant=true 的物料)
        materialVariantService.validateVariantDimensions(existing, request);
    }
}
```

### 3.4 物料主服务核心调度编排（`MaterialServiceImpl`）

```java
@Override
public MaterialResponse createMaterial(MaterialRequest request) {
    // 1. 外键合法性校验 (分类、类型等基础字典)
    validateForeignKeys(request);

    // 2. 解析分类生效策略与路由发号器
    EffectiveCodingPolicy policy = materialCategoryService.resolvePolicy(
            request.getMaterialCategoryId(), CurrentTenant.tenantId());
    MaterialCodeGenerator generator = generatorFactory.getGenerator(policy.getStrategy());

    // 3. 策略前置校验 (existing 为 null)
    generator.validate(null, request, policy);

    // 4. 分配正式物料编码 (SEQUENTIAL 自动算号、FASHION 拼公式、MANUAL 原样使用)
    String allocatedCode = generator.allocateCode(request, policy);
    request.setCode(allocatedCode);

    // 5. 编码全局防重校验
    if (materialRepository.existsByCode(allocatedCode)) {
        throw new ValidationException("validation.material.code.duplicate");
    }

    Material entity = materialMapper.toEntity(request);
    // 关键物化标记落库：仅变体策略标记为 true
    entity.setIsFashionVariant(policy.getStrategy() == CodingStrategyEnum.FASHION_VARIANT);
    applyDefaultValuationClass(entity, request);
    if (entity.getLowLevelCode() == null) {
        entity.setLowLevelCode(0);
    }

    // 6. 持久化落库与异常精细转译
    try {
        entity = materialRepository.saveAndFlush(entity);
    } catch (DataIntegrityViolationException ex) {
        handleDataIntegrityViolation(ex);
    }
    return materialMapper.toResponse(entity);
}

@Override
public MaterialResponse updateMaterial(Long id, MaterialRequest request) {
    Material entity = materialRepository.findById(id)
            .orElseThrow(() -> new NotFoundException("validation.common.not.found"));

    // 1. 物料编码不可变性校验 (严禁改号，入参为空时沿用原号，绝对不重新发号)
    if (StringUtils.hasText(request.getCode()) && !entity.getCode().equals(request.getCode())) {
        throw new ValidationException("validation.material.code.immutable");
    }
    request.setCode(entity.getCode());

    // 2. 外键校验与分类策略解析
    validateForeignKeys(request);
    EffectiveCodingPolicy targetPolicy = materialCategoryService.resolvePolicy(
            request.getMaterialCategoryId(), CurrentTenant.tenantId());
    EffectiveCodingPolicy currentPolicy = materialCategoryService.resolvePolicy(
            entity.getMaterialCategoryId(), CurrentTenant.tenantId());

    // 3. 分类跨策略变更控制
    boolean isCurrentFashion = currentPolicy.getStrategy() == CodingStrategyEnum.FASHION_VARIANT;
    boolean isTargetFashion = targetPolicy.getStrategy() == CodingStrategyEnum.FASHION_VARIANT;
    if (isCurrentFashion != isTargetFashion) {
        // 变体与非变体之间绝对禁止跨策略修改分类
        throw new ValidationException("validation.material.category.strategyMismatch");
    }

    MaterialCodeGenerator generator = generatorFactory.getGenerator(targetPolicy.getStrategy());

    // 4. 执行策略更新校验 (传入 existing = entity，校验维度不可变性并排除自身)
    generator.validate(entity, request, targetPolicy);

    // 5. 实体更新与持久化 (不调用 allocateCode)
    materialMapper.updateEntity(request, entity);
    entity.setProductModelId(request.getProductModelId());
    entity.setColorId(request.getColorId());
    entity.setProductSizeId(request.getProductSizeId());
    entity.setIsFashionVariant(isTargetFashion);
    applyDefaultValuationClass(entity, request);

    try {
        entity = materialRepository.saveAndFlush(entity);
    } catch (DataIntegrityViolationException ex) {
        handleDataIntegrityViolation(ex);
    }
    return materialMapper.toResponse(entity);
}

private void handleDataIntegrityViolation(DataIntegrityViolationException ex) {
    String msg = ex.getMessage() != null ? ex.getMessage() : "";
    if (msg.contains("uk_materials_tenant_fashion_variant")) {
        throw new ValidationException("validation.material.variant.duplicate");
    } else if (msg.contains("uk_materials_tenant_code")) {
        throw new ValidationException("validation.material.code.duplicate");
    }
    throw new ValidationException("validation.material.save.conflict");
}

### 3.5 物料分类治理与权限规格（`MaterialCategoryServiceImpl` 校验与 RBAC）

分类的新增与更新（`createMaterialCategory` / `updateMaterialCategory`）及删除（`deleteMaterialCategoryBulk`）必须严格依照 02 §4.3 实现全量业务校验逻辑：

#### A. 核心校验逻辑规格
```java
// 1. 物料引用时策略锁定 (已有物料禁止修改 code_strategy)
private void validateStrategyLockOnUpdate(MaterialCategory existing, MaterialCategoryRequest request) {
    if (!Objects.equals(existing.getCodeStrategy(), request.getCodeStrategy())) {
        List<Long> subtreeIds = getSubtreeCategoryIds(existing.getId());
        if (materialRepository.existsByMaterialCategoryIdIn(subtreeIds)) {
            throw new ValidationException("validation.materialCategory.codeStrategy.locked");
        }
    }
}

// 2. 层级移动 (parent_id 变更) 治理门禁
private void validateParentChange(MaterialCategory existing, MaterialCategoryRequest request) {
    if (!Objects.equals(existing.getParentId(), request.getParentId())) {
        List<Long> subtreeIds = getSubtreeCategoryIds(existing.getId());
        boolean hasMaterials = materialRepository.existsByMaterialCategoryIdIn(subtreeIds);
        
        // 2.1 子树已有物料时，禁止跨变体/非变体策略移动父节点
        if (hasMaterials) {
            EffectiveCodingPolicy oldPolicy = resolvePolicy(existing.getId(), CurrentTenant.tenantId());
            EffectiveCodingPolicy newPolicy = simulatePolicyWithNewParent(existing, request.getParentId());
            boolean wasFashion = oldPolicy.getStrategy() == CodingStrategyEnum.FASHION_VARIANT;
            boolean willFashion = newPolicy.getStrategy() == CodingStrategyEnum.FASHION_VARIANT;
            if (wasFashion != willFashion) {
                throw new ValidationException("validation.materialCategory.parent.hasMaterials");
            }
        }

        // 2.2 若共用号池已实际发号，禁止变更父级导致号池属主漂移
        if (Boolean.TRUE.equals(existing.getIsSeqShared()) || Boolean.TRUE.equals(request.getIsSeqShared())) {
            String oldSeqKey = "MATERIAL_CAT:" + resolvePolicy(existing.getId(), CurrentTenant.tenantId()).getSeqScopeCategoryId();
            if (sequenceRepository.existsByTenantIdAndSeqKey(CurrentTenant.tenantId(), oldSeqKey)) {
                Long newScopeCatId = calculateSeqScopeCategoryId(request.getParentId(), request.getIsSeqShared());
                if (!Objects.equals(oldSeqKey, "MATERIAL_CAT:" + newScopeCatId)) {
                    throw new ValidationException("validation.materialCategory.parent.seqScopeChanged");
                }
            }
        }
    }
}

// 3. 共用号池合法性门禁 (父级有效策略必须为 SEQUENTIAL)
private void validateSharedPoolEligibility(MaterialCategoryRequest request) {
    if (Boolean.TRUE.equals(request.getIsSeqShared())) {
        if (request.getParentId() == null) {
            throw new ValidationException("validation.materialCategory.shared.parentNotSequential");
        }
        EffectiveCodingPolicy parentPolicy = resolvePolicy(request.getParentId(), CurrentTenant.tenantId());
        if (parentPolicy.getStrategy() != CodingStrategyEnum.SEQUENTIAL) {
            throw new ValidationException("validation.materialCategory.shared.parentNotSequential");
        }
    }
}

// 4. 发号后锁定号池配置与分类代码
private void validatePrefixAndCodeLockAfterIssued(MaterialCategory existing, MaterialCategoryRequest request) {
    String seqKey = "MATERIAL_CAT:" + resolvePolicy(existing.getId(), CurrentTenant.tenantId()).getSeqScopeCategoryId();
    if (sequenceRepository.existsByTenantIdAndSeqKey(CurrentTenant.tenantId(), seqKey)) {
        if (!Objects.equals(existing.getIsSeqShared(), request.getIsSeqShared())
                || !Objects.equals(existing.getCodePrefix(), request.getCodePrefix())) {
            throw new ValidationException("validation.materialCategory.seqKey.locked");
        }
        // 若自身未配前缀（默认以 code 作为前缀），锁定 code 不可更名
        if (!StringUtils.hasText(existing.getCodePrefix()) && !existing.getCode().equals(request.getCode())) {
            throw new ValidationException("validation.materialCategory.seqKey.locked");
        }
    }
}

#### B. 权限控制（RBAC）规范
物料分类编码策略及流水号池配置关乎企业主数据资产的一致性，需依现网规范实施权限收敛：
* **接口权限注解**：
  - 新增分类：`@PreAuthorize("hasAuthority('/mm/material-categories:create')")`
  - 修改分类与策略：`@PreAuthorize("hasAuthority('/mm/material-categories:update')")`
  - 删除分类：`@PreAuthorize("hasAuthority('/mm/material-categories:delete')")`
  - 查询分类树与有效策略：`@PreAuthorize("isAuthenticated()")`（供表单实时解析与物料下拉树使用）
* **岗位职责角色划分**：
  - 编码策略（`codeStrategy`）、前缀（`codePrefix`）与共用号池（`isSeqShared`）配置项仅对拥有 `/mm/material-categories:update` 权限的**基础数据管理员（Master Data Admin）**或**商品企划主管**开放；
  - 研发、采购及仓库操作人员仅具备分类查看与物料建档权限，无权更改分类编码体系。
