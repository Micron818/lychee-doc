## 1. 目标与范围

从工厂订单（FactoryOrder）列表或详情发起「打印」，以 **A4 横向（landscape）** 标准单据版式呈现业务接单确认内容：公司抬头、客户、FO 头信息、**尺码矩阵明细**（型号/客户PO/颜色单元格合并）、**数量合计**、产品样图、签核栏。预览与打印共用服务端 PDF 单一版式。

| 纳入 | 不纳入（本期） |
|------|----------------|
| 单张 FO 的 PDF 预览 + 浏览器打印 | 前端 HTML 打印页 / `/print` 深链（禁止双轨） |
| `sourceType = SALES_ORDER` 且经 `OrderPegging` 关联到 SO 的明细 | `MANUAL` 来源 FO（无 SO pegging） |
| 尺码横向矩阵、样图横排、DRAFT 水印 | **单价、金额、币别**（本期不展示、不合计） |
| （建议同期）归档下载走导出作业 | Excel 模板版、统计分析、邮件外发 |

**报表名称（三语）**

| locale | 名称 |
|--------|------|
| zh-CN | 工厂订单报表 |
| en-US | Factory order report |
| vi-VN | Báo cáo đơn hàng nhà máy |

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 产出物 | **PDF 预览 + 打印**为主；版式对齐订购单（Thymeleaf + openhtmltopdf） |
| 2 | 纸张 | **A4 landscape**（Size 数量不固定，需横向容纳动态列） |

| 6 | 单价 / 金额 | **不需要**；明细与合计均不展示金额相关字段 |

| 11 | 制表人 | `FactoryOrder.createdBy` |
| 12 | 审核人 | `FactoryOrder.confirmedBy`（未确认时可空） |
| 13 | 主管 | 固定标签「主管:」，签名区留白 |
| 14 | DRAFT | **允许打印**，模板加「草稿」水印（对齐订购单） |
| 15 | CONFIRMED 及之后 | 正常正式版式，无草稿水印 |

## 3. 总体流程

```
前端 FO 列表/详情 [打印]
   │  PdfPreviewModal + getFactoryOrderPdfBlob(id)
   ▼
GET /api/v1/pp/factory-orders/{id}/pdf     ← read，inline，不建作业、不落 OSS
   │
   ▼
FactoryOrderPdfRenderer.renderOne(id, locale)
   ├─ FactoryOrderPrintService.getPrintData(id)
   │     ├─ 校验存在；MANUAL → 业务错误
   │     ├─ FO 头 + Company（factory→company）+ Customer
   │     ├─ FO Items → OrderPegging(SALES_ORDER) → SO Item / SO
   │     ├─ Material → ProductModel / Color / ProductSize / Unit
   │     ├─ 组装矩阵行 + sizeColumns 联集 + 数量合计
   │     ├─ 计算 productModel / customerPoNo / colorName 的 rowspan
   │     └─ 样图：按 productModelId 取 primary → OSS 字节 → base64 data URI
   └─ Thymeleaf templates/print/factory-order-pdf.html → PDF bytes
   │
   ▼
前端 blob → objectURL → iframe；工具栏 print()
（可选同期）ExportButton → ExportJobType.PP_FACTORY_ORDER_PDF → 归档 OSS
```

依赖方向与订购单一致：`pp` 实现 PrintService / Renderer /（可选）ExportHandler；common 提供 `PdfRenderSupport`；跨模块 SO 数据经 `RemoteSalesOrderService`（需扩展 DTO 字段）。

## 4. 数据关联

```
FactoryOrder (1)
  ├─ factoryId → Factory → companyId → Company.name          // 公司抬头
  ├─ customerId → Customer.name                              // 客户
  ├─ orderNo / remarks / orderDate / confirmedAt             // 表头
  ├─ createdBy → User.name                                   // 制表人
  ├─ confirmedBy → User.name                                 // 审核人
  └─ FactoryOrderItem[] (supply)
        └─ OrderPegging
              supplyType=FACTORY_ORDER, supplyId=foItem.id
              demandType=SALES_ORDER,  demandId=soItem.id
              peggedQuantity                                         // 报表数量
              └─ SalesOrderItem
                    ├─ customerInternalRefNo / customerOrderNo
                    ├─ unitId → MaterialUnit.name
                    ├─ expectedDeliveryDate
                    ├─ materialId → Material
                    │     ├─ productModelId → ProductModel.code/name
                    │     ├─ colorId → Color.name
                    │     └─ productSizeId → ProductSize.name/sequence
                    └─ salesOrderId → SalesOrder.customerPoNo
```

**无 pegging 的 FO Item**（理论上不应出现于 SALES_ORDER 来源，若出现则跳过并记日志；若整单无有效行则报业务错误）。

## 6. 矩阵组装算法

### 6.1 平坦事实行（Fact）

对每个 FO Item：

1. 查 `OrderPegging`：`supplyType=FACTORY_ORDER AND supplyId=foItem.id AND demandType=SALES_ORDER`
2. 取 SO Item / SO / Material / Size / Color / Model / Unit
3. 产出 Fact：分组键字段 + `productSizeId` + `peggedQuantity`

同一 FO Item 若存在多条 pegging（少见），按条拆分累加。

### 6.2 分组 → 矩阵行

```
groupKey = (
  productModelId, colorId,
  customerPoNo, customerInternalRefNo, customerOrderNo,
  unitId, expectedDeliveryDate
)
```

组内：

- `sizeQuantities[sizeId] += peggedQuantity`（同 Size 多次则累加）
- `rowQuantity = Σ sizeQuantities`

### 6.3 动态列联集

```
sizeColumns = 本单所有 Fact 的 productSizeId 去重
  → 按 ProductSize.sequence ASC NULLS LAST, name ASC 排序
```

模板表头：固定列 + 循环 `sizeColumns` + 小计数量 / 单位 / 交期。  
某行无该 Size：单元格空白（不填 0）。

### 6.4 行排序（服务视觉合并）

必须使相同型号 / 客户 PO / 颜色物理相邻，否则 rowspan 无法合并：

```
productModelCode ASC
→ customerPoNo ASC
→ colorName ASC
→ customerInternalRefNo ASC
→ customerOrderNo ASC
→ expectedDeliveryDate ASC
```

### 6.5 视觉单元格合并（rowspan）

**合并列（仅此三列）**：`productModel`（展示 `code + name`）、`customerPoNo`、`colorName`。  
其余列（内部参号、客户订单号、各 Size、数量、单位、交期）**每行都显示**，不做合并。

**嵌套相等键**（保证子列不跨父列边界合并）：

| 列 | 连续相等判断键 |
|----|----------------|
| productModel | `productModelId` |
| customerPoNo | `productModelId` + `customerPoNo` |
| colorName | `productModelId` + `customerPoNo` + `colorId` |

**算法**（排序后的 `rows` 上跑一遍）：

```
for each mergeColumn in [productModel, customerPoNo, colorName]:
  i = 0
  while i < n:
    j = i + 1
    while j < n and sameKey(rows[i], rows[j], mergeColumn):
      j++
    span = j - i
    rows[i].showX = true;  rows[i].xRowspan = span
    for k in i+1 .. j-1:
      rows[k].showX = false; rows[k].xRowspan = 0
    i = j
```

**模板规则**：

```html
<td th:if="${row.showProductModel}" th:rowspan="${row.productModelRowspan}"
    th:text="${row.productModelCode + ' ' + row.productModelName}">...</td>
<!-- showProductModel=false 的行：不输出该 <td>，由上一行 rowspan 占位 -->
```

`colorName` / `customerPoNo` 同理。

示意（同一型号下多 PO / 多色）：

```
│ 型号A     │ PO-001 │ 红 │ … │
│ (rowspan) │ (span) │ 蓝 │ … │
│ (rowspan) │ PO-002 │ 红 │ … │
│ 型号B     │ PO-003 │ 黑 │ … │
```

> openhtmltopdf 对 HTML `rowspan` 支持可用；跨页时合并单元格可能被拆开显示——可接受，验收以单页观感为主。若实测跨页错乱严重，二期再改为「仅同页合并」或重复打印值。

## 7. 样图策略

1. 从矩阵行收集有序去重的 `productModelId`。
2. 在本单出现的 `materialId` 集合中，查 `MaterialImage`：`isPrimary = true`。
3. **每个 productModel 选一张**：优先「本 FO 出现过的 material 的 primary」；若同型号多 material 都有 primary，取 `materialId` 最小者（稳定可复现）。
4. 若该型号完全无 primary：`imageDataUri = null`，模板仍画固定尺寸空框 + 型号标签。
5. **嵌入方式**：`StorageService` 读对象字节 → 可选缩略（如最长边 ≤ 200px）→ `data:image/jpeg;base64,...`。  
   **不要**在模板里直接挂 CDN 签名 URL。
6. 多产品：**横向排列**；过多时允许换行。

复用点：可扩展 `MaterialImageHelper` 增加「按 materialIds 取 primary 字节/路径」方法。

## 12. 验收标准

1. **SALES_ORDER + CONFIRMED**：正式 PDF，无水印；表头正确；**无单价/金额列**。
2. **DRAFT**：可预览，带草稿水印。
3. **MANUAL**：业务错误「仅支援销售转入的工厂订单」。
4. **同型号多 Size、同分组键**：数量横排；合计数量 = Σ peggedQuantity。
5. **视觉合并**：连续相同的型号 / 客户 PO / 颜色只显示一次且垂直居中；不同值分行；子列不跨父列合并。
6. **部分转入**：数量=peggedQuantity。
7. **多样图**：按型号横排；无 primary 显示空框。
8. **分页**：表头重复；签核尽量不被截断；合并单元格跨页观感可接受。
9. **纸张**：A4 横向。
10. **三语**标签正确；数量千分位合理。
11. Chrome/Edge：预览与打印各验收一次。

## 13. 风险与对策

| 风险 | 对策 |
|------|------|
| Size 列过多导致单元格过窄 | A4 landscape + 略缩字号 |
| openhtmltopdf 外链图失败 | 强制 base64 内嵌 |
| rowspan 跨页显示异常 | 一期可接受；严重则二期降级为重复打印值 |
| 排序不当导致无法合并 | 强制 §6.4 排序后再算 rowspan |
| Remote DTO 扩展影响调用方 | 仅追加字段，全量编译修复 record 构造 |
| FO Item 无 pegging | 跳过；整单无行则报错 |
