# 11 — 示例：生产日报表（Production Daily Report）

> 编写日期：2026-08-14  
> 状态：**已实现（2026-08-14）**  
> 前置：导出框架（02）、进耗存模板 Excel（05）已落地；工单进度（10）仅作双校验 / 单 Sheet 模板的参照，本表**不**做清单并存、**不**做第二 Sheet

## 1. 目标与范围

从工单产量回馈（`ProductionReport`，界面 **MOR**）**列表工具栏**发起导出，按当前筛选条件导出当日报工单，产出带标题区、明细与合计的固定版式 Excel。

实体 `ProductionReport` 是**单据**（报工单）；本作业是把这些单据汇总成 **生产日报表**。作业类型用 `PP_PRODUCTION_DAILY`，避免与实体同名。

| 纳入 | 不纳入 |
|------|--------|
| 列表筛选驱动的多单 Excel；`ExcelTemplateWriteSupport` + `.xlsx` | 单据 PDF / 预览打印 / `/print` |
| **强制**：单一工厂 + **单一报工日** + **报工状态**；标题区标识三者 | 未选厂 / 未选日 / 未选状态时导出 |
| 单 Sheet：1 报工单 1 行 + 产量合计 | 倒扣料 Sheet / `ProductionReportComponent` |
| 明细保留状态列；标题区展示所选状态译文 | 清单类 `ExcelWriteSupport`、第二按钮 |
| 列头 / 状态 / 文件名随 `ctx.locale()` | 统计分析图表、交叉透视、邮件外发 |

作业管线（创建 / 同步·异步 / OSS / 导出中心）**零改动**；只加 Handler + 模板 + 列表按钮。

**报表名称（三语）**

| locale | 名称 |
|--------|------|
| zh-CN | 生产日报表 |
| en-US | Production daily report |
| vi-VN | Báo cáo sản xuất hàng ngày |

**与相近报表的差异**

| 维度 | 05 进耗存 | 10 工单进度 | **11 生产日报** |
|------|-----------|-------------|-----------------|
| 数据 | `InventoryBalance` | `ProductionOrder` | **`ProductionReport`（MOR）** |
| 写入 | 模板单 Sheet | 清单 + 模板双 Sheet | **仅模板、单 Sheet** |
| 强制范围 | 期间 × 工厂 | 工厂 × 计划日期闭区间 | **工厂 × 单一报工日 × 状态** |
| 行粒度 | 1 余额行 | 模板 1 工单 1 行 | **1 报工单 1 行** |
| 状态 | 无 | 跟列表走，含状态列 | **导出必选状态**；标题 + 明细均标识 |
| 口径 | 期间进出存 | 计划 vs 完工 / 齐套 | 该日、该状态下的良品 / 返工 / 报废 |

## 2. 业务决策（已确认）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 报表名词 | **生产日报表**（不是「报工单清单」） |
| 2 | 产出 | **只要 Excel 模板**；无 PDF |
| 3 | 入口 | `/pp/production-reports` 工具栏 **一个** `ExportButton`；不按勾选。`rowSelection` 仍只服务草稿批量删除 |
| 4 | 清单并存 | **不做**。单日报工量远低于 `template-max-rows`（默认 50,000） |
| 5 | 工厂 | 必须单一 `factoryId` |
| 6 | 报工日期 | **强制单日**（不是闭区间）。`from ≠ to` 或无法解析出唯一日 → 拒绝 |
| 7 | 状态 | **必须已筛选报工状态**（与列表 Select 一致：单一值）。**不**在后端再硬过滤 `POSTED`——跟用户所选走（`DRAFT` / `POSTED` / `REVERSED` 均可）。标题区 `{statusLabel}` + 明细状态列 **双重标识** |
| 8 | 倒扣料 | **不要**第二 Sheet；不加载 `ProductionReportComponent` |
| 9 | 行粒度 | 1 报工单 = 1 行 |
| 10 | 工单计划量 | 主表带工单计划 / 累计完工，作对照。系统无「日计划」字段，禁止写成当日计划 |
| 11 | 良品率 | `good / (good + rework + scrap)`；分母 0 则空。百分比文本 1 位小数（对齐 10） |
| 12 | 跨单位合计 | 数量按行加总（对齐进耗存）；范围内单位多于 1 种时标题写 `{mixedUnitLabel}` |
| 13 | `count` / 上限 | 按 **报工单数** 卡 `template-max-rows` |
| 14 | 浏览 vs 导出 | 列表本身不强制填厂 / 日 / 状态；**仅点导出时**前后端双校验 |

## 3. 总体流程

```
报工单列表 [导出]  ExportButton jobType=PP_PRODUCTION_DAILY
   │  前端：单一 factoryId + 唯一 reportDate + 单一 reportStatus
   │  不满足 → message.warning，不发请求
   │  POST /api/v1/report/export-jobs  { jobType, params, sort }
   ▼
ExportJobService（既有）
   ├─ 权限：/pp/production-reports:export
   ├─ Handler.count → requireFactoryDateAndStatus
   │     按报工单数；lychee.export.template-max-rows（默认 50,000）
   ├─ ≤ sync-threshold：同步执行；否则异步
   └─ ProductionDailyExportHandler.export
          ├─ QuerySupport：列表同源 DynamicSpecifications（强制条件已在 params 中）
          ├─ 分页报工单 → Assembler 1:1 行 + 累加合计
          └─ ExcelTemplateWriteSupport.fill（Sheet0）→ OSS → 下载 URL
```

## 4. 数据口径

### 4.1 行粒度

```
ProductionReport（列表 spec 命中，含用户所选唯一状态）
   →  1 行（禁止按倒扣料展开）
```

### 4.2 明细列（列表名 `items`）

来源：`ProductionReport` + fetch `productionOrder` / `productMaterial` / `unit`。工厂、仓库、部门走缓存 / 远程，格式与列表一致（`code - name`）。

标题已声明的范围 **不再进明细**：工厂、报工日。  
状态 **进标题也进明细**（决策 #7）。

| 列 | 来源 | 说明 |
|----|------|------|
| reportNo | `reportNo` | |

| productionOrderNo | `productionOrder.orderNo` | |
| department | 工单 `departmentId` → `BasisCacheService` | 报工单本身无部门 |
| productMaterial | `productMaterial.code - name` | |
| unit | `unit.code - name` | |
| warehouseName | `warehouseId` → `RemoteWarehouseService` | 成品入库仓 |
| batchNo | `batchNo` | |
| goodQuantity | `goodQuantity` | |
| reworkQuantity | `reworkQuantity` | |
| scrapQuantity | `scrapQuantity` | |
| outputQuantity | 派生：三者之和 | |
| yieldRate | 派生：良品 / 产出；0 则空 | 如 `97.1%` |
| plannedQuantity | 工单 `plannedQuantity` | 工单计划，非日计划 |
| orderCompletedQuantity | 工单 `completedQuantity` | 导出时工单累计完工 |
| defectReason | `defectReasonCode`（有字典则译） | |
| remarks | `remarks` | |
| reportedBy | `createdBy` 用户名 | 报工人 |

### 4.3 合计（只扫 `items`）

- `totalGood` / `totalRework` / `totalScrap` / `totalOutput`
- `docCount`：报工单张数
- `yieldRate`：`totalGood / totalOutput`（产出为 0 则空）
- 禁止按倒扣料放大产量

范围内 `unit` 去重后多于 1 种：合计仍写出，标题加 `{mixedUnitLabel}`。

## 5. 强制导出条件

对齐进耗存 05 §4.1.1：前端拦截 + 后端 `count` / `export` 再验，以后端为准。实现放在 `ProductionDailyQuerySupport.requireFactoryDateAndStatus`，禁止 Handler 再写一份解析。

| 维度 | 必填 | params 约定（与列表 `field_op` 一致） | 说明 |
|------|------|--------------------------------------|------|
| 工厂 | 是 | `factoryId` 或 `factoryId_eq`，**单一**值 | 缺失、多选、逗号拼接均拒绝 |
| 报工日 | 是 | 优先 `reportDate` / `reportDate_eq` 单一值；或 `reportDate_between` 且 **两端相同** | 缺日、两端不同、无法解析 → 拒绝 |
| 状态 | 是 | `reportStatus` 或 `reportStatus_eq`，**单一**枚举值（`DRAFT` / `POSTED` / `REVERSED`） | 缺失、多选、`_in`、非法枚举均拒绝 |

不另写一套 Specification：强制条件以列表同源 params 进入 `DynamicSpecifications`；`require*` 只负责「能否解析出单一工厂 + 唯一日 + 单一状态」。其余列表条件（工单号、物料）照常叠加收窄。

校验与文案：

1. **前端**（`beforeExport`）：读 `formRef.getFieldsFormatValue()` / `lastQueryRef`。不满足 → `message.warning`（`pages.pp.productionReports.export.requireFactoryDateAndStatus`），**不调用** `createExportJob`。
2. **后端**（`count` 与 `export` 均调）：
   - 工厂缺失 / 非单一：`validation.export.production_daily.factory.required`
   - 报工日缺失 / 无法解析：`validation.export.production_daily.report_date.required`
   - 解析出区间且 `from ≠ to`：`validation.export.production_daily.report_date.single_day.required`
   - 状态缺失 / 非单一 / 非枚举：`validation.export.production_daily.status.required`

解析成功后写入标题（明细不再重复工厂、报工日）：

- `factoryName`：工厂 `code - name`（与列表工厂列一致）
- `reportDate`：`yyyy-MM-dd`（唯一日）
- `statusLabel`：`MessageService` 解析 `enum.ProductionReportStatus.{code}`（草稿 / 已过账 / 已冲销）

### 5.1 列表搜索 UI（实施时）

当前报工日期搜索是 `dateRange` → `reportDate_between`。为对齐「日报 + 强制单日」：

- 将隐藏的 `dateRange` 改为单一 `valueType: 'date'`，写出 `reportDate` / `reportDate_eq`。
- 表格内报工日列继续展示，`search: false`，避免与搜索控件重复。
- 状态列保持现有单选 `select`（`ProductionReportStatus`）。
- 工厂列保持 `buildFactoryColumn`。
- **不**在进页时强制填满这三项；仅导出时校验。

若实施时暂不改搜索控件、仍用 `between`：仅当两端同一天才视为满足；前后端规则相同。

### 7.2 查询规格

```java
Specification<ProductionReport> filterSpec(Map<String, Object> params) {
    return DynamicSpecifications.build(ProductionReport.class, params);
}

Specification<ProductionReport> fetchSpec(Map<String, Object> params) {
    return DynamicSpecifications.build(
            ProductionReport.class,
            params,
            "productionOrder", "productMaterial", "unit");
}
```

- `params` / `sort` 与 `ProductionReportServiceImpl.getProductionReportPage` **完全同源**，保证导出行集 = 列表在「该厂 × 该日 × 该状态」下翻完的总集。
- **不**附加 `reportStatus = POSTED`。用户选草稿即导出草稿；选已冲销即导出已冲销。状态列与标题必须能对上。
- 无 `sort` 时：`reportNo ASC, id ASC`（同日按单号；列表默认 `reportNo DESC`，日报阅读用正序）。

### 7.3 `count`

```
templateCount = COUNT(列表 spec 命中的 ProductionReport)
```

- `count` / `export` **先** `requireFactoryDateAndStatus`，再 count / 填表。
- `count == 0`：仍生成仅含标题 / 列头的空模板 xlsx，不报业务错误（对齐进耗存）。
- `templateCount > template-max-rows`：`validation.export.production_daily.rows.exceeded`。
- `ExportResult` 行数 = 报工单行数。

### 7.4 Handler 骨架

```java
@Component
@RequiredArgsConstructor
public class ProductionDailyExportHandler implements DataExportHandler {

    private static final String TEMPLATE = "excel/production-daily";

    @Override public ExportJobType type() { return ExportJobType.PP_PRODUCTION_DAILY; }
    @Override public ExportFileFormat fileFormat() { return ExportFileFormat.XLSX; }
    @Override public boolean usesExcelTemplate() { return true; }
    @Override public String requiredAuthority() { return "/pp/production-reports:export"; }

    @Override
    @Transactional(readOnly = true)
    public long count(ExportContext ctx) {
        querySupport.requireFactoryDateAndStatus(ctx.params());
        long rows = querySupport.countReports(querySupport.filterSpec(ctx.params()));
        if (rows > ctx.maxRows()) {
            throw new ValidationException("validation.export.production_daily.rows.exceeded", ctx.maxRows());
        }
        return rows;
    }

    @Override
    public ExportResult export(ExportContext ctx, OutputStream out) {
        DailyScope scope = querySupport.requireFactoryDateAndStatus(ctx.params());
        // 分页 load（SpecificationSliceQuery）→ Assembler.toItemRow
        // 合计扫 items；mixedUnit 判定
        // header：title、factoryName、reportDate、statusLabel、exportedBy/At、col*、total*
        ExcelTemplateWriteSupport.fill(
                out, TEMPLATE, header,
                List.of(new SheetFill(0, localeSheetName, Map.of("items", rows))));
        // 文件名：生产日报表_{factoryCode}_{yyyy-MM-dd}_{status}_{导出日}.xlsx
    }
}
```

## 10. 验收标准

1. 无 `export` 权限时按钮不渲染。
2. **未选工厂、未选唯一报工日、或未选状态**：前端提示，不发请求；API 直调同样 `ValidationException`。
3. `reportDate_between` 两端不同日：前后端均拒绝（`single_day.required`）。
4. **已选单一工厂 + 单日 + 单一状态**：导出成功；xlsx 标题区可见工厂、报工日、状态译文；明细无工厂列、无报工日列；**明细有状态列**且与标题一致。
5. 选 `DRAFT`：只出草稿行，标题为「草稿」；选 `POSTED` / `REVERSED` 同理。**禁止**在未选 `POSTED` 时偷偷只出已过账。
6. 同范围再筛物料 / 工单号：明细与列表翻完的总集一致；合计正确。
7. 无数据：仍出带标题 / 列头的空 xlsx。
8. 切换语言：标题、列头、状态、页签、提示随语言变化。
9. 行数超 `template-max-rows` 或模板缺失：失败信息可理解。
10. 导出中心可见作业类型与下载。
11. 文件中 **无** 倒扣料 Sheet、无组件列。

## 14. 风险与对策

| 风险 | 对策 |
|------|------|
| 未选状态把草稿 / 已过账混在一张「日报」里 | **强制单一状态**；标题 + 明细双重标识 |
| 后端偷偷只出 `POSTED`，与列表不一致 | 禁止额外状态 spec；导出行集 = 列表同源 spec |
| 用户用日期区间想导出一周 | 明确拒绝跨日；提示改选单日（本表是日报） |
| 跨单位数量合计误导 | 单位列可见；多种单位时 `{mixedUnitLabel}` |
| 模板 fill + 大结果集 OOM | 强制单厂 × 单日 × 单状态收束；`template-max-rows` 兜底 |
| 与工单进度报表混淆 | 入口在报工单列表；工单进度仍在工单列表 |
| 误加倒扣料 Sheet | 文档与验收明确单 Sheet；Handler 不注入 ComponentRepository |
