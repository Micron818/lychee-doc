# 04 — 示例：订购单可打印格式表单

一期采用**前端专用打印视图 + 浏览器打印**（选型依据见 01 文档 §3），二期预留服务端 PDF。

## 1. 需求

从订购单列表或详情抽屉发起「打印」，以 A4 纵向标准单据版式呈现订购单（公司抬头、供应商信息、明细表、金额合计、签核栏），调用浏览器打印；多页明细正确分页，表头每页重复。

## 2. 后端：打印数据聚合（`lychee-erp-scm`）

> **注（2026-08-03 版式收敛）**：原对外暴露的 `GET /{id}/print-data` 已删除；`PurchaseOrderPrintService` 仍作为内部数据组装保留，由 `PurchaseOrderPdfRenderer` / `GET /{id}/pdf` 与导出 Handler 复用。下列 DTO 描述仍有效。

现有 `GET /{id}` 返回表头、`POST /{id}/items/page` 返回分页明细，且大量字段是 id/代码值。打印页若自行拼装需多次请求并在前端解析字典，故新增一个聚合只读组装（初期曾暴露为 REST）：

```
内部：PurchaseOrderPrintService.getPrintData(id)
对外预览（收敛后）：GET /api/v1/scm/purchase-orders/{id}/pdf
权限：/scm/purchase-orders:read
```

响应 `PurchaseOrderPrintResponse`（一次性返回、全部名称已解析）：

```java
public class PurchaseOrderPrintResponse {
    // 抬头（租户公司信息，来源：租户/公司主数据）
    private String companyName;
    private String companyAddress;
    private String companyPhone;
    private String companyTaxId;

    // 单据头
    private String orderNo;
    private LocalDate orderDate;
    private String status;                 // 枚举翻译文本
    private String factoryName;
    private String currencyName;           // currencyOptionId → 字典
    private BigDecimal exchangeRate;
    private String paymentTermName;        // paymentTermOptionId → 字典
    private String billingAddress;
    private String shippingAddress;
    private String remarks;

    // 供应商（打印需要完整信息，非仅 code/name）
    private String supplierCode;
    private String supplierName;
    private String supplierTaxId;
    private String supplierAddress;
    private String supplierContactPerson;
    private String supplierContactPhone;
    private String supplierContactEmail;

    // 明细（全量，按 itemNo 排序）
    private List<Item> items;
    public static class Item {
        private Integer itemNo;
        private String materialCode;
        private String materialName;
        private String materialSpec;
        private BigDecimal orderedQuantity;
        private String unitName;
        private BigDecimal unitPrice;
        private BigDecimal taxRate;
        private BigDecimal amount;          // 行金额
        private LocalDate expectedDeliveryDate;
        private String remarks;
    }

    // 合计
    private BigDecimal subtotalAmount;
    private BigDecimal taxAmount;
    private BigDecimal totalAmount;
    private String totalAmountInWords;      // 金额大写（按语言，可选，一期可留空）

    // 打印元信息
    private String printedBy;
    private LocalDateTime printedAt;
}
```

实现要点：

- Service 内 `DynamicSpecifications.fetch(...)` 一次抓取 supplier/material/unit，避免 N+1。
- 枚举与字典翻译按请求 `Accept-Language`（现有 `MessageService` 机制）。
- 业务规则建议：仅 `APPROVED` 及之后状态可正式打印；`DRAFT` 打印时响应带 `draft: true` 标记，前端加"草稿"水印（规则由业务确认，接口先不做硬限制）。

## 3. 前端：打印视图页

### 3.1 路由与入口

- 约定式路由新增 `src/pages/scm/purchase-orders/print/index.tsx` → `/scm/purchase-orders/print?id={id}`。**不加菜单**（非导航页），权限沿用 `/scm/purchase-orders:read`（进入页面即调用 print-data，无权限自然被后端 403 拦截）。
- 入口两处：列表操作列「打印」；详情抽屉底部「打印」按钮。均 `window.open('/scm/purchase-orders/print?id=' + id)` 新标签打开，不打断当前编辑。

### 3.2 页面结构

```
src/pages/scm/purchase-orders/print/
├─ index.tsx            // 取数 + 工具条（打印/关闭按钮，打印时隐藏）+ <PrintablePO/>
├─ PrintablePO.tsx      // 纯展示组件：语义化 <table> 版式（非 ProComponents）
└─ print.less           // @page/@media print 样式
```

### 3.3 打印 CSS 关键点

```less
@page { size: A4 portrait; margin: 12mm; }

@media print {
  .no-print { display: none; }             // 工具条
  // 隐藏应用框架（若布局仍包裹本路由）：
  .ant-pro-sider, .ant-pro-global-header, .ant-layout-header { display: none !important; }
}

.po-items-table {
  width: 100%; border-collapse: collapse;
  thead { display: table-header-group; }    // 跨页重复表头
  tr    { break-inside: avoid; }            // 行不被拦腰截断
}
.po-footer { break-inside: avoid; }          // 合计+签核栏整体不跨页
```

实现说明：

- 菜单由后端驱动、路由为约定式，无法在路由配置层面对该页关闭布局；采用打印媒体查询隐藏框架元素即可满足需求。若开发时验证 `app.tsx` 运行时 layout 配置可按 `location.pathname.startsWith('/scm/purchase-orders/print')` 关闭 header/menu，则优先用该方式使屏显也无框架（实现时二选一，不影响设计）。
- 数据加载完成前禁用打印按钮；提供 `autoPrint=1` 查询参数支持"打开即弹打印对话框"（`useEffect` 中数据就绪后 `window.print()`）。
- 草稿单加对角线水印（CSS `position: fixed` + 半透明文本，`@media print` 下保留）。
- 三语：版式标签全部走 `useIntl`，与数据端 `Accept-Language` 一致。

### 3.4 验收标准

1. Chrome/Edge 打印预览：单页 ≤ 15 行明细时一页呈现；40+ 行明细正确分 2~3 页，每页含表头，签核栏不被截断。
2. 金额/数量列右对齐、千分位、按币别小数位显示。
3. 中文/英文/越南语界面下标签与数据翻译正确。
4. 无 `read` 权限访问 print-data 返回 403，页面显示错误提示。

## 4. 二期：服务端 PDF（✅ 已实现，实施记录）

实施与原设计的对照：

- 依赖：`io.github.openhtmltopdf:openhtmltopdf-pdfbox:1.1.40` + `org.thymeleaf:thymeleaf-spring6`。**放置调整**：位于 `lychee-erp-common`（非 `lychee-erp-report`），因 Handler 在领域模块且领域模块只依赖 common，与 Fesod 的放置理由一致；渲染入口为 common 的 `PdfRenderSupport`（独立 SpringTemplateEngine，`#{key}` 直连既有 MessageSource，不使用 starter 避免干扰 Web 视图解析）。
- 模板：`lychee-erp-scm/src/main/resources/templates/print/purchase-order-pdf.html`，版式移植一期打印视图（良构 XHTML + CSS 2.1 子集；`-fs-table-paginate: paginate` 跨页重复表头；`@page @bottom-center` 输出 `页码/总页数`；草稿单绝对定位旋转水印）。
- 字体：Noto Sans（拉丁/越南语）+ Noto Sans SC 简中子集（均 OFL），Regular/Bold 共 4 档打包进 common classpath `fonts/`，`builder.useFont(...)` 注册并启用子集内嵌；模板 `font-family: 'Noto Sans', 'Noto Sans SC'` 依赖 openhtmltopdf 字族回退。
- 作业框架接入：`ExportJobType.SCM_PURCHASE_ORDER_PDF` + `PurchaseOrderPdfExportHandler`（权限 `/scm/purchase-orders:export`）。框架唯一改动：`DataExportHandler.fileFormat()`（默认 XLSX）+ `ExportFileFormat`，执行器按格式定副档名与 Content-Type。
- 数据源：复用 P1 抽出的 `PurchaseOrderPrintService.getPrintData(id)`；`params.ids` 支持批量，多单合并为一份 PDF、每单独立分页；数值在 Handler 预格式化为字串，模板纯展示。
- 前端入口：打印视图页与详情抽屉的「下载 PDF」按钮（`ExportButton`，`export` 动作门控）；批量列表入口待列表复选框语义（当前仅 DRAFT 可勾选）调整后开放。

## 5. 版式收敛（✅ 已实现，2026-08-03）

打印件与归档件必须一致 → 取消前端自渲染 HTML，版式唯一来源为 Thymeleaf 模板。

| 项 | 调整 |
|----|------|
| 共用渲染 | `PurchaseOrderPdfRenderer`（组模型 + `PdfRenderSupport`）；导出 Handler 委派 |
| 预览接口 | `GET /{id}/pdf` 同步直出 PDF（`inline`），不建作业不落 OSS；删除 `print-data` REST |
| 打印预览 | blob → objectURL → iframe；**原页近全屏 Modal**（列表/抽屉）；已移除 `/print` 深链；打印走 `iframe.contentWindow.print()`；下载 PDF 仍走导出作业 |
| 删除 | `PrintablePO.tsx`；前端版式相关 `pages.scm.purchaseOrders.print.*` 文案（仅保留 `loadFailed` / `previewTitle`） |
| 取舍 | 每次预览消耗一次服务端渲染，换取版式零漂移；水印/页码/三语标签单点维护；原页 Modal 避免新标签二次引导 |
