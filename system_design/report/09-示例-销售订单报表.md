# 09 — 示例：销售订单报表（Sales Order Report）

> 编写日期：2026-08-12  
> 状态：**已实现**（2026-08-12；跨单矩阵 + 仅预览/打印；强制客户+订单日期）  
> 前置：导出框架（02）、单据 PDF 版式收敛（01 §3 / 04）、工厂订单报表范本（08）已落地

## 1. 目标与范围

从销售订单（SalesOrder）**列表工具栏**发起「预览/打印」，按当前搜索条件聚合 **多张 SO → 一张尺码矩阵**，以 **A4 横向（landscape）** 版式呈现业务接单汇总：公司抬头、**查询范围**（客户 + 订单日期区间）、矩阵明细（型号 / 客户PO·单号·状态 / 颜色单元格合并）、**数量与金额合计**、产品样图、签核栏。预览与打印共用服务端 PDF 单一版式。

| 纳入 | 不纳入（本期） |
|------|----------------|
| 列表工具栏 PDF 预览 + 浏览器打印 | 行操作列单张打印、`/{id}/pdf` |
| 筛选条件驱动的 **跨单单一矩阵** | 用户勾选多单 / 按单分页合并（FO/PO 语义） |
| 强制：**单一客户** + **orderDate 区间**；表头展示查询范围 | 归档「导出 PDF」/ `ExportJobType` / `ExportButton` |
| 币别、单价、金额；数量取自 `SalesOrderItem.quantity` | Excel 模板版、统计分析、邮件外发 |
| 尺码横向矩阵、样图横排、型号/PO区/颜色 rowspan | 前端 HTML 打印页 / `/print` 深链（禁止双轨） |

**与 08（工厂订单报表）的核心差异**

| 维度 | 08 FactoryOrder | 09 SalesOrder |
|------|-----------------|---------------|
| 数据范围 | 一张 FO | 查询范围内 **多张 SO → 一张矩阵** |
| 数量口径 | `OrderPegging.peggedQuantity` | `SalesOrderItem.quantity` |
| 金额 | 不展示 | 表头币别 + 行单价/金额 + 金额合计 |
| 选取方式 | 单据 id（列表/详情打印） | **列表筛选条件**（非勾选） |
| 交付 | 预览 +（已有）归档 Export | **仅预览/打印** |
| 「客户PO」列 | 仅 `customerPoNo` | **复合**：`customerPoNo` + `orderNo` + `orderStatus` |

**报表名称（三语）**

| locale | 名称 |
|--------|------|
| zh-CN | 销售订单报表 |
| en-US | Sales order report |
| vi-VN | Báo cáo đơn hàng bán |

## 2. 业务决策（已确认）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 产出物 | **PDF 预览 + 打印**；版式对齐 08（Thymeleaf + openhtmltopdf） |
| 2 | 纸张 | **A4 landscape** |
| 3 | 多单语义 | **跨单一张矩阵**（非 FO/PO 按单分节） |
| 4 | 入口 | **仅列表工具栏**「预览/打印」；无行操作单张报表 |
| 5 | 归档导出 | **本期不做**（无 `SD_SALES_ORDER_PDF` / ExportHandler / ExportButton） |
| 6 | 勾选 | **不参与报表**；列表 `rowSelection` 仍仅服务批量删除（DRAFT-only 可维持） |
| 7 | 强制条件 | **必须**单一 `customerId` + **必须** `orderDate` 日期区间（两端齐全） |
| 8 | 条件 UI | 列表客户搜索改为 **`customerId` Select**（`getCustomerList`）；`orderDate` 沿用现有 `dateRange` |
| 9 | 查询范围展示 | 报表头固定展示：客户名称、订单日期起止；（可选）命中订单张数 |
| 10 | 数量 | **`SalesOrderItem.quantity`** |
| 11 | 币别 / 单价 / 金额 | 表头展示币别；明细展示单价、行金额（未税小计）；合计数量 + 合计未税金额 |
| 12 | 混合币别 | **拒绝**：范围内 SO 的 `currencyOptionId` 必须一致（前后端双校验） |
| 13 | 税率 / 含税 | 本期不展示、不合计（二期可选） |
| 14 | 矩阵分组键 | `productModelId + colorId + salesOrderId + customerPoNo + customerInternalRefNo + customerOrderNo + unitId + expectedDeliveryDate + unitPrice` |
| 15 | 视觉合并 | **productModel**、**orderRef（PO 复合列）**、**colorName** 连续相同值 rowspan（见 §6.5） |
| 16 | DRAFT 水印 | **不做整页水印**；状态在 PO 复合列按行展示即可 |
| 17 | CANCELLED | **排除**：查询默认不含 `CANCELLED`（后端硬过滤）；其余状态纳入 |
| 18 | 样图缺失 | 无 primary 图时仍显示空框（对齐 08） |
| 19 | 签核 | 主管留白；审核人留白；制表人 = 当前用户（打印人） |
| 20 | 公司抬头 | 取范围内 SO 的 `companyId` → Company；**混合公司拒绝**（同混合币别） |

## 3. 总体流程

```
前端 SO 列表工具栏 [预览/打印]
   │  读取 ProTable 当前搜索条件
   │  前端校验：customerId 单一 + orderDate between 两端齐全
   │  SalesOrderReportPdfPreviewModal + postSalesOrderReportPdfBlob(params)
   ▼
POST /api/v1/sd/sales-orders/report/pdf     ← read，inline，不建作业、不落 OSS
   │  body: 与列表同源筛选 params（至少含 customerId、orderDate 区间）
   ▼
SalesOrderReportPdfRenderer.render(params, locale)
    ├─ SalesOrderReportService.getReportData(params)
    │     ├─ requireCustomerAndOrderDateRange(params)
    │     ├─ 查 SalesOrder（同客户、日期内、排除 CANCELLED；可选其它列表条件）
    │     ├─ 校验币别一致、公司一致；解析 currencyCode、customerName、公司抬头
    │     ├─ 查全部 SalesOrderItem → Material → Model / Color / Size / Unit
    │     ├─ 组装跨单矩阵 + sizeColumns 联集 + 数量/金额合计
    │     ├─ 计算 productModel / orderRef / colorName 的 rowspan
    │     ├─ 样图：按 productModelId 取 primary → base64 data URI
    │     └─ 表头查询范围 + 公司抬头 + 制表人
    └─ Thymeleaf templates/print/sales-order-report-pdf.html → PDF bytes
   │
   ▼
前端 blob → objectURL → iframe；工具栏 print()
（无 ExportButton / 无导出作业）
```

依赖：`lychee-erp-sd` 实现 ReportService / Renderer / Controller；common 提供 `PdfRenderSupport`、`MoneyFormatSupport`；主数据经 basis（Material / Company 等）。**不经过** `RemoteSalesOrderService`（本模块直读）。

## 4. 数据关联

```
查询条件
  ├─ customerId（必填，单一）→ Customer.name
  └─ orderDate between from..to（必填）

SalesOrder[]（同客户、日期内、非 CANCELLED）
  ├─ companyId → Company.name / address / phone / taxId   // 公司抬头；混合公司拒绝
  ├─ orderNo / orderStatus / customerPoNo / currencyOptionId
  ├─ orderDate
  └─ SalesOrderItem[]
        ├─ quantity / unitPrice / subtotalAmount
        ├─ customerInternalRefNo / customerOrderNo
        ├─ unitId → MaterialUnit.name
        ├─ expectedDeliveryDate
        └─ materialId → Material
              ├─ productModelId → ProductModel.code/name
              ├─ colorId → Color.name
              └─ productSizeId → ProductSize.name/sequence
```

无明细的 SO 跳过；若范围内无任何有效明细行 → 业务错误「无可打印明细」。

## 6. 矩阵组装算法

### 6.1 平坦事实行（Fact）

对范围内每个 `SalesOrderItem`：

1. 取所属 SO（orderNo / status / customerPoNo / currency）
2. 取 Material / Size / Color / Model / Unit
3. 产出 Fact：分组键字段 + `productSizeId` + `quantity` + `unitPrice` + `subtotalAmount` + `materialId`

### 6.2 分组 → 矩阵行

```
groupKey = (
  productModelId, colorId, salesOrderId,
  customerPoNo, customerInternalRefNo, customerOrderNo,
  unitId, expectedDeliveryDate, unitPrice
)
```

组内：

- `sizeQuantities[sizeId] += quantity`
- `rowQuantity = Σ sizeQuantities`
- `rowAmount = Σ subtotalAmount`（与 `quantity × unitPrice` 在入组单价一致时应等价；以落库小计累加为准，避免二次舍入差）

### 6.3 动态列联集

与 08 §6.3 相同：本结果所有 Fact 的 `productSizeId` 去重，按 `sequence ASC NULLS LAST, name ASC`。

### 6.4 行排序（服务视觉合并）

```
productModelCode ASC
→ orderNo ASC
→ customerPoNo ASC
→ colorName ASC
→ customerInternalRefNo ASC
→ customerOrderNo ASC
→ expectedDeliveryDate ASC
→ unitPrice ASC
```

### 6.5 视觉单元格合并（rowspan）

**合并列**：`productModel`、`orderRef`（复合 PO 列）、`colorName`。  
其余列（内部参号、客户订单号、各 Size、数量、单价、金额、单位、交期）每行都显示。

**嵌套相等键**

| 列 | 连续相等判断键 |
|----|----------------|
| productModel | `productModelId` |
| orderRef | `productModelId` + `salesOrderId` |
| colorName | `productModelId` + `salesOrderId` + `colorId` |

算法同 08 §6.5（排序后扫一遍设 `show*` / `*Rowspan`）。

**复合列模板示意**

```html
<td th:if="${row.showOrderRef}" th:rowspan="${row.orderRefRowspan}">
  <div th:text="${row.customerPoNo}">PO</div>
  <div th:text="${row.orderNo}">SO001</div>
  <div th:text="${row.orderStatusLabel}">Confirmed</div>
</td>
```

## 9. 强制查询范围（对齐进耗存 05）

### 9.1 规则

| 条件 | 必填 | 约束 |
|------|------|------|
| 客户 | 是 | 单一 `customerId`（或 `customerId_eq`）；多值/缺失均拒绝 |
| 订单日期 | 是 | `orderDate` 的 `between`，`from`/`to` 两端齐全 |
| 币别 | 派生 | 命中 SO 的 `currencyOptionId` 必须唯一；否则拒绝 |
| 状态 | 系统 | 硬排除 `CANCELLED`；列表若另筛 `orderStatus` 则叠加（仍不能选出 CANCELLED） |

可选透传列表条件：`orderNo` like、`customerPoNo` like、`orderStatus`、交期区间等——与 `getSalesOrderPage` 同源解析（`DynamicSpecifications`），在强制条件之上收窄。

### 9.2 前后端双校验

1. **前端**（工具栏点击前）：读 `formRef.getFieldsFormatValue()`，不满足客户+日期 → `message.warning`，不请求。  
2. **后端**（`report/pdf` 入口）：`requireCustomerAndOrderDateRange`；币别不一致、无明细等分别抛 `ValidationException`。

### 9.3 结果集上限

建议单次命中 SO 明细行（Fact）上限与导出框架同量级兜底（如 5000 行 Fact）；超限提示缩小日期区间。同步 PDF 预览场景以亚秒～数秒可接受为准。

## 13. 验收标准

1. 未选客户或未选完整订单日期：工具栏点击仅 warning，不发请求。  
2. 条件满足且同币别：一份 PDF、**一张矩阵**跨多 `orderNo`；表头显示客户与日期范围。  
3. 混合币别或混合公司：后端业务错误（前端亦可在预览失败时展示 message）。  
4. 复合 PO 列显示客户 PO、销售单号、状态；连续相同订单在型号下 rowspan 合并。  
5. 数量 = SO 行数量；行金额与合计金额正确；币别格式化合理（`MoneyFormatSupport`）。  
6. Size 横排；合计数量/金额正确；样图按型号横排，无 primary 空框。  
7. 无行操作「打印」；无 ExportButton / 导出中心作业。  
8. 列表勾选仍仅 DRAFT 可勾，批量删除行为不变。  
9. A4 横向；表头分页重复；三语标签正确。  
10. Chrome/Edge：预览与打印各验收一次。

## 14. 风险与对策

| 风险 | 对策 |
|------|------|
| Size + 单价/金额列过多导致过窄 | landscape + 略缩字号；单价/金额固定窄列 |
| 日期过宽结果集过大 | Fact 行数上限 + 提示缩小区间 |
| 同客户多币别 | 硬拒绝，避免错误合计 |
| 范围内多公司 | 硬拒绝（抬头只能一家）；列表可按 companyId 筛选 |
| rowspan 跨页 | 一期可接受（同 08） |
| openhtmltopdf 外链图 | 强制 base64（同 08） |
