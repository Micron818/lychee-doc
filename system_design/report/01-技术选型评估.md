# 01 — 技术选型评估

## 1. 现状约束（选型输入）

- 后端：Spring Boot 3.5.15 / Java 21 / Gradle 多模块（`lychee-erp` 入口 + `adm/basis/mm/sd/pp/scm/wm/fi` + `lychee-erp-common`）。
- 多租户：Hibernate 6 `@TenantId` 判别列，请求内由 `CurrentTenant` 解析，异步线程需手动设置 `TenantContextHolder`。
- **无 Redis、无 MQ**：异步只能靠进程内 `@Async`；作业状态只能落数据库表（MRP 已验证此模式可用）。
- 文件基础设施：Aliyun OSS（`StorageService.upload/delete/generateSignedUrl`，CDN auth_key 签名 URL）。目前系统**没有任何字节流下载端点**，所有文件都经 OSS+CDN URL 交付。
- 当前**无任何 Excel/PDF 依赖**，报表属绿地开发。
- 前端：UmiJS Max 4 + antd 5 + ProComponents；请求经 Bearer token 拦截器；权限模型 `{menuPath}:{action}`，**`export` 已是内建 action**；MRP 页面已有 ProTable `polling` 轮询范式。
- 部署：Aliyun 自有服务器 Docker 单实例（架构上不排除未来多实例）。

## 2. Excel 生成库选型

| 候选 | 许可 | 评估 |
|------|------|------|
| **Apache Fesod（推荐）**<br>`org.apache.fesod:fesod-sheet:2.0.2-incubating` | Apache 2.0 | EasyExcel → FastExcel 的直系后继（2025-12 捐入 Apache 孵化器）。注解驱动（`@ExcelProperty` 定义列头/顺序/格式）、流式写入（内部封装 POI，低内存）、中文社区文档完善。`fesod-sheet` 自带 `fesod-common` 与 shaded POI，无需单独管理 POI 版本。 |
| Apache POI（SXSSF） | Apache 2.0 | 最底层、最灵活，但样板代码多（手动建 Row/Cell/样式），每加一个报表都要写一遍单元格拼装，团队维护成本高。仅在需要复杂版式（合并单元格模板套打）时作为 Fesod 的兜底手段——Fesod 内部即 POI，可混用。 |
| EasyExcel（`com.alibaba:easyexcel`） | Apache 2.0 | **已归档停止维护**，不采用。 |
| dhatim fastexcel（`org.dhatim:fastexcel`） | Apache 2.0 | 极轻量纯写入库，性能好，但无注解模型、无中文生态，列定义全靠手写坐标，不如 Fesod 适合"每个报表一个 DTO"的团队协作方式。 |

**结论：Apache Fesod。** 依赖声明在 `lychee-erp-common/build.gradle`（`api` 级别，版本收敛到 `gradle.properties`），因为各领域模块的导出行 DTO 需要使用其注解。

固定版式套打优先使用 Fesod **`withTemplate` + fill**（见 `ExcelTemplateWriteSupport` / 文档 05）；POI 手写仅作 Fesod 无法覆盖时的兜底。

```groovy
// gradle.properties
fesodVersion=2.0.2-incubating

// lychee-erp-common/build.gradle
api "org.apache.fesod:fesod-sheet:${fesodVersion}"
```

> 注意：Fesod 保留了 `FastExcel`/`FastExcelFactory` 兼容入口但已 `@Deprecated`，编码时直接使用 `FesodSheet` 入口类。

## 3. 单据打印方案选型（订购单表单）

| 方案 | 评估 |
|------|------|
| **A. 前端打印视图 + `window.print()`（一期采用）** | 专用打印路由渲染单据 HTML，打印 CSS 控制 A4 版式与分页。零后端依赖、开发最快、样式迭代成本最低、天然三语。缺点：依赖浏览器打印（Chrome/Edge 表现一致，需验收）、无法产出归档 PDF、不能批量。 |
| **B. 服务端 HTML→PDF：openhtmltopdf（二期预留）**<br>`io.github.openhtmltopdf:openhtmltopdf-pdfbox:1.1.40` | 原 danfickle 项目的社区维护分支（2026-07 仍在发版），基于 PDFBox 3，LGPL（仅链接使用无传染问题）。用 Thymeleaf 渲染 HTML 模板再转 PDF，模板技能与前端打印视图相通。**必须内嵌 CJK 字体**（Noto Sans SC，OFL 许可，随 jar 打包，Docker 镜像无需装系统字体）。适用场景：归档、邮件发给供应商、批量打印。 |
| C. JasperReports | 功能最全但极重：专用设计器（.jrxml）、依赖树庞大、与 Spring Boot 3/Jakarta 兼容需额外处理、团队学习成本高。单据类需求用 HTML 模板即可覆盖，不采用。 |
| D. iText 8 | AGPL/商业双许可，商用需付费，直接排除。 |
| E. 前端生成 PDF（jspdf/pdfmake） | CJK 字体需随前端包分发（数 MB）、复杂表格分页控制差，不采用。 |

**历史结论：一期 A，二期按需 B。** 两者共享"HTML + CSS 版式"技能栈，一期打印视图版式可翻译为 Thymeleaf 模板。

**版式收敛后（现行，2026-08）：采用 B 为单据打印/归档的单一来源。** 前端不再自渲染 HTML 打印页；预览为同步 `GET /{id}/pdf` → blob → objectURL → **iframe**（原页近全屏 Modal），打印走 `iframe.contentWindow.print()`；归档下载仍走导出作业。一期方案 A（`/print` 深链、`PrintablePO`、`autoPrint`）已废弃，禁止再开前端/后端双轨版式。

## 4. 导出执行模型：同步 vs 异步

**约束回顾**：无 MQ，无 Redis；MRP 已验证「作业表 + `@Async` + `AFTER_COMMIT` 事件 + 手动传递租户/安全上下文」模式；`@EnableAsync` 目前使用默认 `SimpleAsyncTaskExecutor`（无池化）。

| 模型 | 评估 |
|------|------|
| 纯同步（请求内生成并流式返回） | 数据量大时占用 HTTP 连接数分钟、网关/浏览器超时、无重试与历史记录；且系统目前没有字节流下载与前端 blob 处理惯例，要新建一套鉴权下载机制。 |
| 纯异步（一律建作业轮询） | 架构统一，但几百行的小导出也要"点击→轮询→再下载"，交互繁琐。 |
| **混合（采用）：统一作业模型 + 服务端自适应执行** | 创建作业时先 `count`：行数 ≤ 阈值（默认 5,000，可配置）则**在请求事务内同步执行完**，响应直接返回 `COMPLETED` 作业（前端立即拿下载 URL）；超过阈值则走 MRP 式异步，前端轮询。对调用方而言 API 完全一致，只是首个响应的状态不同。 |

**改进项**：为导出新增专用 `ThreadPoolTaskExecutor` Bean（`exportTaskExecutor`，core=2 / max=4 / queue=20），通过 `@Async("exportTaskExecutor")` 指定，避免默认执行器无限开线程；队列满时拒绝并将作业标记 `FAILED`（提示稍后重试）。此改动不影响 MRP 现有行为。

## 5. 文件交付方式

| 方案 | 评估 |
|------|------|
| **OSS 上传 + CDN 签名 URL（采用）** | 与现有 `StorageService` / 素材图片交付方式完全一致；下载不占应用连接；下载中心可重复下载；多实例部署无状态。签名 URL 通过专门 API 实时签发，短时效（5 分钟）。 |
| 应用字节流下载（`Content-Disposition`） | 需要新建 blob 下载 + Bearer 鉴权的前端惯例；大文件占用应用带宽与连接；异步作业场景文件本来就要有落地存储。不采用。 |

**实现细节**：
- OSS 路径约定：`{tenantCode}/exports/{jobType}/{yyyyMM}/{jobId}_{yyyyMMddHHmmss}.xlsx`（沿用素材图片的 `{tenantCode}/...` 前缀约定，租户天然隔离）。
- 上传时通过 `ObjectMetadata` 设置 `Content-Type`（xlsx MIME）与 `Content-Disposition: attachment; filename*=UTF-8''...`，浏览器点击签名 URL 即弹出下载并使用友好文件名。现有 `StorageService.upload(path, in, contentType)` 需增加一个可传 metadata/disposition 的重载。
- 文件保留策略：OSS 生命周期规则对 `*/exports/` 前缀 30 天过期删除（`lychee-infra` 记录配置）；`export_jobs.expires_at` 同步写 30 天，过期后下载 API 返回业务错误。

## 6. 前端选型

- **不引入** `file-saver`/`xlsx` 等库：下载即打开签名 URL（`<a download>` 动态点击），无需 blob 处理。
- **不引入** `react-to-print` / PDF.js / `react-pdf` / `@react-pdf/renderer` / jspdf：单据预览用浏览器原生 PDF（iframe）即可；打印打的是服务端真实 PDF，避免二次渲染漂移与额外打包体积。
- 共享组件：`PdfBlobViewer` + `PdfPreviewModal`（blob 预览/打印壳）+ `ExportButton`（归档下载）；blob 工具见 `utils/blob`（`parseFileNameFromContentDisposition` / `assertPdfBlob`）。
- 轮询复用 ProTable `polling` / `setInterval` + MRP 页面已有的状态标签渲染范式。
- 统计图表库（Ant Design Charts 等）留待统计分析类报表立项时再评估，本期不引入。

## 7. 多租户与安全要点（贯穿所有方案）

1. 异步线程必须显式传递：事件对象携带 `tenantId` + `Authentication`，监听器内 `TenantContextHolder.setTenantId(...)` + `SecurityContextHolder...setAuthentication(...)`，`finally` 中双双清理——与 `MrpRunEventListener` 逐字对齐。
2. Handler 内数据读取一律走 JPA Repository（`@TenantId` 判别列自动过滤），**禁止**原生 SQL 绕过租户过滤。
3. 导出权限：创建作业时按 Handler 声明的权限串校验（如 `/scm/suppliers:export`），与前端 `canAction(pathname, 'export')` 按钮门控一一对应；作业查询/下载仅限本租户（`@TenantId` 保证）+ 可选"仅创建人可见"策略（一期先按租户可见，简单够用）。
4. 导出内容的列头与枚举翻译使用作业记录的 `locale` 字段 + 后端 `MessageService`，保证异步线程内仍能按用户语言渲染。
