# 10 — 示例：工单进度报表（Production Order Progress Report）

> 编写日期：2026-08-13  
> 状态：**一期清单 + 二期模板均已实现**（2026-08-13）  
> 前置：导出框架（02）、供应商清单 Excel（03）、进耗存模板 Excel（05）已落地

## 1. 目标与范围

从生产工单（`ProductionOrder`）**列表工具栏**发起导出，按当前筛选条件导出 **多张工单 → 一张扁平行 Excel**：工单进度字段在每行重复，组件领料进度（`required` / `issued`）作为行粒度。

一期与二期是 **两个并存的导出作业**（不是替换）：清单走流式写入、行数上限高；模板填充有独立的更低行数上限（`lychee.export.template-max-rows`，默认 50,000），大数据量仍用清单导出。

| 纳入 | 不纳入 |
|------|--------|
| 列表筛选驱动的多单 Excel；状态等条件与列表所见一致 | 单据 PDF / 预览打印 / `/print` 深链 |
| 一期：纯列清单（`ExcelWriteSupport`，`max-rows`） | 一期标题区、合计行、强制工厂/期间 |
| 二期：**另立**固定版式 Excel（`ExcelTemplateWriteSupport`，`template-max-rows`），与一期并存 | 用二期 Handler 替换一期；统计分析图表、邮件外发 |
| 组件领料进度；无组件工单仍导出 1 行空组件列 | 双 Sheet（工单 / 组件分表） |
| `CANCELLED` 跟列表筛选项走（导出含状态列） | 草稿报工/草稿发料数量（`draft*`） |

**报表名称（三语）**

| locale | 名称 |
|--------|------|
| zh-CN | 工单进度报表 |
| en-US | Production order progress report |
| vi-VN | Báo cáo tiến độ lệnh sản xuất |

**与相近报表的差异**

| 维度 | 08 FactoryOrder / 09 SalesOrder | 03 供应商清单 | **10 工单进度** |
|------|----------------------------------|---------------|-----------------|
| 类别 | 单据类 PDF | 清单类 Excel | **清单类 + 固定版式 Excel 并存** |
| 数据范围 | 单张或跨单接单矩阵 | 主数据一行一条 | 筛选范围内多张 PO，按组件展开 |
| 入口 | 打印 / 预览 | 列表 `ExportButton` | **列表两个 `ExportButton`**（清单 / 报表） |
| 产出 | PDF | xlsx | **xlsx only** |

## 2. 业务决策（已确认）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 报表名词 | **工单进度报表** |
| 2 | 范围 | 列表筛选多单导出；不按勾选；无行操作单张导出 |
| 3 | 产出 | **只要 Excel**；无 PDF 预览/打印 |
| 4 | 一期版式 | **纯列清单**（`ExcelWriteSupport` 流式写入） |
| 5 | 二期版式 | **标题区 + 合计**（`ExcelTemplateWriteSupport`） |
| 6 | 一期 vs 二期 | **并存、不替换**：两个 `ExportJobType`、两个按钮；模板受 `template-max-rows` 限制，大导出走清单 |
| 7 | 明细 | **含组件领料进度**（`requiredQuantity` / `issuedQuantity`） |
| 8 | `CANCELLED` | **跟列表筛选项走**；不硬排除。未筛状态时取消单会出现在导出中（状态列可辨认） |
| 9 | 无组件工单 | **仍导出 1 行**，组件列留空 |
| 10 | 行粒度 | 一行 = 一条组件；工单进度字段在同行重复 |
| 11 | 强制筛选 | 一期不强制工厂/日期；二期模板导出再评估（建议单一工厂和/或日期区间，以压进行数） |
| 12 | 草稿数量 | 不导出 `draftCompletedQuantity` / `draftIssueQuantity` 等；以已过账数量为准 |

## 3. 总体流程

```
前端生产工单列表
   │  lastQueryRef ← toPageRequest(params, sort)
   ├─ [导出清单]  ExportButton jobType=PP_PRODUCTION_PROGRESS
   └─ [导出报表]  ExportButton jobType=PP_PRODUCTION_PROGRESS_TEMPLATE   ← 二期
   ▼
POST /api/v1/report/export-jobs  { jobType, params, sort }
   ▼
ExportJobService（既有）
   ├─ 权限：二者均为 /pp/production-orders:export
   ├─ Handler.count(params)  ← 扁平行数（见 §5.3）；maxRows 按 Handler.usesExcelTemplate() 分流
   │     清单：lychee.export.max-rows（默认 200,000）
   │     模板：lychee.export.template-max-rows（默认 50,000）
   ├─ ≤ sync-threshold：同步执行；否则异步
   └─ 按 jobType 分发
          ├─ ProductionProgressExportHandler
          │     spec = 列表同源 DynamicSpecifications（含用户所选状态，含 CANCELLED）
          │     分页读 PO → 批量组件 → 展开扁平行
          │     ExcelWriteSupport.writePagedExpanded → OSS
          └─ ProductionProgressTemplateExportHandler（二期）
                同一 Assembler / 同一 spec
                ExcelTemplateWriteSupport.fill → OSS
```

作业管线（创建 / 同步·异步 / OSS / 导出中心）**零改动**。一期只实现清单 Handler 与「导出清单」按钮；二期加模板 Handler 与第二个按钮。

## 4. 数据模型与派生字段

### 4.1 行粒度

```
ProductionOrder (列表筛选命中，含用户所选状态)
   └─ 0 条组件  →  1 行（工单列有值，组件列空）
   └─ N 条组件  →  N 行（工单列重复，组件列各异）
```

同工单多行时，Excel 中工单号连续重复，便于筛选/透视；一期不做单元格合并。

### 4.2 列定义（一期）

工单进度列：

| 列 | 来源 | 说明 |
|----|------|------|
| factory | `factory.code - name` | 与列表工厂列一致 |
| orderNo | `ProductionOrder.orderNo` | |
| orderStatus | 枚举翻译 | `enum.ProductionOrderStatus.*` |
| productMaterial | `productMaterial.code - name` | |
| orderUnit | `orderUnit.code - name` | |
| plannedQuantity | `plannedQuantity` | |
| completedQuantity | `completedQuantity` | |
| scrappedQuantity | `scrappedQuantity` | |
| completionRate | 派生 | `completed / planned`；计划量为 0 则空 |
| remainingQuantity | 派生 | `planned - completed`（不扣报废） |
| scheduledStartDate | `scheduledStartDate` | `yyyy-MM-dd` |
| scheduledEndDate | `scheduledEndDate` | `yyyy-MM-dd` |
| actualStartDate | `actualStartDate` | `yyyy-MM-dd HH:mm` |
| actualEndDate | `actualEndDate` | `yyyy-MM-dd HH:mm` |
| overdue | 派生 | 见 §4.3 |
| department | 部门 `code - name` | `BasisCacheService.getAllDepartments` |
| remarks | `ProductionOrder.remarks` | |

组件领料列：

| 列 | 来源 | 无组件时 |
|----|------|----------|
| itemNo | `ProductionOrderComponent.itemNo` | 空 |
| componentMaterial | `material.code - name` | 空 |
| issueUnit | `issueUnit.code - name` | 空 |
| requiredQuantity | `requiredQuantity` | 空 |
| issuedQuantity | `issuedQuantity` | 空 |
| issueRate | 派生：`issued / required`；需求为 0 则空 | 空 |
| pendingIssueQuantity | 派生：`required - issued` | 空 |
| isBackflush | 是/否（三语） | 空 |
| underIssueTolerance | 百分比文本（如 `5%`） | 空 |
| componentRemarks | `ProductionOrderComponent.remarks` | 空 |

列头 i18n 使用后端 `export.production_progress.*`（与供应商导出同一模式，不直接绑前端 `pages.ts`，避免前后端 key 漂移）。

### 4.3 逾期口径

同时满足则为「是」，否则「否」：

1. `scheduledEndDate != null` 且 `scheduledEndDate < 导出当日（租户/服务器日期，与现有 LocalDate 惯例一致）`
2. `orderStatus` 不在 `{FINISHED, CLOSED, CANCELLED}`（已完工/结案/取消不视为逾期）

不按 `actualEndDate` 判断：未完工且计划结束日已过即视为逾期。取消单可出现在导出中，状态列为「已取消」，逾期列为「否」。

### 4.4 比率格式

完工率 / 领料率：小数（如 `0.85`）或百分比文本（如 `85%`）。一期采用 **百分比文本、保留 1 位小数**（`85.0%`），Excel 中可筛选；二期模板可改为数值列以便合计。

## 5. 后端（`lychee-erp-pp`）

### 5.1 登记作业类型

```java
// ExportJobType（common）
PP_PRODUCTION_PROGRESS           // 工单进度清单 Excel（流式，max-rows）
PP_PRODUCTION_PROGRESS_TEMPLATE  // 工单进度报表 Excel（模板填充，template-max-rows）；二期
```

前端 `ExportJobType` 联合类型同步追加（一期可先只加清单 type）。  
`EnumController` 已按枚举反射注册，无需改控制器。  
三语：`enum.ExportJobType.PP_PRODUCTION_PROGRESS` / `enum.ExportJobType.PP_PRODUCTION_PROGRESS_TEMPLATE`。

**必须两个 type、两个 Handler**：模板填充走 `usesExcelTemplate()=true`，作业层才会套用 `template-max-rows`（默认 50,000）；清单保持 `max-rows`（默认 200,000）。同一 type 无法同时服务两种上限，也不能用二期替换一期。

| jobType | Handler | 写入 | 行数上限 | 按钮文案（建议） |
|---------|---------|------|----------|------------------|
| `PP_PRODUCTION_PROGRESS` | `ProductionProgressExportHandler` | `ExcelWriteSupport.writePagedExpanded` | `max-rows` | 导出清单 |
| `PP_PRODUCTION_PROGRESS_TEMPLATE` | `ProductionProgressTemplateExportHandler` | `ExcelTemplateWriteSupport.fill` | `template-max-rows` | 导出报表 |

权限串相同：`/pp/production-orders:export`。展开与派生抽到 `ProductionProgressRowAssembler`，两个 Handler 共用。

### 5.2 查询规格

```java
Specification<ProductionOrder> buildSpec(ExportContext ctx) {
    Specification<ProductionOrder> spec =
        DynamicSpecifications.build(ProductionOrder.class, ctx.params());
    Specification<ProductionOrder> fetch =
        DynamicSpecifications.fetch("productMaterial", "factory", "orderUnit");
    return spec.and(fetch);
}
```

- `params` / `sort` 与 `ProductionOrderServiceImpl.getProductionOrderPage` **完全同源**（`DynamicSpecifications`），保证导出行集 = 列表翻完的总集（含用户筛到的 `CANCELLED`）。
- **不**附加 `orderStatus <> CANCELLED`。未选状态时取消单会出现；用户筛掉取消则导出不含。状态列已导出，无需后端再藏行。
- 列表默认排序为 `orderNo descend`；导出沿用 `ctx.toSort()`（无排序时框架默认 `id DESC`）。Handler 应在无 `sort` 时与列表对齐：优先 `orderNo DESC, id ASC`。组件在工单内按 `itemNo ASC`。

### 5.3 `count`：按扁平行数

同步/异步分流与 `max-rows` 必须以 **Excel 行数** 为准，不能只 `count(ProductionOrder)`（工单少、组件多时会误走同步快路径）。

```
flattenedRows
  = COUNT(组件 JOIN 列表 spec 命中的工单)
  + COUNT(列表 spec 命中、且无任何组件的工单)
```

等价：每个命中工单贡献 `max(组件数, 1)` 行。

建议在 `ProductionOrderRepository` / `ProductionOrderComponentRepository` 用 JPQL 两次 count（同一列表 spec；组件 count 通过 `JOIN ProductionOrder` 套用工单 spec）。禁止为 count 把全部 id 载入内存。

`count == 0`：仍生成 **仅含列头的空 xlsx**（对齐供应商清单），不报业务错误。

模板 Handler 的 `count` 算法相同，但 `ExportJobService` 用 `template-max-rows` 做上限；超限提示用户缩小筛选或改用「导出清单」。

### 5.4 展开写入与框架小扩展

现有 `ExcelWriteSupport.writePaged` 是 **1 实体 → 1 行**。本报表是 **1 工单 → 1..N 行**，在 common 增加重载，避免 Handler 手写 Fesod：

```java
// ExcelWriteSupport
public static <E> int writePagedExpanded(
        OutputStream out,
        String sheetName,
        List<String> headers,
        Function<E, List<List<Object>>> rowsMapper,  // 一实体多行
        Function<Pageable, Slice<E>> sliceLoader,
        Sort sort,
        int batchSize,
        int maxRows)
```

- 分页对象仍是 `ProductionOrder`（`batchSize` 按工单计，默认 1000）。
- `maxRows` 按 **展开后的 Excel 行** 累计；超限抛 `validation.export.rows.exceeded`。
- 每批：`findAll` 工单 → `findAllByProductionOrderIdIn` 组件 → `rowsMapper` 展开 → `writer.write`。
- 不包长 `@Transactional`：`SpecificationSliceQuery` 每批短只读事务；组件查询同批内完成。接受批间微小不一致。

组件 fetch：`material`、`issueUnit`（可用 `DynamicSpecifications.fetch` 或实体上已有 `@ManyToOne` 在 in 查询后 batch fetch）。

部门：`BasisCacheService.getAllDepartments(tenantId)` 一次加载，按 `departmentId` 解析 `code - name`。

```java
        // fileName: export.production_progress.fileName + _yyyy-MM-dd.xlsx
        //           （建议文案「工单进度清单」，与模板「工单进度报表」区分）

```

代码位置：

- `lychee-erp-pp/.../export/ProductionProgressRowAssembler.java`（共用）

### 6.3 交互验收（一期）

1. 无 `export` 权限时按钮不渲染。
2. 小数据量（扁平行 ≤ 5,000）：同步完成并下载，文件名如 `工单进度清单_2026-08-13.xlsx`。
3. 大数据量：通知「导出处理中」→ 轮询 → 自动下载；也可到导出中心下载。
4. 列表筛选工厂/单号/状态/物料后导出：行集与列表分页翻完的总集一致（含筛到的 `CANCELLED`）。
5. 列表仅筛 `CANCELLED`：导出这些取消单（状态列为已取消），不是空表。
6. 无组件工单：Excel 中该工单 1 行，组件列为空。
7. 有 3 条组件的工单：3 行，工单号/计划量等重复，项次 1..3。
8. 切换语言后列头、状态、是否倒冲、逾期「是/否」随语言变化。
9. 清单超 `max-rows`：FAILED + 后端错误消息。
10. （二期）模板超 `template-max-rows`：FAILED，提示缩小筛选或改用导出清单。

## 9. 测试要点

- 单元：Assembler —— 无组件 → 1 行空组件列；3 组件 → 3 行；计划量 0 时完工率空；逾期边界（结束日=今天为否，昨天且 IN_PROGRESS 为是，FINISHED / CANCELLED 即使过期为否）。
- 单元：Handler —— 内存 `ByteArrayOutputStream` + Fesod 读回列头/行数；`orderStatus_eq=CANCELLED` 时导出取消单且状态列为翻译文本。
- `count` 与实际导出行数一致（混合：有组件 + 无组件工单）。
- 集成：租户隔离（作业/下载）；权限 `/pp/production-orders:export`。
- 性能：本地约 5 万扁平行清单导出 < 30s、堆增量可控（分页工单 + 批量组件，禁止一次性 load 全表）。
