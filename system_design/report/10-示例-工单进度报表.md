# 10 — 示例：工单进度报表（Production Order Progress Report）

> 编写日期：2026-08-13  
> 状态：**一期清单已实现**；**二期模板修订（工单行 + 备料汇总 + 第二 Sheet）已落地**（2026-08-13）  
> 前置：导出框架（02）、供应商清单 Excel（03）、进耗存模板 Excel（05）已落地

## 1. 目标与范围

从生产工单（`ProductionOrder`）**列表工具栏**发起导出，按当前筛选条件导出多张工单。一期清单与二期模板是 **两个并存的导出作业**（不是替换），**粒度不同**：

| 作业 | 粒度 | 用途 |
|------|------|------|
| 清单 `PP_PRODUCTION_PROGRESS` | **扁平行**：一行 = 一条组件；工单进度字段在每行重复 | Excel 筛选/透视欠料；流式写入、行数上限高 |
| 报表 `PP_PRODUCTION_PROGRESS_TEMPLATE` | **工单行**：一行 = 一张工单；备料只表达汇总齐套状况。组件领料明细在 **同一 workbook 第二 Sheet** | 进度会材料（完工/逾期/能否上线）；模板填充、行数上限较低 |

清单走 `ExcelWriteSupport`（`max-rows`，默认 200,000）；模板走 `ExcelTemplateWriteSupport`（`template-max-rows`，默认 50,000）。大数据量仍用清单。清单 **文件名与列结构不改**。

| 纳入 | 不纳入 |
|------|--------|
| 列表筛选驱动的多单 Excel；状态等条件与列表所见一致 | 单据 PDF / 预览打印 / `/print` 深链 |
| 一期：纯列清单（`ExcelWriteSupport`，`max-rows`），扁平行含组件领料 | 清单标题区、合计行 |
| 二期：**另立**固定版式 Excel（`ExcelTemplateWriteSupport`，`template-max-rows`），与一期并存 | 用二期 Handler 替换一期；统计分析图表、邮件外发 |
| 模板主表：工单进度 + **汇总备料**（齐套状态/齐套率/欠料项数） | 清单双 Sheet（流式仍单 Sheet） |
| **清单与模板均强制**：单一 `factoryId` + 计划日期闭区间（`scheduledStartDate`–`scheduledEndDate`） | 未选厂 / 未选齐区间时导出 |
| 模板第二 Sheet：备料明细（组件 `required` / `issued`）；无组件工单主表仍 1 行 | 独立第三张「备料明细」导出作业 / 第三按钮 |
| `CANCELLED` 跟列表筛选项走（导出含状态列） | 草稿报工/草稿发料数量（`draft*`） |

**报表名称（三语）**（模板文件名；清单文件名仍为既有「工单进度清单」）

| locale | 名称 |
|--------|------|
| zh-CN | 工单进度报表 |
| en-US | Production order progress report |
| vi-VN | Báo cáo tiến độ lệnh sản xuất |

**与相近报表的差异**

| 维度 | 08 FactoryOrder / 09 SalesOrder | 03 供应商清单 | **10 工单进度** |
|------|----------------------------------|---------------|-----------------|
| 类别 | 单据类 PDF | 清单类 Excel | **清单类 + 固定版式 Excel 并存** |
| 数据范围 | 单张或跨单接单矩阵 | 主数据一行一条 | 清单：按组件展开；模板：1 工单 1 行 + 备料明细 Sheet。**二者均强制单厂 + 计划日期区间** |
| 入口 | 打印 / 预览 | 列表 `ExportButton` | **列表两个 `ExportButton`**（清单 / 报表）；不新增第三按钮 |
| 产出 | PDF | xlsx | **xlsx only** |

## 2. 业务决策（已确认）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 报表名词 | **工单进度报表**（模板）；清单文件名 **不改** |
| 2 | 范围 | 列表筛选多单导出；不按勾选；无行操作单张导出 |
| 3 | 产出 | **只要 Excel**；无 PDF 预览/打印 |
| 4 | 一期版式 | **纯列清单**（`ExcelWriteSupport` 流式写入） |
| 5 | 二期版式 | **标题区 + 合计**（`ExcelTemplateWriteSupport`） |
| 6 | 一期 vs 二期 | **并存、不替换**：两个 `ExportJobType`、两个按钮；模板受 `template-max-rows` 限制，大导出走清单 |
| 7 | 明细 | **清单**：含组件领料进度（`requiredQuantity` / `issuedQuantity`）。**模板主表不含组件列**；组件明细仅第二 Sheet |
| 8 | `CANCELLED` | **跟列表筛选项走**；不硬排除。未筛状态时取消单会出现在导出中（状态列可辨认） |
| 9 | 无组件工单 | **清单**：仍导出 1 行，组件列留空。**模板**：主表 1 行（备料状态=无需备料）；明细 Sheet 无对应行 |
| 10 | 行粒度 | **清单**：一行 = 一条组件，工单进度字段在同行重复。**模板主表**：一行 = 一张工单 |
| 11 | 强制筛选 | **清单与模板相同**：必须单一 `factoryId` + 计划日期闭区间（`scheduledStartDate` ≥ from 且 `scheduledEndDate` ≤ to，两端齐全且 from ≤ to）。两按钮 `beforeExport` + 两 Handler `count`/`export` 双校验。口径见 §5.2.1 |
| 12 | 草稿数量 | 不导出 `draftCompletedQuantity` / `draftIssueQuantity` 等；以已过账数量为准 |
| 13 | 模板备料汇总 | 主表只表达齐套状况（状态 / 齐套率 / 欠料项数）；**禁止**工单行上 `sum(issued)/sum(required)`（跨单位无意义） |
| 14 | 模板双 Sheet | 同一 workbook：Sheet0 工单进度、Sheet1 备料明细；**不是**独立作业。清单仍不做双 Sheet |
| 15 | 齐套口径 | 倒冲件不参与齐套；欠发公差与组件 `underIssueTolerance` 一致（百分数，如 `5` = 5%） |
| 16 | 模板 `count` / 上限 | **按工单数**卡 `template-max-rows`。明细行另见 §7.4：超限时主表仍出、明细 Sheet 不填充并提示改用清单 |
| 17 | 模板合计 | 计划/完工/报废按工单行直接加总（1:1，无需去重）。**禁止**跨组件合计需求/已发 |

## 3. 总体流程

```
前端生产工单列表
   │  lastQueryRef ← toPageRequest(params, sort)
   ├─ [导出清单]  ExportButton jobType=PP_PRODUCTION_PROGRESS
   └─ [导出报表]  ExportButton jobType=PP_PRODUCTION_PROGRESS_TEMPLATE
                    二者共用 beforeExport：单一 factoryId + 计划日期区间两端齐全
                    不满足 → message.warning，不发请求
   ▼
POST /api/v1/report/export-jobs  { jobType, params, sort }
   ▼
ExportJobService（既有）
   ├─ 权限：二者均为 /pp/production-orders:export
   ├─ Handler.count(params) 先 requireFactoryAndScheduleRange（§5.2.1）
   │     清单：扁平行数（§5.3）；lychee.export.max-rows（默认 200,000）
   │     模板：工单数（§7.4）；lychee.export.template-max-rows（默认 50,000）
   ├─ ≤ sync-threshold：同步执行；否则异步
   └─ 按 jobType 分发
          ├─ ProductionProgressExportHandler
          │     requireFactoryAndScheduleRange（count / export 均调）
          │     spec = 列表同源 DynamicSpecifications（强制条件已在 params 中）
          │     分页读 PO → 批量组件 → 展开扁平行
          │     ExcelWriteSupport.writePagedExpanded → OSS
          └─ ProductionProgressTemplateExportHandler
                requireFactoryAndScheduleRange（同一 QuerySupport 方法）
                ReportAssembler：1 工单 → 1 主表行 + 0..N 明细行
                ExcelTemplateWriteSupport.fill（按 sheetNo）→ OSS
```

作业管线（创建 / 同步·异步 / OSS / 导出中心）**零改动**。本修订改模板粒度与双 Sheet，并为 **清单与模板** 加上相同强制筛选；**不改清单文件名、扁平行列结构、按钮文案**。

## 4. 数据模型与派生字段（清单）

本节描述 **清单** 扁平行。模板主表/明细见 §7。

### 4.1 行粒度

```
ProductionOrder (列表筛选命中，含用户所选状态)
   └─ 0 条组件  →  1 行（工单列有值，组件列空）
   └─ N 条组件  →  N 行（工单列重复，组件列各异）
```

同工单多行时，Excel 中工单号连续重复，便于筛选/透视；清单不做单元格合并。

### 4.2 列定义（一期清单）

工单进度列：

| 列 | 来源 | 说明 |
|----|------|------|
| factory | `factory.code - name` | 与列表工厂列一致 |
| orderNo | `ProductionOrder.orderNo` | |
| orderStatus | 枚举翻译 | `enum.ProductionOrderStatus.*` |
| productMaterial | `productMaterial.code - name` | |
| orderUnit | `orderUnit.code - name` | |
| plannedQuantity | `plannedQuantity` | |
| completedQuantity | `completedQuantity` | |
| scrappedQuantity | `scrappedQuantity` | |
| completionRate | 派生 | `completed / planned`；计划量为 0 则空 |
| remainingQuantity | 派生 | `planned - completed`（不扣报废） |
| scheduledStartDate | `scheduledStartDate` | `yyyy-MM-dd` |
| scheduledEndDate | `scheduledEndDate` | `yyyy-MM-dd` |
| actualStartDate | `actualStartDate` | `yyyy-MM-dd HH:mm` |
| actualEndDate | `actualEndDate` | `yyyy-MM-dd HH:mm` |
| overdue | 派生 | 见 §4.3 |
| department | 部门 `code - name` | `BasisCacheService.getAllDepartments` |
| remarks | `ProductionOrder.remarks` | |

组件领料列：

| 列 | 来源 | 无组件时 |
|----|------|----------|
| itemNo | `ProductionOrderComponent.itemNo` | 空 |
| componentMaterial | `material.code - name` | 空 |
| issueUnit | `issueUnit.code - name` | 空 |
| requiredQuantity | `requiredQuantity` | 空 |
| issuedQuantity | `issuedQuantity` | 空 |
| issueRate | 派生：`issued / required`；需求为 0 则空 | 空 |
| pendingIssueQuantity | 派生：`required - issued` | 空 |
| isBackflush | 是/否（三语） | 空 |
| underIssueTolerance | 百分比文本（如 `5%`） | 空 |
| componentRemarks | `ProductionOrderComponent.remarks` | 空 |

列头 i18n 使用后端 `export.production_progress.*`（与供应商导出同一模式，不直接绑前端 `pages.ts`，避免前后端 key 漂移）。

### 4.3 逾期口径

同时满足则为「是」，否则「否」：

1. `scheduledEndDate != null` 且 `scheduledEndDate < 导出当日（租户/服务器日期，与现有 LocalDate 惯例一致）`
2. `orderStatus` 不在 `{FINISHED, CLOSED, CANCELLED}`（已完工/结案/取消不视为逾期）

不按 `actualEndDate` 判断：未完工且计划结束日已过即视为逾期。取消单可出现在导出中，状态列为「已取消」，逾期列为「否」。

### 4.4 比率格式

完工率 / 领料率 / 模板齐套率：一期与模板均采用 **百分比文本、保留 1 位小数**（`85.0%`），Excel 中可筛选。清单不改为数值列。

## 5. 后端（`lychee-erp-pp`）

### 5.1 登记作业类型

```java
// ExportJobType（common）
PP_PRODUCTION_PROGRESS           // 工单进度清单 Excel（流式扁平行，max-rows）
PP_PRODUCTION_PROGRESS_TEMPLATE  // 工单进度报表 Excel（模板：工单行 + 备料明细 Sheet，template-max-rows）
```

前端 `ExportJobType` 联合类型已同步。  
`EnumController` 已按枚举反射注册，无需改控制器。  
三语：`enum.ExportJobType.PP_PRODUCTION_PROGRESS` / `enum.ExportJobType.PP_PRODUCTION_PROGRESS_TEMPLATE`。

**必须两个 type、两个 Handler**：模板填充走 `usesExcelTemplate()=true`，作业层才会套用 `template-max-rows`（默认 50,000）；清单保持 `max-rows`（默认 200,000）。同一 type 无法同时服务两种上限，也不能用模板替换清单。

| jobType | Handler | 写入 | 行数上限 | 按钮文案 |
|---------|---------|------|----------|----------|
| `PP_PRODUCTION_PROGRESS` | `ProductionProgressExportHandler` | `ExcelWriteSupport.writePagedExpanded` | `max-rows`（扁平行） | 导出清单 |
| `PP_PRODUCTION_PROGRESS_TEMPLATE` | `ProductionProgressTemplateExportHandler` | `ExcelTemplateWriteSupport.fill`（按 sheet） | `template-max-rows`（**工单数**） | 导出报表 |

权限串相同：`/pp/production-orders:export`。

查询与分页加载抽到 `ProductionProgressQuerySupport`，两个 Handler 共用。  
**清单**展开与派生仍用 `ProductionProgressRowAssembler`（扁平行，不改）。  
**模板**用独立 `ProductionProgressReportAssembler`（工单行 + 齐套 + 明细行），避免再把组件列展开进主表。

### 5.2 查询规格

```java
Specification<ProductionOrder> buildSpec(ExportContext ctx) {
    Specification<ProductionOrder> spec =
        DynamicSpecifications.build(ProductionOrder.class, ctx.params());
    Specification<ProductionOrder> fetch =
        DynamicSpecifications.fetch("productMaterial", "factory", "orderUnit");
    return spec.and(fetch);
}
```

- `params` / `sort` 与 `ProductionOrderServiceImpl.getProductionOrderPage` **完全同源**（`DynamicSpecifications`），保证导出行集 = 列表翻完的总集（含用户筛到的 `CANCELLED`）。
- **不**附加 `orderStatus <> CANCELLED`。未选状态时取消单会出现；用户筛掉取消则导出不含。状态列已导出，无需后端再藏行。
- 列表默认排序为 `orderNo descend`；导出沿用 `ctx.toSort()`（无排序时框架默认 `id DESC`）。Handler 应在无 `sort` 时与列表对齐：优先 `orderNo DESC, id ASC`。组件在工单内按 `itemNo ASC`。

### 5.2.1 强制导出条件（清单与模板共用）

**两个作业相同**。对齐进耗存 05 §4.1.1、销售订单 09 §9：前端拦截 + 后端 `count`/`export` 再验，以后端为准（防 API 直调）。实现放在 `ProductionProgressQuerySupport.requireFactoryAndScheduleRange`，禁止两 Handler 各写一份。

| 维度 | 必填 | params 约定（与列表 `field_op` 一致） | 说明 |
|------|------|--------------------------------------|------|
| 工厂 | 是 | `factoryId` 或 `factoryId_eq`，且为**单一**值 | 缺失、多选、逗号拼接均拒绝 |
| 计划开始下界 | 是 | `scheduledStartDate_gte`（或 `scheduledStartDate_ge` / `scheduledStartDate` 的 between 下界） | 解析为 `from`（`LocalDate`） |
| 计划结束上界 | 是 | `scheduledEndDate_lte`（或 `scheduledEndDate_le` / `scheduledEndDate` 的 between 上界） | 解析为 `to`（`LocalDate`） |

区间规则：

- `from`、`to` 两端必须都能解析；缺任一端 → 拒绝。
- `from > to` → 拒绝。
- **查询语义（计划窗口落在闭区间内）**：`scheduledStartDate >= from` **且** `scheduledEndDate <= to`。不采用「与区间相交」。
- `scheduledStartDate` 或 `scheduledEndDate` 为 null 的工单 **不命中**（无法判定窗口是否落在区间内）。
- 不另写一套 Specification：强制条件以列表同源 params 进入 `DynamicSpecifications`；`require*` 只负责「能否解析出单一工厂 + 两端日期」。
- 其余列表条件（状态、单号、物料等）照常叠加收窄。

校验与文案：

1. **前端**（清单、报表两个 `ExportButton` 共用同一 `beforeExport`）：读 `lastQueryRef` / `formRef.getFieldsFormatValue()`。不满足 → `message.warning`（`pages.pp.productionOrders.export.requireFactoryAndSchedule`），不调用 `createExportJob`。
2. **后端**（两 Handler 的 `count` 与 `export` 均调 `querySupport.requireFactoryAndScheduleRange(params)`）：不满足抛 `ValidationException`：
   - 工厂缺失/非单一：`validation.export.production_progress.factory.required`
   - 日期两端不齐或无法解析：`validation.export.production_progress.schedule.required`
   - `from > to`：`validation.export.production_progress.schedule.invalid_range`

列表搜索 UI（实施时）：搜索区增加 `valueType: 'dateRange'`、`hideInTable` 的「计划日期」，`transform` 同时写出 `scheduledStartDate_gte` 与 `scheduledEndDate_lte`。表格内 `scheduledStartDate` / `scheduledEndDate` 列 `search: false`。工厂列保持 `buildFactoryColumn`（单选即可满足「单一」）。浏览列表本身不强制填厂/日期，**仅点导出时校验**。

### 5.3 `count`：清单按扁平行数

同步/异步分流与清单 `max-rows` 必须以 **Excel 行数** 为准，不能只 `count(ProductionOrder)`（工单少、组件多时会误走同步快路径）。

```
flattenedRows
  = COUNT(组件 JOIN 列表 spec 命中的工单)
  + COUNT(列表 spec 命中、且无任何组件的工单)
```

等价：每个命中工单贡献 `max(组件数, 1)` 行。

建议在 `ProductionOrderRepository` / `ProductionOrderComponentRepository` 用 JPQL 两次 count（同一列表 spec；组件 count 通过 `JOIN ProductionOrder` 套用工单 spec）。禁止为 count 把全部 id 载入内存。

`count == 0`：仍生成 **仅含列头的空 xlsx**（对齐供应商清单），不报业务错误。清单 `count` / `export` **先** `requireFactoryAndScheduleRange`（§5.2.1），再按扁平行计数。

模板 Handler 的 `count` **不**再用扁平行算法，见 §7.4（同样先 require）。

### 5.4 展开写入与框架小扩展

现有 `ExcelWriteSupport.writePaged` 是 **1 实体 → 1 行**。清单是 **1 工单 → 1..N 行**，在 common 增加重载，避免 Handler 手写 Fesod：

```java
// ExcelWriteSupport
public static <E> int writePagedExpanded(
        OutputStream out,
        String sheetName,
        List<String> headers,
        Function<E, List<List<Object>>> rowsMapper,  // 一实体多行
        Function<Pageable, Slice<E>> sliceLoader,
        Sort sort,
        int batchSize,
        int maxRows)
```

- 分页对象仍是 `ProductionOrder`（`batchSize` 按工单计，默认 1000）。
- `maxRows` 按 **展开后的 Excel 行** 累计；超限抛 `validation.export.rows.exceeded`。
- 每批：`findAll` 工单 → `findAllByProductionOrderIdIn` 组件 → `rowsMapper` 展开 → `writer.write`。
- 不包长 `@Transactional`：`SpecificationSliceQuery` 每批短只读事务；组件查询同批内完成。接受批间微小不一致。

组件 fetch：`material`、`issueUnit`（可用 `DynamicSpecifications.fetch` 或实体上已有 `@ManyToOne` 在 in 查询后 batch fetch）。

部门：`BasisCacheService.getAllDepartments(tenantId)` 一次加载，按 `departmentId` 解析 `code - name`。

## 6. 前端

1. 无 `export` 权限时按钮不渲染。
2. 小数据量（扁平行 ≤ 5,000）：同步完成并下载，文件名如 `工单进度清单_2026-08-13.xlsx`。
3. 大数据量：通知「导出处理中」→ 轮询 → 自动下载；也可到导出中心下载。
4. 已选单一工厂 + 计划日期区间后导出：行集与列表分页翻完的总集一致（含筛到的 `CANCELLED`）；计划开始或结束为空的工单不出现。
5. 列表仅筛 `CANCELLED`（且已满足厂+区间）：导出这些取消单（状态列为已取消），不是空表。
6. 无组件工单：Excel 中该工单 1 行，组件列为空。
7. 有 3 条组件的工单：3 行，工单号/计划量等重复，项次 1..3。
8. 切换语言后列头、状态、是否倒冲、逾期「是/否」随语言变化。
9. 清单超 `max-rows`：FAILED + 后端错误消息。
10. 未选单一工厂或计划日期区间不齐：清单与报表均前端 warning、不发请求；直调 API 则后端 `ValidationException`。
11. （模板）工单数超 `template-max-rows`：FAILED，提示缩小筛选或改用导出清单。明细行超限见 §7.4，**不**导致整份报表失败。

### 7.1.1 强制条件与标题

强制筛选口径 **与清单相同**，见 §5.2.1，不在模板 Handler 内再写一套。

模板在 require 成功后把范围写入标题（清单无标题区，工厂列仍在扁平行中保留）：

- `factoryName`：工厂 `code - name`（与列表工厂列一致）
- `dateRange`：`yyyy-MM-dd ~ yyyy-MM-dd`（`from` ~ `to`）
- 删除初版「未选工厂 → 全部工厂」（`scopeAll`）在模板标题中的使用
- 主表去掉工厂列（标题已声明）；清单扁平行 **仍含工厂列**（无标题区）

### 7.2 备料汇总口径（Sheet0）

工单实体 **没有** 备料汇总字段，由组件派生。数量加权领料率（`sum(issued)/sum(required)`）跨单位无意义，**不用**。

**需备料组件**：`isBackflush` 不为 `true` 的组件（`null` / `false` 均计入）。倒冲件不参与齐套判定、齐套率、欠料项数（报工才发料，计入会把在制工单长期打成未齐套）。

单行 **已齐套** 当且仅当：

1. `requiredQuantity` 为 null 或 `≤ 0`，或
2. `issuedQuantity ≥ requiredQuantity × (1 − tolerance)`  
   - `tolerance = underIssueTolerance / 100`；`underIssueTolerance` 与现网一致，存百分数（`5` 表示 5%）  
   - `underIssueTolerance` 为 null 时按 0

工单级 **备料状态**（三语，见 §8）：

| 条件 | 状态 |
|------|------|
| 需备料组件数 = 0（无组件，或全部倒冲） | 无需备料 |
| 全部需备料行已齐套 | 已齐套 |
| 存在需备料行，且没有任何一行 `issued > 0`，且并非全部已齐套 | 未备 |
| 其他 | 部分 |

判定顺序：无需备料 → 已齐套 → 未备 → 部分。需求量为 0 的行视为已齐套，故「全是 0 需求」归已齐套而非未备。

| 列 | 口径 | 无需备料时 |
|----|------|------------|
| kittingStatus | 上表四态 | 无需备料 |
| kittingRate | 已齐套需备料行数 / 需备料行数；百分比文本 1 位小数 | 空 |
| shortageLineCount | 需备料且 **未** 达齐套阈值的行数 | 空 |

**Sheet0 — 工单进度**（列表名 `orders`）

**Sheet1 — 备料明细**（列表名 `components`）

| 列 | 说明 |
|----|------|

| productMaterial | 轻量工单键 |

### 7.4 `count`、上限与明细截断

```
templateCount = COUNT(列表 spec 命中的 ProductionOrder)
```

- `count` / `export` **先** `requireFactoryAndScheduleRange`，再 count / 填表。
- `count == 0`：仍生成仅含标题/列头的空模板 xlsx（两 Sheet 均可无数据行）。
- `templateCount > template-max-rows`：抛 `validation.export.production_progress.template.rows.exceeded`，提示缩小筛选或改用导出清单。
- **明细行**（组件数）若 `> template-max-rows`：**不**失败整份作业；Sheet0 照常；Sheet1 不填充数据行，标题区写入 `{componentOverflowLabel}`（三语：备料明细超过上限，请使用导出清单）。避免跨单位超宽 workbook，也避免 BOM 很深时把模板内存打满到不可控。
- `ExportResult` 的行数报 **工单行数**（与 `count` / 主表一致）。

同步分流沿用工单数：工单少、BOM 极深时同步路径仍会加载组件；明细截断限制写出体积。若日后成为问题，再把同步分流改为 `max(工单数, 组件数)`，`max-rows` 仍按工单。

### 7.5 写入工具：按 Sheet 填充

现有 `ExcelTemplateWriteSupport.fill` 把所有 `lists` 写到 **默认 Sheet0**（进耗存仍走此路径，**调用不变**）。本修订增加按 `sheetNo` 填充的重载，禁止为工单报表手写 Fesod：

```java
public record SheetFill(int sheetNo, Map<String, ? extends Collection<?>> lists) {}

public static void fill(
        OutputStream out,
        String templateClasspath,
        Map<String, Object> header,
        List<SheetFill> sheets)
```

- 每个 `sheetNo`：`FesodSheet.writerSheet(sheetNo).build()`，先 `FillWrapper` 列表（`forceNewRow`），再 `fill(header)`（两张 Sheet 的列头都走同一 header Map 的 i18n 占位符）。
- 工单 Handler：`SheetFill(0, Map.of("orders", orderRows))` + `SheetFill(1, Map.of("components", componentRows或空))`。
- 既有单参 `lists` 重载委托为 `SheetFill(0, lists)`，进耗存零改动。
- Sheet 显示名：生成器写入两张 Sheet；Handler 若能在 fill 后按 locale 重命名则用 `export.production_progress_template.sheetName` / `componentSheetName`；若 Support 不暴露 Workbook，模板内固定中文名「工单进度」「备料明细」可接受（与进耗存 Sheet 名不 i18n 同类）。**优先**在 Support 重载里按 sheetNo 接受可选 `sheetName`。

### 7.6 模板 Handler 行为

- `count` / `export` 入口先 `requireFactoryAndScheduleRange`（§5.2.1，与清单同一方法）。
- 分页仍走 `QuerySupport.loadSlice`（工单 + 批量组件）；spec 与列表同源，强制条件已在 params 中。
- 每张工单：`ReportAssembler.toOrderRow(...)` → `orders`；`toComponentRows(...)` → `components`（无组件则只主表）。
- 合计只扫 `orders`：计划/完工/报废求和；`kittingStatus=已齐套` 计数；`未备|部分` 计为欠料工单数。
- 删除初版 `Totals` 对扁平行 `requiredQuantity` / `issuedQuantity` 的加总，以及 header 中的 `componentTotal` / `totalRequiredQuantity` / `totalIssuedQuantity`。
- header：`factoryName` + `dateRange`（不再写 `scopeAll`）。
- `fileName` 仍为 `export.production_progress_template.fileName`（工单进度报表），**不改**。

## 9. 测试要点

清单（保持扁平行；本修订加强制筛选）：

- 单元：Assembler —— 无组件 → 1 行空组件列；3 组件 → 3 行；计划量 0 时完工率空；逾期边界（结束日=今天为否，昨天且 IN_PROGRESS 为是，FINISHED / CANCELLED 即使过期为否）。
- 单元：Handler —— 内存 `ByteArrayOutputStream` + Fesod 读回列头/行数；`orderStatus_eq=CANCELLED` 时导出取消单且状态列为翻译文本。
- `requireFactoryAndScheduleRange`（QuerySupport）：缺工厂 / 多工厂 / 缺日期一端 / `from > to` 均抛对应 i18n；清单与模板 Handler 共用。
- 计划开始或结束为 null 的工单不出现在清单/模板结果中。
- `count` 与实际导出行数一致（混合：有组件 + 无组件工单）。
- 集成：租户隔离（作业/下载）；权限 `/pp/production-orders:export`。
- 性能：本地约 5 万扁平行清单导出 < 30s、堆增量可控（分页工单 + 批量组件，禁止一次性 load 全表）。

模板修订：

- 强制条件与清单同一套单测即可，不必在模板 Handler 再测一遍解析。
- `usesExcelTemplate()==true`；`count` = 工单数（有 3 组件的工单仍计 1）。
- 工单数介于 `template-max-rows` 与清单 `max-rows` 之间：报表按钮失败、清单按钮成功。
- 齐套：全倒冲 → 无需备料、齐套率空；三行非倒冲均达标（含公差）→ 已齐套、欠料项数 0；一行已发>0 一行未发 → 部分；全部 issued=0 且需求>0 → 未备。
- 倒冲行不计入欠料项数；明细 Sheet 仍包含该行且 `isBackflush=是`。
- 主表无工厂列、无组件列；计划量不因组件数重复。
- 合计：两张 3 组件工单的计划量合计 = 两张工单计划量之和（不是 ×3）。
- 明细超 `template-max-rows`：主表有行、Sheet1 无数据行且出现 overflow 文案。
- `ExcelTemplateWriteSupport` 多 Sheet：进耗存单 Sheet 回归仍通过。
