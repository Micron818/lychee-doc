# 02 — 导出框架总体设计

目标：一次性建好可复用的「导出作业」基础设施，之后每个新报表只需：后端加一个 Handler、前端加一个按钮。

## 1. 总体流程

```
前端列表页 [导出] 按钮 (canAction(path,'export'))
   │  POST /api/v1/report/export-jobs  { jobType, params, sort }   ← params 即 toPageRequest 的当前筛选
   ▼
ExportJobService.create()
   ├─ 权限校验（Handler.requiredAuthority）
   ├─ Handler.count(params) 估算行数
   ├─ ≤ 5,000 行：请求内同步执行 → 响应返回 status=COMPLETED
   └─ >  5,000 行：保存 PENDING 作业 → 提交后发布 ExportJobCreatedEvent（携带 tenantId + Authentication）
                      │
                      ▼  @Async("exportTaskExecutor") + @TransactionalEventListener(AFTER_COMMIT)
                 ExportJobEventListener
                      ├─ 设置 TenantContextHolder / SecurityContext
                      ├─ status → RUNNING
                      ├─ Handler.export(ctx, out)：分页读取 + Fesod 流式写入临时文件
                      ├─ StorageService.upload → OSS {tenantCode}/exports/...
                      ├─ status → COMPLETED（file_path/file_size/total_rows/execution_time_ms）
                      ├─ 异常：status → FAILED（error_message 截断 500）
                      └─ finally 清理两个上下文
   ▲
前端 useExportJob：同步完成 → 直接取下载 URL；异步 → 每 3s GET /{id} 轮询
   └─ COMPLETED → GET /{id}/download-url（实时签发，5 分钟时效）→ <a download> 触发浏览器下载
```

## 3. 数据库设计（Liquibase：`db/changelog/v1/2026/MMDD-001-report-export-jobs.sql`）

```sql
CREATE TABLE lychee_erp.export_jobs (
    id                 BIGSERIAL PRIMARY KEY,
    tenant_id          BIGINT       NOT NULL,
    job_type           VARCHAR(64)  NOT NULL,            -- ExportJobType
    status             VARCHAR(16)  NOT NULL,            -- ExportJobStatus
    query_params       JSONB,                            -- ProPageRequest.params 快照
    query_sort         JSONB,                            -- ProPageRequest.sort 快照
    locale             VARCHAR(16),                      -- 列头/枚举翻译语言
    file_name          VARCHAR(255),                     -- 用户可见文件名
    file_path          VARCHAR(512),                     -- OSS object key
    file_size          BIGINT,
    total_rows         INTEGER,
    error_message      VARCHAR(500),
    execution_time_ms  BIGINT,
    expires_at         TIMESTAMP,                        -- 与 OSS 生命周期规则对齐（30 天）
    created_at         TIMESTAMP    NOT NULL,
    updated_at         TIMESTAMP,
    created_by         BIGINT,
    updated_by         BIGINT
);
CREATE INDEX idx_export_jobs_tenant_status ON lychee_erp.export_jobs (tenant_id, status);
CREATE INDEX idx_export_jobs_tenant_created ON lychee_erp.export_jobs (tenant_id, created_at DESC);
```

实体：`ExportJob extends AuditableEntity`，`@TenantId Long tenantId`，`query_params/query_sort` 用 Hibernate 6 的 `@JdbcTypeCode(SqlTypes.JSON)` 映射为 `Map<String,Object>` / `Map<String,String>`。

## 4. Handler SPI（新报表唯一需要实现的接口）

```java
public interface DataExportHandler {

    ExportJobType type();

    /** 权限校验串，与前端菜单路径对齐，如 "/scm/suppliers:export" */
    String requiredAuthority();

    /** 行数预估，用于同步/异步分流与行数上限校验 */
    long count(ExportContext ctx);

    /** 生成 xlsx 写入 out；返回实际导出行数 */
    ExportResult export(ExportContext ctx, OutputStream out);
}

public record ExportContext(
    Map<String, Object> params,     // 与列表页 DynamicSpecifications 语义一致
    Map<String, String> sort,
    Locale locale,
    Long tenantId,
    String tenantCode
) {}

public record ExportResult(int totalRows, String suggestedFileName) {}
```

设计要点：

- `params` 直接沿用 `ProPageRequest.params` 的 `field_op` 语法，Handler 内用 `DynamicSpecifications.build(...)` 构建查询 → **导出结果与用户在列表页看到的筛选结果严格一致**，这是清单类导出最重要的正确性保证。
- `ExcelWriteSupport`（common 内工具类）封装通用骨架：Fesod `FesodSheet.write(out, RowDto.class)` + 按 `Pageable` 每批 1000 行循环 `repository.findAll(spec, page)` → `writer.write(batch)`，避免整表载入内存；并内置行数上限（配置项 `lychee.export.max-rows`，默认 200,000）超限抛业务异常。
- 列头国际化：行 DTO 上 `@ExcelProperty` 写 i18n key，`ExcelWriteSupport` 写入前经 `MessageService` 按 `ctx.locale()` 解析（或 Handler 自行组装动态列头 `List<List<String>>`，两种方式框架都支持）。

## 5. 异步执行与上下文传递（对齐 MRP 范式）

```java
// ExportJobServiceImpl.create —— 事务内
ExportJob job = saveJob(request, ExportJobStatus.PENDING);
Authentication auth = SecurityContextHolder.getContext().getAuthentication();
eventPublisher.publishEvent(new ExportJobCreatedEvent(job.getId(), CurrentTenant.tenantId(), auth));

// ExportJobEventListener
@Async("exportTaskExecutor")
@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
public void handle(ExportJobCreatedEvent event) {
    SecurityContextHolder.getContext().setAuthentication(event.authentication());
    try {
        TenantContextHolder.setTenantId(event.tenantId());
        exportJobService.markRunning(event.jobId());          // REQUIRES_NEW
        executeAndUpload(event.jobId());                       // Handler + OSS
        exportJobService.markCompleted(event.jobId(), ...);    // REQUIRES_NEW
    } catch (Exception e) {
        exportJobService.markFailed(event.jobId(), e.getMessage()); // REQUIRES_NEW，截断 500
    } finally {
        TenantContextHolder.clear();
        SecurityContextHolder.clearContext();
    }
}
```

线程池（新增，不影响 MRP 现状）：

```java
@Bean("exportTaskExecutor")
ThreadPoolTaskExecutor exportTaskExecutor() {
    // core=2, max=4, queueCapacity=20, threadNamePrefix="export-"
    // RejectedExecutionHandler：AbortPolicy，创建侧捕获后将作业置 FAILED（提示稍后重试）
}
```

同步快路径：`count ≤ lychee.export.sync-threshold`（默认 5,000）时不发事件，直接在请求线程调用同一段 `executeAndUpload`，响应即返回 `COMPLETED` 作业。

文件生成使用 `Files.createTempFile` 临时文件而非内存 buffer，上传 OSS 后 `finally` 删除。

## 6. REST API（`/api/v1/report/export-jobs`，返回统一 `ApiResponse<T>`）

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | `/` | 按 Handler 的 `requiredAuthority` 动态校验 | 创建作业。Body：`{ jobType, params, sort }`。响应含 `id/status`（同步完成时直接 `COMPLETED`） |
| GET | `/{id}` | `/report/export-jobs:read` | 轮询状态 |
| POST | `/page` | `/report/export-jobs:read` | 导出中心列表（ProPageRequest，`@TenantId` 自动限租户） |
| GET | `/{id}/download-url` | `/report/export-jobs:read` | 校验 `COMPLETED` 且未过期 → `StorageService.generateSignedUrl(path, 300)` 实时签发 |
| DELETE | `/bulk-delete` | `/report/export-jobs:delete` | 删除作业记录并删除 OSS 文件；RUNNING 状态不可删 |

## 7. 前端设计

### 7.1 服务层（`src/services/report/export-job/`）

`endpoints.ts` 增加 `report.exportJobs` 路径组；`api.ts` 提供 `createExportJob / getExportJob / getExportJobPage / getDownloadUrl / deleteExportJobBulk`；`model.ts` 定义 `ExportJob`、`ExportJobStatus`。

### 7.2 通用工具与 Hook

```
src/utils/download.ts
  downloadByUrl(url: string): void        // 动态 <a href download> click；签名 URL 无需 Authorization

src/hooks/useExportJob.ts
  const { runExport, exporting } = useExportJob();
  runExport(jobType, pageRequest)
    ├─ createExportJob → COMPLETED?→ 直接 getDownloadUrl → downloadByUrl → message.success
    └─ PENDING → notification（可关闭，提示"导出处理中，可稍后到导出中心下载"）
        → 3s 间隔轮询 getExportJob（上限 5 分钟，超时提示去导出中心）
        → COMPLETED → 自动下载 + 成功提示；FAILED → error 提示 errorMessage
```

### 7.3 共享 `ExportButton`（对齐 `AddButton`/`BatchDeleteButton` 范式）

```tsx
<ExportButton
  jobType="SCM_SUPPLIER"
  getPageRequest={() => lastPageRequestRef.current}  // 页面持有最近一次查询条件
/>
// 内部：useAccess().canAction(pathname, 'export') 不满足则不渲染
```

列表页在 `request={...}` 包装函数中把 `toPageRequest(params, sort)` 存入 ref，保证「导出的就是当前筛选的」。

### 7.4 导出中心页面（`src/pages/report/export-jobs/index.tsx` → `/report/export-jobs`）

- ProTable 列：作业类型（valueEnum + i18n）、状态标签（复用 MRP `renderStatusTag` 风格）、文件名、行数、大小、耗时、创建人/时间、过期时间；操作列「下载」（仅 COMPLETED 且未过期）。
- 轮询：复制 MRP 范式——`onLoad` 检查是否存在 RUNNING/PENDING，有则 `polling=3000`。
- 菜单/权限：后端菜单数据新增 `/report/export-jobs` 节点与 `read/delete` 权限；三语 `menu.ts`、`pages.ts` 补充 key（`menu.report.export-jobs`、`pages.report.exportJobs.*`）。
