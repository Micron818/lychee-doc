# 07 — 示例：物料标准成本（MaterialCost）Excel 导入

作为导入框架的首个落地案例，验证「模板下载 → 上传 → 校验落库 → 错误报告」完整闭环。  
前置：[06 导入框架总体设计](./06-导入框架总体设计.md) 的框架能力就绪。

## 1. 为什么首例选 MaterialCost

| 理由 | 说明 |
|------|------|
| 业务刚需 | 财务开账/期间切换时常需批量维护标准成本；期间结转虽有 `carryForward`，新建期间与调价仍依赖手工录入 |
| 模型清晰 | 业务键稳定：`company + material + fiscalPeriod + STANDARD_COST`；组件成本加总规则已在 Service 内 |
| 导入价值高 | 单条 UI 录入效率低；Excel 批量是典型场景 |
| 约束可测 | 仅允许手工标准成本；来自成本计算（`costCalculationId != null`）的行只读；重复键与公司-期间匹配均可验证 |

## 2. 业务规则（导入侧必须遵守）

对齐现有 `MaterialCostServiceImpl`：

1. **仅导入 `CostMethod.STANDARD_COST`**。Excel 不出现成本方法列；Handler 写死 `STANDARD_COST`。`ACTUAL_COST` 由成本计算产生，禁止手工导入。
2. **业务键**：`(companyId, materialId, fiscalPeriodId, STANDARD_COST)`。同一键至多一条「可维护」记录语义上由 Service 的 duplicate 校验与 activate 互斥保证。
3. **`unitCost` 不导入**：由 `materialCost + laborCost + overheadCost` 计算（`applyCostComponents`，精度 6 位）。
4. **UPSERT**：
   - 键不存在 → `createMaterialCost`
   - 键存在且 `costCalculationId == null` → `updateMaterialCost`（可改成本组件 / 激活）
   - 键存在且 `costCalculationId != null` → **行失败**（`validation.material_cost.from_calculation.readonly`）
5. **CREATE_ONLY**：键已存在 → 行失败（`validation.material_cost.duplicate`）。
6. **`isActive`**：空则新建默认 `true`；`true` 时走现有 deactivate 同键其他有效行逻辑；`false` 则写入非有效。
7. **公司与期间**：期间必须属于该公司（`validatePeriod`）；物料必须存在。
8. Excel 使用 **业务编码** 而非内部 ID：公司编码、物料编码、会计年度、期间号。

## 3. 模板与导出行 DTO

### 3.1 列定义（Sheet「数据」）

| index | 字段 | i18n key（列头） | 必填 | 说明 |
|------:|------|------------------|:----:|------|
| 0 | companyCode | `pages.table.company` 或 `pages.fi.materialCost.import.companyCode` | ✓ | 公司编码 → `companyId` |
| 1 | materialCode | `pages.table.material` / `...import.materialCode` | ✓ | 物料编码 → `materialId` |
| 2 | fiscalYear | `pages.fi.fiscalPeriod.fiscalYear` | ✓ | 会计年度 |
| 3 | periodNo | `pages.fi.fiscalPeriod.periodNo` | ✓ | 期间号（1–12 等，与 FiscalPeriod 一致） |
| 4 | materialCost | `pages.fi.materialCost.materialCost` | ✓ | 材料成本 |
| 5 | laborCost | `pages.fi.materialCost.laborCost` | ✓ | 人工成本 |
| 6 | overheadCost | `pages.fi.materialCost.overheadCost` | ✓ | 制造费用 |
| 7 | isActive | `pages.fi.materialCost.isActive` | | 空=新建默认 true；布尔或是/否/Y/N（按 locale 解析） |

> 建议新增专用 import 列头 key（`pages.fi.materialCost.import.*`），避免与列表「公司/物料」展示文案冲突；三语写入前后端 messages。

不出现在模板中的字段：`id`、`unitCost`、`costMethod`、`costCalculationId`、`calculatedAt`、审计列。

### 3.2 行 DTO

模板生成时列头列表按 index 顺序用 `MessageService` 解析；`ExcelReadSupport` 导入时用同一列表做首行校验。

### 3.3 说明 Sheet（可选，推荐一期带上）

第二 sheet「说明」纯文本：

- 仅导入标准成本；勿改列顺序与列头。
- 业务键 = 公司编码 + 物料编码 + 年度 + 期间号。
- 单位成本 = 材料 + 人工 + 制造费用（系统自动计算）。
- 来自成本计算的标准成本行不可被导入覆盖。
- `isActive` 取值说明（三语在模板生成时按 locale 写入）。

## 4. 后端：`MaterialStandardCostImportHandler`

### 4.2 Handler 骨架

```java
@Component
@RequiredArgsConstructor
public class MaterialStandardCostImportHandler implements DataImportHandler {

    private final MaterialCostService materialCostService;
    private final MaterialCostRepository materialCostRepository;
    private final FiscalPeriodRepository fiscalPeriodRepository;
    private final BasisCacheService basisCacheService;       // 公司列表
    private final RemoteMaterialService remoteMaterialService; // 需扩展按 code 查询，见 §4.3
    private final MessageService messageService;

    @Override public ImportJobType type() {
        return ImportJobType.FI_MATERIAL_STANDARD_COST;
    }

    @Override public String requiredAuthority() {
        return "/fi/material-costs:import";
    }

    @Override public Class<?> rowType() {
        return MaterialStandardCostImportRow.class;
    }

    @Override
    public void writeTemplate(OutputStream out, Locale locale) {
        // ExcelWriteSupport 或专用 TemplateWriter：写表头 + 可选 1 行示例 + 说明 Sheet
    }

    @Override
    public ImportResult importData(ImportContext ctx, InputStream source) {
        ImportMode mode = parseMode(ctx.options());
        List<String> headers = expectedHeaders(ctx.locale());
        // 预热：公司 code→id；可按批收集 materialCode 批量解析
        return ExcelReadSupport.readPaged(
            source, MaterialStandardCostImportRow.class, headers, ctx,
            batch -> persistBatch(batch, mode, ctx));
    }
}
```

### 4.3 编码解析（实施时需补的远程能力）

当前 `RemoteMaterialService` 仅有 `getMaterials(Set<Long> ids)`，导入需要按编码解析：

| 依赖 | 解析方式 |
|------|----------|
| 公司 | `BasisCacheService.getAllCompanies(tenantId)` 建 `code → id` Map（公司数量小） |
| 物料 | **扩展** `RemoteMaterialService`：`Optional<RemoteMaterialDTO> findByCode(String code)` 或 `Map<String, RemoteMaterialDTO> findByCodes(Set<String> codes)`（MM 模块实现，租户内 code 唯一） |
| 期间 | `FiscalPeriodRepository.findByCompanyIdAndFiscalYearAndPeriodNo(companyId, year, periodNo)` |

物料批量解析优先 `findByCodes`，避免每行一次远程查询。

### 4.4 单行处理伪码

```java
void persistRow(MaterialStandardCostImportRow row, int excelRow, ImportMode mode, List<ImportRowError> errors) {
    Long companyId = resolveCompany(row.getCompanyCode());      // 失败 → errors.add
    Long materialId = resolveMaterial(row.getMaterialCode());
    FiscalPeriod period = fiscalPeriodRepository
        .findByCompanyIdAndFiscalYearAndPeriodNo(companyId, row.getFiscalYear(), row.getPeriodNo())
        .orElseThrow(...);                                      // → 行错误

    MaterialCostRequest req = new MaterialCostRequest();
    req.setCompanyId(companyId);
    req.setMaterialId(materialId);
    req.setFiscalPeriodId(period.getId());
    req.setMaterialCost(row.getMaterialCost());
    req.setLaborCost(row.getLaborCost());
    req.setOverheadCost(row.getOverheadCost());
    req.setIsActive(parseBoolean(row.getIsActive()));         // null 合法

    Optional<MaterialCost> existing = materialCostRepository
        .findByCompanyIdAndMaterialIdAndFiscalPeriodIdAndCostMethod(
            companyId, materialId, period.getId(), CostMethod.STANDARD_COST);

    try {
        if (existing.isEmpty()) {
            materialCostService.createMaterialCost(req);
        } else if (mode == ImportMode.CREATE_ONLY) {
            throw new ValidationException("validation.material_cost.duplicate");
        } else if (existing.get().getCostCalculationId() != null) {
            throw new ValidationException("validation.material_cost.from_calculation.readonly");
        } else {
            materialCostService.updateMaterialCost(existing.get().getId(), req);
        }
    } catch (ValidationException | NotFoundException ex) {
        errors.add(new ImportRowError(excelRow, row.getMaterialCode(), translate(ex)));
    }
}
```

### 4.5 是否需要 `upsertForImport`

一期可直接调现有 `create` / `update`。若 profiling 显示每行 `reloadResponse` + `fillMaterial` 过重，再在 `MaterialCostService` 增加：

```java
/** 导入专用：跳过响应富化，仅返回 id；规则与 create/update 一致 */
Long upsertStandardCostForImport(MaterialCostRequest request, ImportMode mode);
```

文档约束：业务规则仍只维护在 Service 一处，Handler 不复制 duplicate / readonly / 期间校验逻辑。

### 4.6 文件内重复键

同一 Excel 内两行相同业务键：

- 按出现顺序处理；后行覆盖前行（UPSERT）或后行失败（CREATE_ONLY 在首行已成功后）。
- 可选增强：预扫检测文件内重复并全部标错——一期不强制，可在说明 Sheet 提示「请勿重复键」。

## 8. 交互验收标准

1. 无 `import` 权限时 `ExcelImportButton` 不渲染。  
2. 下载模板：列头为当前 UI 语言；含说明 Sheet。  
3. 用模板填 10 行合法数据 UPSERT：全部成功，列表可见，`unitCost` = 三成本之和，`costMethod=STANDARD_COST`。  
4. 重复导入同一文件 UPSERT：幂等更新（成本变更生效）。  
5. CREATE_ONLY 对已存在键：行进错误报告，其它行成功。  
6. 物料编码不存在 / 期间不属于公司 / 列头被改：分别行失败或作业失败，消息可理解。  
7. 覆盖 `costCalculationId != null` 的标准成本行：该行失败，文案指向只读。  
8. 失败报告可下载，含行号、物料编码、错误信息；修正后重导成功。  
9. 超过 `sync-threshold` 的文件：异步作业 + 导入中心可查；完成后通知。  
10. 租户隔离：租户 A 作业对租户 B 不可见。
