# 用户训练文档写作约定

> 适用于 `lychee-doc/user_training/` 下全部文档。

## 1. 语言

- **源语言：中文（zh）**。所有业务含义以中文稿为准。
- **同步语言：越南文（vi）**。路径与文件名与 `zh/` 一一对应（仅正文语言不同）。
- **不维护英文用户手册**。界面若显示英文，训练文档仍用中文描述菜单中文名，并在术语表标注缩写。
- 修改中文后：在变更说明中标注「vi 待同步」；越南文 PR 只做翻译对齐，不改流程逻辑。

## 2. 受众与语气

- 读者是操作人员与业务主管，不是开发。
- 使用「请进入…」「点击…」「确认状态变为…」。
- 禁止粘贴 API 路径、类名、SQL、内部枚举英文堆砌；必要时在「状态说明」用表格给出「界面用语 ↔ 含义」。
- 可引用研发文档作规则来源，但必须改写成用户语言，并在文末「规则来源」用相对路径标注（可选）。

## 3. 单篇结构（剧本 / 手册强制）

```markdown
# {标题}

> 受众：{角色} | 模块：{ADM/BASIS/MM/...} | 版本：YYYY-MM-DD
> 预计时长：{分钟} | 语言：zh

## 1. 业务目标
## 2. 前置条件
## 3. 操作步骤
## 4. 状态与权限说明
## 5. 验收标准
## 6. FAQ / 禁忌
## 7. 练习题（可选，课堂用）
```

角色手册可将「操作步骤」改为「日常工作清单」；速查文档可只保留入口、状态、禁忌三节。

## 4. 菜单与按钮写法

- 菜单路径使用界面中文名，用 `→` 连接，例如：`采购管理 → 采购订单(PO)`。
- 按钮、状态用「」括起，例如：点击「提交」、状态变为「已审核」。
- 缩写首次出现写全称：`销售订单（SO）`，其后可只用 SO。
- 与 [`glossary.md`](./glossary.md) 冲突时，以术语表为准并回改正文。

## 5. 截图

- 存放：`assets/screenshots/{module}/`，例如 `assets/screenshots/scm/po-print-toolbar.png`。
- 文件名：英文小写 + 连字符；同一截图中越共用，**不按语言各存一份**（除非 UI 语言导致版面差异且必须对照）。
- 截图环境：固定训练租户与示例主数据；避免真实客户隐私。
- Markdown 引用使用相对路径：`![说明](../../assets/screenshots/scm/xxx.png)`（按文件深度调整）。
- 正文以步骤可独立完成为准；截图为辅助，缺图不阻塞先发文字版。

## 6. 版本与状态标记

文首元数据建议：

| 字段 | 含义 |
|------|------|
| 版本 | 文档修订日期 `YYYY-MM-DD` |
| 状态 | `草稿` / `可试讲` / `已定稿` |
| vi 同步 | `不适用` / `待同步` / `已同步 YYYY-MM-DD` |

定稿后的流程变更须同时改剧本、术语表（若有新词）、本仓库 README 索引。

## 7. 与代码 / 设计文档的边界

| 文档位置 | 读者 | 内容 |
|----------|------|------|
| `lychee-doc/user_training/` | 用户、实施、培训师 | 操作步骤、验收、禁忌 |
| `lychee-doc/system_design/` | 研发 | 技术方案、SPI、架构 |
| `lychee-backend/docs/` | 研发 | Schema、状态机、实现计划 |

训练文档需要状态规则时，从设计文档**翻译**过来，不整段复制。

## 8. 越南文翻译检查清单

- [ ] 路径与 `zh/` 文件一一对应  
- [ ] 菜单名与系统 `vi-VN`（或现行越南语）界面文案一致  
- [ ] 缩写（SO/PO/GR…）保持与中文版相同  
- [ ] 步骤编号与验收标准与中文版一致（禁止擅自增删业务步骤）  
- [ ] 更新 `vi/index.md` 同步状态表
